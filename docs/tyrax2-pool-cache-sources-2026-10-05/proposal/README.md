# Private same-ELF pool geometry/color cache diagnostic

This proposal starts from frozen night-ablation-physical-v3 and adds a real baseline/candidate selector to one poolBatchFlush transformation. It is not a night-mask cut, production mode, accepted native/runtime result or measured improvement. Root alone owns eventual new-fixture integration, source/assets freeze, compilation and devices. Original frozen fixtures, split-only proposal, repository and outputs remain unchanged.

NightPlan kind 4 accepts `4 order 0 0`, uses ordinary and extra masks zero, and sampler On in all three phases. Order 0 is baseline/candidate/baseline; order 1 is the reverse. Kinds 0..3 always select baseline. The flag is applied at phase boundaries before beginLoop, independently from sampler mode. The original 5,400-loop / 384-sample clock protocol, normal present, night time, geometry, camera and HUD are retained. Arm changes preserve warm cache state; the phase warm region precedes tax800/sample900 rather than introducing a cache reset.

Both arms build the original seven-word ordered member key and run the same reason comparison. The baseline branch retains the exact original full rebuild statements. The candidate branch is the separately reviewed geometry/color split: identity/order/cardinality/vertex/ST stamp changes rebuild all streams and bbox; RGB/FIX-only changes rebuild and bind colors, preserve vertex/ST arrays and stamps/count/bbox, and keep original color arithmetic and order. A separate flag really selects those distinct bodies. No wait, fence, mutable-stream lifetime, shader, texture, geometry or pipeline policy changes.

Only existing poolBatchAdd eligibility is optimized: non-volume scene spot pools with flashGoboTex match and single source color. Torch/receiver/beam work and volume paths are not the candidate's bill. A cut of the complete Pools family is an upper-context diagnostic, not achievable cache savings. Earlier helper/rebuild notes and split-only target compilation are historical evidence and cannot be transferred as current native/runtime acceptance.

Pool witnesses run only on frames750/1155 using existing collectCounters. Counters describe nonempty eligible flush attempts, unchanged/geometry/color-only reasons, initial subset of geometry, actual selected geometry/color-only actions and total eligible batch vertices. They are reset only on those sparse frames; invalid/overflow rejects a capture. No observer field is written in tax/sample windows. NIGHTPOOLPHASE/NIGHTPOOLGATES bind separate flag and counter schemas rather than repurposing night mask fields. Sparse zero color-only observations mean activation is unproven; they cannot establish zero full-window hits. Sparse positive observations show the selected action only on those frames, not a full-window count. Geometry/cache key comparison, flag branches, code/layout and cold recording are common source costs and remain unpriced.

Baked streams fold color content stamps, while retained blocks REF current arrays. The candidate retains original color binding/mutation lifetime; no new target borrowing or retirement proof is asserted. Full 2^32 stamp collisions, unstamped edits and original unkeyed metadata remain inherited limits. Actual R5900, partial/direct/baked/retained routes and appearance still need root's independent gates.

The fresh exact-function oracle uses the actual V3 original function, actual generated BagArray and actual Color header/constructor. Explicit host Vec4/renderer/matrix/bag ABI shims are disclosed. O0/O2 byte/version tests exercise old/new flag changes without resetting caches, all16 bytes of vertex/ST/color output, RGB/FIX-only stable geometry, membership/order/source/lifecycle changes, wrap crossing, randomized valid sequences, reasons/actions, empty/zero-vertex batches and counter inactivity/overflow. Host parity is neither PS2 floating-point parity nor DMA/GS correctness. Actual-function O0/O2 controls passed 1,329 cases / 11,722 checks each. Fresh plan/runtime/parser controls passed 20 complete 5,400-loop transcripts (kinds0..4, bothorders, O0/O2), 47 strict negatives, 21 malformed configuration checks per run and an actual kind4 CLI invocation. All three counter structures stay byte-identical outside750/1155; original sampler/alias/analyze-loop bytes remain V3-identical.

The comparison is each candidate's own same-ELF baseline in both orders, all sampler arms On. There is no constant fee subtraction, no source-cross subtraction, no additive accounting of coupled light/receiver masks, no 60 FPS or positive-benefit claim. PLAN.md records the approved interface. Root-only integration helpers verify pinned inputs before any write and only create a new external destination; no launch/build is performed by this package.
