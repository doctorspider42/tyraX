# Night-only eleven-object static-batching review

Read-only source audit and design archive. No source candidate, source mutation, build, emulator, hardware operation, new elapsed measurement or performance estimate was produced. Repository files and the frozen companion-census fixture were inspected. `source-pins.json` binds the reviewed bytes and records the prior eleven-object mapping audit.

## Eligibility and the actual opt-out

The selected scene0 rows111..121 are eight warm window boxes and three garage trim/blade boxes. They are one-part primitive boxes with no collision (`collision=2`), no physics, `dynLit=0`, unlimited draw distance (`0`), and authored `batchStatic=0`. All eleven are also **reflected**. Their stable IDs are documented in the earlier `night-main11-source-review-v1/report.md`.

`examples/vehicle-playground/authoring/build-district.py:247-248` creates these night boxes with `reflected=True`. `src/templates.cpp:8078` rejects `o.reflected` in `staticBatchEligible`; `src/staticbatch.cpp:237` reports `Reason::Reflected`. The source contract is explicit in `src/templates.cpp:8008-8040`: reflection and portal consumers resubmit individual objects and do not consume the merged main-view batch. The inference that reflection explains this authored opt-out is supported by that contract; no separate author statement about intent is available. A deliberate per-object visibility opt-out is not established.

Generated `game_collision.gen.cpp:2170` admits only `batchStatic` rows. The runtime builder additionally excludes matrix owners, reflective materials, oversized model spans, incomplete multi-part groups and surviving singleton groups (`:2171-2255`). The selected primitive materials do not contain reflection textures. Their **object-level** reflected flag is the important authoring exclusion.

Forcing `batchStatic=1` alone is unsafe. `buildStaticBatchList` clears scene-load dirty for true members (`:2256-2274`); the main object loop skips them (`game_physics.gen.cpp:1847-1849`). Individual geometry starts empty on scene load (`game_scene.gen.cpp:1076-1093`). Shared-env reflection (`game_physics.gen.cpp:1449-1474`) and per-object reflection (`:2964-2980`) still iterate reflected members, but rebuild only if dirty. A newly force-batched object can therefore have neither dirty nor an individual bag when an unchanged reflection consumer reaches it.

Changing `reflected=false` is not an equivalent optimization: it removes authored reflection content and changes the reflection reuse/content key (`game_physics.gen.cpp:1337-1355`). Neither force flag is proposed for production.

## What existing batching already preserves

`DistrictMood::update` changes visibility once per mood or scene generation (`scripts/district_mood.cpp:15-34`). It does not mark geometry dirty when toggling visibility. `renderStaticBatches` compares each member's active/visible state with its shown snapshot and rebuilds a stale batch (`game_collision.gen.cpp:2690-2711`). It skips empty output. Thus jointly hiding or showing eleven members is expressible with the existing visibility contract.

`rebuildStaticBatch` owns combined vertices, colors and ST arrays (`:2307-2315`). It stages probe illumination explicitly, then stages each member's AO/emission inputs from that member's center/radius (`:2355-2379`). Primitive material Kd/Ke, texture and UV inputs are selected per member (`:2429-2447`). `pushVert` in `game_runtime.gen.hpp:1163` applies member transforms and material inputs. The cyan and pink rows sharing one null-texture group do not imply a single group color. Reused batch storage receives a new bboxVersion (`game_collision.gen.cpp:2468`) and world-space identity model. The package pin and culling setup are at `:2479-2484` and `:2054-2061`.

These source mechanisms support preserving member material and transform semantics. They do not prove byte-identical output for this unimplemented experiment. Batch center/radius also change dynamic-light selection and culling/package partitioning. `dynLit=0` on authored rows must not be treated as proof that every shader-selection difference is irrelevant. A larger AABB can accept geometry whose original object was culled; output ordering and depth/clip boundaries change. The existing lamp grouping heuristic is not a numerical equivalence oracle.

## Narrow main-only design: separate carriers, independent invalidation

An isolated generated-game experiment could retain the original `ObjectGeometry::parts` as owned carriers for secondary views and use additional merged bags only for main-view submission. This needs private selection/preparation changes; it is not supported by changing the existing flag alone. No new public engine API is required by the design, but no implementation is authorized by this archive.

1. Select only the eleven stable authored IDs in scene0, with explicit runtime guards for primitive type, one part, nonmoving matrix ownership, materials and the reviewed source contract. Keep reflected/visibility/light/effect flags unchanged. Build only their three predicted subset groups rather than admitting them into unrelated existing groups. Record actual membership before interpreting results.
2. Keep normal individual geometry storage and bag ownership for these objects. A main-only membership map must not mean "individual carrier absent". Existing scene-load `objectGeometry` initialization remains. Prepare missing carriers with the original object geometry builder at a safe point before any secondary consumer; preparation must use the normal illumination/material staging. Both benchmark arms must pay common carrier/group setup, with that absolute setup/footprint explicitly unpriced if excluded from windows.
3. Separate membership/invalidation from the shared dirty bit. `rebuildObjectGeometry` clears dirty immediately (`game_collision.gen.cpp:1103-1106`). Shared-env reflection precedes `renderStaticBatches` (`game_physics.gen.cpp:1216`, reflection rebuild `:1467`, batch render `:1563`). Consequently a dirty reflection rebuild can otherwise erase the signal that would demote or invalidate a batch. This is an existing known pattern: portal and outline consumers deliberately avoid rebuilding dirty batched members (`game_physics.gen.cpp:3502-3507`, `:4474-4479`). Reusing only the lazy-empty-carrier pattern does not solve dirty selected members.
4. The conservative design is a private pre-secondary-view reconciliation at a safe frame boundary: detect selected members with dirty or changed eligibility; demote each from main-only groups and mark the affected group dirty **before** a secondary consumer can clear the bit. Let the ordinary solo preparation/render path handle the changed object. Missing unchanged carriers can be built there without consuming a pending demotion signal. Do not temporarily clear and restore shared dirty around a renderer call: callers may mutate more than that scalar and existing consumers rely on its ordering. Day/night visibility alone changes group shown-state, not membership or individual geometry.
5. Demotion must be idempotent for split views and all subsequent renders in one frame. An off-arm must not trigger demotion merely because it uses original individual bags. Existing regular `objectBatchOf` behavior should remain unchanged for unrelated objects; a private main-only map should avoid changing portal/shadow/outline branches that interpret global membership. If a transform/material mutation occurs, the member remains solo until an explicit safe regroup event; no implicit per-frame regroup.
6. Submit original individual bags in secondary views. Skip only the selected **main-view** draw when the candidate is enabled and its current merged representation is valid. On the control arm submit the original main bags, without a merged main draw. No arm may change reflection content-key inputs or reflection cadence to create a different workload. Pass selection must distinguish split-screen main views from secondary portal/mirror/env cameras; do not assume every `renderScene` invocation is the only main view.
7. Keep existing synchronization and ownership guarantees. Group buffers and individual vectors must coexist; merged bags must own copies rather than borrowing member vectors that a rebuild can resize. Preserve submitHeavy, existing VIF1 waits/batches and GS target transitions. No rebuild, resize, reset or phase switch can release arrays still referenced by an outstanding chain. The original per-object submission ownership comment is at `game_physics.gen.cpp:1825-1826`. Existing scene switches clear individual storage (`game_scene.gen.cpp:1076-1077`) and static group storage (`game_collision.gen.cpp:2050`); any extra private membership/carrier state must reset with that same scene generation and retain the original synchronization order.

This design is compatible with independent carriers in principle. Compatibility is conditional on pre-consumer dirty reconciliation, explicit pass selection, source-identical carrier preparation and original DMA lifetime rules. The current engine has useful precedents for solo carriers alongside batches, but no all-reflection-safe main-only ownership contract proven by this audit.

## Qualification before interpreting any measurement

Use a private same-ELF candidate toggle with both orders and unchanged full-night workload. Cold witnesses should establish actual group/member counts, no duplicate main submission, accepted/culled group status, original individual carrier count/readiness, material/transform keys and no unexpected demotion. Do not infer these from eleven authoring rows or predicted groups.

Compare each merged member's original positions/colors/ST and exact numerical transform/material inputs against its separately prepared carrier under matching illumination; offsets may differ, but vertex/order semantics must be defined. Check actual lighting selection inputs and conservative cull differences rather than asserting equality from dynLit0. Preserve every reflection consumer's selected member geometry/visibility and content-key inputs; aggregate reflection counts alone are insufficient if the reflection cadence differs between phases. Qualify day/night toggles, scene reset, split main views and camera movement; inject an isolated dirty transform/material change outside priced windows to exercise demotion and carrier lifetime. Any mode that cannot preserve a selected member must fall back to its original main submission.

Only after semantic and target ownership qualification can timing address whether fewer main bags help. This archive makes no elapsed, fps, gain or release claim.
