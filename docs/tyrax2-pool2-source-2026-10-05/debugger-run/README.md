# Root-owned observed Run action

Exact source supports Run action, while source-confirmed Space binding does not guarantee direct XSendEvent key delivery to an unfocused Qt render child. Actual root launch PID13513 demonstrated that boundary: Space resumed an initial BIOS pause; a second --window Space after debugger focus did not resume the ELF-entry pause. Root's observed Run button click relative110,47 in client1322x974 succeeded. Those live observations belong to root's archived screenshots/logs, not this source-only helper.

owned-observed-run.py preserves that narrow observed click contract. It requires a root-authored observation JSON binding pid/window/display, dimensions1322x974, x110/y47, observedAction Run, observedPhase ELF-entry-pause, exact observedPC equal the diagnostic ELF entry, screenshot path and SHA256. Default preparation reads only files and writes a NEW plan. --execute is root-only: it rechecks actual /proc executable/cmdline, launch ELF/profile, live _NET_WM_PID and debugger title, exact geometry, paused PINE state and absence of READY/REJECT before one XTEST mouse click. It never assumes key --window activates/focuses a Qt widget. No retries or final-halt release are allowed.

Root creates this record from the current observed owned UI; do not reuse screenshot/window IDs across fresh processes. If layout/geometry/action differs, this helper rejects and root must observe a new reviewed control route. Run dispatch alone is not accepted guest resume, ready/halt or output correctness. Require source-bound protocol and exact final paused PC/ready marker/SaveState separately. Both status-before and status-after may be1 after a short completed guest run.

For future fresh launches, root may use StartPaused=false while retaining -debugger. The actual first launch had StartPaused=true, giving initial BIOS pause and later automatic ELF-entry pause. One unconditional Space/click after any paused status would therefore be ambiguous. This helper permits only root-observed actual ELF-entry pause and no protocol READY. Preserve original launch/profile/failed key-delivery evidence before changing a future launch helper.
