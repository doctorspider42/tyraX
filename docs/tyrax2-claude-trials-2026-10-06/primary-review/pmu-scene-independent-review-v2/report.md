# PMUv2 independent source review

Source/control-order review PASS as unreleased draft, not source-freeze or hardware-lifetime approval. Review ran no builds, harnesses, emulator or console operations. Manifest501 hashes and existing root host harness source/log bindings match. Manifest frozen=false and source-freeze runtime gate remains blocked.

No COP0 Count write/read or new waits in PMU namespace. Configure799 observes PCCR immediately before writing and refuses any enabled configuration. Scene entry accepts only previously known stopped PCCR0x000340d0; reset counters occurs before enable0x800340d0. Both arms use the same128 reset/enable/stop sequences and384 common PCCR reads. On alone adds four ordered mfpc/sync reads per sample,512 total and128 raw rows. Ordered I/D reads span slightly different intervals and cannot imply simultaneous exact boundaries.

Unknown entry or pre-stop changed PCCR remains untouched. RAII ordinary returns stop the still-owned exact active configuration; changed scene/frame invalidates data but still stops known PMU ownership. Missing, nested or multiple Scene attempts, wrong stopped readback, endpoint high bit/decrease and incomplete rows invalidate acceptance. Cleanup is read/verify only. Ownership is local-state plus configuration-value identity, not a global reservation: a foreign owner adopting the same PCCR value cannot be detected; check/write races remain possible without a qualified ownership environment.

Existing actual-source host fake wrapper harness proves ordered control/state behavior, unknown setup/entry/exit untouched, early return, nesting, frame/context changes and overflow-shaped endpoint rejection under its fake values. It does not execute real wrappers, count events or prove hardware exception/lifetime semantics. Existing synthetic parser controls reject wrong config/counts, missing stops, ownership, missing/duplicate/Off rows and invalid endpoints. Parser explicitly labels raw activation/provisional differences only, common serialization unpriced, no miss totals or safety claim. Runtime guard demands frozen source AND boundedEnabledLifetimeQualified plus runtimeReleaseBlocked=false before release.

fail() invalidates results but does not permanently disarm subsequent locally-known samples; e.g. a high-bit endpoint is rejected after stopping, but later scopes may enable again. This is an operational limitation, not acceptance of those results, and reinforces keeping runtime blocked. The inherited Scene can hang before its destructor; per-Scene enable therefore has no prospective lifetime bound. Primary31-bit unmaskable-overflow and missing maximum event-rate qualification remain release blockers.

## Compile-only assembler gate proposal

The adjacent proposed TU mechanically copies the exact current non-host wrapper definitions from the pinned header and exports six noinline/used functions: pmu_opcode_readPcr, readI, readD, configureStopped, resetEnable, stopOwned. Compile only with the installed EE compiler and target ABI flags, without a game link or runtime launch; disassemble that object with installed EE objdump. Verify mfps PCCR, mfpc PCR0/PCR1, mtps PCCR, mtpc-zero PCR0/PCR1 and sync.p placement in the named exports, no mtc0 Count and no undefined wrapper call. Pin compiler path/version/flags, input header/TU/object/disassembly hashes and actual opcode words. This resolves assembler acceptance/encoding only; full-game linked placement, ownership, overflow and runtime lifetime remain separate gates. This reviewer only wrote the proposal, did not compile it.
