# Private r7-resetdiag loader preparation

This is a diagnostic copy, not a reset fix. The user confirms the resident console loader is r7; the earlier local-artifact version ambiguity is therefore not a claim that the console is running r6. No public source was edited, and no emulator, console request, client kill, loader launch or flash was performed. Native EE/IOP builds use the existing WSL PS2DEV and ps2-packer, no Docker.

## Breadcrumb channels and interpretation

IOP `RESETDIAG IOP_RECEIVED_VALID_RESET` is emitted only after validating the six-byte reset command, before SPU2 silence and SIF forwarding. It is an IOP printf on the old resident tty path; queued UDP output can be lost during reset. Missing output does not establish nonreceipt. IOP `RESETDIAG IOP_UDP_BOUND port=18194` is emitted only after the actual command socket bind succeeds.

EE stage2 means pkoReset was entered; stage3 means ResetEE returned after hardware quiesce. Those stages use a volatile ledger plus one GS BGCOLOR privileged-register write (red/yellow), no EE stdio, GIF packets, PMODE mutation or SetGsCrt call. **The colour may be hidden by the running framebuffer or a disabled display circuit; these are not guaranteed visible TV markers.** The ledger symbol addresses are recorded in actual link maps. There is no new dump mechanism: if the EE command thread is stuck, a normal remote dump may also be unavailable.

Only after the original init_scr completes, safe `scr_printf` emits `SCREEN_INITIALIZED stage=4`, then `FRESH_IMAGE_HANDOVER stage=5` immediately before ExecPS2. Fresh main reports the previous ledger value, then stage6 main,7 SIF,8 IOP-reset-begin. Stage9 records accepted SifIopReset in the ledger only: **no screen draw was inserted between that call and the two original BOOTEND polling edges**, to avoid adding a delay in this sensitive interval. Stage10 follows successful IOP reset waits;11 follows the original loadModules return. Actual EE handler initialization prints its thread and DMAC-handler IDs, and `EE_CMD_INIT_RESULT` reports the original initCmdRpc return (stage12 for nonnegative,13 for negative).

Do not interpret stage12 alone as complete loader readiness: require the separate IOP UDP-bound witness, valid EE handler IDs, normal module/error output and ultimately a fresh known-good ELF start. Original loadModules does not validate every module return, and this diagnostic does not change that behavior. All original r7 reset ordering, IOP reboot count, module choices and error handling remain. No per-frame or rendering/audio instrumentation was added. Reset-only output changes timing and footprint; no measured zero-tax claim.

## Native artifacts and residency

- `ps2link-r7-resetdiag-low.elf`: 235444 bytes, SHA256 `4cb4e406a228a6a60d3bcf30b29117fed4f080dfeedd4b3b6abe9802009df42d`, entry `0x94818`; initial load span 0x94000..0xdee60.
- `ps2link-r7-resetdiag-low-packed.elf`: 104196 bytes, SHA256 `df9aedf1328f0f6b1f1d4327e2c4d09c2c701ca12ccaa5df1e3afef8d8c6fde4`, entry `0x1d0001c`; initial load span 0x1cec160..0x1d05c60.
- `ps2link-r7-resetdiag-high.elf`: 235444 bytes, SHA256 `54fb4f0c04188523301f7f9ccab3c3af151f173a95f708249a4949c2ac197a77`, entry `0x1ee8818`; initial load span 0x1ee8000..0x1f32e60.

The packed low artifact initially loads a decompressor/data stub high in RAM, then expands the actual low image at0x00094000..0x000dee60. Actual low image remains below0x00100000 and below the historical noUSB tail that booted from FMCB; this is a size/layout qualification, **not an actual FMCB boot pass**. Low unpacked can overwrite FMCB's active loader and is not the menu artifact. High unpacked occupies0x01ee8000..0x01f32e60 and can collide with a game using the top of EE RAM. None is USB-HID-enabled; normal pad/network paths remain, but keyboard/mouse support is intentionally absent.

**Do not execee a loader over the current resident ps2link as a routine test.** Same-address replacement overwrites the resident loader before handover, and existing pkoRestartImage source records a failed low-over-high network handover too. Even distinct link addresses do not prove safe resident replacement. Safest later qualification is a separately named low-packed artifact booted from a known launcher/cold console under root/user control, using the existing working IPCONFIG.DAT (do not guess the gateway or overwrite the working loader). This preparation provides no flashing/launch automation and keeps the current console run intact. Once the diagnostic banner/address is confirmed and initial loader readiness is demonstrated, a known-good minimal game can test the reset transition while root observes TV and an independently owned UDP console witness. A hung console still requires physical recovery.

## Evidence

`source-manifest.json` pins all authored private sources and unchanged parent identities; five files differ (Makefile version pin, EE declaration/main/reset diagnostics and IOP command diagnostics). `native-proof.json` binds the actual EE/IOP object files, actual embedded local IOP IRX bytes, final full low/high compile logs, link maps, packed artifact and exact compiler/packer/module/stub hashes. Werror builds complete without warnings. No conventional .d files are generated by this inherited loader Makefile; actual compile/link log, source hashes, objects and link maps are retained instead. Focused actual object disassemblies are alongside the proof. Manifest remains frozen=false and runtimeReleased=false pending independent root review; native pass is not device qualification.

The first native path failure (missing PS2SDK/bin), and two packer relative-path failures are retained, including rejected zero-byte packed outputs. `native-v1` preserves the first successful diagnostic binaries before removing a risky screen operation between reset acceptance and BOOTEND waits. The final artifacts listed above contain only the ledger store in that interval. These historical artifacts are not the final candidate.

## Root review repair: GS MMIO width

The earlier native candidate used EE unsigned long (32-bit) for BGCOLOR and emitted sw. That entire candidate is retained under native-v2 and is unqualified; no runtime bug is claimed because it was never executed. The final helper declaration and definition use SDK u64 (tamtypes.h) and a volatile u64 register pointer. Actual final EE object emits `sd a1,224(v0)` with v0=0x12000000, an eight-byte store to0x120000E0. Actual ledger remains an ordinary32-bit volatile store. `actual-resetDiagEarly-final.txt` and native-proof.json bind this instruction. Low/high/packed were rebuilt from fresh objects; no PMODE or runtime execution was added.
