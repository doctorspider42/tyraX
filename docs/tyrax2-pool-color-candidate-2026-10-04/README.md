# Private pool-batch geometry/color split proposal

This is an appearance-preserving source candidate relative to frozen night-ablation-physical-v2, not a measured optimization or accepted target build. It changes only poolBatchFlush in game_lighting.gen.cpp. No existing fixture, repository, device, native build or shader is changed. There is no new borrowing, geometry lifetime rule, DMA ordering, wait or fence.

Eligibility is narrower than the full Pools cut: the existing poolBatchAdd branch accepts scene spot pools only when no spot volume was built, flashGoboTex is present and matches the pool texture, and the pool has a single source color. Torch receivers, beams/coronas and shadow-volume work are outside this batch optimization. The current experiment has no measured color-only hit count. Membership can alternate across partitions or portal views in the same frame, so a static scene does not guarantee hits.

The existing seven-word key and its construction are unchanged. On a changed key, compare each ordered member's identity and vertex/ST content stamps (words 0..2). Any cardinality, identity, order, vertex or ST stamp change rebuilds geometry/ST/colors, rebinds all streams and advances bboxVersion as before. If those fields are equal, update colors only with the exact original RGB * (FIX / 128) expression and member/vertex order, rebind their stamped stream, and retain vertex/ST storage, content stamps, count and bboxVersion. An unchanged full key performs no array write. Empty flush and whole-batch destruction/recreation retain existing behavior. No geometry equality is inferred from colors, positions, a sample, or a bounding box.

The contract depends on genuine BagArray mutation stamps. Unstamped edits, identity truncation off the PS2 pointer ABI, counter collisions after a complete stamp wrap, and exception-safety limitations are inherited contracts, not solved here. The host oracle exercises a bounded wrap crossing; it does not prove freedom from a full 2^32 stamp collision. Source metadata/texture/model changes not represented by the original key retain the original policy, rather than becoming new eligibility claims.

The baked cache key folds the color content stamp, so color changes continue to invalidate baked payload bytes despite stable geometry/bbox. The retained command cache stores REF tags referencing current arrays, not copies of these many-color values; pointer/count changes still invalidate its key. This proposal does not alter either engine cache. Partial/copy paths and final EE/VIF/GS behavior still need root's native/runtime verification; host render capture is not a DMA or retirement model. Multiple pending submissions and color-buffer reallocation inherit the original per-flush mutation and binding sequence; no new lease safety is asserted.

Host controls compile the exact extracted original/candidate functions at O0 and O2 using the actual generated BagArray and actual Color header/constructor. Vec4, renderer, matrix and bag ABI use explicit host shims. Each run passed 1,322 cases / 11,622 checks: exact vertex/ST/color bytes (all 16 bytes per value), member order/count, binding/version ownership, RGB/FIX-only stability, membership replacement/order/duplicates, source geometry/ST changes, grow/shrink, empty flushes, full batch and source recreation, finite/NaN/Inf/signed-zero host arithmetic, bounded stamp wrap and 1,000 randomized valid sequences. Color-only cases require unchanged geometry stamps/pointers/bbox and an advanced color stamp; geometry cases require full refresh. Host floating-point parity is not actual R5900 or pixel parity.

Earlier ee-resumed-pool-reason-census/report.md records historical helper residue around 0.181–0.194 ms, nested submission around 0.704–0.716 ms and roughly 0.25–0.32 rebuilds/frame, with Lamp7 FIX107..110 a plausible cause. That proposal calls its reason observer unexecuted; this new candidate does not upgrade those notes into a fresh qualified capture. They bound expectations qualitatively: the entire mask2 difference cannot be sold as achievable cache gain. Neither historical counters nor broad cut timings establish the color-only portion in the current source/scene.

Before a hardware pricing trial, independently review this source delta and host closure, compile the actual EE code, check color-stamp propagation on direct/baked/retained/partial routes, and verify same-ELF baseline/candidate activation outside measured windows. An eventual benchmark should distinguish unchanged, geometry rebuild and color-only rebuild plus emitted batch vertices; zero color-only hits means inactive. Existing geometry/ST replay costs remain, and observer/common code/layout costs need their own qualification. No target patch is applied automatically by this package.
