Minimal FPP drive is supplied as a route which exits the starting vehicle. No third-person animated ownership qualification follows from these two manifests; root must select a player-model fixture and positive witnesses.

5. `stop-root.py --launch <owned-launch.json>` stops only that exact reviewed PID/exe/profile/ELF and retains all live artifacts. Xvfb remains for explicit root cleanup. Never stop a generic PCSX2 process or unlink other sockets.

Helpers have not been executed to build or launch. ## Additional source fixtures

`prepare-additional-fixtures.py` appended four new source fixtures without overwriting the original vehicle manifests, draft pins or fixture-index.json. Additional pins are in additional-fixture-index.json and individual *-draft.json files. No build or runtime qualification was performed.

- `portals-players`: existing portals scene and camera routes, only public receiver policy/debug settings changed. It checks that portal drawing retains identity and remains visually intact; this authored scene has no point light and cannot prove positive dynamic-light reception.
- `showcase-players`: existing showcase, including authored point lights, portal and mirror. Root can qualify ordinary world lighting rejection and intact secondary views. No 60 FPS claim follows from this debug fixture.
- `animated-all` and `animated-players`: existing small two-players split scene, P2 joined at start, two third-person cat players, two ordinary animated cat models and one red dynamic point light. All four receivers share cat.glb, white base color, scale and the actual nonempty Armature|Armature|ArmatureAction clip (105 channels). Players and models occupy separate nearby positions. Ambient .08 and directional diffuse 0 make the intended point-light contribution visible. The world clones run the same selected clip automatically; actual frame/pose synchronization is unqualified until inspected after boot. Source equality of the selected clip is not equality of runtime animation cursors.

Minimal root sequence is the animated All/Players pair before the expensive showcase. Capture both split views at rest after equal startup intervals; confirm both active players receive the red light while ordinary model clones lose that contribution only in Players mode. Confirm world clones still animate in both modes and both players remain independently controllable. A visual difference alone does not establish which live object received a light: review generated player/animation indices and root-resolved live P1/P2 selection with the corresponding symbol file. Normal livedbg progress/snapshots can witness transforms and flow state, but do not export PipelineInfoBag receiver flags or lighting results. If exact ownership or animation-cursor witnesses are unavailable, record those checks as unqualified rather than inferring them from debug progress. A separate private observer build may be needed; no helper adds production diagnostics or claims that instrumentation survived normal CLI regeneration.
