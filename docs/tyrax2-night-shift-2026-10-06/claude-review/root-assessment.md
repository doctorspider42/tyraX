# Root assessment of the independent Claude CLI report

Claude CLI completed successfully using the configured default model, with 79 recorded Read/Glob/Grep calls and no command, edit, hardware or agent tool. `report.md` is the unmodified returned report. `stdout.jsonl`, the exact prompt and invocation/completion hashes preserve its provenance. The following assessment is separate from Claude's claims.

| Idea | Assessment and next gate |
| --- | --- |
| 1. Companion-pass preparation | Strongest implementation lead. The generated `game_physics.gen.cpp` loop really renders main/AO/emission/environment passes consecutively. First census actual adjacent bag identities and day/night frequency; do not assume every pass has matching geometry or metadata. Reuse only geometric facts with explicit ownership and camera/model/bbox epochs; material, light opt-outs, program/package class, texture state and alpha remain per-pass. No gain is yet priced. |
| 2. Split previous-frame waits | Useful refresh, not a newly discovered missing measurement. October 4 V3 already bound one presentation's pacing to its completion: non-pacing remainder 0.002919/0.003221/0.003219 ms (384-sample mean 0.003120), in that older fixture. The raw 13.8 ms completion number includes pacing. The report incorrectly describes the only relevant wait observation as October 2. Today's renderer layout/sky/clock differs, so an inexpensive same-ELF refresh could check this; no current large wait is demonstrated. |
| 3. EE hardware counters | Sensible way to distinguish instruction/cache effects, conditional on verifying R5900 event selector availability and semantics from primary toolchain/manual sources. A miss count is not critical-path stall time; overlapping misses cannot be multiplied by one assumed latency to produce a CPU bill. Counter setup/read overhead needs its own same-ELF control. Low misses do not prove only one remaining lever. |
| 4. Producer restamps/rebuilds | Concrete source observation; runtime activation remains missing for several producers. Count rebuilds and rescanned vertices by producer before changing invalidation. Retained blocks must still rebuild when live vertex/color data changes. Previously inactive torch-pool findings cannot be generalized to every named producer. |
| 5. Direct bbox handle | Conditional ownership optimization. Guard id/count/program-size/version and cache lifetime; eviction/reindex generation must invalidate handles. A handle does not by itself remove corner-data cache misses. Require measured lookup activity and benefit before widening the public bag ABI. |
| 6. Two-phase preparation | Conditional scheduling experiment, not a free loop reorder. Preserve submitted order, borrowed data lifetime, custom VU parameters and per-pass environment paint writes. Pointer-based descriptors alone do not freeze mutable data. Limit first qualification to owned contiguous passes and verify I-cache relevance. |
| 7. Material descriptor | Plausible adjunct to companion preparation, with renderer residency, mutable material/info, texture relocation and program/package invalidation. Source redundancy is not a measured gain. |
| 8. Move draw assertions | Assertions are active in this build, but blanket removal is inappropriate. A future validated owned-bag path could price redundant checks while retaining safe public entry points. Mutation/scene replacement and borrowed pointer lifetime require checks; one successful first draw is not permanent validity. |

Two additional qualifications: tiny memo gains do not prove the arithmetic itself is cheap, because probe/key costs can consume savings and common disabled footprint is unpriced. No scoped elapsed sum is a pure scalar EE bill. VU0 remains a hypothesis requiring batch size, ownership, transfer/setup and target rounding qualification; the report's decision not to prioritize it is reasonable, not a proof of impossibility.

Recommended next experiment: a cheap, producer-attributed census of actual companion opportunities and geometry rebuilds, comparing the same fixed day/night pose. If substantial owned runs exist, implement a narrow geometric preparation token and price it in both physical orders with unchanged packets/consumer fences. Optionally refresh the existing completion-minus-contained-pacing check for the new fixture, rather than restarting with a disruptive GPU-hold experiment. Hardware counters are a later diagnostic gate if the census does not identify a sufficiently broad active boundary.

No proposal in the report was promoted, built or physically priced during this audit. This completes the requested three leads plus independent review, and leaves full-quality night 60 FPS open.
