# TyraX development

This file holds the rules every change needs. The detail lives in `references/` - **read the reference(s) the index at the bottom names for the area you touch before editing**. `PROGRESS NNN` citations point at entries of the retired `PROGRESS.md` (in git history; `docs/backlog.md` has the recipe). New work records itself in its commit message and PR body.

## What this project is

An editor for the [Tyra](https://github.com/h4570/tyra) PS2 engine (C++20, Dear ImGui docking + GLFW + OpenGL 3.3, Windows, Linux and macOS). It edits a **data model** (scenes, objects, terrain heightmaps, flow graphs, preferences) stored as a `<name>.tyra` manifest plus one `objects/<id>.json` per object, and on every build **generates a complete PS2 game project** (C++ sources, Makefile, docker-compose.yml). The game is compiled by native PS2DEV + vendored OpenVCL by default (Docker is a selectable fallback; image from `docker/Dockerfile` via `.github/workflows/toolchain-image.yml`, `${TYRAX_IMAGE:-h4570/tyra}`; read `docs/toolchain-image.md` first) and launched in PCSX2 or deployed to a real PS2 over ps2link.

```
ImGui UI (app.cpp + *_ui.cpp) ──edits──> Project model (project.hpp)
        │ commitChange()                    │ save()/load()
        ▼                                   ▼
  undo history (history.hpp)     <name>.tyra + objects/<id>.json + <name>.history + terrain-*.heights
                                            │ refreshGenerated() at build start
                                            ▼
                templates::generate() (templates.cpp + game_templates.inc) → game sources
                                            │ Runner (runner.cpp)
                                            ▼
              native PS2DEV build → make → bin/<name>.elf → PCSX2 / ps2link
```

Sibling skills: **tyra-engine-dev** (the PS2 engine fork in `vendor/tyra`), **tyra-testing** (build, run, verify - read before claiming a change works), **tyra-docs** (docs update in the same commit), **tyra-pr**, **tyra-vehicle-modeling**.

## Core rules

### 1. Editing model: mutate, then `commitChange()`

- UI code mutates `project_` freely; one logical user action ends in ONE `commitChange()` (pushes an undo snapshot, marks dirty, bumps `modelEditSerial_`). **No autosave**: bytes reach disk only on an explicit Save. Skip the commit and undo/redo, the dirty flag and collaboration sync silently break (peers see only edits that pass `commitChange()`, `applySnapshot()` or `setDirty(true)`).
- `commitChange()` is the verb for project-wide data too (no undo step is created - the snapshot carries only scenes - but it dirties and syncs; per-widget commits are free).
- **Never `saveAll()` from a widget** - only for explicit save commands and asset-import side effects (the list is in editor-ui-and-conventions.md; adding a call site is almost certainly wrong).
- A window owning a `project::Section` compares `project::sectionJson()` before/after its whole body in addition to any `changed` flag (snapshot `before` AFTER on-entry repairs; `commitIfEdited` lambda for early returns).
- View state (render mode, projection, active scene) is not an edit. Stored-but-not-undoable editor state (layouts, breakpoints) uses `setDirty(true)`.
- `commitChange()` does not touch the viewport: a setting that changes the PICTURE calls `applyProjectToViewport()` (deferred until `!IsAnyItemActive()`).
- **A checkbox never reports `IsItemDeactivatedAfterEdit()`** - commit on its return value. That call is for dragged/typed widgets.

### 2. Generated-file ownership

- `refreshGenerated()` (project.cpp) runs at every build start. **Always overwritten** = an explicit hand-written path LIST (first line `// Generated by TyraX. Do not edit - regenerated on every build.`). **User-ownable** = `src/terrain_game.cpp`, `inc/terrain_game.hpp`, `inc/controls.hpp`, `inc/scripts/script.hpp`, `inc/scripts/flow_nodes.hpp` (regenerated while the `Delete this line to take ownership` marker survives). **Written if missing** = notices, launchers, `.gitignore`s, `.gitattributes`, `COLLABORATION.md`. `.vscode/extensions.json` is merged.
- **A new generated file must be added to the overwrite list in the same commit**, or it is written once by `project::create` and never refreshed (the Remote Pad shipped devkit code into a RELEASE build this way). A file in no list reaches only projects created after it existed.
- **Writes compare bytes first** (`writeFile`) - this is what keeps game builds incremental. Never emit volatile content; route binary bakes through `writeFile` too.
- Game-visible data goes through codegen, never hand edits. New generated files use `.gen.hpp`/`.gen.cpp`. Never emit something that breaks projects that own `terrain_game.cpp` (data into regenerated headers, behavior into ownable sources). A new baked folder needs a `res/.gitignore` rule AND the append-if-missing migration. `.res-baked/gi/` is checked in, not an artifact.
- A conditionally emitted file is deleted when it stops applying; generated output stays `git diff --check` clean; new features emit nothing when OFF (byte-identical regeneration).

### 4. Twins and oracles

The editor and the PS2 game compute many things twice (host C++ for preview/bake, generated C++ for the console). **Change a formula -> find and change its twin in the same commit.** Known twin sets: viewport shading `SHADE_COMMON` vs generated shading; terrain splat + `tintNoise2`; `occShapeAt`/`aoShadeMul`/`shapeBlocksRay` (host, game, viewport FS); `seqCameraUp` (3-way); `ambience::evaluate` vs `daynight.gen.hpp`; `scrollsim` vs `scroller.gen.cpp`; `procgen` vs `procrt` emitted evaluator; `roadgen` (list + strips) vs `buildRoads`; `vehiclesim` vs the vehicle runtime; `staticbatch` vs `buildStaticBatchList`; `menulayout`/`menubake` text vs runtime `drawFontText`/icons; `hudanim.hpp`; `livedbg`/`livetime`/`livepad`/`livereplay` layouts vs generated runtimes; `tmdl` writer vs `TmdlLoader`; `project::tripleBufferingFit` vs `allocateVramBuffers`; `blssClashes()` vs `blssClashesFor`. Mechanical oracles exist for some: `verify-road-twins.py`, `verify-batch-twins.py`, `--gi-gpu-check`, `--vu-check`/`--vu-replay`, `tools/bag-array-enforcement.sh`, `--audit-release`.

### 5. Platform parity and paths

- Files existing once per platform are edited as a PAIR in the same commit: `deps.ps1`/`deps.sh` (the ONLY dependency list), `setup.*`, `build.*` (`.cmd` files are thin wrappers - keep them so), `tools/toolchain/prepare-host.*`/`native-build.*`, the installer pair (same package CONTENT), `CMakeLists.txt` `if(WIN32)`/`else()`, `platform.cpp` `#ifdef _WIN32`/`#else`. OS differences live only in `platform.cpp` (+ `platform_mac.mm` for the bits that need AppKit, the merged title bar). macOS is the POSIX half: an `#elif defined(__APPLE__)` inside it where Linux reads `/proc` or shells out to freedesktop tools, `uname -s` = `Darwin` branches in the `.sh` files.
- Code must build with BOTH GCC/libstdc++ and Apple clang/libc++: declare an `operator==` before a type that compares a `vector` of it, `static_cast<long long>` a file-time `count()` (`__int128` in libc++), and `sizeof` asserts over structs holding `std::string` carry both numbers.
- Never join paths with `"\\"` or by hand: `Project::filePath(rel)` / `templates::nativePath(rel)`; normalize before a path leaves the process. Nested command-line arguments go through `platform::shellArg()`. Never kill processes by name - ownership from the command line (`processesNamed` + `killProcess`); `Process::kill()` kills the tree.
- Every RGBA texture upload uses `glUploadTexRgba` (one-call `glTexImage2D` with data crashes the AMD driver).
- A new source file must be added to `CMakeLists.txt` (no glob).

### 6. Conventions

- Panel text is terse: numbers, names, one-line verdicts; explanation in a 1-3 line tooltip; the long story in `docs/`. An empty panel says why in one line.
- Tools menu: one flat list under `SeparatorText` headers, alphabetical within each; never submenus.
- Wrap literal pixel sizes in `App::scaled(px)`; zoomable canvases use `PushFont`, not `SetWindowFontScale`.
- ImGui labels are IDs (`##suffix` to disambiguate); popup open/draw use the same string; `SetNextItemAllowOverlap()` for widgets over a `Selectable`; tooltip helpers after `IsItem*` queries.
- Files `snake_case.cpp/.hpp`, flat `src/`; split a window past ~2000 lines into its own `*_ui.cpp` (App members still declared in app.hpp).
- One feature = one commit whose message says what was done and HOW it was verified (dead ends included); a fact worth re-reading goes into `docs/` or a skill. Docs are updated in the same commit (tyra-docs skill). Comments explain constraints, not narration.
- Imported real-world measurements convert through `ProjectSettings::unitsPerMeter`.
- Do not add a runtime `if (debugEnabled)` - debug features are compiled out of release builds.

## TyraX 2.0 integration

The editor is 2.0.0; the combined project format is 114. Read
[TyraX2 integration notes](references/tyrax2-integration.md) before changing
frame ownership, pipeline recording or the associated acceptance tooling.
The TyraX2 performance investigation is closed: the notes summarise its
conclusions and pitfalls, and its lab scripts and raw evidence are only in
git history.

| `chargen.cpp/.hpp` + `chargen_kit.cpp` | Character Generator | The editor and `--chargen` read the embedded studio kit. Five bodies built with `custom_body.py` share slider IDs, 50 bones and 87 clips. The 16 items and migration names come from `tools/chargen-kit/studio_*.py` and `studio/`. The foreground groom has its own atlas, crowd accessories share one. Creator options use material names `opt-`, `optd-` and `opth-`; the hat twin shares the plain hairstyle texture and UV inset. See docs/character-generator.md for custom items, export, variants, clips and model choice groups. |
| `charanim.cpp/.hpp` | ~1030 | Retargeting onto a Mixamo-named, identity-bind rig (the Character Generator's): `retarget` for an imported library or `.tmocap` take, `prepareLive`/`applyLive` for the phone link (the clip path is built ON the live path, so they cannot drift), the ground solve, and `poseMesh` - host linear-blend skinning, the twin of the console's VU0 pass, which lets the editor preview play any clip. Host-only, no GL. The generator's OWN clips are retargeted offline (tools/chargen-kit/anim_retarget.py) and are not touched here; the old analytic idle/walk/run/jump generator was removed. |
| `posefilter.cpp/.hpp` | ~110 | **One-euro filter over a frame of joint rotations** - the shake monocular tracking leaves, taken out without taking the movement with it. The cutoff RISES WITH SPEED, which is the whole point: slow motion is mostly noise and is filtered hard, fast motion is mostly signal and is barely touched, so there is no mode switch and no fixed-smoothing compromise. Traps: a quaternion and its negation are the same orientation and blending the two goes the LONG way (align every input to the state first); the filter is TIME-based so a dropped frame does not change how much it smooths; and the textbook `derivativeCutoff` of 1 Hz is tuned for a mouse pointer - at that value it cannot follow a 2 Hz gesture, the cutoff never opens and the filter sits 18 deg behind a punch (3 Hz here). Constants came from a SWEEP scored by how an eye weights defects, not by taste: measured, still-jitter 1.85 -> 0.48 deg and still-error 1.22 -> 0.58, a fast punch pays 3 deg and ZERO frames of lag. Reset it wherever root motion is reset - a stream that jumps has not moved. |
| `visionpose.cpp/.hpp` | ~330 | **Head and wrist orientation from Apple's Vision, solved on the HOST.** ARKit body tracking reports the head and both wrists and solves NONE of them (mocap.hpp); hand and face tracking on iOS live in Vision, a different framework over the same camera frames. The phone therefore sends OBSERVATIONS (landmarks, face angles, camera orientation) and this module does the geometry - deliberately, because C++ here is testable without a Mac and a fix does not need a release + AltStore round trip. Three findings are load-bearing and each cost a rewrite: two projected DIRECTIONS are two constraints on three unknowns, so direction-only matching failed 8 of 9 synthetic cases by 24-166 deg - the LENGTHS (foreshortening) are the third constraint, and only their ratio matters so no intrinsics are needed; the four palm landmarks are COPLANAR and a plane's image equals its mirror's, so the THUMB (off-plane) is what tells a palm from the back of a hand; and the rest-pose tie-break must be feeble (0.002, not 0.02) or it drags correct answers home by 8-19 deg. Measured: clean geometry <=1.2 deg, realistic landmark noise 4.8 deg, and `Tracker` (prior + slerp) halves jitter - at 0.5% noise worst-case 95.7 -> 49.5 deg. Host-only, no GL; the harness is scratchpad/vision_check.cpp. |
| `mocap.cpp/.hpp` | ~300 | Reader for **`.tmocap`** phone takes - ARKit body-tracking recordings from the companion app [tyrax-mocap](https://github.com/doctorspider42/tyrax-mocap) (own repo, sibling of tyrax-cam; the format lives in its PROTOCOL.md, so **the layout is in two REPOSITORIES** - the reader validates every field and names the one that was wrong). Host-only, no GL. It decodes, decomposes the matrices and renames ARKit's joints to the rig's Mixamo names, then hands `charanim::retarget` an ordinary source `Skel` - after that a phone take IS a Mixamo import. Two things are load-bearing: a take carries the skeleton's **rest pose** (there is nothing to take the retarget's delta against otherwise) and the performer's height is read off it (so a tall performer does not lift a short character off the floor); and matrix **scale is dropped** on decompose - ARKit's skeleton-scale estimation puts the performer's real limb lengths there, and carrying them across stretches the character to match whoever stood in front of the camera. The height is composed through the FULL transforms, not by summing local Y - ARKit expresses a bone's offset in its PARENT'S ROTATED frame (thigh->shin reads `(0.42, 0, 0)`, along the bone), so the naive sum measured a 1.71 m performer as 0.13 m and the character flew off the screen. `buildSource` is shared with the LIVE link, and `writeTake` is the editor's half of the format - the Mocap window records the SOURCE frames, not the retargeted pose, because a take is reusable on any character. **The body's HEADING is on the ANCHOR, not on the hips joint** - measured: across a take in which the performer walked a full circle, `hips_joint`'s own rotation was constant TO THE BIT while the anchor swung 177 deg, so a reader that keeps only the anchor's position retargets a circle as marching on the spot; the heading is composed onto the hips on decode, and `writeTake` stores it or a recorded live take loses the turn again. It must be RELATIVE to the first frame: ARKit's world zero is wherever the phone pointed at session start, so an ABSOLUTE heading faces the character in an arbitrary direction (it looked like "rotated 90 degrees to the camera"). The hips TRANSLATION was already rebased that way - both halves of the anchor have to be, and for a while only one was. **And the rebase is `At * conj(A0)`, NOT `conj(A0) * At`**: the left form expresses the turn in the FIRST FRAME'S anchor basis, which is not the world's (same convention that makes hips->spine measure sideways), so the character's world-space bind gets a rotation about axes 90 deg off and TOPPLES instead of turning. Guard when reading a take: ARKit never rotates `hips_joint`, so a channel that does was written by a recorder that folded the heading in while also storing it on the anchor - `mocap::load` repairs that by restoring the rest value and says so. `load` also reports which mapped bones the take NEVER moves: ARKit reports but does not SOLVE both wrists, both ankles, the toes and the head-relative-to-neck (zero variation over 277 frames), and "the source has no wrist data" looks identical on screen to "the retarget is broken". |
| `gltfwrite.cpp/.hpp` | ~330 | **glTF 2.0 binary writer** - the exact inverse of `glbparser::parseSkel`, and the reason a generated character can be a plain asset instead of a private format. Emits only the subset glbparser reads (one buffer, no sparse accessors, embedded PNGs, flat triangle lists, LINEAR/STEP samplers), plus POSITION min/max so the file also opens in Blender. Bones are written verbatim and the mesh hangs off ONE appended node, so palette/channel node indices stay exactly what the caller built. `SkelNode::name` round-trips through it. |
