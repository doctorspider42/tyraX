# Lighting and the host bakes (AO, GI, probes, shadows, pre-lit, model AO, sky)

Read when you touch any host-side light/occlusion/shadow bake (`aobake`, `gibake`, `gigpu`, `matbake`, `modelao`, `litbake`, `shadowbake`, `blobshadowbake`, `occlusionbake`, `reflscenery`, `decalproj`), lightmaps/probes in codegen, the ambience presets / day-night cycle, stars or the painted sky.

## Shared rules for every bake

- **Host-only, no GL** (aobake/decalproj pattern): pure functions of (project, scene, ...) so a 40-line harness can run them.
- **Determinism**: each sample's spiral is seeded from a hash of the element's OWN identity (texel coordinate, triangle index, probe index), never a running counter, so the partition across threads moves the wall clock and not one byte. Check with `cmp` on the output (`.res-baked/gi/scene<N>.gi`, `.shadow`), never by assertion.
- **Signatures hash CONTENT, never mtimes**, and asset files with `wire::hashFileEolAgnostic` (CRLF counts as LF) - every bake signature: shadow, GI, pre-lit, model AO (1.164.2; GI cache v8, model AO cache v2, pre-lit `kSigVersion` 2, shadow cache v8). A raw-byte hash made checked-in caches read stale on a CRLF checkout.
- **Bumping a cache version makes every checked-in cache unreadable**: re-bake the examples in the same commit (`git ls-files examples | grep res-baked`). GI v7 landed without it and all four GI examples silently shipped the fallback.
- **A DISCRETE decision must not ride on a tolerance**: aobake's importance pre-pass turns a measurement into a texel budget and the packing, so GPU-vs-CPU float noise re-packed the whole atlas (13-34% of bytes differed, looked like a broken kernel). The pre-pass is pinned to the CPU (`bakeSceneLightAtlas`'s `giLayout`, ~3% of the pass).
- **An object that does not exist at runtime must not bake anything**: `collectOccluders`, `collectEmitters` and the atlas loop skip `scrollsim::memberTemplateFlags` (scroller templates) and invisible walls.
- **Pollers run from `drawUI`, not window bodies** (`giBakerPoll`, `litBakerPoll`, `modelAoPoll`, `shadowBakerPoll`, `updateTick`): a finished job must land whether or not its tab is open; results apply as ONE undo step.
- `--bake-status <dir>`: read-only freshness check (GI, shadows, pre-lit, model AO; exit 3 = stale). Headless twins: `--bake-gi`, `--bake-shadows`, `--bake-prelit`, `--bake-model-ao`, `--bake-particles`, `--gi-gpu-check`.

## Shared infrastructure

- `bakepar.hpp` (~70): the bakers' parallel-for (aobake, gibake). **DYNAMIC schedule** (threads pull chunks off an atomic counter): regions range 128x128..4x4, so static slices measured 270% CPU of 800% on gi-showcase vs 488% dynamic. **A body writes only to its own element's slot** (per-element arrays folded after the call: `jobBake`/`jobLit`, `rowOcc`/`rowLight` in aobake.cpp). **Granularity trap**: aobake's texel pass splits per (region, ROW); splitting rows within each region left every region under the single-thread floor and paid a launch per region - SLOWER than sequential.
- `bvh.cpp/.hpp` (~220+65): the flat binned-SAH BVH shared by matbake (one model) and gibake (a scene); moved out of matbake so there is one traversal.
- `bakegl.hpp`: hidden-context creation + RAII restoration shared by GPU GI and impostor capture; each baker owns a separate context (a background GI bake cannot race a capture); create on the main thread.

## Baked AO and the lightmap atlas (`aobake.cpp/.hpp` ~2.1k+370, docs/ambient-occlusion.md)

- Ships as **per-pixel AO textures** drawn as extra alpha-blended passes (black RGBA32 + GS alpha-over = exact per-pixel multiply). **Palettized alpha loses the gradient in the engine's tRNS->CLUT path - keep these RGBA32**, both capped 256^2:
  - `terrainAOMap`: heightmap horizon scan + occluder contact per texel -> `.res-baked/aomap/`; its RGB carries the terrain's baked emissive light, drawn as a second additive chunk pass. `SCENE_AO_MAP_OCC`/`SCENE_AO_MAP_LIT` say which channels exist; `SCENE_AO_MAP_LIT` also tells `buildTerrainChunk` to leave the light out of the vertex bake (miss either half and it lands twice). Occlusion pass vertex colour MUST be black once RGB is populated (white drags light into the multiply); a TEXTURED terrain stays on the vertex path (a flat add blows out dark texels).
  - `bakeSceneAoAtlas` / `bakeSceneLightAtlas`: per-scene primitive lightmap atlas -> `.res-baked/aoatlas/` + UV rects in `ao_data.gen.hpp`; regions mirror the builders' UV layouts (box 6 / sphere 1 / cylinder 3 / cone 2 / plane 2); generated `pushVert` emits atlas STs via `g_aoRegion`. Box front/back V=0 is the TOP: keep `primmesh::unitBox`, generated `addBox` and aobake's region inverse together (1.152.0); geometry UV changes also invalidate procedural bake hashes and GI caches.
- `collectOccluders` (solid `castShadow` objects -> oriented box/sphere shapes) is the single source for codegen AND viewport uniforms; its model-AABB callback must stay GL-FREE (`Viewport::modelBounds`, not `modelDraw`). Casting is per object (`SceneObject::castShadow`, in `liveLinkRecipeHash`); receiving is automatic.
- Objects whose atlas comes out fully lit are dropped (stay batchable); covered objects render solo. texbake, `ao_data.gen.hpp` and the scene-table batching bit reuse the SAME deterministic bake.
- Spawned clones/physics receive via a per-vertex fallback (`aoShadeMul`, a three-way twin: generated game <-> viewport `aoOcclusion` <-> host `occluderOcclusionAt`). **Model RECEIVE via the per-vertex path is disabled** (`g_aoOff` for type 5; `modelAO` + `.aov` sidecar + the LeanObjLoader reader stay parked); model SELF-AO is modelao.cpp. Generated Blocks chunks get vertex AO (`g_aoOff` is `d.type == 5 && !blockAo`; procedural-and-prefabs.md). Settings `aoEnabled/aoStrength/aoRadius` on ProjectSettings + AmbiencePreset.
- **Analytic per-vertex bakes** (AO occluders, emissive lights; docs/emissive-materials.md): `objectShape` (shared by `collectOccluders`/`collectEmitters`) -> table in `ao_data.gen.hpp` -> evaluated per vertex at scene load from ONE distance-to-shape query (`occShapeAt`, three-way twin: host, game, viewport FS). **Pruning is load-bearing**: the local list is collected once per object / per terrain chunk, never scanned per vertex (an 1100-object scene cost ~170 ms per chunk); every bake site needs its own collect - `rebuildStaticBatch` bakes MANY objects, so the collect belongs inside its member loop.
- **Per-vertex is not enough for strong gradients** (a box face is two triangles -> diagonal seam; Terrain detail 32 over 64 units = one sample per 1.94 u). Both go through a **lightmap**: primitives via `bakeSceneLightAtlas`, terrain via `terrainAOMap` - each ONE 256^2 RGBA32 image, A = occlusion, RGB = emissive light; two passes whose VERTEX COLOUR selects channels (MODULATE: black sees only the alpha multiply; the RGB add is modulated by white for objects, by the terrain base tint for ground). **A new per-texel bake claims a free channel in those images, not a third texture.** Anything on the vertex path (models, clones, physics bodies, textured receivers) needs a flag saying which route it took or the term lands twice: `SCENE_AO_ATLAS_LIT` per object, `SCENE_AO_MAP_LIT` per scene.
- **Shadowing an analytic light** = a segment test against the same shapes (`aobake::shapeBlocksRay`: slab for box, quadratic for sphere; twins in game + viewport FS). Prune casters by the LIGHT's reach (own list, not `SCENE_AO_RADIUS`); exclude the receiver's and the emitter's own shapes; bias the ray off the surface. Emitters are AREA sources: host bake and viewport cast `kEmisShadowSamples` (8) rays (ray 0 to the nearest surface point, the rest over the silhouette via fixed `kEmisShadowDisk`, no RNG), using the unblocked fraction; rays below the receiver's horizon are left OUT of the vote. The game's per-vertex path stays at ONE ray (8 rays = +200 ms EE scene load on examples/glow) - the one documented divergence.
- **Atlas region sizing is importance-weighted per AXIS**: a 6x6 probe grid per region gives the peak (sets AREA, density `sqrt(peak)`) and the gradient along each axis (splits area between them); bisection raises density until full. The atlas DIMENSION comes from unweighted area (VRAM must not move with weighting). Raising the old flat 128-texel per-axis cap made things worse.
- **A lightmap texel's ALPHA MUST NEVER BE 0** (`kMinLightmapAlpha` = 2): StaPip's GS alpha test passes only alpha != 0 (`stapip_qbuffer_renderer.cpp`), both passes sample the same texture, so zero occlusion kills the ADDITIVE light pass too (hard texel holes that look like low resolution - dump the alpha before touching resolution). The engine's PNG loader scales 0..255 -> 0..128 by integer division, hence 2, not 1.
- **Per-texel bakes average over the texel footprint** (`kSuper`) - sub-texel penumbrae alias into staircases otherwise.
- **Facing terms**: `max(0, N.L)` is wrong for area stand-ins (seams on box corners). Occluder bake: linear wrap `0.35 + 0.65*N.L`; emissive: half-Lambert squared `((1+N.L)/2)^2` (linear wrap still hits zero at a finite angle - a visible edge in the dark).

## Global illumination (`gibake.cpp/.hpp` ~1.55k+290, docs/global-illumination.md)

- Tessellates a scene (primitives via primmesh, static .obj via objparser, terrain heightfield) with per-triangle albedo/emission; ONE hemisphere gather over sky + sun + emissive area lights + baked point lights, iterated for bounces.
- **Ground grid lines follow the objects** (`Scene::groundX/groundZ/groundH`): bounce is stored per triangle at its centroid, so a 3-unit ground triangle under a 1-unit wall hands sunlit light to the shadowed face's lowest texels as teeth; `build` tessellates objects first and puts a line at every grounded footprint's AABB edges. `groundSurfaceY` searches that grid - re-derive the traced ground from it, never from a cell count.
- Owns almost nothing of delivery: plugs into the existing atlas/regions/codegen/texbake via `aobake::LightFn` and REPLACES what the atlas RGB means (incoming light, all sources, all bounces) - at 256^2 RGBA32 = 19% of GS VRAM the image cannot grow.
- With a fresh bake: `SCENE_AO_ATLAS_GI` / `SCENE_AO_MAP_GI` make the vertex shade go BLACK (`g_giLightmap`), and every surface a lightmap cannot cover reads the **L1 SH probe grid** (12 B + 1 liveness byte per probe; `g_giProbeShade`, `inc/probe_data.gen.hpp`) - models, textured surfaces, physics bodies, clones, characters. Never both; either way the ambient + directional term, baked point lights and emissive pools are skipped. **A new geometry-baking site (builder, LOD path, batch kind) must STAGE `g_giLightmap`/`g_giProbeShade` explicitly** - they persist between calls.
- Explicit, cached bake in `.res-baked/gi/` (checked in; content signature over scene + settings + every file read). Codegen/texbake/viewport only READ it; a stale cache falls the whole scene back to the pre-GI bake together. `Baker` = matbake's progressive-worker idiom. UI: Ambience Editor's **Global illumination** tab (`App::drawGiBakeSection`, hud_ui.cpp); `giBakerPoll` from `drawUI`.
- **The two LIGHTMAP passes are 98% of a bake** (they live in aobake): `--bake-gi` prints `gibake::Timings` - build 0.01 s / solve 0.05 s / atlas 3.63 s / terrain 3.97 s / probes 0.16 s on gi-showcase. Optimising the solve or probes saves nothing. The split exists because the total hid the atlas pass running single-threaded.

### GPU backend (`gigpu.cpp/.hpp` ~670+105, `gigpu_metal.mm` ~450)

- **Two backends, one interface, edited as a PAIR**: `gigpu.cpp`'s GL half is `#ifndef __APPLE__`; macOS (GL 4.1, no compute) uses `gigpu_metal.mm` (Metal, ARC via a per-file `-fobjc-arc`, MSL kernel compiled at runtime with fast math OFF - `MTLMathModeSafe`/`fastMathEnabled = NO` - or the epsilons move). `compare()` is shared. The MSL `Params` uses float4 for the float3s so the host struct matches without packed-type rules. No window and no main-thread rule on Metal; headless works. A kernel change goes into the C++ gather, the GLSL AND the MSL; `--gi-gpu-check` on a Mac checks the Metal one (0.001-0.003%).
- GL 4.3 compute twin of `gibake::gather` + `directAt` + `skyRadiance` + `bvh::trace`/`rayTri`. (1) **An accelerator WITH a reference; the CPU integrator is never deleted** - `--bake-gi` runs headless/in Docker with no context, so every path survives `available()` == false. Context = hidden GLFW window (not EGL, to avoid a per-OS pair); never `glfwTerminate` (kills the editor window); `ScopedCurrent` restores the previous context (or a bake blanks the viewport). (2) **No bit-identity**: the ONE bake compared with a tolerance; a cache records its backend. (3) **Automatic oracle**: `--gi-gpu-check <projectDir>` gathers one sample set both ways, fails above 1% relative mean error (reads ~0.003%). Run after touching EITHER side.
- The unit is a BATCH: 41-67x vs one core at ~170k points, 20-50x at 21k, 1.2x at 2.6k cold. Against the 8-core bake: atlas 3.51 -> 0.55 s, terrain 4.21 -> 0.40 s, but TOTAL only 4x because **0.86 s per process is GL context creation** (one-scene project 2.8x). Quote the 8-core column.
- GUI: ONE editor-wide switch for every GPU bake, *Edit > Preferences > Build > Use the GPU for bakes* (`EditorConfig::gpuBakes` / `App::gpuBakes_`, editor.ini `gpuBakes`, default ON; the old `giGpuBake` key is deliberately not read - it was written as 0 everywhere). It drives the GI gather and the impostor capture (`modelimpostor`/`treeimpostor` `gpu` argument). The Ambience Editor's Bake column only SAYS which engine ("Bakes on the GPU", badge) with a *Change* link (`prefCategory_ = 3`). A new GPU bake reads `gpuBakes_`, never a switch of its own; the CLI keeps opt-in `--gpu` flags (it reads no editor.ini). A new row there pushed the Bake buttons outside the window (see editor-ui-and-conventions.md, clipped widgets). Pinned-CPU layout result: rects/lit/firstRegion identical, light channels differ in 0.3% of bytes by <= 2/255, occlusion identical.

### Probe lighting

- `templates.cpp::giSHLights` is shared by `fillDynLitColors` and animated rendering; both game-hpp templates carry `AnimPart::litDirs` and `ObjectGeometry::animLightMat`. Pose sharing must never share light directions. `animLightMat` removes instance scale from the normal transform (VU1 lit programs do not normalize). Viewport `SHADE_COMMON::giProbe` uses `uGiReceiver` for the matching centre lookup and signed RGB sum; static probes use full L1. examples/probe-lighting.
- Full RGB SH receivers (1.74.0): generated `giSHLights` replaces dominant-direction extraction for animated and explicitly dynamic-lit receivers - identity directions, signed RGB axis colours, L0 + live ambient, per-part `signedSH` flag set every frame. Clear all unused colours when falling back to classic lighting. Probe cache format unchanged.

## UV-space map baker (`matbake.cpp/.hpp` ~1.1k+185, docs/material-baking.md)

Material Editor's raytraced baker for ONE model's surface detail: conservative UV rasterization -> per-texel samples, BVH, cosine golden-spiral hemisphere rays (per-texel seeded rotation, bit-identical at any core count); one pass yields AO + bent normal + thickness + curvature + position + OS-normal; optional high-poly cage projection along smoothed low normals; flood dilate. `matbake::Baker`: progressive worker (growing rounds, `snapshot()`/`version()` polling, gbuffer+BVH cache keyed by `MeshInput::signature` so sampling-only slider drags re-bake nearly free).

## Automatic model AO (`modelao.cpp/.hpp` ~520+195, docs/ambient-occlusion.md "Model AO")

- matbake AO run per model ASSET automatically and multiplied into the texture the model ships: transform-invariant (one map per asset) and **zero extra GS VRAM** (rides an existing texture).
- **`applyToRgba` is THE multiply**, called by texbake (shipped PNG, before resize and CLUT), `Viewport::glTexture` (uploaded pixels) and litbake (albedo it reads). Never touches ALPHA (StaPip discards alpha-0 texels).
- Cache `.res-baked/modelao/<pair>-<signature>.png` (freshness = one `fs::exists`); signature over .obj CONTENT + every resolved .mtl + texture DIMENSIONS + ray/distance knobs - never texture PIXELS (repainting must not invalidate) nor `strength` (apply-time remap).
- `plan()` owns eligibility; every refusal is named: static .obj only, textured materials only, a texture shared by >1 model asset is skipped (two UV layouts), `*-lit.png` skipped. Traps: texbake's `.res-baked` vanished-source sweep must skip `modelao/`; atlas MEMBERS never pass texbake's mirror loop, so the multiply happens in the page compositor too.
- `Project::modelAoMode` per-asset override: joins `retargetAssetPath`, NOT `rebuildAssetUsage`. UI: `App::drawModelAoSection` (Ambience Editor > Baked lighting), `App::modelAoPoll` starts a run only when the INTENT changes (a scan parses every .obj).

## Pre-lit models (`litbake.cpp/.hpp` ~750+215, docs/prelit-models.md)

- Scene light gathered per TEXEL and multiplied into one placed object's own texture - the only per-pixel static light a TEXTURED surface can take (the lightmap pass is additive and the GS blend `C` is always an alpha, so texture x lightmap is not expressible). No own integrator/rasterizer: gibake computes, matbake's UV walk, this joins.
- (1) **Albedo comes from the model's OWN .mtl**, never the material the last bake assigned (idempotent re-bake), but `modelao::applyMapFile` IS folded in. (2) **`applyToObject` writes one .mtl entry per material NAME the model uses** (all to one image): overrides bind by `usemtl` name; a missing name renders a pure white block under prelit's neutral vertex colours (found in PCSX2). (3) **`sceneSignature` hashes the scene AS AUTHORED** (pre-lit overrides normalized back to `prelitSource`), else applying a bake stales itself and its neighbours; accepted price: bounce off a neighbour's new pre-lit texture stales nothing.
- Fields: `prelitWanted` / `prelitSig` / `prelitSource` (asset path -> `retargetAssetPath`). `Baker`: one `gibake::build` + one `solve` per SCENE (the solve is nearly all wall clock), N objects out. UI `App::drawPrelitSection` (Baked lighting tab), `App::litBakerPoll`, `--bake-prelit`.

## Baked shadow decals (`shadowbake.cpp/.hpp` ~1.44k+280, docs/shadows.md)

- For every object with `shadowMode == 4`: trace its shadow along the scene's sun into a tile, pack tiles into shared 256x256 atlas pages, project onto receivers with `decalproj`. **The atlas is what makes it affordable**: one page = one bag = one submit per layer, vs ~1 ms EE per unmerged bag. Folding a tile rect costs nothing (decalproj UVs are already [0,1]).
- (1) Direction = `project::resolvedSettings(p, sc).lightDir` (ambience preset + day/night at `ambience::bakedHour`) - same field gibake reads. (2) **Receiver search uses the SCENE tree; shadow rays use a CASTER-ONLY tree** (scene occlusion would double-darken overlaps). Each tile COLUMN starts past the caster's last surface IN THAT COLUMN (`casterTree`, 1.162.1; global depth floated shadows a metre off buildings). The caster never receives through the main projection, but its near-horizontal faces within `kSelfFloor` (1.0) of its base get a second per-piece occlusion-checked pass (any of 7 points x 9 sun-disk rays, 1.163.2), and a column STOPS at such a floor face. Roads receive via `decalproj::Receivers::roads`. (3) The projector is a synthetic `SceneObject`; the tile is laid out in the basis read BACK from `decalproj::projectorBasis` (at gimbal lock `eulerFromBasis` folds roll into yaw -> mirrored tile otherwise). (4) **`strength` rides tile ALPHA, never the tint** (tint = `skyColor * brightness * ambient`).
- **Ground shadow maps** (`Options::groundRes`, 1.163.0): one 4-bit mask per terrain chunk replaces the terrain as a decal receiver, traced against a merged all-caster tree; `kGroundChunkCells` (16) must equal the game's `TERRAIN_CHUNK_CELLS`; the cache's ground tail is optional on read.
- **Background re-bake** (1.164.0): `App::shadowBakerPoll` re-bakes the active scene 1 s after the last edit when `bakedShadowAutoBake` is on (an edit cancels an AUTO bake, never a manual one); the viewport uses `loadAny` (stale allowed), codegen `load` (fresh only).
- Cache `.res-baked/shadow/`, content-hashed, checked in; texbake writes pages from the same cache codegen reads UVs from. **No GPU backend, by measurement**: ~24 rays at one caster's 12-triangle box vs GI's 128 at the scene; `--bake-shadows` prints wall clock (0.02 s on a two-caster fixture) + `Bake::timings`. The one slow case (Motor District 13.3 s) was `decalproj::project` re-parsing every .obj and re-tessellating roads per caster; decalproj now caches parsed models (path+size+mtime) and road triangles (input hash): 0.98 s, byte-identical.

## Other bakes

- `decalproj.cpp/.hpp` (~500+85): projected-decal geometry. `project(Project, SceneData, decal)` clips receiver triangles (terrain + overlapping objects; roads optional) against the decal's oriented unit-cube projector, computes UVs + normal offset, returns world-space triangles. Used by the viewport AND codegen (`decalDataHeader` -> `inc/decal_data.gen.hpp`); **no projection/clipping on the EE**. Receivers use `primmesh` (conforms to exactly what the viewport draws).
- `blobshadowbake.cpp/.hpp` (~155): per-object cheap-shadow mask: rasterizes a primitive/static OBJ top-down, or frame zero of a GLB/FBX, into a soft 128x128 alpha PNG. `SceneObject::blobShadowTexture`/`blobShadowSize` are in equality, live-link recipe hash and asset retarget/usage. Codegen emits the variable-length path/footprint through sparse `objectBlobTextureFor` (not a `SceneObjectData` column). Runtime: one terrain-conforming yaw-aligned quad; rejects by caster draw distance and a whole-footprint frustum AABB before terrain sampling.
- `occlusionbake.cpp/.hpp` (~230, docs/occlusion-culling.md): voxelises only closed, proved-opaque static OBJs, greedily merges eroded interior cells into <= 32 inner boxes; repeated assets share the work. `occlusion_data.gen.hpp` = boxes + per-object receiver/occluder flags. Runtime projects each box as one convex hull into a 48x42 CPU depth buffer, erodes coverage, expands candidate AABBs, rejects solo objects/batches/procedural chunks only when every cell is safely behind. **Road chunks opt out of both this test and the whole-AABB frustum pre-test** (long shallow bounds gave false-hidden asphalt; StaPip clips them precisely). Near-plane/screen-edge uncertainty and occluders themselves stay visible. Keep the two per-object opt-outs independent (transparent/holed geometry must not occlude; an object may separately refuse being culled).
- `reflscenery.cpp/.hpp` (~365+80, docs/reflective-materials.md "Static scenery in the probe"): with `reflectionScenery`, every static object becomes one oriented untextured box (material average colour; gibake-style Kd x texture mean) in the shared `@sky` probe. Host decides WHICH (`verdictFor`, printed in Properties) and WHAT (`collect`, using public `aobake::objectShape`); `reflSceneryTable` emits `REFL_SCENERY` only while on; generated capture (`{{REFL_SCENERY_KEY}}`/`{{REFL_SCENERY_CAPTURE}}`) merges boxes into one bag per 96-unit cell and layer, skips cells outside the probe frustum, lights with `shadeOf()`. Not free: 1.2-1.65 ms per capturing frame on the Motor District (EE clipping of near boxes). Movability = `objectRuntimeMovable` with LAYER ignored; *Show in reflections* objects keep their own path. **`ground()`** (`reflectionGroundProxy`): 64x64 albedo map per scene (terrain base + splat + roads painted by ribbon coverage), `REFL_GROUND_*` only while on; capture swaps `renderTerrain()`/`renderRoadChunks()` for a 21x21 height-following grid in 3x3 bags rebuilt when the eye crosses a cell (roads baked in so the rebuild never calls `roadSurfaceAt()`; 1 bag and 4x4 bags measured worse).

- Shared bake starters: `App::startGiBake(all)`, `startShadowBake(all)`, `startModelAoBake()`, `startPrelitBake(onlyStale)` (+ `prelitPendingCount()`); the tab buttons AND the Build menu items (palette: "bake") call them - a new bake gets a starter + a `menuact::MenuItem` + `menuact::Hint`.

## Ambience presets and the day/night cycle (`ambience.hpp/.cpp` ~300+360, docs/day-night-cycle.md)

- `AmbiencePreset` = sky/lighting/AO/fog mood a scene picks; fields mirror `ProjectSettings`, and `project::resolvedSettings` overlays them so all consumers read ONE set of fields. `DayCycle` + `DayKey`: sun/moon arcs + cyclic keyframes; **`ambience::evaluate` is the single answer** (resolvedSettings -> vertex bake, aobake, gibake + probes, `SCENE_LIGHT_*`, runtime projected shadows/flare/god rays; codegen `SCENE_SUN_*`/`SCENE_MOON_*`; viewport discs; editor readout). Host-only (`Resolved` exists so ambience need not include project.hpp).
- Resolved light is **clamped to +5 deg elevation** (horizon light = zero diffuse on flat ground; below = lit from underground). The sun/moon handover **switches** direction to the dominant body while `Resolved::shadowFade` takes cast shadows to 0 across the swap - **never blend two near-opposite directions** (weighted sum cancels -> 180-degree flip; zenith rescue `4*w*(1-w)` points straight up; azimuth blending flips on the +-180 seam). The switch happens at 0.03% shadow opacity (167.97 deg change at fade 0.0002; worst visible step 0.24 deg/min). Only DIRECTIONAL casters (projected silhouettes) multiply alpha by `g_shadowFade`; blob shadows don't (fading them unmoored every object at twilight); bakes ignore the fade.
- `renderProjShadows` once dropped the sun below ~14.5 deg (`syd < 0.25`, because the receiver patch caps at 3.5x caster radius) - 4.15 h of no shadows under a 28-degree arc. Now a smoothstep from the light's 5-deg floor to 16 deg folded into candidate score and alpha: shadows present 15.70 -> 21.33 h/day, longest gap 4.15 -> 1.33 h (the handover).
- Elevation capped BELOW the pole (`kMaxLightElevation` 88): `M4x4::lookAt` builds from a hardcoded world-up (`$vf6 = {0,1,0}`) with a double cross product, so a vertical light degenerates every derived basis (projected shadows' light camera). **Anything that builds a basis from the light direction inherits this.**
- A new cycle field joins `operator==`, the `"cycle"` object in `write/readAmbienceSection`, and `project::clampDayCycle`.
- Ambience Editor **Simple view** (`ambience_simple_ui.cpp`, default; `editor.ini` `ambienceDetailed` picks Detailed): stores NOTHING of its own - every control reads back from the preset (key averages, nearest compass point, nearest fog level in metres x `unitsPerMeter`) and writes by rescaling the same fields, so the two views cannot disagree. Looks = `ambience::defaultKeys()` reshaped + hour + fog level + stars (a look is "selected" only while the preset still equals it exactly). Scripts: `Simple` / `Detailed`, tiles by look name, `Time of day` (drag), `Thick` etc. (fog), `Time passes`.
- **Runtime half** (`DayCycle::runtime`): `templates::dayNightHeader` emits `inc/daynight.gen.hpp` (inline functions; both game-cpp heads need it) reproducing `ambience::evaluate` + `driftGrade` from scene_data tables. A harness over 1440 minutes: 1.2e-7 on directions, exactly 0 on colours and grade - keep it. Traps: the header must be in `refreshGenerated`'s overwrite list; `postFx.setGrading` takes FIXED POINT (`unsigned char` gain 128 = 1x, `short` lift, `mixAmt` 0..128); `time` (where the clock starts) vs the hour geometry bakes at are different - **`ambience::bakedHour` is the one answer for bake-side consumers** (`DAYCYCLE_STARTS` vs `DAYCYCLE_BAKEDS`).
- Color grading (`grading.hpp` ~80): DaVinci-style presets compiled to GS-blender integers (per-channel gain, lift, mix toward a colour; saturation approximated by mixing toward mid-grey; no gamma); the viewport replicates the quantized math incl. the 0..255 clamp after every step.

## Night sky and painted sky

- `starfield.cpp/.hpp` (~150+60, docs/day-night-cycle.md "Stars"): `generate(Params)` -> stars (direction, size, RGB, magnitude tier); viewport and generated `buildStarField` each build quads, so codegen ships ~400 ROWS not ~2400 vertices. Affordable only via `StaPipInfoBag::additiveBlendFix` (additive 3D bag `Cs*FIX + Cd`, the light beams' trick): brightness/colour ride Gouraud vertex colours, one bag per magnitude tier (`kTiers` = 3) = three submits; dusk fade (`DayKey::stars`) and twinkle are the bag's FIX byte per frame, never a rebuild. Determinism via `mix32(seed, index, channel)`; the Milky Way PULLS stars toward the band (a reject loop thins the sky as the slider rises); a star **must** use the soft corona sprite (an untextured quad is a hard square), so `projectStarCycle` forces the `flare-corona.png` bake and `STAR_COUNT > 0` forces its load.
- `skytex.cpp/.hpp` (~55+45, docs/sky-texture.md): the ONE crop of an equirectangular panorama the dome samples (`crop`: top `kVMax`, AREA-averaged to 256x128 - bilinear sparkles at 8x) and the ONE UV rule (`domeUv`). texbake ships `.res-baked/sky/scene<N>.png` (8-bit) and skips `res/sky/`; the viewport uploads the same pixels; codegen emits `SKY_TEXTURE_*` only when a scene has one and `buildSkyDome` carries the third `domeUv` copy under `SKY_TEXTURES_ON`. Field on `AmbiencePreset`, `ProjectSettings` and the scene sky override (written only when set); a real asset reference (`retargetAssetPath`/`rebuildAssetUsage`). With a texture the dome's vertex colour is a TINT (128 at the authored hour), so the cycle still darkens it.
