# Generated-game rendering, static batching, bags, meshes, materials, particles

Read when you touch how the generated game draws (static batching, `dirty`/matrix path, bag arrays, LOD/impostors/proxies, env maps, triple buffering, submission scopes), the model bakes (`tmdl`, `meshlod`, `meshstrip`, `texatlas`, `texbake`, `stochtile`, `primmesh`), `.mtl` material features, or particles.

## Viewport <-> game twins (general rule)

The editor viewport and the PS2 game must agree. Shading, terrain sampling, sky and the reflective matcap (sphere-map STs from the camera-space normal, docs/reflective-materials.md) are implemented twice (GLSL/C++ in viewport, codegen in templates). Change one formula -> grep for its twin. Examples: terrain splat painting (docs/terrain-painting.md: per-vertex weights -> Gouraud alpha over the tiled base, in `buildTerrainChunk` (StaPip layer bags under a blending info bag) AND `buildTerrainChunkMesh`; weights are per-vertex `SceneData::splat` on the heightmap grid, no resampling); macro ground variation `tintNoise2` (templates.cpp above `buildTerrainChunk` and viewport.cpp). Static object/batch vertex colours are Gouraud (terrain flat); this does not change OBJ face normals or grant imported meshes a lightmap.

## Static batching (docs/static-batching.md)

The game merges non-moving primitives and compact imported-model parts into texture/cell bags (`staticBatchEligible`/`batchBlockedNames` in templates.cpp; `buildStaticBatchList`/`rebuildStaticBatch` in the game template).

Invariants:
1. Any runtime path that mutates a rendered object property sets `RuntimeObject::dirty` (demotes a batched member to its own bag; otherwise the change silently doesn't render). Visibility flips are the exception (caught by a snapshot).
2. A new *reference kind* that can move/hide/re-submit objects at runtime (like sequences and mirror target lists) joins `batchBlockedNames()`; flow nodes are covered generically (`strKind == ObjectName`).
3. A new exclusion-worthy per-object property (special draw path, streaming mechanism) joins `staticBatchEligible()` **and gets a `staticbatch::Reason`** (else the panel names an older rule). `SceneObject::batchExclude` is deliberately the FIRST test in both.
4. **Count before excluding**: on the Motor District `drawDistance != 0` alone held all 70 models solo (27 boxes of 142 objects batched). Read `batchStatic` out of the regenerated `inc/scene_data.hpp` in the same commit. Often a per-object VALUE can become part of the group KEY instead (`drawDistance` now is: tested once per batch against the box over member positions in `renderStaticBatches`, docs/model-pipeline.md "Draw distance on a batch"). A batch-level test must never go through the `shown` snapshot (camera-dependent flips would re-bake every frame).
5. **The grouping cell derives from content, never the map**: `max(mapW / 4, 48)` gave a 2048 map 512-unit cells, merged 1,100 objects into FOUR batches and turned a 0.46 ms win into a 3.20 ms loss on `examples/large-terrain`. `cellFor` bounds the cell by the group's shared draw distance (`min(80, 145)` = 80 on the district). A per-group key is also a per-group SCALE; and a ratio is not automatically scene-independent (an occupancy threshold was rejected: the district's win comes from 6.7%-fill cells).
6. **A batch must not throw away the baked triangle strip**: `rebuildStaticBatch` must read `stripVerts`/`stripRun`, not `GameModelPart::verts` (reading the list made batching a net LOSS: +3.3% vertices, +1.7% bags, `strip` packages down 3,900). Runs are self-contained `stripRun` vertices; `pinPackageSize(bags, stripRun)` makes each package one run; `stripRun` is part of the key; strip/list is all-or-nothing per batch. When A/B'ing read `verts`, never `trianglesCull` (strips count `size-2` incl. degenerates, lists `size/3`).
7. **A bag gets ONE dynamic light** (`StaPipCore::render` picks it from the bag's bounding sphere): `lampOf` in `buildStaticBatchList` keys lamp reach (7 of 49 district batches mixed lit/unlit before). Any key that merges more objects must be checked: do members of a group agree on the lamp?
7b. **Texture filter is part of every texture key** (docs/texture-filtering.md): `StaticBatch::textureFilter` + `addMember`, the twin's `Batch::textureFilter` (oracle fixtures L/M), and `procInstGeoRange`'s per-(texture, filter) groups. With atlasing two members share one `Texture*` page but a bag has ONE `TEX1`; keying by the pointer alone silently draws one of them with the other's filter. A missing texture (nullptr) carries filter 0 so it stays in the untextured class (fixture E).
8. **Model batches stay within spatial cells** (Aster: cross-district groups destroyed culling; per-object material groups widened bounds and cost more fill than they saved). Parts group by loaded `Texture*` + coarse world cell; singleton groups rejected; models whose horizontal footprint exceeds half a cell stay solo; mesh LOD, impostors, reflections, dynamic lighting and runtime-reference objects stay solo. A multi-part member may be in several batches (`objectBatchOf == -2`): yes/no tests use `!= -1`; helpers needing one batch require a non-negative index. Dirty demotion removes every part before the object path draws it.
9. `buildStaticBatchList` rejects `wantsMatrixPath` even when stale data says `batchStatic` (a world-space batch would make the solo loop skip a vehicle/scroller); guard before group construction.
- Beware the near-miss: `SceneObject::dynamicLighting` (sets `bag->lighting`, selects `cull_td`) is NOT the runtime per-bag light pick (`wantsLightPick = !bag->lighting && info->dynLightPick`, feeds the colour programs' single spot slot).

**The twin and its oracle** (`staticbatch.{hpp,cpp}` ~280+550, `staticbatchdisk.cpp` ~170, `batch_ui.cpp` ~460; Tools > Static Batches, View > Static batches, `--batch-report`): the grouping runs on the EE at scene load over loaded `gameModels`/`gameMaterials`, live `g_dynLights` and engine `Texture*` pointers, so it cannot move host-side without changing every project's output. `staticbatch.cpp` is the host twin (no GL/ImGui/templates.cpp); the disk-backed asset supplier is a SEPARATE TU (`staticbatchdisk.cpp`, may include templates.hpp for `bakedModelPath`) so the twin links alone. **Oracle is mandatory**: `examples/vehicle-playground/authoring/verify-batch-twins.py` lifts `buildStaticBatchList` VERBATIM by string index, compiles it against stubs and diffs member assignment over eleven fixtures (proven able to fail). Eligibility is oracled by `batchStatic` (87 of 142 on vehicle-playground; the twin reproduces the game's recorded 65-in-48). **Trap**: `acquireTexture` caches by PATH and returns nullptr for a missing file, and bags group by that pointer, so missing textures batch with untextured primitives - fixture E pins it; "fixing" it makes the panel wrong. `Reason` has two stages (build = object property; runtime = depends on cell-mates). The panel computes nothing; the viewport draws a flat `BatchOverlayBox` list.

## `dirty`, the matrix fast path, coarse boxes

- `RuntimeObject::dirty` makes `renderScene` rebuild the object's whole WORLD-space vertex array on the EE: right for one-shots (Move/Rotate/Set Position, recolor), ruinous per frame. Continuous motion belongs in a game-loop pass on the **matrix fast path**: `rebuildObjectGeometry(i, /*localSpace=*/true)` ONCE (gated on `physFastPathEligible`) bakes local vertices, then `updateObjMat` refreshes `objectGeometry[i].objMat` and VU1 applies motion. Users: physics bodies (PROGRESS 116), `updateSpinners()` (Spin Object node writes a RATE; PROGRESS 222). Ineligible objects (usable, reflective, animated models) fall back to `dirty`. Trade-off: baked shading freezes at the promotion pose.
- A generated SCRIPT asks via the RuntimeObject: sets `wantsMatrixPath`, reads `onMatrixPath` (mirror of `ObjectGeometry::matrixMode`, kept by `rebuildObjectGeometry`); `renderScene` promotes. The promotion is checked BEFORE `dirty` (the object dirties itself the frame it asks); only a SCALE change still needs a `dirty` re-bake (scale is baked into local vertices). Endless scroller clones: 16 -> 50 FPS on examples/endless-runner.
- `ObjectGeometry::coarseBox` + `coarseObjectOutside()` reject a whole model before its parts enter StaPip (main and portal views). EVERY object with geometry gets the box since 1.124.1 (the old three-part threshold was refuted on hardware: StaPip classifies an off-screen bag in ~17 us vs ~2 us for this test, paid again per companion bag - lightmap, emission, env). Don't restore a threshold without a console A/B (docs/profiling.md, "The game side of the object loop"). Keep precise per-part/package culling for intersecting models, transform frustum planes for matrix-mode local vertices, skip impostors (billboards rewrite vertices), bypass when a VU script moves geometry beyond the box.
- `renderProcChunks()` and the road-only env pass reject a chunk's world AABB against the frustum before StaPip (1.117.1) - removes wholly invisible bags only; StaPip still clips intersecting ones.

## Bag arrays and version stamps (docs/bag-content-version.md)

- **`contentVersion`**: the baked VIF stream INLINES vertex payload, so an array rewritten in place (re-shade, per-frame fresnel) leaves its block stale while every other key is unchanged. Chunk/part passes reusing one vertex buffer share ONE `contentVersion`. Do NOT widen `bboxVersion` to cover it (that conflation IS the defect). Every bag-backing array in the game is a `BagArray<T>` (`inc/bag_array.gen.hpp`, always overwritten): `data()` is const, no public writable pointer, the four `bind()` overloads aim stream pointer AND stamp together, every mutating member stamps - a raw write does not compile (`tools/bag-array-enforcement.sh` is the negative test; it goes red if `data()` becomes non-const). Resize a converted fixed C array before its FIRST updater, not merely before its lazily bound bag: indexing an empty `BagArray` is a null write PCSX2 hides and hardware reports as a cause-3 TLB miss at `BadAddr 0` (vehicle smoke, skid, glow were the case). Engine-owned exception: skinning writes LOD 0 in place (moves positions/normals, covered by `bboxVersion`).
- **`bboxVersion`** = "the bounding BOX moved"; the engine's package-bbox cache (`StapipBagBBoxesCacher`) is keyed by vertex pointer, so passes with differing stamps recompute each other's boxes every frame. **A per-frame rebuilder must not bump it when it rebuilt the same bytes** (`bounds` recomputes and `dispatch` rebuilds retained command blocks - the wheel batch's unconditional `++g_bboxStamp` was a fifth of the Motor District's render submission, docs/wheel-rebake-skip.md). Shape: address the buffer by SLOT, keep an exact (not hashed) per-slot input signature, rewrite only changed slots, bump only when one did; check the buffer's ADDRESS and LENGTH too (the cacher stores no count); trim the slot table in step with the vertex vector (else one frame of stale geometry).
- **A bag lit by VU1** (opt-in dynamic lighting, `GeoPart::litBag`): normal capture is per PART (`g_litNormals` staged inside each builder loop; pointing at `parts[0]` piles every part's normals into part 0 and the model renders flat white); light colours in the same space `pushVert` used for that part (255 untextured / 128 textured, `GeoPart::litScale`; the untextured lit program never reads the colour bag, so albedo rides in the light); exclude from `staticBatchEligible`; seed colours where the bag is WIRED (a dirty object is rebuilt inside the draw loop after that frame's update).

## Frame-level settings whose answer lives in the engine

- **Triple buffering** (docs/frame-pacing.md): the engine can REFUSE it, so `project::tripleBufferingFit` is a HOST TWIN of `RendererCoreGS::allocateVramBuffers`' headroom check and Preferences warns with numbers. Reserve constants are shared by convention - change both - and the twin must know what else the engine allocates first: the BLSS low-res colour target (plus, for Particles only, the low-res z target) is placed AFTER the layout (in neither the reserve nor `getHeapWords()`), and a project whose scenes MIX - or that has a Set Upscaler node, or draws particles only - pins z at full display raster. Hence `tripleBufferingFit(const Project&, const ProjectSettings& staged, modeKey)` + `project::tripleBufferingModes`: `supportedModes` lists modes a player can switch INTO and `RendererCore::setDisplayOutput` re-runs `allocateVramBuffers` on each, so the setting is a REQUEST. The dialog answers per mode, greys the tick only when no mode fits (never the untick), names disagreements, and computes the way out (probes a `blssEnabled = true` copy: true at 512x448, false at 512x512).
- **Hybrid triple buffering** (1.153.0): one PSMCT32 draw target + two PSMCT16 display targets + PSMZ32 scene z; the engine rotates only display slots 1/2 and fences the finished copy before queueing; slot 0 stays the draw target. Same project flag/generated option (no migration). Temporal history and extrapolation remain unavailable with it.
- **GS headroom uses whole page rows**: 64x32 at 32 bits, 64x64 at 16 bits, including the Z format. A 512x224 CT16 target costs 256 KiB, not 224 KiB.
- **Frame extrapolation** (docs/frame-extrapolation.md): a behavior switch in user-ownable sources (`presentExtrapolatedFrame` in both main heads + both game-hpp declarations); owned projects never receive it. BLSS (Whole 3D scene) x extrapolation is mutually PREVENTED in the settings (blss.md).
- **Motion-blur idle clear** (`ProjectSettings::motionBlurIdleClear`, 1.89.0, docs/motion-blur.md): the authored amount lives in `g_motionBlurBase` (UI Editor or Set Motion Blur); after ~0.12 s below the camera translation/turn-rate threshold the game sends zero for ONE frame, then restores the base even while parked. Never turn it into continuous speed scaling (kills blur on objects passing a still player). Reset camera/idle state on scene load. Key written only when false; update equality, serialization, UI, `sceneDataContent` and BOTH game templates together. Detector in units per SECOND (per-frame comparison failed at ~30 FPS on hardware). Vehicle speed feel adds `g_vehBlurFix` as a floor under `g_motionBlurBase`.

## Submission (engine-side, inherited by rebuilding)

- Static object submission scopes (1.93, docs/static-submission-batching.md): the main Objects loop opens a StaPip submission batch around owned per-object geometry; end and reopen around reflected-object probe rendering and serialized per-object cost measurements; end before the outer Objects timing boundary and later passes. Don't move already-submitted stream writes or external GS/view operations into the scope. End submits asynchronously; streams stay immutable through the next VIF1 sync. Game-overridden programs, clipping/copy paths, large bags and nonresident/non-REPEAT textures keep immediate submission.
- Retained static command data (1.96.0, docs/retained-static-commands.md): inside that scope a wholly visible static bag's VU1 command block is captured once and replayed by memcpy; only MVP, picked light and frustum classification are rebuilt. Engine-only; packets byte-identical; nothing in src/ changed.

## Static models: consolidation, proxies, impostors, env maps

- `templates::bakeStaticModels` merges OBJ parts only after final atlas texture, Kd/Ke, reflection state and LOD chain are known (exact render-state equality; material NAMES are not render state). Build strips AFTER the merge (may cross former `usemtl` boundaries). Never merge ordered billboard-impostor parts (part index = capture view).
- `modelproxy.cpp` (~110): a one-material convex XZ footprint prism assigned through the non-billboard `impostorPath` (an ordinary OBJ/MTL, not a new asset type). `SceneObject::reflectionProxy` (format v57): the game lazily builds one 12-triangle untextured box bag from current visual bounds, submitted only in the two dynamic env-map object loops (main rendering, collision, picking stay full detail).
- Dynamic env-map paths submit `renderTerrain()` then `renderRoadChunks()` before reflected objects (1.117); the latter filters `procChunks` to reserved owner `-3` - never call the general procedural renderer there (every prefab/runtime volume would be submitted again). The probe reuses the main camera's resident ring; no independent terrain streaming for a 128px view.
- Shared dynamic env sampling uses the LEVEL capture's world-up, not the pitched chase camera's; static sphere-map images keep the view basis; reflected-ray probes their own. Viewport `envSt` mirrors this. Diagnose by inspecting the env target separately from the car (populated target + unchanged car = a sampling problem).
- **Distant foliage impostors** (1.73.0, docs/impostors.md): `treeimpostor.cpp` bakes eight orthographic captures (binary alpha, RGB padding) into a 4x2 atlas + eight ordered OBJ material parts; only one part (two triangles) draws. `treegen::writeImpostor` serves the UI and grove generator. Fields `impostorPath`/`impostorDistance`/`impostorBillboard` (JSON `impostor`, `impostorDistance`, `impostorBillboard`, format v40) - update equality, serialization and recipe hash together; default false keeps legacy far OBJs. Codegen keeps the original collision identity; the billboard path selects a camera-local yaw sector and updates six positions/STs in place. All parts must survive the model bake in order. Tilted / non-uniform-XZ transforms fall back to near geometry. Viewport capture selection and stable upward lighting must match the runtime. The OBJ loader recomputes face normals (writing `vn` alone changes nothing). No engine/VU changes.
- Universal OBJ capture (1.74.0): `impostorbake.hpp` describes textured parts; `treeimpostor.cpp` owns the shared rasterizer/tree adapter; `modelimpostor.cpp` loads OBJ/MTL parts, overrides, Kd, source images. `props_ui.cpp` "Bake impostor" makes one scene commit on success and invalidates viewport assets. Missing inputs and reflective/emissive parts fail before writing. The grove's host helper bakes trees and a waystone via this adapter - keep its compiler command in sync with its deps.
- Impostor views (1.75.0, format 41): `impostorViews` 4/8/16 (default 8); the requested count is pending until a successful bake; the committed count drives picking, viewport and runtime. `impostorgpu.cpp` supplies an optional GPU capture callback registered in main (CPU-only tools stay GL-free); private GL function table; allocate-then-fill textures (AMD workaround).

## Model formats and bakes

- `tmdl.cpp/.hpp` (~200+155, docs/model-pipeline.md): the binary static model the game ships; pure serialization (`tmdl::Model{parts, min, max}` -> bytes; `.tskl` conventions: 4-byte magic, `u32` version read as a range, packed LE, fixed NUL-padded strings, counts + inline arrays). Written by `templates::bakeStaticModels` (from `refreshGenerated`, so `--refresh-gen` produces it without Docker); read by the engine's `TmdlLoader`, returning the same `LeanObjMesh` as the .obj loader (one geometry path). Resolved at bake: triangulation, flat normals, V flip, material assignment incl. per-object .mtl override, atlas UV rects folded into UVs, bin-relative texture paths, LOD tiers, and (v3 trailing section, only with *Flashlight shadow volumes*) the positions-only **shadow proxy** for models over `meshlod::kShadowProxyMaxTris` (1200; torch and the frame's carving spot light extrude it). texbake then skips mirroring the source .obj; the Runner sweeps superseded ones from `bin/`. **Layout lives in two files with "keep in sync" comments.** The game never reads .obj.
- `meshlod.cpp/.hpp` (~360+105): bake-time quadric-error half-edge collapse shared by `.tskl` and `.tmdl` bakes; tier policy (`kRatios` 0.5/0.25 of welded count, `kMinCorners`, `kShrinkSlack`). **`weld(..., keyNormals)` must be FALSE for static meshes** (flat per-face normals make every position a seam twin; nothing decimates) - `generateTiers` welds by position+uv and calls `recomputeFaceNormals` after. Animated meshes keep `keyNormals` (authored smooth normals are data). Primitives need no proxy (the game's `primShadowMesh` runs `addBox/addSphere/...` on an identity object - generators emit WORLD-space per-object triangles, the reason geometry features have a separate primitive branch). `generateShadowProxy` welds ALL parts by position only and decimates with `lockBorders=false` (Garland's perpendicular-plane penalty; locked open borders stall far above the 1200 budget). **Same bytes on every OS:** a bake output that is committed (.tmdl, AO atlas rects, physics hulls, the star table) or hashed into a cache signature must not depend on the platform - ties in `std::sort` are broken explicitly (libc++ and libstdc++ order equals differently), trig goes through `detmath.hpp` (libm last bits differ), and CMake builds with `-ffp-contract=off` (Apple Silicon clang fuses FMAs). A Mac once read a Windows GI cache as stale through one ulp of a sun direction. **Second trap:** the quadric sees a FLAT grid as free to collapse, and on a model the grid is often there only to carry per-vertex light (GI probes, baked lamps) - a tier of a floor slab keeps a few long triangles and visibly changes brightness. That is why the game picks a static model's level by the distance to its world box (`coarseBox`, 1.177.12), not its origin: a floor you stand on stays on tier 0 (docs/model-pipeline.md, "LOD distance is measured to the box").
- `meshstrip.cpp/.hpp` (~310+105, docs/model-pipeline.md "Triangle strips"): welds corners by their EXACT 32 bytes (position, normal, UV - a crease/seam stays two corners), walks strips over edge adjacency, packs into independent runs of `kRun` = 75 vertices (the VU1 package size the game pins: `StaPipBag::stripped`). Returns false when strips are no smaller (caller keeps the list). Seeds fewest-neighbours-first; SIX seed orientations (a strip's trailing pair is ordered; reversed triangles are free since nothing backface-culls): on a 200-cell row, index order + 3 orientations gave 201 strips of length 4, both rules one strip of 402. **Weld key is a property of the BAG** (`Weld`): `kFull` for anything shaded; `kNoNormal` (position+UV) ONLY for a bag rendered unlit with one flat colour - used by `vehbake` for the wheel; using it on a lit bag is a rendering bug. Harness: expand strips back and compare triangle multisets (tyra-testing).
- `primmesh.cpp/.hpp` (~170+30): GL-agnostic unit-primitive tessellation (box/sphere/cylinder/cone/plane -> pos+normal+uv), the single host source (viewport, decalproj receivers, gibake). templates.cpp keeps its own generated-string builders for the PS2 (the pre-existing twin).
- `objparser.cpp/.hpp` (~450+110): editor-side Wavefront .obj/.mtl reader; `load(..., splitObjects)` keeps `o`/`g` groups apart (model importer); `applyMaterialOverride` (animated models' `.mtl` override; only Kd + texture survive).
- `texbake.cpp/.hpp` (~960+40): build-time texture bake mirroring `res/` into `.res-baked/` (what the generated Makefile copies next to the ELF), quantizing PNGs to 8/4-bit per project policy (`Project::textureQuality` per asset); sources untouched. Applies the modelao multiply, atlas pages, stochastic supertiles, sky crops, shadow pages; treats `.uvs` sidecars as editor-only.
- `pngquant.cpp/.hpp` (~540+70): median-cut RGBA + Floyd-Steinberg -> palettized PNG (PLTE + tRNS; PSMT8/PSMT4); `quantizeRGBAToMemory` is the in-memory twin (vehicle textures).
- `texatlas.cpp/.hpp` (~560+115, docs/texture-atlasing.md): `ProjectSettings::textureAtlas` packs small (<= 128) clamp-safe map_Kd textures into shared 256x256 pages. Deterministic plan (eligibility with real model UV bounds via objparser, dir-grouped shelf packing, 2px gutters) consumed by texbake (composites pages, rewrites baked .mtl with `# tyra-uvrect`, skips members) and templates.cpp (`TEXTURE_ATLAS_INFO` boot line). Runtime: LeanObjLoader parses the hint (models remap at load; `LeanMtlMaterial::uvRect` -> GameMaterial -> `g_primUvRect` multiply in `pushVert` for primitives). Exclusions: terrain (tiling), emitters (VU1 UVs), decals/mirrors/portals, refl maps, textureQuality-pinned assets, cross-DIRECTORY refs (a SUBDIRECTORY token like `Textures/wall.png` is fine since 1.60.0 - refusing it disqualified every Kenney-style pack), author keep-outs, a group whose only member would sit alone. Grouping = the .mtl's directory OR an author `Project::atlasControl` group; members bucketed by average hue so a page's shared CLUT isn't split between clashing images. Pages quantize as ONE image, so atlasing a 4-bit project can COST VRAM - `texatlas::vram()` computes both sides; `--atlas-report` / Tools > Texture Atlas (`atlas_ui.cpp`) print them with every refusal reason.
- `stochtile.cpp/.hpp` (~160+40, docs/terrain-painting.md): texture bombing - bakes a source tile into one larger still-tileable supertile (<= 512^2) by scattering rotated/flipped/offset feathered patches on the torus (zero runtime cost). texbake writes `.res-baked/stoch` (regenerated wholesale, exempt from the vanished-source sweep); the viewport uploads the same pixels; codegen points the terrain texture table + tiling at it (`bakedBinPath`/`factorFor`). Deterministic (seeded from the source path). Per base / per layer (`SceneData::terrainBaseStochastic`, `TerrainLayer::stochastic`).

## Materials live in the `.mtl`

A `SceneObject` carries only `materialPath`; a material feature rides in the Wavefront file as a standard-looking statement, **parsed FOUR times, kept in sync**: `src/objparser.cpp` (host/viewport), `App::loadMaterialFile`/`saveMaterialFile` (Material Editor's staged `MatEdEntry`, mateditor_ui.cpp), and `parseMtl` in the engine's `lean_obj_loader.cpp` (fills BOTH `LeanObjMaterial` for models and `LeanMtlMaterial` for primitives). Members: `refl` (docs/reflective-materials.md), `Ke` emission (docs/emissive-materials.md), `# tyra-uvrect` (atlasing), `# tyra-filter` (texture filtering, docs/texture-filtering.md - BAKE-ONLY: texbake writes it from `Project::textureFilterOf(source texture)`, only the engine parses it; the editor parsers never see it because sources never carry it), editor-only hints `# tyra-brightness` / `# tyra-glow` / `# tyra-glow-light` / `# tyra-bake` (colour x strength round-trip).
- A hint carrying authored controls behind a resolved statement (`Ke`) has ONE resolve function (`App::matEdKe`) used by the writer AND every preview; the reader keeps the raw statement out of the staged fields (else hint and statement clobber each other by line order).
- Runtime plumbing for a new field: a member on BOTH `GameModelPart` and `GameMaterial` **in both game-hpp templates** (`TPL_GAME_HPP_ORBIT` and `TPL_GAME_HPP_FPP`), copies in `loadModelAsset`/`loadMaterialAsset`, a staging global next to `g_primKd` set in BOTH `rebuildObjectGeometry` and `rebuildStaticBatch` (miss the second and batched props lose it). Asset-import and texbake `.mtl` rewriters pass unknown lines through verbatim.
- Animated `.glb`/`.fbx` take a `.mtl` override via `objparser::applyMaterialOverride`, which carries only `Kd` + texture; refl/Ke have no `.tskl`/VU1 slot - say so in docs rather than fake it.
- `mateditor_ui.cpp` (~3.9k): Material Editor - `.mtl` load/save, paint-layer stack + its own undo, raytraced map bake, UV validator, texture hot reload (`liveTexNotify`, devkit-and-live-channels.md).

## Particles (docs/particles.md)

- `particletex.cpp/.hpp` (~280+50): host-only deterministic `generate(ParticleTexGen)` -> smoke/flame/glow RGBA, PREMULTIPLIED (an additive bag ignores texture alpha, so the shape lives in RGB); `writeAssets` writes `res/materials/particles/<stem>.png` + a one-material `.mtl`, each only when bytes change. `particle_ui.cpp` (~480): Tools > Particle Editor (window key `particles`).
- **A linked emitter (`SceneObject::particleEffect`, by NAME) gets the effect's values COPIED into its own emitter fields by `project::applyParticleEffects`** (called from `commitChange()` and end of `load()`), so codegen, viewport, Live Link and the time machine never learn the library exists. A new emitter field an effect drives = FOUR places: `ParticleEffect` (+ `operator==`), the section writer/reader, `applyParticleEffect`, the editor widget. The window commits only when `!IsAnyItemActive()` (the copy rewrites SCENES).
- Vehicle smoke is the second consumer: `VehicleDef::smokeEffect` (wins over `smokeMaterial`) -> one `VEHICLE_SMOKE_LOOKS` row per definition (look numbers + up to 8 flipbook frame `.mtl`s) via `vehbake::smokeLookOf` (the ONE effect->smoke mapping); the runtime keeps a pool (`VehFx`) per definition with its own texture/blend via `acquireTexture` (smoke textures do NOT join `MATERIAL_PATHS`). Built-in `vehicles/fx-smoke.png` = `particletex::generate(vehbake::builtinSmokeRecipe())` - ONE procedural smoke generator. `--bake-particles` is the headless twin.
- **Flipbooks**: frames `framePath(mtl, k)` listed CONTIGUOUSLY after frame 0 in `MATERIAL_PATHS` (runtime addresses `material + k`; `emitterFlipbookFrames` falls back to 1 otherwise); residency keeps all loaded.
