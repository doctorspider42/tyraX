# Assets: Asset Browser, model import, animation (clips, import, retarget), UV unwrap, tree generator

Read when you touch `assetbrowser.cpp`, `modelimport*.cpp`, `glbparser`/`fbxparser`, `animedit`, `animmerge`, `uvunwrap`, `treegen`, or add a new asset file type / asset-path field.

## Asset Browser (`assetbrowser.cpp` ~2.2k, docs/asset-browser.md)

- `res/` IS the asset database: views over the file system (`scanAssetTree`, throttled while open) plus two things a file manager cannot do:
  - **`rebuildAssetUsage`**: ONE pass over the model recording every stored asset path (unused ring, inspector user list, delete warnings; keyed off `modelEditSerial_`).
  - **The sibling invariant**: Wavefront references (`mtllib`/`map_Kd`/`refl`) are bare names resolved next to the referencing file, and the PS2 cannot walk `..`, so `moveAssets` moves a transitively closed dependency group (`assetWavefrontDeps`), COPIES a dependency the files left behind still need, and REFUSES rather than half-applying a breaking move; `renameAsset` (same folder) rewrites siblings (`rewriteWavefrontRef`) and carries an exclusively owned `.mtl`.
- **`retargetAssetPath` is the single list of every field that stores an asset path** (project-model-and-serialization.md). Sidecars (`.uvs`, `.aov`, `.drone`, `<tex>.layers/`) travel with their asset; a baked `.tmdl` is deleted for the next build to redo.
- **A new file type becomes a first-class asset** by joining `assetKindOf`/`assetKindName`, the filter-chip counts, `matchesFilter`, `kindColor` (APPEND - cases are numeric, inserting shifts every colour), `activateAsset` and the inspector switch (`.drone` is the worked example).
- Host-only except `Viewport::assetThumb` (one render per asset into a dedicated FBO, copied into its own texture, a few per frame) - the non-UI half is harness-testable (PROGRESS 105).

## Model importer (`modelimport.cpp/.hpp` ~1.17k+150, `modelimport_ui.cpp` ~940, docs/model-import.md)

- **The ONE model importer**: host-only `load` -> `plan` -> `write` (+ `staticTwin`), shared by the Import model window and `--import-model`. Every format lands in one neutral `Source` (objects -> material pieces, 8-float corners, PNG images) and leaves as the same shape: static = `.obj` + `.mtl` + PNGs; animated = the `.glb`/`.fbx` + `.mtl` + PNGs.
- **There is always a `.mtl`** (white `default` when the file has none); an animated model wears it through `materialPath` (`addModelObject`/`assignModel` set the sibling `<stem>.mtl`; `applyMaterialOverride` maps an unnamed part to `default`).
- (1) **`.fbx` is read straight off ufbx, not through `parseSkel`**: the skeletal parse gives every rigid mesh node a matrix-palette slot and the slot is a BYTE, so a 546-prop pack lost every object past the 256th. `.glb` still goes through `parseSkel` and has that limit (documented).
- (2) **Static vs animated is the ENTITY's choice** (Add object > Object > Model... / Animated model..., `openModelPicker`): a `.glb` placed as a static Model gets a `<stem>.obj` twin (`staticTwin`, bind pose, an existing `.mtl` untouched). No new `PrimitiveType` or field - the kind is the extension of `modelPath`.
- (3) **`assignModel` is the one answer to "what resets when a model changes"** (clips, Player locomotion clips, the material that came with the old model; a deliberately assigned shared `.mtl` stays).
- The window's VU1 vertex readout runs `meshstrip::build` on flat-normal copies of the plan (the bake's own answer). Preview = `Viewport::renderImportPreview` (own FBO; per-mesh offset = a split model's origin).
- **Pickers list from `scanAssetTree` (every model under `res/`), never `listAssetFiles("models")`**: models may live anywhere (`examples/showcase` keeps 105 in `res/aster/`); a `res/models`-only picker showed such projects ZERO models - this is the whole old-project compatibility story (no migration). `pickableModel` excludes build products and derived models (`impostors/`, `proxies/`, `procgen-` chunks). The Folder field goes through `normalizeModelFolder` (res/-relative, safe segments, no `..`).
- `objparser::load(..., splitObjects)` keeps `o`/`g` groups apart for the importer's split.

## Animated model parsing

- `glbparser.cpp/.hpp` (~1.6k+210): glTF binary importer + morph-frame baker. The PS2's DynPip renders MD2-style morph frames, so clips are SAMPLED on the PC (node TRS evaluated at a fixed rate, CPU skinning, per-frame vertex/normal arrays); `parseSkel` builds `glbparser::Skel` for the `.tskl` bake; `uniqueNodeNames` runs at the end of BOTH parseSkel implementations.
- `fbxparser.cpp/.hpp` (~1.1k+80): FBX via vendored ufbx (`vendor/ufbx`). Fills the SAME `glbparser::Baked`/`Skel` structures (downstream is format-agnostic); the `animimport::` namespace in its header is the extension dispatch every import site calls. FBX curves resampled at 24 Hz + RDP-reduced; axes/units normalized to glTF; external textures copied in at import.

## Clip editing (`animedit.cpp/.hpp` ~380+80, Tools > Animation Editor, docs/animated-models.md)

Non-destructive, host-only. `Project::animClipEdits` holds one `AnimClipEdit` per touched (model, SOURCE clip): rename, time scale, trim window, default loop; `ProjectSettings::animSourceFps`/`animPlayFps` give the project speed ratio (`projectTimeScale`). `applyClipEdits` folds them into a parsed `Skel` right before `writeTskl` in `bakeAnimAssets` (templates.cpp): trim (interpolated boundary keys, rebased to 0) -> scale times -> rename; the source file is never touched; the console pays nothing. **The viewport is the twin**: `Viewport::setAnimEdits` (pushed each frame) makes `updateAnimPose` trim/retime the same way; `renderAnimPreview` poses at an explicit time. Change both. Clip names in the model are SOURCE names; every reference (`SceneObject::animClip`, Player locomotion clips, Animation node's Clip param) stores the EFFECTIVE (post-rename) name: `effectiveName`/`sourceName` translate, `App::effectiveClips` is what pickers list, `App::renameAnimClipRefs` retargets on rename. `animedit::importsFor` is the ONE translation of `Project::animImports` to `ImportSpec` (read by `bakeAnimAssets` - merging FIRST, so an imported clip is ordinary to LOD, edits and writer - and by the per-frame `Viewport::setAnimImports` push).

## Animation import and retargeting (`animmerge.cpp/.hpp` ~2.35k+360, docs/animation-import.md)

- Host-only, no GL/ImGui/project.hpp. **The merge operates on the PARSED SKELETON** (`glbparser::Skel`), never a ufbx scene - format-agnostic (`.fbx` Mixamo clips onto a Blender `.glb` is the common case).
- Same-skeleton merge path: bones match BY NAME (exact, then namespace-stripped + lowercased: `mixamorig:Hips` finds `Hips`), rotations copied verbatim (rigs must share bind orientation). **Safety comes from `TranslationMode`**: bone LENGTHS live in translations, so copying all translation channels rebuilds the DONOR's proportions; the default keeps translation on ROOT BONES ONLY; dropped channels fall back to the TARGET's bind transform (= keep your own proportions), which is also why it composes with `parseSkel` (which already drops bind-equal channels). Root motion is re-expressed around the target's rest hip and scaled by hip heights (`retargetRoot`).
- **`SkelNode::name` is HOST-ONLY** (`writeTskl` does not serialize it; no .tskl version moved). `glbparser::uniqueNodeNames` prevents two nodes answering to one name.
- Traps: (1) `poseGlobals` may NOT assume parent-before-child (glTF order is arbitrary; a forward pass measured 0.42 units of vertex error) - resolve locals first, compose along the parent chain. (2) Never parse two models per frame: `compatibility()` is computed inside `App::animImportProbe` (ONE parseSkel pair, cached in `animProbeCache_` with the boneMap in the key) - never via `glbInfo` (its full morph bake stalled the editor).
- `skelToBaked` is the PREVIEW half: editor surfaces consume morph frames built by posing the parser's OWN scene, which knows nothing of merged clips, so a model with imports is posed/skinned from the merged skeleton (agrees with the parser's bake to 4e-4). `bakedWithImports` is the gate every preview site calls; a model with NO imports routes straight to `animimport::bake` (untouched path). `refreshPoseBounds` re-unions `Skel::min/max` after a merge (the console frustum-culls and box-collides with those).
- **Bone-mapping editor** (Map bones...): `MergeOptions::boneMap` (explicit pairs consulted BEFORE name matching), `suggestBoneMap` (never applied by the merge itself - only offered), `bindGlobals` (bind positions for the canvas). The suggester is multi-signal (`buildBoneInfos`): name tokens through a synonym table (`boneSynonym`: upperarm/arm, thigh/upleg...), token Dice + joined-name LCS, side words collapsed (left->l/right->r) under a HARD side guard (never pair an l-bone with an r-bone; `geoSide` = sign of X), bone-tree structure (depth/subtree/child counts), normalized bind geometry (positions + directions), and anchored consistency over 8 rounds (a mapped parent makes children search among the mapped target's children). Weights 0.5/0.15/0.2/0.15, threshold 0.5. `detectAffixRule`/`applyAffixRule`: one strip/add prefix/suffix rule voted over the unmatched set (>= 3 and >= a third must apply) - one reviewable button. **Alias book**: `canonicalBoneKey` -> target name in `<configDir>/bone-aliases.ini`, written on every Apply, capped 800; nearly maxes the name signal but CANNOT outrank a perfect name+structure match (harness-pinned). Harness proof: rename every donor bone, name match drops to 0%, the suggester recovers the full mapping, mapped merge == self-merge bit for bit.
- `posedPreview` (Test pose): donor posed from its clip, target posed by borrowing mapped rotations + retargeted root (= what the merge bakes); self-pose tracking bounded at 0.06 ONLY when the clip animates bones alone (helper-node tracks are dropped by policy; asserting exactness there was a wrong test twice).
- AI assist: `aiMapPrompt`/`parseAiBoneMap` (hierarchies + bind positions out; validated one-per-donor pairs back; fences/junk tolerated), run through an `aigen::Generator`, landing as ONE MORE suggestion group - never applied on its own.
- **Stall rules**: (1) `animmerge::SkelCache` (`App::skelCache_`): every UI-thread consumer (probe, mapper, glbInfo) parses a FILE once, revalidated by size+mtime; `invalidateAnimCaches` deliberately does NOT clear it. (2) `glbInfo` for a model WITH imports reads `animmerge::mergedSkel` (clip names, bounds, materials) - the morph skinning pass is the most expensive thing the editor does to a model. (3) The viewport's animated bake is ASYNC (viewport.md); workers get copies and no SkelCache.
- **Full retargeter** (v1.30): `buildRetargetCtx`/`retargetLocals`/`mergeRetargeted`; path chosen per import by the mapped bones' BIND ORIENTATION GAP (`retargetInfo`; < 3 deg = verbatim channel copy, bit-exact - keeps harness identity checks meaningful; else, or with mirror/facing, the full path). Full path RESAMPLES at 24 Hz: per bone, world delta from ITS OWN bind applied onto the target's REFERENCE pose (target bind rotated per bone into the donor's bind directions, minimal arc, leaf inherits parent), locals recomposed top-down, RDP-reduced, constant-at-bind channels dropped. The reference pose is load-bearing (a plain bind-offset delta left an A-pose clip floating 45 deg high on a T-pose rig; reference-pose retarget ends the raised-arm fixture exactly horizontal). Facing = world yaw, auto from each rig's ankle->toe direction (`feetForward`), override 0/90/180/270 per row. Mirror = M*G*M world reflection + side-counterpart swap via `canonicalBoneKey`. Twist: an unmapped bone between two mapped ones takes HALF its child's twist (exact; no joint moves) - twist bones MUST be in the ctx so `mergeRetargeted` emits their channels (the first version lost them; harness read 0 deg). Root motion travels in WORLD space scaled by bone-span height ratio. Contact IK is deliberately NOT here.

## UV unwrap (`uvunwrap.cpp/.hpp` ~510+55, Material Editor > UV check > "Unwrap UVs...")

Smart-project: normal-clustered charts (angle threshold, BFS over shared edges), per-chart planar projection + tightest-bbox rotation, ONE global scale (uniform texel density), shelf packing with a bleed margin; deterministic. Two fronts: `unwrapObjFile` rewrites a static .obj IN PLACE preserving every non-`vt` line byte-for-byte; `unwrapTriangles` unwraps a position-welded soup for ANIMATED models - the editor writes a `<model>.uvs` sidecar ("TXUV", per part: material name + corner UVs) that `animimport::bake` AND `animimport::parseSkel` fold in (fbxparser.cpp), so previews, matbake and the shipped .tskl + LODs all see it; parts match by material name + vertex count (stale sidecars self-ignore); texbake treats `.uvs` as editor-only. The UI invalidates viewport/model/bake caches and re-runs the validator.

## Tree generator (`treegen.cpp/.hpp` ~830+130, docs/tree-generator.md)

`leafStyle == 3` uses the embedded `tree_foliage.inc` tone/cutout stamp, authored
by `tools/bake-tree-foliage.py` in Blender. Regenerate the stamp and source PNG
together. Forest/hero presets append to the original six (indices remain stable).
Only the new style samples anchors across the whole crown and along branches
independently of ring count, preserving old recipes.

EZ-Tree-inspired, host-only pure functions over `Params` (harness: link treegen.cpp + define `STB_IMAGE_WRITE_IMPLEMENTATION`; PROGRESS 104). `Params::height` is the tree's SIZE (`thickness`, `leafSize` are fractions of it - new world-space params follow that rule). `Params::crown`: 0 spread (branching recursion) or 1 conical (the trunk keeps its leader; `conicalWhorls()` hangs rings of boughs with a length PROFILE - a conifer is a different rule, not a tuning). `generate()` builds a recursive skeleton into tapered tubes + leaf quads; `bakeBarkTexture`/`bakeLeafTexture` bake tileable 128^2 textures (leaf card: **hard 0/255 alpha** with opaque colours dilated into the margin - the tRNS->CLUT path loses soft gradients and bilinear would fringe); `writeAssets()` emits `.obj` + `.mtl` + PNGs into `res/models/trees/`; `writeImpostor` bakes impostors. **Deterministic in `Params`** (each branch's RNG derives from (parent seed, child index), so a slider adjusts rather than reshuffles). The tree enters the scene through `addModelObject()` - nothing downstream knows trees exist; never add a scene-object type for it. UI: `App::drawTreeGeneratorWindow`/`rebuildTreePreview`/`addTreeToScene` (hud_ui.cpp) + `Viewport::renderTreePreview` on its OWN `treeFbo_`.
