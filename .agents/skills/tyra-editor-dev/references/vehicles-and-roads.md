# Vehicles and roads

Read when you touch `vehbake`, `vehiclesim`, `vehcheck`, `vehicle_ui.cpp`, the generated vehicle runtime (`TPL_GAME_VEHICLES` / `vehicleImpl`), `roadgen`, `junction_ui.cpp`, or road/junction codegen (`buildRoads`). Modelling a NEW car: see the tyra-vehicle-modeling skill. Primary docs: docs/vehicles.md, docs/roads.md.

## Files

- `vehiclesim.cpp/.hpp` (~1.7k+560): wheel detection + the drive model; host-only (no GL/ImGui/App/project.hpp). Single source for the editor test drive (App drives the preview through `step`) and the generated runtime (per-frame twin). Twins with generated code: `bodyRotation`/`vehBodyRotation`, `damagePerformance`, `impactFromDelta`/`dentHash`/`applyDent` vs `vehDentHash`/`vehicleDentApply`, `rpmFor`/`vehRpmFor`, `revLimiterStep`/`revLimiterDipRpm`/`revLimiterOnset` vs `vehRevLimiter*`, `speedFeel`/`updateVehicleSpeedFeel`.
- `vehbake.cpp/.hpp` (~2.3k+320): the vehicle import bake - one `.glb`/`.fbx` in, body `.tmdl` + one wheel `.tmdl` out. Host-only (harness = 40-line main). Deliberately a VEHICLE importer, not a general static .glb path. `kMaxExhausts` = 6.
- `vehcheck.cpp/.hpp` (~1.3k): `--vehicle-check`, the drive model's property tests (exit 0 = all hold).
- `vehicle_ui.cpp` (~1.7k): Tools > Vehicle Editor (edits `Project::vehicles`; the scene knows only a name), `viewportBody`.
  Inspector = scope switch (`vehicleSel_ == -2` is Defaults, `vehicleScopeVehicle_` the car it returns to) + `VehTab` tabs by goal. Every tuned value goes through `tunedRow`/`tunedSlider`: caption | control | a fixed state SLOT (`slotW`, field trimmed with `ui::SetNextRowFieldTrim`) holding Own+revert / Defaults (hover: Make own) / Model / the reason a row is faded / in Defaults the follower squares + Follow popup. Never draw inheritance into the caption column again (it overlapped long labels). A new tunable needs `visitVehicleTuning` (project.hpp) to get inheritance, counts and the tab badge (`tabOfSection`).
- `roadgen.cpp/.hpp` (~1.2k+420): the road spline tessellator; host-only; single source for the viewport and the generated boot-time `buildRoads` raw-string twin in templates.cpp. CHANGE ONE AND CHANGE BOTH.
- `junction_ui.cpp` (~370): junction overrides UI (markers, selection, Junction section); a junction is selected by identity (`App::junctionSel_`), not object index.

## Vehicle geometry

- `glbparser` batches primitives by MATERIAL, incl. geometry from several rigid nodes. `vehbake::meshNodes` and `collect` split a single-weight, identity-IBM part per triangle's palette owner before detecting body and wheels; a genuinely skinned part stays on the dominant-owner path. Without it, four wheels sharing one atlas go to one node and vanish into the body. Rigid nodes sharing one material may collapse to one owner on import; the example preparation keeps one material slot per wheel.
- **Wheel batch is a TRIANGLE STRIP** (1.107.0, "The wheel batch is a strip"): vehbake builds it (vehicle models never pass `bakeStaticModels`) with `meshstrip::Weld::kNoNormal` (unlit, single-coloured bag). Each wheel's block is rounded up to whole runs (else a VU1 package splices two wheels into one triangle). Since 1.117.4 the BODY has a separate `kFull` attempt (legacy flat-shaded bodies honestly refused; a smooth atlas-authored CC96 part: 11,058 list corners -> 4,212 strip vertices, 148 -> 57 packages). **Never `kNoNormal` on the lit body.** Lamp parts stay lists (their rear/front ranges are corner indices). `TYRA_STRIP_VEHICLE_BODIES_BAKE=0` = editor-build A/B control (changes the body `.tmdl` only).
- **Special body parts**: `lamps`, `merged-matte`, and `glass` (split from the palette merge only when `glassOpacity < 1`, after the lamps, never decimated/tiered/mirrored, skipped as wheel carrier; drawn at the translucent tail by `renderVehicleGlass`; the object pass skips it via `GeoPart::translucent`). Any new per-part rule in vehbake (shine, decimation, tiers, carrier) must decide what it does with each; a new object-part render loop owes the `translucent` and `lodHidden` tests.
- **Far tiers** (1.134.0, "Distant vehicles", "An authored far model"): the carrying part is MEASURED (`farPart`, adopted with the lamp indices); the runtime asks that part for its tier - never `parts[0]` (the lamps on a car with lamps; never tiers; drew a second wheel set through every far tier). `VehicleDef::farModel` = authored low-poly twin; `collectFarModel` collects it in the FULL model's canonical frame/origin, matches images by decoded pixels, runs before the palette is sized (its untextured materials share the merge). Unreached parts go into `farHideMask` (`GeoPart::lodHidden`) except `lamps`. Body tier = `vehicleLodTier` (hysteresis; `trafficDistance` for every car but the driver's) via `{{VEHICLE_LOD_TIER}}`/`{{VEHICLE_LOD_HIDE}}` hooks in the object LOD block, not the row's `meshLod`. `applyGeoLod` sets `stripped` for EVERY tier it binds and binds `lodStripVerts` when present. Mixed definitions keep separate runtime wheel batches (a palette car never samples through a textured car's image); verify both together at near range; far tiers carry their own baked wheels.
- **Wheel simplification** protects the outer tyre band; tiny budgets are soft and Import details reports actual cost. `wheel_blur` is a reserved auxiliary node excluded from detection in every mode (incl. None and Automatic). Verify automatic and authored modes at swap speed; body decimation is independent.
- **Textured vehicles**: `vehbake::Result::textures` holds bin-relative names + PNG bytes; `bakeProject` and `vehicleRefreshBake` both write them. The viewport resolves `ModelPart::bakedTextureRel` per draw (never a cached GL name). Palette UV fixup visits only palette parts (real UV V=-1 is valid). A wheel/body image + Kd match permits textured wheels in body distance tiers. Check with the GGBot GLB in Motor District (PNG references, in-game texture, four detected wheels, distant silhouette).
- **These images are the one shipped model texture that does NOT pass through texbake** - anything texbake does must be redone here. `textureQuant` was missed (a 4-bit project shipped a 256x256 RGBA32 car = a third of the texture heap, docs/gs-vram.md): `bakeProject` runs `pngquant::quantizeRGBAToMemory` (in-memory: the bake content-compares before writing). The `-palette.png` ramp is exempt. Do not gate on the output FILE being smaller (GS cost is pixel format; dithering makes palettized PNGs deflate worse). **Palettizing is a TRADE**, gated on the project setting: +0.51 to +0.74 ms per pose on the Motor District (0.119 MB heap free, nothing evicted), with `finish_ms` rising on poses whose frames are byte-identical between arms - live hypothesis: shrinking an allocation moves every later address and changes GS texture-cache behaviour scene-wide (applies to ANY texture-size change; decisive test = pad allocations back and re-measure).
- A rebuild that REUSES a GeoPart (Repair Vehicle, damage re-bake) resets `envColors` to the 128 placeholder, so it must also clear `envPaintValid` and `paintMapSrc` (else the paint pass's quantized view key reads "same view" and the car shows full reflection until the camera turns).

## Vehicle runtime rules

- **Bank/suspension**: `vehiclesim::bodyRotation` / generated `vehBodyRotation` apply vehicle-local pitch and roll before heading, then convert to ordinary object XYZ Euler (use that conversion for body AND wheels; roll on world Z makes bank heading-dependent). Ground-plane fitting uses the hardpoints' projected spacing. Clearance probes are position constraints only (never spring target or velocity source). The wheel batch composes three transform columns per wheel outside its vertex loop. Keep vehiclesim.cpp, vehicle_ui.cpp and the runtime in step.
- **Sleep**: a grounded car sleeps only after 25 stopped updates, when not driven, no AI route, and all looping audio channels silent. Prompt/enter handling stays before the gate; car-to-car collision after it (the response assigns motion and wakes the car next frame). `Vehicles_update` and `Vehicle_sleep` hardware-trace scopes prove it.
- **Exit**: clamps the authored door-side offset outside half the track + tyre radius + player clearance, then floors the player at terrain height; Use and Exit Vehicle share `exitAtDoor`.
- **Damage** (1.138.0, "Damage"): `damageVisual` gates dents, loose pieces, broken lamps, damage dust, engine smoke (the meter still accumulates if mechanical is on); both off = skip impact tracking. `damageMechanical` gates power loss and wreck immobilisation (incl. AI and nitrous). `damagePerfCurve` shapes partial loss (`vehiclesim::damagePerformance` <-> runtime). These fields join tuning inheritance and the format.
  1. A hit = the velocity change the frame's collision stages imposed (`VehicleRt::dmgPreV` taken at loop top for sleepers and right after the drive integrates); `updateVehicleDamage` runs after the car-vs-car pass. Never write a non-collision speed change between those points (reads as a crash).
  2. Dents are a function of REST position only (welded corners cannot split); the rest copy lives in `VehDamageGeo`, re-captured whenever a part's `baseStamp` moves - so anything that bumps `baseStamp` without rebuilding is captured as undamaged.
  3. Dents write matrix-path LOCAL vertices via `BagArray::span` and bump `baseStamp`/`bboxVersion`; they skip lamp and glass colours (`renderVehicleGlow` owns lamp colours; `lampBroken` is how damage speaks to it). `damage*` DriveSpec keys show on the Damage tab and are skipped by Driving by that PREFIX - keep it.
- **Loose pieces** (1.139.0): a piece is a vertex RANGE of a body part's tier-0 array (`VEHICLE_PIECES`, measured into `VehicleDef::pieces`), safe to collapse only because the bake gave each piece whole strip runs. Anything re-ordering/re-stripping a body (new weld key, part merge, run packing change) must keep that (else a bonnet tears a fender triangle). `vehiclePiecesCollapse` runs after every write that could re-grow a lost piece (dent, re-capture). Debris: `vehDebris_`/`vehDebrisBatches_` (one world bag per texture, rebuilt only while dirty), kicked by cars, off collision boxes, deleted past 60 units. The same reorder puts a shiny textured part's matte (near-black texel) triangles LAST; `applyVehicleEnvLimits` shortens that part's env bag to the prefix every frame (`VEHICLE_ENV_LIMITS`; rebuild/tier swap resets it). The editor mirrors by splitting the part in `viewportBody`.
- **Exhaust pipes** (1.167.0): `vehbake::build` reads geometry-free nodes named `exhaust*` (case-insensitive) as {opening, direction} in the canonical body frame; direction = node +Y for glTF, +Z for FBX (measured); exactly vertical = unrotated empty = straight back. `adoptMeasured` carries `VehicleDef::exhausts` (format v93) into `VEHICLE_EXHAUSTS`; runtime `vehicleExhausts()` is the ONE pipe list (nitrous flame, upshift backfire, `updateVehicleExhaustSmoke`), falling back to two guessed rear pipes. `kVehExhaustMax` (runtime) >= `vehbake::kMaxExhausts`. Exhaust smoke rides the tyre-smoke pool: every spawn site takes `VehFx::takeSmoke()` (resets per-puff `smokeScale`/`smokeFade`; bumping `smokeNext` by hand inherits the last puff's size). `exhaust*` keys on the Effects tab (section "effects" in `visitVehicleTuning`). Headless refresh/build adopt markers in memory only; the GUI tick (or hand edit + `--resave`) persists.
- **Lamp glow** (1.141.0): lamps measured per LAMP (connected components -> `VehicleDef::lampGlows`), emitted as `VEHICLE_LAMP_GLOWS` only when `drive.lampGlow` > 0, drawn by `renderVehicleLampGlow` through `beamCoronaTex` - so `projectUsesBeams` is true for such projects (gates the `hud/flare-corona.png` bake and load) and must keep the texture for every vehicle project (the upshift backfire uses the same textured corona batch). Arrays are fixed-size, sized in `setupVehicles`, written by slot (a previous frame's DMA may still read them). Nitrous flame = extra quads (`VEHICLE_NOS_FLAME_USED`). `backfireT` must tick outside the skid-smoke branch (a handbrake slide froze the flash). `lamp*` keys on Effects.
- **Speed feel** (`feel*` keys, Look tab): `vehiclesim::speedFeel` <-> `updateVehicleSpeedFeel` (called from the driver-camera block; nullptr on foot eases everything back and restores FOV). Talks to the loop via `g_vehShake` (applied after Camera Shake) and `g_vehBlurFix` (floor under `g_motionBlurBase`); both game heads carry the consumers - edit as a pair.
- **RPM and sound**: `rpmFor`/`vehRpmFor` allow RPM up to `nosTopSpeed` x redline in final gear while the high-rev crossfade stays capped at full volume. `DriveSpec::powerFade` and the generated longitudinal step apply the same speed-squared fade incl. nitrous relief. The high-rev sound has its own onset and pitch endpoints in VehicleDef (keep serialization, inheritance, `VehicleDefData` and host audition in step); idle loop pitches from launch, the second loop fades in only above its onset. The high-rev enabled switch keeps the sample/curve but codegen emits a silent slot; host audition uses only idle. **Rev limiter** (`revLimiter`/`revLimiterRate`) is presentation only: the dip lives beside `rpm` (`limiterDip`), never subtracted from it (the gearbox reads smoothed rpm); audio, test-drive readout and audition subtract it.
- **Controls card** (1.169.0, "Controls card"): `VehicleDef::tutorialSeconds` (Driver tuning key, JSON `"tutorial"`, written only when non-zero, format v94) emits `tutorialFont`/`tutorialSecs` at the END of `VehicleDefData` (keep the empty `VEHICLE_DEFS` initializer in step). Runtime text; `kVehTut` is the ONE row table (role, fallback pad button, label) and must mirror the fallback buttons `updateVehicles` reads when an `IA_ROLE_VEH_*` is -1 (a new driving button needs a row). Glyphs from `g_inputBind` every frame; unusable rows filtered by `vehTutRowApplies`; stick glyphs via `menubake::optionalBuiltinIconNames()` + `project::ensureStickIcons`.
- `collideVehicleCamera` runs in both game tails after shake and separation, excluding the driven chassis.
- HUD fonts for driveable instances are prewarmed in `setupVehicles` (game-screens-menus-text.md).

## Tuning inheritance (1.153.0)

`Project::vehicleDefaults` is a singleton in `Section::Vehicles` (`writeVehicleArray`/`readVehicleArray`). `VehicleDef::inheritDefaults` is true for new definitions; pre-v85 files without an explicit flag stay local; vehicles-branch files with an explicit flag keep it (both branches reused v82/v83, so v85 unifies; normalization preserves tuning). `visitVehicleTuning` = shared registry of tunable fields and section ownership. `tuningOverrides` holds individual field keys (historical group keys expand during resolution; old "sounds" group overrides also expand to headlights). UI controls edit directly; diffing against the resolved pre-frame definition creates only changed keys. Section "Use defaults" clears its keys - skip those keys in the same-frame diff or the reset recreates them. Geometry keys stay local (`vehicleGeometryKey`). `applyVehicleDefaults` resolves at section-read, commit and codegen. Global asset refs join asset-browser and particle-effect renaming. Global UI reuses tuning tabs without import/test-drive tabs. Headlights belongs to Effects (UI and Use defaults).

## Vehicle Editor preview and sound

- Live preview = a separate lazily created `Viewport` owned by App: reuses cached vehbake models, previews wheel spin/steering and fast-wheel hysteresis, never moves scene entities. Replacing/clearing vehicle draws destroys their VAO/VBOs; the preview drops its private texture cache on bake changes (reused palette paths show edited colours). Shut the preview down before the GL context. Triangle budgets need an explicit editor-only unlock; reflection maps use project texture thumbnails.
- `audiopreview::EngineLoop` decodes samples off the audio thread and owns host audition (atomics carry pitch/revs/volume); stop audio before destroying callback state.
- Sound selectors list all project WAVs. Continuous roles (`engineSound`, `engineHighSound`, `screechSound`) declare encoded loop intent via optional `inc/vehicle_sound_loops.gen.txt` (from resolved definitions; refresh rewrites it and removes stale intent; always-overwritten list). Legacy `-loop.wav` still works.

## Roads

- **Lateral span reduction** (1.85.0, docs/roads.md "The lateral budget"): the roadgen/`buildRoads` twins sample every lateral height, then keep the horizontal collapse, or merge a non-flat span's lateral cells into MAXIMAL RUNS whose every dense sample lies within `kSpanFlatness` of an affine 3-D quad with parallelogram defect within `kSpanShear` (1e-5 and 0.05, roadgen.hpp). Never infer planarity from the shoulders (interior crowns/saddles keep samples). It used to be all-or-nothing and bought nothing (terrain cell 4 u vs 0.5 u lateral sample; all 26 cells of a 13-unit street survived). Lessons: test SUB-spans; and measure which gate fires (the UV budget, not the surface one, was blocking: a trapezoid's two triangles interpolate ST with different affine maps and every district street is curved).
- **Strips** (1.96.0): `roadgen::tessellateStrips` is a THIRD twin beside `tessellate` (triangle list; source of truth for viewport, picking and the align pass) and `buildRoads`. Both host emitters share `buildRows` and `spanCuts` (sampling, heights, texture arc length, lift, planar-span reduction in ONE place). `spanCuts` holds the greedy extension `while (j1 < crossSteps && spanIsExact(rows, i, j0, j1 + 1)) ++j1;` that `verify-road-twins.py` pins by TEXT (its dense reference deletes that line). templates.cpp carries both budgets as literals (raw-string code cannot read constants), held by a `static_assert` against roadgen.hpp at its top. Strips: 93,150 road vertices in 90 chunks vs 13,176 in all baked models; 0.355-0.374x vs models' 0.732x. Rules: dense spans strip ACROSS the road, collapsed full-width spans ALONG it (laterally a collapsed span is break-even and triples GS primitives - 1.000x on every flat fixture); only one interleaving reproduces the list's quad DIAGONAL; runs may not straddle chunks, so `kChunkSpans` (36) and `kChunkBudget` (1800) live in roadgen.hpp; the terrain builder strips **only with a terrain material** (the untextured checker is per QUAD colour).
- **Oracle**: `examples/vehicle-playground/authoring/verify-road-twins.py` compiles both implementations and compares strip output vertex for vertex and chunk for chunk, plus exact triangle-SET equality vs the list and the dense baseline. `ROADSTRIP`/`TERRAINSTRIP` in `bin/log.txt` carry each producer's surface triangle count (pipeline counters cannot compare across representations; docs/model-pipeline.md "What the triangle counters count"). ROADS logs emitted vertices and chunks. The district's seven-road network is an EE memory stress case.
- **Bounded V** (1.117): both emitters and `buildRoads` rebase longitudinal V by `floor(V at chunk start)` (texture-identical under REPEAT; keeps hardware ST bounded - topology was not the smear's cause). The oracle canonicalizes whole V repeats when comparing list vs strip (they may chunk differently); runtime-to-host strips stay exact per chunk. Since 1.117.2 `TYRA_STRIP_ROADS` defaults 1 (0 = diagnostic list arm): road-only district 63,966 vertices / 880 packages -> 24,576 / 347, same 21,322 surface triangles.
- **Sample step** (1.119): optional `roadSampleStep` (1..2, default 1) must reach `roadgen::tessellate`, viewport draw/pick and generated `RoadDefRt`/`buildRoads` alike; texture V still integrates at the original 1 m cadence (else lane marks slide). Motor District: Ring road and East crest at 1 m, other five at 2 m; don't make 2 m a universal default without crest/bend tests. `road-budget-sweep.py` (referenced by docs/roads.md; not in the repo) compared candidates against the dense surface.
- **Intersections**: Properties stores a material path in the legacy-named `roadTexture`/`roadIntersectionTexture`; `project::resolveRoadTexture` resolves the first `map_Kd` (direct PNG values still work). Two crossing roads' intersection references must match. `roadgen::findJunctions` samples the same Catmull-Rom centre line; codegen uses the centre + four strip-overlap corners. Since 1.151.2 `roadgen::tessellateJunctionSurface` fits an adaptive conforming mesh against actual road triangles with 0.02-unit clearance; codegen bakes XYZUV in `ROAD_JUNCTION_VERTS` (`buildRoads` only uploads); flat patches keep four triangles. Generate source roads with the rendered terrain triangle sampler (`roadgen::terrainHeight`), not `project::heightAtWorld`'s bilinear. Never move pairing/fitting onto the EE.
- **Every crossing decision is `roadgen::planCrossings`** (1.145.0, "Junction overrides"): patch or not, who runs through, which spill survives, per-junction overrides (`SceneData::roadJunctions`, matched by road-id pair + nearest position) and winner OVERLAYS. Codegen, `Viewport::syncRoadDraws` and the test drive (`roadgen::addCrossingsToSurface`) only read it, over `project::crossingRoads`. Spills are filtered PER CROSSING (a triangle belongs to its pair's nearest crossing); overlay decals precede spills (the console reads all spill Y before adding chunks, so the overlay height reaches the spill via the row's `lift`, not `roadSurfaceAt`).
- **Road editing** (1.151.0): loops repeat the first XZ pair at the end of `roadPoints`; `roadgen::isClosed`/`controlCount` hide the seam sentinel; host and `buildRoads` wrap Catmull-Rom neighbours and final tangents together (no format field). `moveControl`/`removeControl` preserve closure and minimum counts. Properties: collapsible Crossings/Points + reversible Closed loop toggle; viewport Shift-click deletes, endpoint snap closes at release, one undo each. Outlines reuse `Viewport::RoadDraw` (full-width soft borders keep a separate outline). During viewport drag only, both crossing caches defer work to release. UI scripts can target `Road point N` handles and use `shiftclick`. Verify loop seams + open-road parity with the twin oracle.
- Road chunks opt out of occlusion culling and the whole-AABB frustum pre-test (lighting-and-bakes.md); roads receive baked shadows via `decalproj::Receivers::roads`; decalproj caches road triangles.
