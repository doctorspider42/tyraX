# The upscaler (BLSS) - editor side

Read when you touch `blss_ui.cpp`, the BLSS settings/per-scene override, the Set Upscaler (BLSS) node or `ctx.upscaler`, BLSS codegen/interlock, `project::blssUse`, or quote any BLSS number. User doc: docs/upscaler.md. Engine half: tyra-engine-dev references/blss.md. Measurements: docs/profiling.md ("Timing a frame that BLSS is in").

BLSS = a reduced raster + ONE bilinear pass, nothing else. The neural reconstruction (6-12-3 MLP, `src/blss.cpp`/`blsscorpus`/`blssscene`/`blss_window.cpp`, `--blss-train/-eval/-emit/-coverage`, Tools > Neural Upscaler, `resources/blss-default.net`, its CI workflow, `inc/blss_net.gen.hpp`, bag proxies, jitter/sharpen/temporal/debug views, the host twin) was deleted in 2.1.0: +0.29..+0.42 dB over bilinear, ~5 ms EE, break-even 13 coverages vs 2.6 plain. Do not resurrect a twin: nothing on the host models the composite any more.

## Files
- `blss_ui.cpp` (~580): `App::drawBlssSettings` (the block in *Project > Preferences > Graphics > Advanced*), `blssVramLine` (exact VRAM cost for this project's display mode), `blssClashesFor` / `drawBlssClashWarning` / `blssSelectClash` (the live mirror of the build interlock). App methods declared in app.hpp, own TU.
- Codegen: `blssInit` / `blssSceneSetup` / `blssSceneRender` / `blssClashes` / `blssInterlock` in `templates.cpp`; the particles bracket in `renderScene()` and the runtime switch in `updateAdaptiveResolution()` (`game_templates.inc`, both orbit and FPP heads).
- `project::blssUse` (project.cpp/hpp), `project::tripleBufferingFit`.

## Settings
`ProjectSettings`: `blssEnabled` (project DEFAULT), `blssScale` (0 = 2x2, 1 = 1x2), `blssAdaptive`, `blssParticles` ("Draw reduced: Whole 3D scene / Particles only", written only when true). Per scene: `SceneOverrides::upscaler` carries `blssEnabled` ONLY (`"blss": { "enabled" }`); scale, shape and adaptive stay project-wide because they decide what VRAM is reserved at boot.
- **Format 118** drops `blssNetwork`, `blssSharpen`, `blssTemporal`, `blssJitter`, `blssDebugView`, a scene's upscaler `"network"` and the `blssShots` section on save; the reader ignores them. Bumped so an older editor cannot read the missing `blssNetwork` as true. No migration.
- **`p.settings.blssEnabled` is almost never the question**: use `project::resolvedSettings(p, sc)` per scene and `project::blssUse(p)` for the project (`any` / `anyNative` / `mixed` / `particles` / `runtime`); `blssUse(p, defaults)` answers for a staged, not-yet-committed default. `mixed` is decided on RESOLVED values (byte-identical regeneration is a property of the outcome).
- **A Set Upscaler (BLSS) node anywhere** (scene objects or prefabs) sets `runtime` and forces `any`, `anyNative` and `mixed` true: the build reserves BOTH rasters (z at the full raster + the low-res target, the per-scene table, `setScene()` at every load) so a runtime switch moves no VRAM and evicts nothing. `ctx.upscaler` from a script (-1 leave, 0 scene default, 1 off, 2 on, 3 automatic) needs the node somewhere (or *Adapt resolution*) for the same reason.

## Codegen
- Placeholders `{{BLSS_INIT}}`, `{{BLSS_SCENE_SETUP}}` (shared `loadScene`), `{{BLSS_SCENE_RENDER}}`, each in BOTH game heads. Nothing is emitted while no scene resolves it on (beyond `BLSS_ADAPTIVE`/`BLSS_PARTICLES` = 0): a project with it off generates what it generated before BLSS existed.
- `scene_data.hpp`: `BLSS_ADAPTIVE`, `BLSS_PARTICLES`, and when on `BLSS_ENABLED`, `BLSS_SCALE_X/Y`, plus the per-scene table (`BLSS_ENABLEDS[]`, `BLSS_NATIVE_SCENES`, `BLSS_SCENE_ON`) only when mixed.
- Whole scene: `configure(sx, sy, BLSS_NATIVE_SCENES || BLSS_ADAPTIVE)` and the loop's `beginScene / renderScene / endScene / composite` around the non-split branch, then post fx and 2D at full res. Particles only: `configure(sx, sy, true, true)` (+ `setScene(!BLSS_ADAPTIVE, true)` when not mixed); the loop's bracket is a plain `renderScene()` and `renderScene()` wraps the emitters in `beginParticles/endParticles` - main view only, never during a split pass, skipped when no emitter has particles, `stapip.core.flushDeferred()` first.
- `updateAdaptiveResolution()` runs before the bracket: a scene load resets `upscalerMode` to 0 (scene default); modes 0 scene / 1 native / 2 reduced / 3 automatic. Automatic: start native, four frames over 1.35 fields → reduced, 150 frames within 1.10 → probe native. The timer is the previous LOOP, never scene CPU time (cannot see GS fill stalls). Hardware is the decision gate (PCSX2's software fill never crosses the threshold the console does).

## The interlock
- **`blssClashes()` (templates.cpp) is the source of truth**, asked only for *Whole 3D scene* (`blssUse(p).particles` returns empty: the opaque scene keeps full raster and full z, so nothing clashes). Per scene, of every scene resolving it on: DoF quantised to 1/128 with non-zero focus or the `Set Depth Of Field` node, portals only when **linked** to another Portal in the same scene, split view only with a **second `Player`**, frame extrapolation when on.
- `blssInterlock()` writes `#error` lines into a TU OF ITS OWN (`src/gen/blss_interlock.gen.cpp`), emitted only while clashing and DELETED by `refreshGenerated` when it stops (it used to live in `inc/scene_data.hpp`: ~14 TUs, one clash printed 42 times). ONE SHORT LINE per clash naming the pair, the scene and one fix; `errorSafe()` on the whole line (an unpaired apostrophe after `#error` warns *missing terminating ' character* in every TU).
- The editor mirrors those conditions from ONE place (`blssClashesFor`/`drawBlssClashWarning`) - edit together with `blssClashes()`. `assumeProjectDefaultOn` walks scenes INHERITING the default as though on (explicit off still skipped) for the informational block.
- **BLSS x frame extrapolation is PREVENTED**, not warned (setting vs setting): whichever is on greys the other with the reason IN LINE. Only the TICK is blocked, never the untick (a project can arrive with both on - hand-edited `.tyra`, older editor, a node - so the build interlock stays); the upscaler side gates on `s.blssEnabled`. The other clashes are setting vs scene CONTENT (cannot grey a placed portal).

## VRAM and triple buffering
- `blssVramLine` and `project::tripleBufferingFit` are host twins of the engine's reserve: the low-res colour target always, the low-res z target too for Particles only (`setLowResTargetScale(sx, sy, withDepth)`), and a full-size z whenever the project is mixed or particles-only (the engine pins `setZRasterScale(1,1)`). Only a uniform *Whole 3D scene* project gets the z shrink that pays for a third display buffer. Change one side → change the other.

## Numbers to quote
Pass price 0.5174 ms per full-screen pass at 512x448 on hardware (0.5896 at 512x512); PCSX2 under-reports fill ~76x (no PCSX2 GS timing is admissible); fill retention 0.7548 at 2x2; plain break-even 2.6 coverages at 512x448; adaptive on `upscaler-lab` 16.1 → 44.0 FPS on the parked camera. Particles only is not yet priced on hardware.
