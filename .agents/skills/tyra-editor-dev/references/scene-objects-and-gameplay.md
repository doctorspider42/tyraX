# Scene object types, collision, areas, physics, portals, terrain, cutscenes

Read when you add a `PrimitiveType`, touch collision, comments/screen icons, areas (catch, live, reverb), the endless scroller, physics bodies, placement snapping, invisible walls, portals, the optional terrain, object groups, or the Cutscene Director / camera takes.

## New object type

- `PrimitiveType` enum (project.hpp): values 0-22 used (Box..Cone, SpawnPoint 4, Model 5, Player 6, Emitter 7, SoundEmitter 8, PointLight 9, SavePoint 10, Empty 11, Plane 12, Decal 13, Camera 14, Mirror 15, Portal 16, Area 17, Scatter 18, Scroller 19, Comment 20, Vehicle 21, Road 22); `kPrimitiveTypeCount` (= Road + 1) bounds "every type" loops. Values are serialized - keep them stable.
- Chain: enum -> mesh/marker in viewport.cpp (+ a `pickBounds` case) -> insert menu in app.cpp -> codegen + runtime -> AI Assistant gets it for free (`primitiveTypeName` over `kPrimitiveTypeCount`).
- Per-object variable-length data: do NOT grow the fixed `SceneObjectData` POD; emit a flat side table into scene_data.hpp keyed by (scene, object) - `OBJECT_SCRIPT_ATTACHES` / `MIRRORS` / `SCROLLERS` / `REVERB_ZONES` pattern, or a sparse helper (`objectBlobTextureFor`).
- **A type with no geometry must join every marker skip list** - scattered by NUMBER (`o.data.type == N` lists): the USE-target scan, the carry/throw sweep, `physObstacle`, the geometry `switch` in templates.cpp, `flowRaycast` in `flowGraphScript`, `blocksNavigation` (navmesh.cpp), `objectShape`/`regionCountFor` (aobake.cpp; its `default` excludes unknown types). Miss one and an invisible marker blocks the player or eats a raycast.
- **Collision is ONE pair**: `collidePlayer`, `sweepSphere` (camera boom) and `objectOutsideSplitBand` go through `objectCollides`/`objectCollisionBox` (three hand copies had drifted: the scroller marker blocked the camera but not the player; none turned the box by an animated model's `modelYaw`, so an X-forward character collided at 90 degrees). Host twin: `placement::collisionBox`/`collides` (View > Collision boxes overlay, placement snap, drag/paste raycast). A new collider type is TWO functions. **Which objects to test comes from ONE broad phase** (`broadPhaseNear` / `broadPhaseAlong` over engine `Tyra::BroadPhase`, docs/collision-boxes.md "The broad phase"): grid or loose octree per project (`ProjectSettings::broadPhase` -> `SCENE_BROADPHASE`) or per scene (`SceneOverrides::broadPhase` -> `SCENE_BROADPHASES`, emitted only when a scene overrides), boxes refreshed per frame (`g_frameStamp`), at the loop's two refresh boundaries (after the script stage, after the spinners: `broadPhaseInvalidate()`; a refresh that changes nothing placed skips the rebuild) and on spawn/(de)activation, each box the union of the full-rotation OBB (sweep, physics) and the walker's upright yaw-only box - code that moves a collider and queries in the SAME stage calls `broadPhaseInvalidate()` in between; candidates come back ascending (the walker's pushes are order-dependent) and the walker asks a full Y column (its box path reads any floor below / ceiling above); `kBroadPhaseVerify` cross-checks it. A new contact query asks it - never a fresh walk of `runtimeObjects`. Both overlays (editor + in-game `renderCollisionBoxes`, `ProjectSettings::showCollision`) exist because a box disagreeing with its mesh is otherwise invisible. Per-model smaller boxes: `Project::modelCollision` (`Section::ModelCollision`, docs/collision-boxes.md "A smaller box"; joins `retargetAssetPath`, not `rebuildAssetUsage`) -> `placement::collisionBox`'s `boxes` argument and `MODEL_COLL_BOX` in generated `objectCollisionBox` - pass the map wherever the question is "what collides".
- **A type whose data drives OTHER baked objects** (heaviest kind; `Scroller` 19 is the reference): codegen APPENDS clone objects to the scene table (authored indices must never shift or every graph/mirror/player reference retargets) and emits a director script that repositions them. Follow the `scrollsim.cpp` host / `scroller.gen.cpp` per-frame-twin split; flag duplicated formulas in both files.

## Invisible walls

Box with `collisionMode == 3` (`collision: invisible`, format 32), not object visibility. Still a collision/nav/physics obstacle; `rebuildObjectGeometry` emits no parts; `staticBatchEligible` rejects it; the viewport draws a cyan wire box (a pick wire-box tier). AO shape/atlas collection, GI geometry + signature, projected shadows and raytraced/reflected views must all exclude it. Already in equality and `liveLinkRecipeHash`. docs/collision-boxes.md.

## Comments (`PrimitiveType::Comment`, docs/comments.md) - the non-geometry type

- The viewport skips the type; the app draws a **screen-space icon** over the image (`App::screenIcons` / `drawScreenIconOverlay`, built on `Viewport::projectToImage`). Particle emitters joined (`ScreenIcon::emitter`, round flame badge) because their cone hid the effect. A new click-not-see marker = one branch in `screenIcons` and the overlay.
- ONE function computes icon positions; overlay and picker both read it. Hit test in SCREEN space at the head of `App::viewportPick` (a fixed-size icon stays clickable at any distance; the 3D `pickBounds` box is only for rubber band and gizmo). The View toggle (`showCommentText_`, default off) controls TEXT expansion, not existence; layer visibility goes through `App::isObjectHiddenInEditor` (drawing, picking, rubber band, gizmo).
- `commentText` reaches nothing downstream and is deliberately out of `liveLinkRecipeHash`.
- Creating one focuses the Properties prose field in two stages: `pendingFocusWindow_` brings the dock tab forward at the END of the frame, so `commentFocus_` stays armed until `IsWindowFocused` says the tab is front (an inactive tab still runs its body with `SkipItems`; clearing early loses the first typed sentence).

## Object groups (docs/object-groups.md)

`SceneObject::editorGroup`: scene-local persistent selection identity (objectJson/parseObject, `operator==` for history/session). Expanded child rows call `selectOnly(i, false)`; `selectionGroupMember_` keeps undo from expanding that selection. Other selection helpers expand membership before manipulating; the gizmo applies a world delta about the centroid; Properties uses a rigid matrix delta for group rotation. Paste renames groups and internal object references; prefab capture clears membership. Editor-only - no runtime hierarchy.

## Areas (`PrimitiveType::Area`, docs/areas.md)

- Pattern for "replace a hand-typed distance with a placed volume": the volume is an ordinary `SceneObject` (transform = box), referenced BY NAME (`SceneObject::catchArea`, `SceneLayer::streamArea`, flow `str` with `FlowParamKind::AreaName`). Point test in exactly two places: `project::areaContainsPoint` (host: previews AND codegen) and `pointInArea` emitted into `scene_data.hpp` (both generated TUs; putting it in the DATA header keeps one definition). `project::areaCaughtObjects` is the ONE expansion (Properties preview, viewport mirror preview, baked target tables, `batchBlockedNames`). New consumers call these.
- **Live catch area** (`catchAreaLive`): re-tested every frame, but only `project::areaLiveCandidates` (objects that can move; `project::objectRuntimeMovable` over `project::runtimeRefNames`) - the exact complement of the immovability `staticBatchEligible` relies on, so a live candidate always has the solo bag a second submit needs. Immovable rest stays baked; movable objects are dropped from the fixed list (no double submit). Candidates bake into shared `CATCH_CANDIDATES` sliced per owner (`liveArea`/`firstCand`/`candCount` on `MirrorData`/`PortalData`/`CamFeedData`); `TerrainGame::collectLiveCaught` walks a slice plus the spawn pool. A new "can move at runtime" rule belongs in `objectRuntimeMovable`.
- **Reverb zone** (docs/reverb.md): SPU2 hardware reverb authored as a room. `REVERB_ZONES` side table with the box unbaked (`TerrainGame::updateReverb` reads live transforms via `pointInArea`). One global decision per frame: the listener is in one room (highest `priority` wins). Two reverb units (one per SPU2 core); `updateReverb` cross-fades: the incoming room takes the free unit while silent (switching the algorithm zeroes its SPU2 work area), then both depths ramp. Per-sound control is a BIT (`SceneObject::soundReverb`, Play Sound's `Dry`) - no per-voice wet level in hardware.
  - **Every play site** offsets its channel by `ScriptContext::reverbBusBase` (0 = core 1, 24 = core 0) - a voice is committed to a room when it starts; a site that forgets is heard in the room just left. Per-channel caches key on the bus (`sndChBus` beside `sndChVol`/`sndChPan`).
  - `reverbPresets()` (flowgraph.hpp) is the single preset table (Area combo, Set Reverb node, codegen) and its ORDER IS WIRE FORMAT (`Tyra::AudioReverb::Preset` = libsd `SD_EFFECT_MODE_*`): append only.
  - **Voices are finite** (24 per bus: 16 Play Sound + 8 emitters, docs/sound.md). Allocation lives in exactly two places: `pickSoundSlots` (emitter loop: per-frame ranking by priority then loudness, with a steal margin) and `flowPickSfxChannel` (flow TU: an ended voice, else lowest priority strictly below, else DROPPED - unlogged, it is the feature working). The table is per bus and resets when the room moves cores (the outgoing bus's voices are not stolen from).

## Endless scroller (`scrollsim.cpp/.hpp` ~370+215, docs/endless-scroller.md)

Host single source for `PrimitiveType::Scroller`: belt axis, segment length, pattern period, clone count, recycle `wrapU` and placement at a scroll distance. Viewport ghost preview and codegen (clone rest positions + `SCROLLERS`/`SCROLLER_CLONES`/`SCROLLER_HIDDEN`) read it; generated `ScrollerDirector` (`scroller.gen.cpp`) is the per-frame twin (`sc_wrapU`, cell arithmetic, `sc_varyHash`/`cellAdjust`). **Per-cell variation**: `Placement::cell` counts along the INFINITE belt (the runtime folds its accumulator for precision, counts the folds and adds them back); `memberVary`/`cellAdjust` hash it into presence, yaw, lateral offset, scale. Derive everything from that hash, never running state. **Anything that bakes the scene as authored must skip belt members** (`memberTemplateFlags`; aobake ignoring it burned a permanent dark patch at the belt origin, invisible in the editor). Clones use the matrix path via `wantsMatrixPath` (runtime-rendering-and-meshes.md).

## Physics (docs/physics.md)

- Rigid bodies: `updateObjectPhysics` predicts the pose, collects corner contacts (terrain, `objectCollisionBox` boxes WITH rotation, collision meshes per corner ray, hull vs hull) and solves with sequential impulses + split impulse.
  - Orientation truth = `TerrainGame::physBodies` (quaternion per physics object), re-derived from `data.rotation` whenever something ELSE wrote position/rotation/spin; code inside the solver must update `PhysBody::lastPos/lastRot/lastSpin` when it writes, or its write reads as external next frame. `spin[3]` is world angular velocity in deg/frame.
  - A shove with a point of application goes through `physPushAt` (player walk-into, car bumper), never a bare velocity add (no spin -> no tipping). A car's bumper push divides EVERY component by mass, hop included (an unscaled hop tipped a 60-mass dumpster).
  - `physBodies` may reallocate while slots are handed out: `updateObjectPhysics` takes every slot BEFORE holding a reference.
  - Mesh collision: since 1.83.0 the static-solid pass has its own `collision == 1` branch over `GameModel::collider` (vertical floor ray previous->current underside, side-aware `resolveSphere` for walls, velocity reflected along the push) - a body inside a merged building's AABB was otherwise ejected through the floor. `sweepSphere` (camera boom, carried object, carry whisker, non-physics thrown arc) still uses the whole-mesh box.
- `physhull.cpp/.hpp` (~250+50): host-only. `build(points)` reduces a mesh to at most `kMaxVerts` (24) support points along a fixed direction priority list (axes, downward box corners, edge diagonals, Fibonacci fill), brute-forces face planes over triples, drops non-corner points, integrates the SOLID hull's volume, centre of mass and second moment. `physHullBlock` emits `PHYS_HULLS`/`PHYS_HULL_VERTS`/`PHYS_HULL_PLANES`/`MODEL_PHYS_HULL`/`PHYS_PRIM_HULL` into `inc/model_data.gen.hpp` for every static model a physics object uses + the four unit primitives - ALWAYS emitted (the template reads them unconditionally). `PhysBody::lv`/`lp` in both game-hpp templates are sized 24/44 by hand, held by a `static_assert` to `PHYS_MAX_HULL_*` - raising `kMaxVerts` is three places. Harness: link physhull + primmesh (+ objparser); a unit box reads volume 1, covariance 1/12.

## Placement (`placement.cpp/.hpp` ~200+110, docs/object-placement.md)

Host-only. `worldAabb` (rotated+scaled unit primitive, or model bounds via `aobake::ModelAabbFn`), `isSupport` (solid primitives / save points / models with `collisionMode != 2`), `restOffsetY`/`restOffsetYGroup` (rest on the highest surface under the FOOTPRINT: terrain at corners+centre plus overlapping AABB tops). `ceilingY` is the behavioral switch: `FLT_MAX` = insert/paste (stack on what's under), the object's own underside = `End` drop-to-floor (nothing may lift it). Not a collision solver (no sweep/penetration). Callers: `App::snapInsertedObject` (every add path), `App::movePasteStaged`, `App::dropSelectionToFloor`; callbacks `Viewport::modelLocalBounds`, `Viewport::terrainHeight` (same triangle heightfield the game walks). `App::placementHeight()` returns an EMPTY `HeightFn` without terrain ("no terrain under the footprint").

## Optional terrain (`TerrainConfig::enabled`, docs/terrain.md)

Reference for "a subsystem a scene can be built without". The flag rides `project::create`'s `terrain` argument, the scene table's `"terrain"` object and `SceneData::operator==`.
- **One decision in the height sampler**: `terrainHeightAtScene` returns `TERRAIN_VOID_Y` (deep but FINITE -1e6) without terrain, so ~30 generated sites (walkers, physics contact, spring arm, raycasts, `aoShadeMul`'s ground term, blob shadow fade) need no branch. Finite matters: infinity makes NaN geometry.
- **Explicit `TERRAIN_ENABLED` only where a site BUILDS something**: `resetTerrainChunks` (no chunks -> `renderTerrain` and streaming are no-ops), `setupLightPools`, the projected-shadow patch, rain fall length, player spawn Y (uses the spawn point's own Y).
- **Host bakes read `sc.terrain.enabled` themselves**: navmesh empty grid, decalproj drops the terrain receiver, gibake skips ground soup + terrain lightmap and mixes the flag into its signature, aobake's atlas drops ground contact, texbake skips ground textures/stochastic supertiles; `collectTexturePaths` skipping it makes `TERRAIN_TEXTURES` -1.
- Editor twin: `Viewport::terrain_.enabled` (viewport.md). Rule: a new terrain consumer asks `sc.terrain.enabled` / `TERRAIN_ENABLED` in a builder; a consumer of terrain HEIGHT needs nothing.

## Portals (docs/portals.md)

- **The doorway rule** (1.81.0): `TerrainGame::portalDoorwayOpens(obstacle, plane, pierce)` is the ONE implementation of "while a body's motion pierces a linked opening, the geometry it was cut into stops blocking" (was four copies: `collidePlayer` armed by `updatePortalPass`, `sweepSphere` armed by `armSweepPass`, the physics static pass, the render exit test). Obstacle extent via `objectCollisionBox` + `boxRotate` with the box's own off-origin centre (never `0.5 * scale` / `o.data.position`).
- **Two halves**: fully behind the plane, OR the box CONTAINS the pierce point (a merged model holding walls, jambs and roof straddles the plane - showcase's `district-pavilion`). Pierce point sources: `portalCarryAim` publishes `portalAimPoint`; `armSweepPass` copies to `sweepPassPoint`; the physics pass keeps it beside `aimPlane`; `updatePortalPass` publishes the walker probe pushed onto the plane as `portalPassPoint`. **A plane and its pierce point always travel together.**
- For a WALL portal (`|plane.y| < 0.5`) the rule opens walls, not floors: `collidePlayer` and the physics pass keep the obstacle's ground response (mesh floor ray, box walk-onto/landing) and drop sides/overhead (skipping the whole obstacle dropped the walker under the map - the cellar mesh is its own floor). A floor portal opens everything.
- **Whatever hopped through is shown by it**: `portalLastCrossed[oi]` (set by updatePortals' object block and the thrown arc via `portalLastHop`) makes `portalShowsObject`/`portalCanCross` true and `renderOnePortalView` draws it on top of the authored list. Log lines `Portal: player crossed` / `Portal: object N crossed` are the replay-readable signal. Replay with an ABSOLUTE project path or from the repo root (native build gets `fs::absolute(p.dir)`; a relative `--replay examples/x` used to cd into `examples/x/examples/x`).
- Portal exit rejection uses `objectCollisionBox` + `boxRotate` incl. the mesh's offset centre (never infer an imported extent from scale). Static bags crossing the exit use `renderExitClipped` (interpolates all attributes); since 1.77.2 `GeoPart` owns clipped streams per portal keyed by source bboxVersion/pointer/count/layout, model matrix and exit plane; only an invalidation drains PATH1 before replacing buffers; view-camera changes reuse them; refresh live bag descriptors even on hits; whole-front bags bypass; animated bags keep the bounds-only path.
- Portal Point Light effects are authored through the portal object list (props_ui.cpp). Generated `updateAndRenderLightBeams` accepts the virtual eye/look target and portal index, reusing `portalShowsObject`, exit-plane and draw-distance filtering inside the destination depth/mask bracket; default args keep the ordinary camera pass. Baked GI and projected light pools are separate paths.

## Cutscenes and camera takes

- `sequence.hpp` (~610): Cutscene Director model + shared math: `Sequence` (object tracks + camera shots - free or bound to Camera entities - widescreen bars, fades, skippable). **Per-channel keys** (format 120): `SeqObjectKey::mask` (`kSeqCh*`, one bit per pos/rot/scale axis + colour + visibility; missing in JSON = all, so old keys are full poses); `seqSampleComponent` interpolates a component between the keys carrying its bit only (twin: the generated `sampleObj`, emitted masked ONLY when some key is partial - otherwise the player is byte-identical); edits go through `seqSetKey`/`seqClearKey`/`seqSplitKey`/`seqSettleKeys` (split before retiming part of a key, merge within `kSeqKeySnap` on release). `seqEase`/`seqSample`/`seqBarsFractions`/`seqShakeOffset`/`seqCameraForward` (each mirrored in the generated player). **Camera roll**: `seqCameraUp(fwd, rollDeg)` is a THREE-way twin (host bake, viewport `camView`, generated `upFor`); `seqRollFromUp` inverts; roll 0 reproduces the old `(0,1,0)`. `SeqCameraKey::roll` is for FREE shots only; a bound shot takes its basis from the entity's Euler via `seqCameraUpFromEuler` because **`rotation.z` is NOT a lens-axis roll** (`Rz*Ry*Rx`: on a camera pitched 40 deg, `rotation.z = 90` swings the aim 54 deg). `seqEulerFromBasis` bakes a recorded roll into rotation tracks. Project-wide, persisted, not in undo. Compiled to `src/gen/sequences.gen.cpp` (player Script + bars/fade `renderOverlay`). `seqBarsFractions` takes the display aspect (resolved per frame - widescreen can flip while running).
- `cutscene_ui.cpp` (~3.4k): Director window - transport + full-height timeline | side column (foldable shot over the Key/Sequence inspector). The dopesheet is a row list (`rowList`: camera, fades, track > channel > axis, + channel chips) built per frame from `seqOpenRows_`; a diamond acts on `key.mask & row.bits`, the selection carries `selectedSeqBits_`, and object-key drags are the Director's own (`seqDrag*_`, not an ImGui active item) because a partial retime splits - re-indexes - the key. Phone link UI, the "Import take..." modal (`seqTake*_`), `phoneCamTick`.
  - **Hide HUD = `ScriptContext::hudSuppressed`, a SECOND flag beside `hudVisible`** (Set HUD Visible owns that one; restoring it on release would re-show a HUD the game hid). Covers the stack, bars, baked texts, USE prompt and `updateUseTarget`; deliberately not runtime text (subtitles).
  - **A skippable cutscene OWNS the `menu` action**, intercepted at the top of `updateGameMenu` BEFORE the pause toggle (otherwise the press opened the pause menu, which paused the director). The confirmation is a per-project menu ROLE (`GameMenu::skipMenu`, the `saveMenu` precedent) + one `MenuEntry::Action`; a Close row is the "no".
- `camtake.cpp/.hpp` (~580+140, docs/camera-takes.md): phone ARKit 6DoF takes -> camera keys. Acquisition (`CamTake` from CamTrackAR `.hfcs` via a minimal XML reader, canonical CSV, live `phonecam` stream) is separate from bake (`bakeCamTake`: scale/yaw/origin/time mapping + time-parameterized RDP or fixed-rate resampling -> free `SeqCameraKey`s). **`mapCamSample` is public so the live view uses the same mapping as the bake.** Live-only `CamTakeMapping` fields: `hasAnchor`/`anchor` (Recentre pins a pivot; a stream has no meaningful first sample) and `keyRate` (mutually exclusive with `tolerance`). The resampler derives key times from the STEP INDEX, never `t += step` (drift -> duplicate times).
- `phonecam.cpp/.hpp` (~690+225, docs/phone-camera.md): live phone viewfinder (JPEG stream of the viewport out, ARKit pose in). `phonecam::Link` = Runner/Session idiom: worker owns transport + JPEG encode; `drainEvents()`/`drainPoses()` once per frame in `App::phoneCamTick` (the ONLY place link data meets `project_`/ImGui). Uses `wire::makeWebSocketTransport()` (never sockets directly). Poses ride a bounded ring (`kMaxPendingPoses` 2048; a stalled UI drops old samples); a waiting preview frame is REPLACED; `previewWanted()` gates on send backlog (a weak link costs frame rate, never latency). `testClientPage()` = self-contained HTML client on a plain GET (synthetic poses on purpose - it is the verification path). The phone app is NOT in this repo: `github.com/doctorspider42/tyrax-cam` (Expo + Swift ARKit module); its `PROTOCOL.md` twins `docs/phone-camera.md` - **a protocol change lands in both and bumps `phonecam::kProtoVersion`**. Nothing reaches codegen.
