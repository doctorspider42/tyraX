# Acceptance recipes — physics, particles, procedural placement/bakes, model import, game audio

Read when: you change rigid-body physics, the particle library / vehicle smoke, procedural placement or frozen bakes, the model importer / model picker, or need to verify the game's audio.

## Rigid-body physics (docs/physics.md)

1. **Hull** — host harness on `src/physhull.cpp` + `src/primmesh.cpp` + `src/objparser.cpp`, print `build()`: unit box volume 1.0, covariance 0.0833 on the diagonal; legged props keep feet as lowest corners (`examples/physics-playground` stool/table/chair/barrier: four at y = 0).
2. **Codegen** — `--refresh-gen` + grep `inc/model_data.gen.hpp` for `PHYS_HULL_COUNT`, `MODEL_PHYS_HULL`.
3. **Behaviour** — PCSX2 boot of a short-path copy, `--capture-frame` contact sheets of the fall; rest check (two captures seconds apart after settling don't differ at the props).
- **Energy** (screenshots can't judge it; injected energy looks "lively"): instrument the COPY's generated `src/terrain_game.cpp` (never the template) with a `TYRA_LOG` of awake count + summed squared velocity every 100 frames, compile with `tools/toolchain/native-build.sh` directly (`--build` regenerates it away); both must fall. Cost: `profTicks()` around `updateObjectPhysics()` vs a baseline arm generated by an editor built from the parent commit in its own worktree (same example, same engine flags).
- `pkill -f <pattern>` kills the shell running it — select PCSX2 by pid via `/proc/<pid>/cmdline | tr '\0' ' '`. A second PCSX2 on the same ELF halves both frame rates.

### Fixed-input VU0 backend throughput

Add `--micro-stream` to a private collision fixture prepare/instrument. The
startup probe validates two 224-case corpora outside timing, then measures
scalar, previous/chained micro, packing-only and prepacked chained paths.
`vu0_stream_analyze.py` requires all 80 rows and equal hashes across micro
schedules. Interpret this as backend cost, not whole-scene FPS. Preserve a
separate full-scene shadow pass for buffer lifetime/contact-order changes.
The distinct near-minimum-axis startup case must set the scalar confirmation
flag; removing its guard must fail the host oracle. Record confirmation counters
(CCD/tie/parallel) when attributing stream throughput.
No Vec4/COP2 calls may run while another micro packet is active, including
inside EE result reconstruction or canonical positive-CCD confirmation.

### Dense interpenetration on physical PS2

Use `tools/ps2rig/overlap_diagnostic.py` after a private micro-comparison fixture
is instrumented, then native-build and deploy with the resident-IOP marker.
`overlap_analyze.py` requires all 720 first-frame-inclusive calls, a successful
intentional FPU division/invalid-operation monitor, no EE/VU0 invalid/divide/
overflow flags, complete contact accounting and passing scalar shadow checks.
Finite values alone do not exclude an EE divide-by-zero (finite saturation).
Logging changes subsequent real dt; do not quote this diagnostic's FPS or compare
its shadow-enabled micro cost against scalar. Preserve original timing separately.
For micro settle/recovery qualification, add `--settle-check` to the fixture
and to `vu0_sat_analyze.py --mode verify`; require all four 1260-row phases.
See `tools/ps2rig/README.md` and the 2026-10-29 overlap report: 128 coincident
boxes produced 8156 contacts and a 474 ms scalar physics call without an arithmetic
exception. Contact-density stalls and permanent hangs are different diagnoses.

## Particle library (docs/particles.md)

- `--bake-particles <dir>` re-bakes every effect texture, re-syncs linked emitters, regenerates. Run twice, `md5sum` the PNGs (second run changes nothing). Grep `inc/scene_data.hpp` for a linked emitter row (values = the EFFECT's; last column `emitAdditive`) and `inc/model_data.gen.hpp` for `MATERIAL_PATHS`; `VEHICLE_SMOKE_LOOKS` row of a definition whose `smokeEffect` names the effect (`inc/scene_data.hpp`: `effect` 1, frame `.mtl` paths; vehicle-playground's Rally 04 links "Rally dust", two-frame flipbook).
- Texture harness: host-harnesses.md (`particletex.cpp`). The built-in tyre puff (`vehbake::builtinSmokeRecipe`) was picked side by side with the hand-written puff. Composite each over DARK and LIGHT backgrounds (premultiplied flame looks right on one; a smoke edge shows only on the other).
- Console: `examples/particle-lab`, `--build --run`, `--capture-frame`.

## Procedural placement (1.154.0+) and frozen bakes (1.156.0)

- Host harness: spatial hash vs an independent all-pairs AABB rejection oracle (rotated/off-centre assets, different sizes, clearance, cell boundaries, giant-bound overflow). Painted islands inside a footprint, upper-layer occlusion, absent terrain, spline bends, closed roads, road width/point edits invalidating `bakeHash`. Repeat evaluation and baking; serialization; runtime capability rejection. Drive *Validate Placement*'s checkboxes and material picker via `--ui-script`. vehicle-playground's procedural scene for refresh-gen + a boot; benchmark many candidates only in the host filter, never as a PS2 timing claim.
- Road path filtering (1.155.0): origins vs an independent point-in-triangle oracle over straight, curved and closed ribbons; legacy roads=0/1, both road targets, no roads, missing/non-road targets; *Only* ignores canopy width but keeps independent collision/material checks.
- Procedural node param combos register scoped labels: open `Roads/Road/Material` by name and assert options (no coordinate workaround).
- **Frozen bake**: freeze a stale/unbaked scratch volume, then move roads, edit terrain/materials, seed and graph params. Generated object JSON + mesh hashes identical before/after both ordinary and forced `bakeAll` and refresh-gen; save/reload, repeat. `anyStale` ignores it; explicit `bakeVolume` refuses. Unfreeze → stale → rebake → output changes. Missing `frozen` defaults off; equality notices the flag. Runtime freezing fails without mutation. Drive *Frozen* via `--ui-script`, save/reopen, check the checkbox and disabled bake/clear/mode/instance controls. Viewport capture: frozen chunks visible without live instances; *Show preview* hides them.

## Model import and the model picker (docs/model-import.md)

- Headless core: `TYRAX --import-model <proj> <file> [--split none|top|mesh] [--pivot keep|bottom|center] [--keep f] [--max-texture px] [--animated] [--no-static] [--textures dir] [--name stem] [--dry-run]`. `--dry-run` prints objects, top-level groups, missing textures, the plan (triangles, list vs strip vertices); otherwise writes into `res/models` (split: `res/models/<name>/`); never touches the project file. Count objects vs the source (a 546-mesh `.fbx` must report 545–546, not 256 — the palette-limit bug); read one written `.obj`/`.mtl`; `--refresh-gen` a project using it: static → `.tmdl`, animated → `<stem>__ovr*.tskl` (sibling `.mtl` override).
- The window opens a NATIVE file picker; on Linux it's `zenity` → fake it:
```bash
printf '#!/bin/sh\ncat /tmp/pick.txt\n' > /tmp/fakebin/zenity; chmod +x /tmp/fakebin/zenity
echo /path/to/models.fbx > /tmp/pick.txt
PATH=/tmp/fakebin:$PATH TYRAX --ui-script <proj> "frames 20; click 'Import model...'; wait 3;
  click 'Import model/##split'; click 'One per top-level object (465)';
  click 'Import model/Add to the scene'; click 'Import model/Import'; wait 6; key ctrl+s"
ls <proj>/objects | wc -l      # one object per imported model
```
- Picker tiles are labelled by file name (`click 'Choose model/##modelgrid/cat.glb'`). Picking a `.glb` from **Model...** must leave `<stem>.obj` beside it and the existing `<stem>.mtl` byte-identical (md5).

EE-side logs are invisible for audio — meter the PCSX2 process: Windows WASAPI session peak (`AudioMeterInformation`); Linux `pactl list sink-inputs` (PCSX2 sink input volume/peak) or a short `parec` of the monitor source. Silence vs bursts at expected times; by-ear checks stay with the human. Loop/mono ADPCM header bytes: acceptance-vehicles-roads.md "Sounds" and e2e-pcsx2.md. ## Collision pipeline regression gates

Compile `tools/verify-collision-broad-phase.cpp` with engine
`src/physics/broad_phase.cpp`, and the standalone `verify-collision-bvh.cpp`
and `verify-collision-geometry.cpp`, using `-I vendor/tyra/engine/inc`.
Use a scratch executable under the primary checkout's `.tmp/tests/` (Windows
MinGW: `-static` avoids resolving another toolchain's runtime DLL).
The gates cover moving-object rejection, randomized conservative queries,
stacked floors, baked-data roundtrips/corruption, crossed hulls, hull edge
extraction, sphere/corner distances and face/edge/vertex continuous sweeps.
Then regenerate both FPP and orbit projects, build and boot the physics
playground copy, drive its controller, and compare VU0/scalar transforms on the
physical console before reporting timing gains.

Run `tools/verify-collision-codegen.py --editor <editor> --scratch <primary-checkout>/.tmp/tests` for collision-sidecar lifecycle/incrementality; it owns and cleans its temporary project.

The `verify-collision-envelope.cpp` oracle checks 50,000 rotated, swept box
pairs against full SAT/CCD and requires every reference hit to survive the
conservative bounds test, including separated-endpoint pass-throughs. The
collision stress rig's new completeness columns also require all generated
contacts to reach the solver and all car-prop candidates to be tested. Use
`--uncapped-baseline` for equal-completeness performance comparisons.

The envelope oracle also compares the shared-projection SAT/CCD routine with
the independent discrete-then-sweep reference (hit, depth, normal, point), and
requires analytic OBB projection to retain every reference hit. OBB projection
rounds outward; it keeps all face/edge axes and is enabled only for known boxes.


Prepared-contact solver acceptance: `tools/verify-contact-solver.cpp` embeds
an independent reference from 2ed7cb6f7 and compares 2000 coupled 48-contact
graphs with the prepared scalar solver (six velocity / three split passes).
The `tools/ps2rig/contact_solver_probe.hpp` startup probe compares reference,
prepared scalar and VU0 on 64 graphs before timing. Solver storage uses an
explicit quadword-aligned allocator; test host allocation and EE/VU0 load/store
alignment. Full-game timing uses `collision_stress.py --solver-comparison`
with baseline 2ed7cb6f7: 42 phases, three arms, reversed order on repeat. Pass
`--solver-comparison --complete` to the analyzer. No collider/friction/inertia
or timestep simplifications are allowed in this comparison.

The solver rig forces `TYRA_PHYSICS_PREPARED=1` in its candidate translation
unit, independently of the shipped prior-solver default. Qualify the default
integration with a fresh stock code generation/native build too. The final
lazy-response fixture source is b8bd7f719; its 42-phase report includes the
entire preparation/copy-back scope. Preserve both repeats and report whole
FPS alongside solver cost: +128 VU0 had cheaper solves but lower FPS.

Temporal physics acceptance: build/run tools/verify-contact-history.cpp and the
cached-axis extension of verify-collision-envelope.cpp. The temporal rig uses
--temporal-comparison --baseline ef9597bda --uncapped-baseline for 56 phases:
prior scalar, geometry cache only, cache + warm starting, then added islands. Analyze
with --temporal-comparison --complete. All arms keep six velocity/three split
passes and full contacts. Stage scopes for grid/query/SAT are nested; do not
sum them again into world/body parents. Track velocity-energy, penetration,
awake populations and warm matches, and check waking after a car impact.

The stationary --settle-check gate uses eight four-arm phases, 1260 rows each.
Use --temporal-arms 3 only for the archived initial six-phase prototype.

The refined pair-admission gate is tools/verify-body-pair-grid.cpp linked with
engine src/physics/broad_phase.cpp: 200 scenes/128 bodies, all-pairs envelope
oracle and candidate order. For the focused cache-only hardware follow-up use
--temporal-comparison --temporal-arms 2 (28 phases); warm/island code is compiled
out. The raw candidate/rejection counters count work, not omitted contacts.

Completed physical gates: temporal-four56*600, temporal-settle8*1260 and
refined-cache28*600, total60480 measured frames; all-arm contact/candidate
accounting and clocks passed. Sources407585452 and3fa710314 are in the result
JSONs. The refined non-box software probe had34 finite aggregate samples,
matching the earlier per-frame telemetry. This is not non-box hardware timing.
