# Acceptance recipes — vehicles, roads, road/terrain strips, junctions, vehicle editor, sounds

Read when: you change vehicle physics/contact/damage, wheels, vehicle rendering (textures, env reflections, wheel batches, far tiers), the Vehicle Editor, vehicle sounds / sfx conversion, roads (tessellation, strips, LOD spans, height index, junctions, editing), terrain strips, or static-batch grouping.

Fixture: `examples/vehicle-playground` (Motor District), copied to a short path. Far-tier checks: cli-and-codegen.md.

## Vehicles in game

- **Damage** (docs/vehicles.md): `--vehicle-check`'s `-- damage --` block = host rules. In game, `On Start -> Enter Vehicle` seats the player in the CC96 facing +z; `--pad "hold r2; wait 12; release all"` drives into the arena wall → `bin/log.txt` `VEHDMG ... hit` (impact, damage %, vertices moved, µs). Throttle R2; since 1.147.0 reverse = L2 held from standstill (`hold l2`; brakes first if rolling); left stick only steers. To SEE a front dent, back off a few units and HOLD R3 (rear view puts the camera ahead of the nose) during `--capture-frame` (against a wall the rig sits inside it). Loose pieces: `VEHDMG <car> lost <kind> ...`; Ravager into the arena wall loses kinds 5 and 1; a `--capture-frame` burst right after `lost 1` catches the bonnet airborne. Force a door off: park another car broadside across the start lane in a scratch copy (object JSON `position`/`rotation`), raise its `damageLoose`.
- Editor side (no game): Damage tab > *Hit front* with the car framed via the manifest's `editor.cam` (`[yaw, pitch, dist, tx, ty, tz]`, radians) and `selectedObject` — edit inside the `editor` block, not a global replace (vehicle definitions also have `"cam"`).
- **`--vehicle-check`** after any contact/transform change: bank fixture restrains horizontal translation but keeps gravity; six headings; 20/25/50/120 Hz; generic renderer vs wheel-rig orientation incl. Euler-singular headings; missing terrain contacts; alternating 50/8.33 ms steps with only a bumper supported (must not generate launch velocity). Host properties, not PS2 frame rate — drive vehicle-playground for runtime; measure wheel-batch changes with unchanged mesh + camera.
- **Tyre contact is a LOG LINE**: `VEHCONTACT car N def D parked|driven gap1000 ... roadlift1000 ...` (lowest drawn tyre vertex minus `groundSurfaceAt`, per wheel, mm; parked once on sleep, driven every second, nothing on a far tier). 0 = on ground; -119 on a road was the terrain-only contact bug; -7 = definition radius behind baked wheel (docs/vehicles.md "Wheels on the road surface"). Check one car on a road and one on bare terrain (road-lift column distinguishes).
- **Textured vehicles**: `vehbake::Result::textures` holds bin-relative names + PNG bytes; `bakeProject` and `vehicleRefreshBake` both write them. Viewport resolves `ModelPart::bakedTextureRel` per draw (never a cached GL name). Palette UV fixup visits only palette parts (real UV V = -1 is valid). Wheel/body image + Kd match permits textured wheels in body distance tiers. GGBot GLB in Motor District: PNG references, in-game texture, four detected wheels, distant wheel silhouette. Rigid nodes sharing a material may collapse to one dominant owner on import (example prep keeps one material slot per wheel).
- **Env reflections**: shared dynamic env sampling uses the LEVEL capture's world-up, not the pitched chase camera's; static sphere maps keep the view basis; reflected-ray probes their own; viewport `envSt` shader mirrors this. Diagnose by inspecting the env target separately: populated target + unchanged car under scenery hide/show = sampling problem, not capture failure.
- **Wheel batches**: mixed definitions keep separate runtime batches (palette car + textured car together at near range); far tiers carry their own baked wheels. Per-definition position/colour/UV buffers live until scene unload (PATH1 DMA may still read one while the next is prepared). Conservative CPU reject covers the real rig (mesh radius, track, wheelbase, full suspension travel, steer, spin, body attitude) with the active camera/frustum and the body's visibility, draw-distance and split-band gates. Near/far LOD crossing: no duplicate/missing wheels; capture the `Wheels` render-cost row.
- **Defaults + chase camera (1.153.0)**: resave a legacy definition — tuning stays local. Scratch project: change global accel, damage, nosCapacity → inheritance, local accel and zero-capacity overrides, silent sounds override survive save/load and reach `VEHICLE_DEFS`; global defaults work with no vehicles. UI script targets: *Global defaults*, *Inherit global defaults*, *Has nitrous*. Boot a third-person Player beside a car, Use → `VEH avatar 0` while seated; exit → visibility + door placement. A blocker behind the chase boom must reduce `boom100` below `want100`; removing it restores. Include rotated boxes, terrain, collision-none, self exclusion, far/rear views; clearance runs after shake.
- **Vehicle Editor UX**: isolated copy; assert three car rows, `Vehicle preview canvas`, `Spin wheels`, `Listen to engine`; Speed above/below the fast-wheel threshold, orbit/zoom, capture normal/fast/steered previews for all three cars; audition stays checked (device/decoder opened), follows Revs, stops on selection/close. Cost: changing a triangle slider before the advanced checkbox leaves the saved budget unchanged; unlock → edit/save/reload. Reflection choices are thumbnails + *Dynamic sky* + *Import PNG*. Host audition ≠ SPU2 ADPCM; a native build verifies the idle WAV encodes as a loop.
- **Inheritance**: new car → save → no `tuningOverrides`, resolved global fields. Edit one Driving/Driver/Sounds param → only its key added. Change a global sibling → reaches all cars, edited field survives. *Use defaults* removes only the current section's overrides, survives save/reload. Pre-83 local/group files keep authored values incl. empty sounds and zero volumes.
- **Tyre reduction**: `@auto` at 32 triangles on all three models (actual cost, continuous outer tyre); authored `wheel_blur` at speed from both sides. None/`@auto` still detect exactly four wheels when the GLB contains `wheel_blur`. Original GLB mesh/material/image prefixes unchanged; repeat authoring byte-identical.

## Sounds

- **Vehicle sound import**: ordinary WAV (no `-loop.wav`) in idle/high-rev and tyre-squeal dropdowns → save/reload, audition. Headlights only in Effects; its *Use defaults* resets Effects without Sounds. Optional `vehicle_sound_loops.gen.txt` rewritten/deduplicated, deleted when the last ordinary continuous role goes. Native AND Docker encoder header byte 6 through one-shot → loop → one-shot with WAV mtime unchanged; gear-shift-only sounds stay one-shots, suffix loops stay loops. Paths with spaces; already-fresh encoded cache.
- **SFX conversion (1.157.0)**: `wavconvert::soundIssue` requires canonical mono PCM16/22050; import and *Project > Sounds > Convert* downmix too. Runner calls `wavconvert::bakeSounds` AFTER texbake, BEFORE either backend → `.res-baked/sfx` (never modifies `res/sfx`). Both encoders read the mirror, check cached APCM byte 5 (mono) and byte 6 (loop), keep the source path for role matching. Conversion error fails the build. Test stereo PCM16, PCM24, float, extended headers, odd metadata chunk; duration, source hashes, incremental mtime stability, ADPCM mono/loop headers in BOTH backends. **Decode the ADPCM and compare waveform to the converted WAV** — header checks missed adpenc's corrupt stereo reader (`fread(wave+i, 2, ...)` advances one byte). Music stays stereo unless its mono option is chosen.

## Roads and terrain strips (1.96.0+)

- Oracle: `examples/vehicle-playground/authoring/verify-road-twins.py` (Python 3 + g++, seconds, no emulator): compiles the host tessellator AND the generated `buildRoads` body with storage stubs; checks strip output vertex-for-vertex and chunk-for-chunk, run invariants (interior runs exactly `roadgen::kStripRun` = 75, multiples of 3), expanded triangle SET vs list emitter, terrain folds, both Market endpoints, the old fan regression, clearance sweep, non-empty runtime junction uploads. Since 1.105 it prints per fixture: worst surface error vs dense reference, worst UV drift (texels), worst **T-vertex** seam (exact test: vertex strictly inside another triangle's XZ edge and off it in Y — sampling at vertices has a 5e-5 barycentric noise floor, bigger than real seams). Only the three `heightfield ...` fixtures (road over a 4-unit triangulated grid) exercise the span merge. Run it first, always.
- Since 1.117 road V is rebased by a whole repeat per chunk (bounded physical-GS ST); the oracle compares V modulo integers (positions, U, fractional V, host/runtime streams exact). Don't switch to raw V equality. Physical-console stationary capture is the acceptance gate (PCSX2 never reproduced the stretched-one-texel smear): first check each chunk's V begins in `[0,1)` and stays within ~that chunk's nine repeats, then park the same camera on hardware and confirm lane markings.
- **Strip/list knob**: road strips ship on since 1.117.2 (`ROADSTRIP ... strips 1` expected). List control = `TYRA_STRIP_ROADS=0` (generated game `#ifndef`, default 1; gate is `TYRA_STRIP_ROADS && minPackageSize() >= stripRun`, `stripRun = 75u`). The old "flip `minPackageSize() >= 72` in templates.cpp" recipe is stale. Across an A/B: producer surface-triangle counts identical, then packages, vertices, synchronized frame costs, several physical-console road views. Terrain needs a terrain MATERIAL to strip (`TERRAINSTRIP ... strips 0` = no material, not a failure). Editing generated `src/terrain_game.cpp` doesn't survive `--build` (it regenerates) — use `-D`/native-build or the editor.
- "Do both arms draw the same thing": `ROADSTRIP scene N strips S packages P triangles T` and `TERRAINSTRIP scene N chunk cx,cz ...` — surface triangle counts (degenerates dropped) MUST match; `FTCLIP` cull/clip/guard triangles are GS primitives and differ ~1.5x between representations.
- **Road height index (1.123, docs/roads.md)**: `roadSurfaceAt` (17 samples per blob shadow / light pool / glow patch) answered from a uniform XZ grid built after roads. Gate: `TYRA_ROAD_INDEX_VERIFY` (generated `terrain_game.cpp`, default 0 — costs more than it checks, never in a measurement): flip to 1 AFTER `--refresh-gen`, build with native-build directly, drive, read `ROADINDEXVERIFY checked N bad M`; `ROADINDEX cells NxN entries M` at load = grid built. District: 140 000 queries, 0 mismatches day and night. Off-road queries agree trivially (broken control stayed green 40 000 queries until the walk crossed a street); falsify by shifting the query one cell in x → first mismatch reported with its point.
- **Motor District flat-road spans (1.85.0)**: host `roadgen.cpp` and generated `buildRoads` sample every lateral height, keep the horizontal collapse or merge a non-flat span's lateral cells into maximal runs within `kSpanFlatness` (surface + seam) and `kSpanShear` (UV) in `roadgen.hpp`. Don't infer planarity from shoulders (interior crown/saddle keeps samples). `ROADS` logs emitted vertices + chunks. The seven-road district is an EE memory stress case.
- **Junctions**: cross two roads with the same intersection texture, one with none, one pair with different values → only the first pair yields a `ROAD_JUNCTIONS` row (12 vertices / 4 triangles on flat ground). Since 1.151.2 uneven junctions refine conformingly on the host (≤256 triangles), shipped as baked XYZUV in `ROAD_JUNCTION_VERTS`; viewport and PCSX2 patch must match. Move one spline off the crossing, resave + refresh → row disappears. `--road-crossings <dir> [scene]` lists every crossing and exits 1 on an orphaned override.
- **Road editing (1.151.0)**: loops repeat the first XZ pair at the end of `roadPoints`; `roadgen::isClosed`/`controlCount` hide the seam sentinel. Host + generated `buildRoads` wrap Catmull-Rom neighbours and final tangents. No format field. `moveControl`/`removeControl` preserve closure + minimum counts. Properties: collapsible Crossings/Points, reversible *Closed loop*; viewport Shift-click deletes, endpoint snap closes on release, one undo each. Outlines reuse `Viewport::RoadDraw`; full-width soft borders keep a separate outline; crossing caches defer during drag. Verify loop seams + open-road parity with the road twin oracle; UI scripts target `Road point N` and use `shiftclick`.

## Static-batch grouping oracle

`examples/vehicle-playground/authoring/verify-batch-twins.py`: lifts `TerrainGame::buildStaticBatchList` VERBATIM by string index, compiles it beside its host twin `src/staticbatch.cpp` (read by *Tools > Static Batches*, the overlay and `--batch-report`), diffs batch assignment over eleven fixtures (texture/cell/lamp/strip-run keys, singleton drop, oversized-model guard, batching off, MISSING-TEXTURE: `acquireTexture` returns nullptr so missing textures batch with untextured primitives — a "fixing" twin is wrong). Asserts the lifted body still contains the key names; verified it can FAIL (break a key → two fixtures disagree, non-zero exit).
- **Stale (029d84fb6): the script reads `src/templates.cpp` but the function body now lives in `src/game_templates.inc` (included by templates.cpp) → it exits `FAIL: buildStaticBatchList not found in src/templates.cpp`.** Point it at `game_templates.inc` before relying on it.
- Eligibility needs no harness: `batchStatic` in generated `inc/scene_data.hpp` = twin stage-1 verdict (`--refresh-gen` + census: 87 of 142 on vehicle-playground). `--batch-report` totals vs the game's `Static batching: eligible 87, solo 22` / `65 objects in 48 batches`.
