# Audio: audsrv fork, ADPCM, streaming, SPU2 reverb, sound conversion

Read when: you touch `audio/` (`AudioSong`, `AudioAdpcm`, `AudioReverb`), `vendor/tyra/audsrv/`, sound-play sites in generated code, or `wavconvert`/ADPCM encoding; or diagnose crackle, wrong speed, silence, stutter, or audio-caused frame drops. Docs: docs/sound.md, docs/reverb.md, docs/profiling.md.

## Basics
- `AudioSong` is WAV-header-aware (TyraX; parses RIFF in memory).
- audsrv streams PCM only; ADPCM is for one-shots (`adpcm.tryPlay`); an ADPCM voice cannot be STOPPED, only (re)started.
- **Channel budget per bus** (generated game; every new sound goes to the CURRENT room's bus): 0-15 Play Sound, 16-23 sound emitters. Auto cycle runs 16 (it ran 24 and stole emitter channels / bounced off them as "busy"). Who wins when all are busy: docs/sound.md (priority, then loudness); engine side = `forcePlay` + `endedMask`.
- **`AudioAdpcm::forcePlay`** plays over a busy channel: `AUDSRV_ADPCM_FORCE` flag bit ORed into the channel number (masked off by the fork, skips its ENDX busy check). The refusal was a software check in `audsrv_ch_play_adpcm`, not hardware (KON restarts a sounding voice). Riding the channel number cost no new IRX export (adding one touches every linker's import list). **Whether a forced restart CLICKS is unsettled on hardware** (PCSX2 untrustworthy on SPU2). If it clicks: drop the victim's volume and play next frame, or KOFF first and let ADSR release (both +1 frame latency).
- **`AudioAdpcm::endedMask(core)`**: SPU2 ENDX, one bit per voice, one IOP RPC. Ask per PLAY REQUEST, never per frame (a play already costs 2-3 RPCs).
- **`audsrv_ch_play_adpcm` returns "unknown sample" as POSITIVE `AUDSRV_ERR_ARGS` (5)** — indistinguishable from a channel number by sign. `tryPlay` demands an explicit channel come back as itself (freed/never-loaded samples used to "succeed" silently).
- Debug builds: `AudioAdpcm` logs why a sound didn't play (once per channel per reason: no sample, busy, audsrv error) + a one-line SPU2 dump at each channel's first successful play (per-voice volume/ADSR/start address, core VMIX masks, MMIX, master and reverb volume) — diff a working channel against a silent one.

## Blocking RPCs and streaming
- **A blocking audsrv RPC stops the WHOLE library**: one IOP RPC server thread + one EE completion semaphore (`audsrv_rpc.c`). `audsrv_wait_audio(n)` blocks in `WaitSema(queue_sema)` until `n` bytes free; `AudioSong::work()` called it per music chunk → every other audsrv call queued behind it: **~10 ms/frame in PCSX2 on `examples/showcase`, FRAME 20 → 30 ms (solid 25 FPS) for the track's first pass**. Now polls `audsrv_available()` (ring pointers, instant) with `Threading::sleep(1)` between tries; four retriggering emitters + streaming music 28-30 → 20.0 ms. **Prefer non-blocking query + sleep** (`audsrv_available`/`audsrv_queued` over `audsrv_wait_audio`). Symptom shape: the frame drop appears in whatever code calls audsrv next — the profiler blamed the emitters for the music's lock.
- **Music over ps2link stutters because of the network**: the song's `host:` freads run TCP on the IOP beside audsrv; the ring (10 feeds × 512 samples, ~107 ms, in INPUT bytes) refills late. Song in RAM → ring ~90 % full. Smaller chunks make it worse (more RPCs on a starved IOP → slow motion); `audsrv_play_audio` TRUNCATES what doesn't fit. Debug warns "Music ring ran low" when a refill finds the ring > 70 % empty.
- Mono/low-rate streams need smaller chunk size + fill threshold or the ring starves.
- **EE buffers handed to SIF DMA must be written back first** (`SifWriteBackDCache(ptr, size)`); `audsrv_load_adpcm` didn't (fixed 2026-08-06 in the fork). Write-back cache + DMA reads RAM → a freshly `fread()` sample reached the IOP as stale memory — the console's SECOND sound was silent, first fine; **PCSX2 emulates no EE cache** → perfect there. Applies to ANY new EE→IOP transfer. Tell: audsrv reports the sample header back — a nonsense `pitch` where an earlier load was sane (1881 vs 0x41C00000).
- WAV: 8-bit PCM is unsigned (0x80 = silence), audsrv mixes signed → XOR 0x80 or it wraps at every zero crossing (loud crackle at correct pitch). The WAV parser walks RIFF chunks in memory (`fseek`/`ftell` unreliable over host fs). Missing music WAV = `TYRA_SOFT_ERROR`, skip.

## The audsrv source fork (`vendor/tyra/audsrv/`)
- IOP and EE sources in-tree at ps2sdk `e78a9cb2` (audsrv is LGPL v2 per file headers). `build.sh`/`build.ps1` rebuild the three committed artifacts in `bin/` (`audsrv.irx`, `libaudsrv.a`, `audsrv.h`) that `src/runner.cpp` overlays into the build. **Change sources → re-run the script and commit `bin/` in the same commit**; no game build compiles audsrv.
- **Except `docker/Dockerfile.fromsource`**, which compiles the EE half itself (committed `libaudsrv.a` carries GCC 11.3 LTO bytecode newer GCC refuses) and skips the overlay → a source change reaches that image only after it is rebuilt. Crossing point: `ee/src/sif-compat.h` — upstream renamed ten EE SIF RPC entry points to `sce`-prefixed ones; SDKs export disjoint sets; the header aliases them under `TYRAX_PS2SDK_SCE_SIF` (only the image sets it; `__has_include` can't tell the pinned headers apart). Included FIRST, before any ps2sdk header (aliases must rewrite declarations). Fork README, change 3.
- `./build.sh --check` diffs a fresh build against committed artifacts: `audsrv.irx` byte-identical; `libaudsrv.a` never (ar stamps members, LTO section names carry a random id) → member SIZES compared.
- The fetched ps2sdk (a build TREE; Makefiles include `$(PS2SDKSRC)/Defs.make`) has a mirror fallback `doctorspider42/tyrax-vendor-ps2sdk` (`PS2SDK_MIRROR` in build.sh). Losing upstream costs the ability to REBUILD the module only (game builds use the installed SDK).
- **Sample RAM is first-fit** (`audsrv_load_adpcm` in `iop/src/adpcm.c`, fork README change 5): the sample list is kept sorted by SPU2 address and a new sample takes the lowest gap between neighbours that fits (from 0x5010), so `audsrv_free_adpcm` frees RAM wherever the sample lies - unlinking reopens the gap, neighbours merge by themselves. Upstream was a stack (only freeing the tail reclaimed anything). A LIFO caller gets the same addresses as before. Proof recipe: load four 360 KB samples over ~0.4 MB, free the FIRST, load a fifth - it lands at the first's `ssa` (the one-time SPU2 voice dump), where a stack would have needed 2.22 MB.
- **A new `audsrv.irx` must move the native toolchain stamp**: `tools/toolchain/setup.sh` hashes `bin/audsrv.irx` into `AUDSRV_TREE_SHA`; a new stamp drops the engine objects, which is what re-embeds the irx (the Docker path md5-stamps it in `runner.cpp`). Before 2.2.0 only `ee/` was hashed, so a rebuilt irx silently never reached native games.
- **Voices on BOTH cores**: channels 0-23 = core 1 (unchanged), 24-47 = core 0. Upstream muted core 0's master (making the second reverb unreachable — reverb is per core, fed only by that core's voices). Unmuting was the whole change (core 1's `AVOL` already 0x7fff; `cdrom.c` always raised core 0's master for CDDA). `AudioReverb` exposes `BusA` (core 1) / `BusB` (core 0); the game cross-fades rooms (a room owns a bus, incoming takes the free unit while silent, depths ramp past each other). **A voice is committed to a bus when it starts**: every play site offsets its channel by `ScriptContext::reverbBusBase` (0 or 24), or the sound lands in the room the listener left.

## SPU2 reverb (`AudioReverb`, `audio/audio_reverb.*`, docs/reverb.md)
- audsrv exposes playback only; registers come from PS2SDK **`ps2snd.irx` + `libps2snd`** (EE RPC client over the `libsd` the engine already embeds; AFL 2.0). Cost: one `.irx-em`, one loader call, `-lps2snd` in Makefile.base. audsrv and ps2snd are co-clients of libsd.
- **`sceSdInit()` clears libsd's transfer callbacks — the ones audsrv's streaming ring installs.** So the reverb RPC bind runs BEFORE `audsrv_init()` and the effect-enable bit AFTER it (audsrv's `sceSdInit(COLD)` resets core attributes). Wrong order: MUSIC silent, no error, sfx fine.
- **libsd defaults send EVERYTHING to the effect bus**: `VMIXEL`/`VMIXER` all 24 voices set; `MMIX` bits 4/5 route core input (streamed song) to reverb. A per-voice send normally REMOVES a voice; keeping music dry is an explicit write (bit meanings confirmed against libsd's block-transfer handler clearing bits 6/7, the dry pair, when a stream ends).
- **`sceSdSetEffectAttr` zeroes the work area only if effects were ALREADY enabled** (`effects_disabled && clearram` in libsd effect.c) → enable, then set, or old SPU2 RAM circulates as noise.
- Reverb RPCs cost like audsrv's (synchronous SIF beside the music stream): generated game quantises wet depth to 64 steps and sends only changes (same as `updateSoundEmitters` for volume/pan). Per-frame RPCs show in frame rate.
- Presets occupy 8-96 KB at the TOP of the 2 MB SPU2 RAM; audsrv loads ADPCM from 0x5010 upward → collide only past ~1.9 MB. Preset changes zero that area → only at zero wet level, never per frame.

## Sound conversion and loop flags (editor side, both build backends)
- `wavconvert::soundIssue` requires canonical mono PCM16/22050; import and Project > Sounds > Convert downmix too. Runner calls `wavconvert::bakeSounds` AFTER texbake and BEFORE either backend, preparing `.res-baked/sfx` without modifying `res/sfx`. Both encoders read this mirror, check cached APCM byte 5 (mono) and byte 6 (loop intent), keep the source path for role matching. A conversion error fails the build. Music stays stereo unless its own mono option is chosen.
- Test stereo PCM16, PCM24, float, extended headers, odd metadata chunk; verify duration, source hashes, incremental mtime stability, ADPCM mono/loop headers in BOTH backends. **Decode the actual ADPCM and compare waveforms** — header checks missed adpenc's corrupt stereo reader (`fread(wave+i, 2, ...)` advances one byte).
- Vehicle loops: project WAVs assigned to idle/high revs/squeal listed in optional generated `inc/vehicle_sound_loops.gen.txt`; `tools/toolchain/native-build.sh` (Windows via `native-build.ps1`) and the Runner's Docker fragment encode them with `-L`, plus legacy `*-loop.wav`. Header byte 6 must match the desired mode both directions (mtime alone misses assigning/removing a continuous role). Loop flags affect every use of a sample → separate file for a one-shot version. Seam preparation stays authored.
- **An EE thread that must answer the IOP has to outrank the game thread
  (0x40)**, because the game thread never blocks: `graph_wait_vsync` is a busy
  poll and the frame yield is off unless the Live Debugger is attached. audsrv's
  EE callback server ran at 0x60. The IOP playback thread waits for each
  fill-buffer callback to complete, so it stalled for good once loading ended,
  and the SPU2 looped its last 1024-sample block (21 ms) as a buzz a few seconds
  into every song, in PCSX2 and on hardware alike. Fixed in the fork (0x8, its
  README change 4; docs/sound.md, "Music turns into a buzz"). The tell is a
  capture whose autocorrelation at lag 1024 (48 kHz) is 1.000. An EE that is
  only late with data loops the ~107 ms ring instead.
