# Measuring engine performance: instruments, rules, traps

Read when: you measure or claim a PS2 frame-time change, add counters/brackets, read `FTCLIP`/`FTPKT`/`FRAMETIME`/`STAPIP*` lines, use the hardware timeline, or compare two builds. Subsystem-specific numbers live with their subsystem (static-pipeline.md, submission-dma.md, vu1-microprograms.md, blss.md). Docs: docs/profiling.md, docs/render-submission-attribution.md, docs/hardware-profiler.md, docs/ee-submission-rearchitecture.md, docs/performance-hardware-recheck.md.

## Rules
- Baseline method: PCSX2 FPS on the SOFTWARE renderer, 3+ samples before and after; pixel-compare screenshots to prove output unchanged.
- **PCSX2 is not a timing witness for**: GS fill (under-reports **76x**), EE data cache (none emulated → cache-trading changes are upper bounds), DMA completion (completes before the EE runs on → lifetime races invisible), libm weighting (doesn't transfer per-function), EE exceptions (can't produce them). Attribute on hardware.
- **A/B game-code changes with ONE ELF toggled at boot**, not two builds: code layout moved `work` ~0.4 ms between two builds of the generated game (docs/ee-submission-rearchitecture.md "How to A/B a change to GAME code"); between two engine builds `bounds`/`prepare` move up to ~0.17 ms on the console — the two-boots-of-one-ELF floor doesn't cover it. Read a change's delta in the brackets it touches.
- **Never infer boundedness from `drain`** (GS backpressure stalls the EE inside submission; `drain` is only the tail). Change the GS load and see if the frame shortens.
- A cache that never converges contaminates the next measurement — instrument WHY it misses (`STAPIPMISS`).
- **Missing resources invalidate comparisons**: native compilation alone doesn't populate a missing `.res-baked` mirror; PNG soft-error placeholders and skipped TMDLs leave a game doing far less work. Validate deployed asset hashes and actual GS images, not linking or equal triangle counts between two broken fixtures (docs/performance-hardware-recheck.md, Sept 14 correction).
- Fixture noise: chunk-streaming fixtures (`examples/large-terrain`) — always capture a same-build control; parked scenes may settle differently between identical-ELF runs (check structural counters first).
- Live Debugger key `liveDebug` on = ~500 ms/frame host I/O inside the measurement.
- A measurement returning 0 must be reported as a failure (else "the button does nothing").

## Instruments (all compile out by default — keep shipped values)
- **`TYRA_FRAME_PROFILE`** (`inc/debug/frame_profile.hpp`, default 0): FRAMETIME line in the generated `drawDebugHud`; one guarded "fairness fence" drain in both arms; enables `StaPipTelemetry` reading and `TYRA_STAPIP_PACKET_PROFILE`.
- **`StaPipTelemetry`** (opt-in): cull/clip/outside routes, active-plane population, qbuffer flushes, VIF1/VU1 wait ticks, `programSetSwaps`; disabled → AABB early-out kept, no COP0 reads. Reader: the **`FTCLIP`** line (`cull=P/T clip=P/T guard=P/T out=... flush=... vuwait=...` once a second beside FRAMETIME). `takeTelemetry` clears as it reads — **drain every frame**.
- **`FTPKT`** (`TYRA_STAPIP_PACKET_PROFILE`): walks the completed DMA/VIF chain in `sendPacket`, per-producer totals every 50 frames; admissible only with `bad=0`; GIF/GS totals derived from the selected program and package count. 2026-09-22 physical capture: 765–826 A+D writes and 197–213 XGKICKs per garage frame. Aligning only each `BagArray` base to 128 bytes = measured dead end (1 200-byte package stride loses alignment; work +0.09–0.18 ms) — don't restore without a package-owned packed stream.
- **`TYRA_STAPIP_ATTRIB`** (`stapip_attrib.hpp`, default **0**, must stay 0 shipped): StaPipTelemetry's three brackets don't cover all of `StaPipCore::render` (head = fog decision + thirteen `TYRA_ASSERT`s, which release games execute — no game build defines NDEBUG — and the tail). Adds `renderTicks` around the whole function, six-way split of `prepare`, five-way of `bounds` (with bbox cacher hit/recalculate/fresh counters; the per-frame expiry scan lives OUTSIDE render() → lands in `finish`), and a split of package creation in `dispatch` (docs/render-submission-attribution.md). Hook cost measurable: +0.122 ms on `bounds`, +0.062 on `dispatch` (children over-report 6.3 % / 1.1 %; one COP0 read ≈ 11 cycles). Findings: bbox cacher NOT the cost (226.5 lookups = 0.118 ms, 1.44 probes each, zero allocations) — 0.618 ms was 10.5 `recalculate()` forced by a caller bumping `bboxVersion` every frame; 22 % of `bounds` was `StaPipQBufferRenderer::setMaxVertCount` fanning one u32 to all 32 qbuffers per bag (now early-returns when unchanged: −0.34 ms, byte-identical).
- `STAPIPRET`, `STAPIPBAKE`, `STAPIPMISS`, `VRAMSTAT`/`VRAMRES`/`VRAMEVICT`, `BLSS*`, `GPUHOLD`: see submission-dma.md, textures-vram.md, blss.md.
- Render-cost telemetry includes both uniform and geometry VIF waits (counting only geometry under-reports sync); the counters overlap stages.
- **Hardware timeline**: `tools/hardware-trace.py arm PROJECT` before a boot, export the complete `bin/hardware-trace.csv` to HTML/Perfetto; or natively (1.92) Debugger > Hardware timeline (`src/hardware_timeline.cpp`, same bounded CSV; arms the next boot, frame selection, zoom, raw marker tooltips, inclusive totals). Engine captures bounded RAM events without new drains and writes after sampling. Scope totals overlap; VIF1 DMA wait is not VU1 execution; VIF/GIF snapshots are not utilisation. Compare unarmed/armed controls, reject dropped/stale events, rank with unarmed controls. Detail scopes separate package creation/classification, qbuffer copies, packet construction (docs/hardware-profiler.md).
- Free RAM: `Info::getFreeRAMSize` (devkit-debugging.md).

## Facts worth reusing
- VU1: 0.0768 ms per cycle per triangle (garage); EE: 2.362 µs per package; ~565 `div.s` a frame = 0.007 ms (~2 100 EE cycles); one full-screen textured blended GS pass 0.5174 ms at 512x448, 0.5896 at 512x512; FlushCache 17.9 µs per call.
- `Math::sqrtNonNegative` uses EE `sqrt.s` only for known non-negative squared lengths; don't substitute it for a general sqrt with errno/domain behaviour.
- **Chase-view reality** (stationary night vehicle entry): the older GPU-hold sweep's 2.5–3.5 ms overlap estimate does not bound it — the camera doubles StaPip calls and submits 46 096 primitives incl. strip joins. Reprice GPU-hold/segments in that view before promising a frame-pipeline gain; dynamic-light and raster suppression probes identify material costs without isolating VU1/GS utilisation (docs/ee-submission-rearchitecture.md "Stationary night vehicle entry: what TyraX2 would and would not solve").
