# Renderer feature additions (post-fx, shadows, render targets, billboards, portals, split view, VU0 tracer, warp)

Read when: you touch `RendererCorePostFx`, `RendererCoreShadowMap`, `RendererCoreAlphaMask`, `RendererCoreEnvMap`/`camFeed`, billboards, portals, `RendererCoreSplitView`, `renderer/rt/`, `RendererCoreWarp`, or any raster-redirect bracket. GS register traps common to all of them: gs-state.md. The raster-redirect state machine (`RasterTarget`, `emitRasterRestore`) is described in blss.md and is shared by every bracket here.

## Post-fx (`RendererCorePostFx`, GS blits)
- **Bloom**: optional bright-pass `setBloomThreshold` — one quarter-res sprite subtracting flat grey via `(0 - Cs)*128/128 + Cd`; GS clamps at 0 so sub-threshold pixels drop out, halo collapses onto emissives (docs/emissive-materials.md). `setBloomSpread` = 1..4 soften rounds, doubled tap offsets each, ping-pong buffers, 4 sprites a round.
- **God rays** (`PassGodRays`, `setGodRays` strength + per-frame `setGodRaysSun` screen pos/visibility from the game): bright-pass on quarter-res buffers (subtract flat 150, double back up — 96 washed the frame white, the sky IS bright), zoom toward the sun (2 ping-pong passes, s=0.72), composite additively at half strength.
- **DoF** (`PassDof`; UI Editor / Set Depth Of Field node): reuses the bloom blur chain; composites via full-screen sprites at real GS depths under GEQUAL; world distance → GS z from the shared perspective matrix. **Must run right after the 3D scene, before ANY 2D** — sprites stamp z = max over their rect and punch sharp rectangles into a later z-tested pass.
- **Custom effects**: `applyCustom()` + `RendererCore::applyCustomPostFx()` (docs/custom-screen-effects.md); body appends GS prims through public `blit()`/`flatQuad()` and framebuffer/noise/scratch accessors; engine wraps state setup/teardown + DMA kick.
- **Packet size**: `packet2_create(768, …)` in `renderer_core_postfx.cpp`, sized for the WORST case of every pass at once (blit = 12 qwords, flat quad = 7). Undersized corrupts the GIF stream — grow it when a pass gains primitives. (Skill previously said 512; code says 768.)
- Low-res work buffers use the frame PSM (`fbPsm`/`psmFor`) so the blur chain never converts; film-grain noise stays PSMCT32 (uploaded, not rendered).
- **Motion blur**: ONE 16-bit conversion, then an explicit history break. Lerps the previous real frame over the fresh destination in one sprite; 1:1 UVs biased +0.5 texel at both ends; splitting into two passes feeds PSMCT16 rounding back as brightness loss. Generated game emits one clean frame after the camera settles, then restores the amount (docs/motion-blur.md). Needs `hasRealFrame()` (off under Hybrid).
- `apply()` early-returns with no pass enabled — so a bug in its restore block hides in projects with bloom/grain at 0 (see blss.md, ZBUF mask).

## Per-bag blend / env family
- `PipelineInfoBag::additiveBlendFix` (original reflective env pass): non-zero → `StaPipCore::render` drains PATH1 (`sync.align3D()`), sets global `ALPHA` to `Cs*FIX/128 + Cd` via `RendererCoreGS::setAlpha`, restores alpha-over after. **Superseded** by the in-band per-mesh ALPHA qword (`VU1_ALPHA_ADDR` + `StoreTyraGifTags*Alpha`): every StaPip mesh's tag block carries its blend, no barriers; dynpip keeps the original 7/5-qword macros. `subtractiveBlendFix` exists for volume counting.
- Texture filtering per bag (docs/texture-filtering.md): `StaPipTextureBag::filter` (0 = follow the info bag, 1 = nearest, 2 = nearest mag + linear min) overrides `lod` MMAG/MMIN where `sendObjectData` writes the bag's TEX1 qword - the ONLY StaPip TEX1 write, so stamps/retained/baked routes inherit it. Loaders: `# tyra-filter` in `parseMtl`, `.tmdl` part flags bits 1-2 -> `LeanObjMaterial`/`LeanMtlMaterial::textureFilter`. DynPip has no field (the game draws nothing through it).
- StaPip `TCE` env programs: matcap ST from normals in the ST slot + `StaPipTextureBag::coordinatesAreNormals` + camera basis at `VU1_ENV_BASIS_ADDR` (EE uploads it transposed and pre-scaled as three qwords so VU1 does right/up in one accumulator chain).

## Render targets: `RendererCoreEnvMap` and `camFeed`
- Env map: 128×128 VRAM target for GT3-style reflections; FRAME/SCISSOR/XYOFFSET/ZBUF redirect bracket with a dedicated 128×128 z (reflected objects occlude correctly) + `RendererCore3D::pushEnvView/popEnvView`. Exposed as VRAM-resident `Texture::vramResident` that `useTexture` binds without PATH3 upload (docs/reflective-materials.md). `popEnvView` restores the frustum planes its push saved (no longer rebuilds from the caller's camera — the shadow pass passed no `up`).
- `RendererCore::camFeed`: second `RendererCoreEnvMap` for CCTV feeds (docs/texture-feeds.md), +128 KB VRAM, Clamp wrap; plain surface UVs read the target UPSIDE DOWN unless V flips (GS rows top-down).
- **Both opt-in**: `RendererCoreEnvMap::setEnabled` via `EngineOptions::envMapTarget`/`camFeedTarget` (editor: `projectNeedsEnvMap`/`projectNeedsCamFeed`). Off → `getTexture()` returns **nullptr**, `begin()`/`end()` no-ops. New callers null-check; a third such target is opt-in from the start. (They were 128 KB each incl. z, a quarter of the 32-bit texture heap.)

## Projected shadows: `RendererCoreShadowMap`
4 lazily allocated 64×64 VRAM slots + one shared cleared z; env-map-style raster redirect per caster — `begin(slot)` per caster, ONE `end()`. Game re-submits the caster's bags under a `pushEnvView` "light camera" and draws a terrain patch sampling the slot by light-space UVs. `allocate()` only when a project has "Cast shadow" objects; `init()` re-places buffers after a display-mode VRAM reset. Receiver patch STs ran -0.38..1.39 → clamp them on the EE where built (see gs-state.md, CLAMP).

## Shadow volumes: `RendererCoreAlphaMask`
Destination-alpha mask for the torch and (since 1.67.0) the frame's one carving spot light (docs/flashlight.md "The shadow", docs/shadows.md "Spot-light shadow volumes"). ONE band and ONE bracket per LIGHT per frame: each user clears, counts, draws, repaints before the next starts.
- `begin`/`beginKeep`/`end` bracket FBMSK to the alpha bits for convex 1-bit set/clear. **`repaintAlpha()` is MANDATORY after the last DATE pass** (SDTV flicker filter displays per-pixel alpha — gs-state.md).
- Counting (mesh-shaped volumes): `allocateCount()` claims a raster-sized PSMCT16 count target (permanent-region discipline, refusal graceful via `countReady()`); `countBegin()` redirects FRAME there while ZBUF stays the scene z; volume bags count with `additiveBlendFix`/`subtractiveBlendFix` (+N front / -N back, TestOnly z); `countResolve()` converts count>0 into alpha MSB with ONE textured sprite (TEXA.AEM=1 → all-zero texel alpha 0, else TA0=0x80; ATEST!=0 makes the write an OR; packet restores CLAMP to REPEAT itself because `emitRasterRestore` doesn't know texture state).
- Count lives in COLOUR channels of a never-displayed target because blending never writes A. N=32 clears 16-bit 8-step quantisation + dithering ±4. **Count targets must bracket `DTHE = 0`** (`countBegin` does; console dithers counts → residues; gs-state.md).
- Works at both colour depths (band follows frame PSM: PSMCT32/512 KB, PSMCT16/256 KB). The one-release 16-bit refusal over "dashed green marks down two fixed screen columns" was blamed on masked writes at PSMCT16 — measured wrong: a four-mask FBMSK probe reads identically on hardware and PCSX2 (0x00FFFFFF colour-neutral, alpha half works); an 8-vantage A-B-A sweep put the marks on countResolve's TEX0 base (SLID band base 8/8, band's own base 0/8). The write side slides FRAME by `bandY0` page rows, so the read must NOT slide as well as subtracting `bandY0` from V. **Still open**: why texels sampled by an alpha-only masked pass tint the picture, and why marks also appear above the band boundary.
- Prefer full-height targets over slid FRAME.FBP (`allocateCount` does at 16-bit); see gs-state.md.
- `RendererCoreAlphaMask::begin()`/`maskClear()` re-assert `FBA = 0` per frame.

## Billboards (`StaPipBillboardBag`, StaPip `billboard` programs)
- Vertex slot = PARTICLE CENTRES; ST slot = one qword of 2×2 basis weights per particle; one colour per particle. VU1 expands each centre to a camera-facing quad (6 GS vertices) from right/up at `VU1_BILLBOARD_BASIS_ADDR` (× MVP once per mesh), culls per QUAD with one `clipw` per corner.
- C++ must keep prim giftag NLOOP = 6× input (`gsVertexCount`); undercount stalls the GIF.
- Requires: multi-colour, no lighting, `frustumCulling` `None` + no clip checks (the one legitimate `None` — per-quad ADC replaces wrap protection), and a texture bag whose image may be null (it carries the params channel). Swapping `right`/`up` and re-rendering draws the same centres for another view (portal through-view).
- **Residency** (since 2026-09-26 VU1 audit): `setProgramsCache` sizes the class set as `createProgramsCache` packs it (`programSetWords`, even-rounded, shared image counted once) and appends the billboard pair (206 words) when total < `Path1::getDrawFinishAddr()`; `ensureProgramSet` is then a no-op. All-class VU1-clipping set with clip TD on the TC image ≈ 1740 of 2042, so every built-in config fits. Only a set grown past that by project programs falls back to swap-on-demand (two VIF1 drains + ~15.5 KB MPG upload per transition; the district paid it several times a frame). Boot log: `StaPip VU1 program set: N programs, billboards resident|swapped on demand`. `StaPipTelemetry::programSetSwaps` (CSV `Program_swaps_count`).

## Portals (docs/portals.md)
`RendererCore3D::pushPortalView` (view-matrix-only swap, main projection kept, exact frustum planes at the virtual camera) + `RendererCore::portalViewBegin/End` → `RendererCorePostFx::portalMaskBegin/portalMaskEnd`. Destination renders IN-PLACE into the real framebuffer right after the frame clear, scissored to the quad's screen bbox; the opening is carved with reversed-z ops (no stencil): re-far the bbox z, cap the interior with a z-only ALWAYS fan at surface depth, repaint the still-far ring via a GEQUAL sprite at z=0. Both wrappers drain PATH1 unconditionally and do NOT latch the post-fx drain gate. `portalMaskEnd` NLOOP = 13 + fan verts. Since `332f3193` both read `getRasterTarget()` and restore via `emitRasterRestore()` (per-field XYOFFSET bias included); `Begin` re-narrows scissor to the bbox AFTER the restore, `End` releases it.

## Split screen: `RendererCoreSplitView` (`renderer/core/splitview/`, `RendererCore::splitView`)
Per half: drain PATH1, shift XYOFFSET so the CENTRAL h/2 rows of the unchanged full-screen projection land on that half (vertical crop, proportions exact), scissor to the half. **No per-half clear** — beginFrame's clear covers both and scissor clips every write incl. z (the first version copied the env map's clear sprite: two half-screen fills + FINISH stalls per frame for nothing). Game swaps cameras with `renderer3D.update(cam2)` (pipelines read view/frustum lazily per mesh); animation advance/skinning only in the FIRST half (`splitSecondPass`). Any bracket restoring a full-screen raster (env map!) must not run inside a split half.

## VU0 micromode ray tracer (`renderer/rt/vu0_raytracer.{hpp,cpp}` + `vu0_rt_kernel.vclpp`)
Raytraced mirrors (docs/raytraced-reflections.md), exported by `<tyra>`. The ONLY VU0 microprogram: same vclpp/vcl/dvp-as pipeline, uploaded to VU0 micro memory (0x11000000), kicked with `vcallms 0` per image row, params/results via VU0 data memory (0x11004000), sync by polling VPU STAT bit 0 (`cfc2 $29`). No XGKICK/EFU/xtop; branchless nearest-hit via saturation step masks (`clamp(x*1e38,0,1)` — VU floats saturate, no inf/nan). Synchronous: macro-mode COP2 (Vec4/M4x4) shares VU0's registers so it never overlaps engine math; clobbering VF01+ between kicks is safe (every macro op reloads operands). Mirror/feed targets use per-bag clamp (gs-state.md).

## Frame extrapolation: `RendererCoreWarp` (`renderer/core/warp/`, docs/frame-extrapolation.md)
Re-draws the last finished frame under a newer camera as a textured grid (world at half the field rate).
- **The IDENTITY warp is the test**: `from == to` must reproduce the source exactly — wrong TEX0, region clamp, UV encoding or strip order show as tearing/garbage. Check first.
- **Overcounting NLOOP is as fatal as undercounting** (restore block claimed 4 regs, wrote 3 → hang in `draw_wait_finish`, clean log).
- Degenerate camera basis silently becomes an identity copy (every corner takes `wPrev < 1e-3` fallback): "warp does nothing" == "bad basis".
- A non-blending pass must not write `TEXA`/`COLCLAMP` (the warp did, hue-shifting all later blends — gs-state.md).
- Real/warped frames alternate per field; a Wayland screencast is not frame-accurate enough (ten captures of a marked warp frame byte-identical) — build a game-side A/B.
- History guards for any present-without-render (two needed): `getPreviousRealFrameBuffer()` (`flipBuffers` records `lastRealBuffer`; a `synthetic` flip doesn't claim it), and with **two** display buffers two flips per loop make history == render target - sampling it is feedback, not history (three buffers cannot hit it). Any new history reader must guard both. (The old neural BLSS temporal pass was the second reader; it is gone, and Whole-3D-scene BLSS + extrapolation is still refused at build, blss.md.)
- `RendererCore::getStallTotal()` = never-reset running stall total beside resetting `takeStallTicks()` (used by the extrapolation gate and profiling rig); a third reader (interleaved-passes tuner, docs/interleaved-passes.md) diffs the total.

## Live texture reload
`Texture::sourcePath` = full load path set by `TextureRepository::add` (`name` keeps only the basename). Generated `live_tex.gen.cpp` matches repainted files against it and re-uploads via `RendererCoreTexture::updateTextureInfo` to the SAME VRAM address (docs/live-link.md). The engine always constructs the clut `TextureData`; non-paletted textures have `clut->data == nullptr` — test data presence, not the pointer.
