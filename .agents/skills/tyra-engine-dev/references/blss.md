# `RendererCoreBlss` — the reduced-raster upscaler, console half

Read when: you touch `renderer/core/blss/`, the raster redirect (`RasterTarget`, `redirectRasterTo`, `emitRasterRestore`), z-buffer sizing/`zBuffer.mask`, `GS_SET_ZBUF` anywhere, a pass that copies the z buffer, or quote a BLSS number. User doc: docs/upscaler.md; measurements: docs/profiling.md ("Timing a frame that BLSS is in").

BLSS draws part of the frame into a reduced GS target and blows it back up with ONE bilinear pass. `engine->renderer.core.blss`. Inert, zero VRAM when not configured. The neural half (per-tile MLP, bag proxies, jitter, sharpen, temporal history, debug views, the host twin) was DELETED in 2.1.0: +0.29..+0.42 dB over bilinear for ~5 ms EE, break-even 13 coverages vs 2.6 plain. There is no host twin any more - nothing on the editor side models the composite.

## API
- `configure(scaleX, scaleY, nativeScenes, particles)` — init-only, top of the generated `init()`, before any texture. Re-lays the permanent VRAM region when `needsBufferRealloc()` (z size follows the raster) via the `setVramRebuild` hook = `RendererCore::rebuildPermanentBuffers()` (`setDisplayOutput`'s mode-change branch minus the mode; deliberately no `gs.reinit()` - `graph_set_mode` would reset the GS mid-init). `particles` reserves the low-res z target too.
- `setScene(upscale, particles)` — per scene / at runtime. Flips flags, republishes `settings->setRasterScale`, re-derives projection (`core3D->setFov`), restores `zBuffer.mask = getZMaskDefault()`. Touches NO VRAM. A shape `configure()` did not allocate for renders native.
- Whole scene: `beginScene(clear)` / `endScene()` / `composite()` — all no-ops unless `isEnabled()` (the generated loop always emits all three; per scene needs no branch).
- Particles only: `beginParticles()` / `endParticles()` — no-ops unless `isParticleMode()`.
- `isEnabled()` (whole scene live), `isParticleMode()`, `isActive()` (either: the frame runs synchronous GS brackets - TyraX2 overlap falls back).
- `RendererCoreGS::setLowResTargetScale(sx, sy, withDepth)` — the permanent reserve for the low-res colour (and, `withDepth`, z) target, independent of the pinned Z raster and the active raster; set by `configure()` before the realloc decision, kept across scene and display-mode switches; `setScene()` must not change it. Host twin: `project::tripleBufferingFit` charges both (display-framebuffers.md).
- `RendererCore3D::refreshRasterProjection()` — re-derives projection + viewProj MID-FRAME (the particles bracket switches the raster between opaque scene and emitters). `setFov()` is the between-frames version.

## The two shapes
- **Whole 3D scene**: raster redirected to the low-res target; the MAIN z buffer is used at the low-res stride (a prefix of it - FRAME.FBW gives the stride), so z SHRINKS (57 344 vs 229 376 words at 2x2, 512x448) and more than pays for the colour target. Composite = one textured sprite-strip pass, bilinear, screen-origin XYOFFSET + per-field bias. Refused by codegen with DoF, linked portals, split view (display-res depth no longer exists) and frame extrapolation.
- **Particles only**: opaque scene full-res against full z (`configure` pins `setZRasterScale(1,1)`, same as `nativeScenes`). `beginParticles()`: align3D, then (1) DEPTH copy - full z read as a PSMZ texture, written POINT-sampled into the low-res z seen as a frame of the same PSMZ format (every bit survives); (2) COLOUR copy - box-filtered (bilinear tap between four texels) with vertex alpha 0; (3) redirect to the low-res target, ZBUF = low-res z with writes masked, FBA = 1, `applyRasterScale(true)`. `endParticles()`: align3D, projection back, restore raster, (4) at 32-bit a DATE pass (DATM = 1, FBMSK keeps RGB) rewrites the alpha byte to exactly 0x80 where FBA set the top bit - otherwise 0xFF reads as a factor of two; at 16-bit `kMaskTexa` expands the A bit to 0/0x80 for free; (5) composite `Cs*As + Cd*(1-As)` bilinear over the display buffer, FBMSK keeps display alpha (the alpha-mask passes own it). Clashes with nothing. Cost: two quarter-area copies + one full-screen blend; VRAM = low-res colour + low-res z (448 KB at 512x448x32, 2x2).
- Codegen side of the bracket (`renderScene()` particle loop in game_templates.inc): **main view only, never in split screen** (each half is a scissored view of one buffer; one full-screen copy cannot serve both), skipped when no emitter has a live particle, and **`stapip.core.flushDeferred()` BEFORE `beginParticles()`** - queued StaPip stamps are opaque scene and must land before the copies read it.

## Traps paid for - keep them
**Raster redirect is explicit state on `RendererCoreGS`.** `RasterTarget` (frame address, `FBW`, scissor, `XYOFFSET` in 1/16 px) via `redirectRasterTo()`/`endRasterRedirect()`/`getRasterTarget()`, restored by the **shared `emitRasterRestore()`** used by env map, camera feed, shadow map, portal masks and the warp — so brackets **nest** inside BLSS. Publish the redirect BEFORE anything nests. **Do not make `getCurrentFrameBuffer()` return the redirect target**: restores touch four registers and only FRAME comes from it (→ 512-wide SCISSOR over 256-wide FRAME, wrong XYOFFSET), and it breaks post-fx callers + BLSS' own passes. `getCurrentFrameBuffer()` = the display buffer. **All brackets share one restore — do not add one that doesn't.**
- XYOFFSET is written BEFORE the clear sprite. 3D wants window-centred (`2048 - lowW/2`); copies and composites want screen-origin (`2048, 2048`); only the pass writing the scanned buffer adds `getFieldYOffset16()` (it once added it unscaled inside a reduced raster → 1.5 rows at 2x2 instead of 0.5).
- `emitRasterRestore()` writes `ZBUF` explicitly and **LAST** (not via ps2sdk `draw_enable_tests`): returning from the shadow map with ZBUF on the 64×64 silhouette z made every receiver patch fail GEQUAL.
- **Restore SCISSOR before the full-screen composite.** `endParticles()` runs `emitRasterRestore()` FIRST; left at the low-res scissor it clipped the composite to the top-left quarter (hit while building Particles only).
- **`DTHE = 0` while a PSMZ target is written** - dithering a z buffer seen as a frame adds noise to depth. Restore to `settings->isDitherActive()` after.
- **TEXA**: `kMaskTexa = (0, 0, 0x80)` for 16-bit colour AND PSMZ16 copies (else bit 15 of every depth reads back as 1); back to the DRAWING-ENVIRONMENT value `kEnvTexa = (0x80, 0, 0x80)` before any 3D - NOT the GS reset value: 24-bit textures take alpha from TA0 and `ATEST NOTEQUAL/AREF 0` would delete every one. Same rule for `COLCLAMP`/`TEX1`: put back what `draw_setup_environment` left (disassembled `libdraw.a`), never a guessed reset value (gs-state.md, "Restoring a register nothing else writes is a GUESS").
- **CLAMP** is restored from `RendererCoreGS::currentTextureWrap()`, never REPEAT/CLAMP literals - the next bag's `setBagWrap` compares against that cache (gs-state.md, REPEAT contract). The copies use a REGION clamp to the real extent (TEX0 TW/TH round up to a power of two).
- Blits are 32-px sprite strips (page cache) in one 512-qword packet; GIF NLOOP counts every register row - a miscount stalls the GIF forever with a clean log (hang in `draw_wait_finish`).
- `beginScene`'s drain is NOT removable (PATH1 preempts in-flight PATH3; the clear must finish before VU1 kicks). Every bracket starts `if (path1->isVU1Configured()) sync->align3D()` - before VU1 is up the FINISH handshake spins forever.

**`zBuffer.mask` is OWNED BY THE ALLOCATOR.** `allocateVramBuffers()` DERIVES it (1 whenever z is smaller than the display raster; `getZMaskDefault()`); only the whole-scene bracket opens it (0) and closes it (`getZMaskDefault()`, never literal 1 - 0 in a mixed game; the literal masked the next native scene's depth). Every `draw_enable_tests`/`draw_setup_environment` reads that field, so full-screen 2D/HUD/post-fx at `z = 0xFFFFFFFF` can't stamp past a small allocation.
- **The z-mask/CLUT disaster (broken TWICE).** First: `configure()` assigned the flag one statement before the rebuild that cleared it → mask 0 all run, full-res passes stamped 512×448 words of depth past `ZBP` (ZBUF has no width; stride comes from `FRAME.FBW`) into the texture heap. Symptom: **every 4-bit palettised texture drew NOTHING** (depth landed on the 8×2 CLUT, zeroed CLUT alpha, `ATEST NOTEQUAL` discards); 24-bit textures kept drawing → looked like a CLUT bug for two sessions. Second: `RendererCorePostFx::apply()`'s restore re-programmed ZBUF with hardcoded mask 0 (ps2sdk `draw_enable_tests()` emits only `GS_REG_TEST_1`); read as "BLSS deletes the terrain"; hidden because `apply()` early-returns without post-fx. **Grep `GS_SET_ZBUF` before adding a full-screen pass; never write the mask from one** - BLSS' own copies write ZBUF with mask 1. Diagnostic: inventory what ELSE vanished (the crosshair did) before theorising. **An allocation is not an addressable extent.**
- **`nativeScenes` pins the layout.** A game whose scenes (or a Set Upscaler node / adaptive resolution) can go both ways calls `configure(..., nativeScenes = true)` → `setZRasterScale(1,1)` before the realloc decision → z covers the display all run, `needsBufferRealloc()` stays false, `setScene()` is free. A scene change NEVER absorbs a re-layout: `loadScene()` frees/re-acquires textures ref-counted and never calls `vram.reset()`/`evictAll()`. PCSX2, ~1 200 switches: zero evictions, resident count/free VRAM constant.
- `init()` re-places the targets on `allocated`, not `enabled` (a display-mode switch during a native scene would leave `lowVram` in freed heap).
- The low-res target was once in neither `getHeapWords()` nor the reserve when the triple-buffer check ran (`configure → rebuild → allocate`) - hence the explicit `setLowResTargetScale` reserve (display-framebuffers.md).

## Costs and measurements (real PS2 unless stated)
- **Pass price**: one full-screen textured blended pass = **0.5896 ms at 512x512, 0.5174 ms at 512x448** (per RASTER; `perMpx` agrees to 0.3 %). PCSX2 reports **0.0077 ms** — under-reports GS fill **76x**; NO PCSX2 GS number about BLSS is admissible.
- **Fill retention at 2x2: saved = 0.7548 × scene fill** (hardware fit, five load points, RMS 0.093 ms). `blssScale 0` = `Scale::X2Y2` = a quarter of the pixels, not half.
- **Plain whole-scene break-even 2.6 coverages at 512x448** (2.3 at 512x512): EE `begin` 0.41 + `end` 0.10 + ~0.01 packet, composite GS 0.50. `begin`+`end` is a floor (the redirect's GS round trips). The brackets serialise, so deleted EE work can reappear as `end` in a GS-busy frame - prefer frame-level A/Bs.
- **Regime = heavy overdraw.** `upscaler-lab` 3 072 blended puffs: 530 → 157 ms (3.4x); retuned 568 billboards: 52.95 → 32.42 ms (1.63x, still paying the network). Adaptive on its parked camera: 16.1 → 44.0 FPS. EE-bound frames gain nothing.
- **`drain ≈ 0` does NOT mean EE-bound**: GS backpressure stalls the EE inside submission (charged to `submit`); both arms of the 3.4x win read `drain = 0.02`. Change the GS load and see whether the frame shortens.
- Counters (`inc/debug/frame_profile.hpp`, `TYRA_FRAME_PROFILE`): `tBlssBegin` (beginScene / beginParticles), `tBlssEnd`, `tBlssComposite` (composite / endParticles), `tBlssCompositeEe`. The six neural split counters and `FTSPLIT` read 0.
- Particles only is NOT yet priced on hardware.
- Fixture traps: Live Debugger key is **`liveDebug`** (on = ~500 ms/frame of host network I/O); the rig's window mean once summed ticks in a u32 (overflow above ~290 ms/frame; now u64). For a frozen-camera A/B on `upscaler-lab` drop the director object (its On Start plays the "haze tour") and set the Player's walk/look speed 0.
