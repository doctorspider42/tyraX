# `RendererCoreBlss` — the neural upscaler's console half

Read when: you touch `renderer/core/blss/`, the raster redirect (`RasterTarget`, `redirectRasterTo`, `emitRasterRestore`), z-buffer sizing/`zBuffer.mask`, `GS_SET_ZBUF` anywhere, or BLSS measurements/nets. Docs: docs/neural-upscaler.md, docs/blss-reconstruction.md (the arithmetic + twin contract), docs/profiling.md.

3D renders into a half-res VRAM target; a per-tile MLP decides how to reconstruct. `engine->renderer.core.blss`; generated `init()` calls `configure()` + `setNet()`, scene is bracketed by `beginScene()` / `endScene()` / `composite()`. Inert, zero VRAM when off.

## Modes and per-scene setting
- **Plain mode** (`configure()`'s 7th arg `network` = false) — what most projects should use: no bag proxies, tile accumulators, reprojection, feature grid or MLP; composite = ONE textured quad instead of the 476-vertex Gouraud grid. Redirect, shrunken z and VRAM saving unchanged.
  - The pipeline's gate is **`wantsProxies()`, never `isEnabled()`** — StaPipCore computes a per-bag world sphere before calling; `proxy` is 2.34 ms of a 4.60 ms bill.
  - `configure()` **forces `jitterOn` false** in plain mode (only the temporal pass could fuse jitter phases).
  - Base pass = one CELL of the grid (one-cell TRIANGLE_STRIP), not a GS sprite (would save 7 qwords but uses a different rasteriser path, unanswerable from here). Neural build whose net asks nothing vs plain build: byte-identical over 811 426 pixels, nine cross-pairings.
- **Per scene**: `configure(..., nativeScenes)` (init-only) + `setScene(upscale, network)`.
  - `configure()` re-lays the permanent VRAM region and evicts every texture (z size follows the raster) — safe only at the top of `init()`. A scene change does NOT absorb it: `loadScene()` frees/re-acquires textures ref-counted and never calls `vram.reset()`/`evictAll()`.
  - Mixed games PIN the layout: `nativeScenes` makes `configure()` call `RendererCoreGS::setZRasterScale(1, 1)` before the realloc decision → z covers the full display all run, `needsBufferRealloc()` stays false. `setScene()` flips `enabled`/`useNet`, republishes `settings->setRasterScale`, re-derives projection (`core3D->setFov`), drops `hasPrev`, restores the z mask — no allocation/eviction/packet. PCSX2, ~1 200 switches: zero evictions, resident count/free VRAM constant, scene-load within 0.5 ms of controls.
  - Colour-target reserve: `RendererCoreGS::setLowResTargetScale`, separate from pinned Z and active raster; `configure()` sets it before `needsBufferRealloc()` (mixed projects must recheck triple-buffer headroom even when Z never shrinks). Preserve it across native-scene mode switches; `setScene()` must not change it.
  - `endScene()` restores `gs->getZMaskDefault()`, never literal 1 (0 in a mixed game; the literal masked the next native scene's depth pass).
  - `init()` re-places the low-res target on `allocated`, not `enabled` (a mode switch during a native scene would leave `lowVram` in freed heap).
  - `jitterWanted` kept apart from `jitterOn` (the request must survive a plain scene).
  - `beginScene`/`endScene`/`composite` return immediately when `enabled` is false — the generated loop always emits all three.
- `configure(…, bool jitter = true, bool network = true, bool nativeScenes = false)` — engine default jitter is true, but the project field **`blssJitter` defaults false** (project.hpp) and `examples/upscaler-lab` ships it off.

## The twin contract
`src/blss.cpp` (editor) is the other half; docs/blss-reconstruction.md is the contract: same sampling (12.4 UV quantisation, bilinear taps at UV − half texel, 4-bit weights combined `>>8`), same 8-bit blend chain with GS `(A−B)*C>>7` truncation and 0..255 clamps, same `accumulate`/`buildReproj`/`buildFeatures`/forward pass. Training labels come from a host oracle on this formula — divergence trains for a machine that doesn't exist. Regression test: `tyrax-editor --blss-eval` (parity break = trained row well below oracle row). **Change one side → change the doc and the other side.** Proxy rules are twinned with `src/blsscorpus.cpp` (`bagOf()`, `kProxyVerts = 24`). The host twin does NOT model the jitter switch (jitter-off nets slightly out of distribution).

## Things paid for — keep them
**Raster redirect is explicit state on `RendererCoreGS`.** `RasterTarget` (frame address, `FBW`, scissor, `XYOFFSET` in 1/16 px) via `redirectRasterTo()`/`endRasterRedirect()`/`getRasterTarget()`, restored by the **shared `emitRasterRestore()`** used by env map, camera feed, shadow map and (since `332f3193`) portal masks — so brackets **nest** inside BLSS. They used to restore the display buffer unconditionally from inside `renderScene()` (first one silently turned BLSS off for the frame). **Do not make `getCurrentFrameBuffer()` return the redirect target**: restores touch four registers, only FRAME comes from it (→ 512-wide SCISSOR over 256-wide FRAME, wrong XYOFFSET, jitter dropped), and it breaks four post-fx callers + BLSS' own `endScene()`/`composite()`. `getCurrentFrameBuffer()` = the display buffer. **All four brackets share one restore — do not add a fifth that doesn't.**
- XYOFFSET is written BEFORE the clear sprite. 3D wants window-centred (`2048 - lowW/2`); the composite's 2D-style passes want screen-origin (`2048, 2048`).
- `emitRasterRestore()` writes `ZBUF` explicitly and **LAST** (not via ps2sdk `draw_enable_tests`): returning from the shadow map with ZBUF on the 64×64 silhouette z made every receiver patch fail GEQUAL.
- Jitter = raw 1/16 units on XYOFFSET (12.4 → ±4 = ±¼ px; host reproduces bit-for-bit).
- The shared restore re-applies the per-field bias (`RendererCoreGS::getFieldYOffset16`, non-zero only for `InterlacedField`). It was removed from `beginScene` (it added it unscaled inside a raster whose row is `scaleY` physical rows → 1.5 rows at 2x2 instead of 0.5); interleave belongs only to the pass writing the scanned buffer.

**Z follows the RASTER.** `allocateVramBuffers()` sizes z from `RendererSettings::getRasterWidthUI/HeightUI` — 57 344 words vs 229 376 at 2×2: 672 KB back at 512×448, 768 KB at 512×512, against 224/256 KB for the low-res colour target. BLSS leaves MORE texture VRAM (Pal576i 512×512, `VRAMSTAT` frame 240: 0.227 MB free off, 0.727 MB on, one eviction fewer). FRAME and ZBUF bases are independent; low-res pass writes a contiguous z prefix at the low-res stride.
- **Invariant: `zBuffer.mask == 0` only INSIDE the low-res bracket.** `allocateVramBuffers` DERIVES it (1 whenever z is smaller than the display raster); `beginScene`/`endScene` open/close. Every `draw_enable_tests`/`draw_setup_environment` reads that field, so full-screen 2D/HUD/post-fx at `z = 0xFFFFFFFF` can't stamp past the small allocation.
- Worst bug: `configure()` assigned the flag one statement before the rebuild that cleared it → mask 0 all run, full-res passes stamped 512×448 words of depth past `ZBP` (ZBUF has no width; stride comes from `FRAME.FBW`) into the texture heap. Symptom: **every 4-bit palettised texture drew NOTHING** (depth landed on the 8×2 CLUT, zeroed CLUT alpha 0, `ATEST NOTEQUAL`/`AREF 0` discards); 24-bit textures kept drawing → looked like a CLUT bug for two sessions. **An allocation is not an addressable extent.**
- Ordering: z sizing needs the scale only `blss.configure()` knows, z is allocated third in `gs.init()` → `configure()` re-lays via `RendererCore::rebuildPermanentBuffers()` (gated on `needsBufferRealloc()`) = `setDisplayOutput`'s mode-change branch minus the mode. Deliberately no `gs.reinit()` (`programDisplay()`'s `graph_set_mode` would reset the GS mid-init).
- **Broken TWICE — treat `zBuffer.mask` as owned by the allocator.** Second time: `RendererCorePostFx::apply()`'s restore re-programmed ZBUF with hardcoded mask 0; ps2sdk `draw_enable_tests()` emits only one A+D qword at `GS_REG_TEST_1` (disassembled `libdraw.a`) so it didn't cover it; next frame's `clearScreen` sprite stamped 512×448 words into the heap. Read as "BLSS deletes the terrain" (`examples/showcase` has one texture, the terrain's); hidden because `apply()` early-returns without post-fx. **Grep `GS_SET_ZBUF` before adding a full-screen pass; never write the mask from one.** (docs/neural-upscaler.md §5.) Diagnostic: the broken arms also lost the crosshair sprite — inventory what ELSE vanished before theorising.

**History = `frameBuffers[1 - context]`** (previous presented frame, full-res); needed a new `RendererCoreGS` accessor (stock returns the buffer being drawn into). Note `1 - context` is a two-buffer expression — see display-framebuffers.md.

**How a bag is described (wrong for eleven commits).** Was one bounding SPHERE per bag → for floors/terrain `wNear = w − radius` hits the near clamp, screen box = frame; every tile read `depth = 1, depthGrad = 1, coverage = 1`; whole frame = TWO proxies. Now (all twinned with `blsscorpus.cpp`):
1. `addBagBox()` projects an object-space AABB through the MVP, near-clips along its **twelve edges** (8 corners = one mat-vec + three scaled columns).
2. `StaPipCore` submits **one box per VU1 package** from the cached `StaPipBagPackagesBBox`, cap `kMaxProxiesPerBag = 32`, consecutive parts merged above (only enlarges).
3. A box that **straddles the eye AND still fills the frame after clipping is dropped** (threshold-free).
4. **`PipelineInfoBag::blssProxy`** opt-out — codegen clears it for sky dome, star field, sun/moon discs (a dome CAP evades rule 3).
- `addBagSphere()` = fallback without package bbox. Booted `fpp`, debug view 2: **2 → 41 proxies, 196/196 → 159/196 tiles covered, `depth` 1/1/1 → 0/.737/1, 5.00 → 1.96 mean passes.**
- **Emitter rule ships OFF** (`TYRA_BLSS_EMITTER_PROXY` 0, host `--emitter-proxy`): billboard bags (`frustumCulling = None`, no package bbox) got a radius-0 sphere → nothing described particles (98.7 % of fill on `upscaler-lab`, 95.6 % on `showcase`). Rule = one AABB over the centres per BAG, grown per axis by `|R.axis|*(max|m00|+max|m10|) + |U.axis|*(max|m01|+max|m11|)` (exact for ordinary emitters, √2-conservative for fog swirl; per bag because pool order = spawn order). Measured on: proxies 198 → 207, covered tiles 147 → **224/224**, `texDetail` 0.466 → 0.211, but `coverage` becomes constant 1.000 and `depthGrad` spread 0.101; BLSS EE **3.21 → 4.09 ms**, break-even **13.1 → ~15.3**. Off.
- **Spatial split of emitters = measured NO (2026-08-09), don't reopen**: 224/224 before/after, `coverage`/`depthGrad` still 1.000, proxies 207 → 241 of 310, tile updates 2 636 → 6 077, EE 4.07 → 5.25 ms, break-even ~15.3 → ~18.2. A partition of a solid region tiles it (same union); Tyra pools are never clustered (`updateParticles` spawns uniformly over the XZ rect). The flat channel is the FIXTURE (one small emitter: `coverage` 0.690, 67.8 % at 1.000; `--blss-coverage` counts 71.65 of 72.23 coverages as emitters). Open item: the corpus draws no particles (docs/backlog.md).
- **Proxy budget** `TYRA_BLSS_PROXY_BUDGET` (default 0): caps proxies at the tiles a bag's box covers; 198 → 116 on `upscaler-lab`, moves only `coverage` 0.631 → 0.638. May not go to 1 until `bagOf()`/`bagList()` cut the same way (twin-contract change).

**The instrument is PERMANENT.** `logFeatureSpread()` under `blssDebugView = 2` logs once a second to `bin/log.txt`: `BLSSGRID` (tile/proxy counts), `BLSSWORST` (widest proxy — named the sky dome in one shot), `BLSSFEAT`/`BLSSOUT` (min/mean/max per channel/output), `BLSSFILL` (occupancy via `emitGrid`'s rule). Channel names/order = `blss::kFeatureNames` exactly; host side `tyrax-editor --blss-eval --probe "<BLSSFEAT line>"`. A previous round deleted it after one read → net fitted to one distribution, run on another. Inside `#ifndef NDEBUG` (a `make release` has no `TYRA_LOG`; the editor's game build isn't release). Enable: *Debug view* → "Log the feature spread to bin/log.txt (no tint)" (*Project > Preferences > Display > Frame delivery > Tuning the network*, *Project > Preferences*); since `7d3dbf67` the combo offers view 2 (`project.cpp` clamps `0..2`).

**Composite GS state the engine never wrote before**: `TEXA` (per-vertex-alpha trick: `TFX=MODULATE` + `TCC=0` + vertex RGB 128 → RGB = texel, A = vertex alpha) and **`COLCLAMP`** (inherited 0 would wrap and break parity on saturated pixels). Alpha test disabled during it (weights ARE vertex alpha; `ATEST_METHOD_NOTEQUAL` would discard zero-weight corners).

**Own packet, worst-case sized**: one tile row = 34-vertex TRIANGLE_STRIP × 3 qwords/vertex → passes 2..5 ≈ 5 700 qwords (the shared 768-qword post-fx packet would corrupt the GIF). Never size off the typical case. **Strip vertex order is load-bearing**: `(i,j) (i,j+1) (i+1,j) (i+1,j+1) …` — host models that diagonal.

**`emitGrid`'s skip rule is in the host's cost model**: a cell is drawn unless ALL FOUR corner alpha bytes are zero (one kernel tile lights nine cells). Host oracle charges it (`--fill-weight`); `--blss-eval` reports occupancy by the same rule — changing it changes what the net was trained to want. Shipped net: mean **1.87 passes held-out, 1.67 in distribution** (bilinear 1.00, worst 5.00); oracle better PSNR at 1.36. At shipped deadzone point and sharpen are culled 0 %; only temporal draws widely. Occupancy sd 0.30 over 39 fold-runs (one fold 2.12).

## Costs and measurements
- **Pass price (real PS2)**: one full-screen textured blended pass = **0.5896 ms at 512x512, 0.5174 ms at 512x448** (per RASTER; `perMpx` agrees to 0.3 %; docs/profiling.md "The calibration gate"). PCSX2 reports **0.0077 ms** — under-reports GS fill **76x**; NO PCSX2 GS number about BLSS is admissible.
- First hardware A/B: +9.83 ms/frame, saved nothing (EE-bound; `drain` 0.02, `endScene` overhang 0.03) — **PROVISIONAL**, taken with the z-mask defect (palettised surfaces missing); retake owed.
- **EE half** (counters `tBlssProxy` in StaPipCore; `tBlssReproj`/`tBlssFeat`/`tBlssNet`/`tBlssPacket`/`tBlssAccum`/`tBlssEnd`): PCSX2 `blssrig`: net 3.96, proxy 3.26, pkt 0.61, reproj 0.39, feat 0.14 (`runNet` largest). newlib `tanhf`/`expf` compute in DOUBLE, EE has no double FPU (15 activations/tile = 15 software round trips).
- Four bit-identical cuts (2026-08-08): proxy near-clip takes each in-front corner ONCE (−1.10 ms; wholly-in-front boxes skip the edge loop); deadzone compare before the logistic (monotone; −0.57 ms, guard-banded within 0.01); `passHasAlpha()` skips passes with no non-zero corner (point+sharpen every frame, −0.30); `addBag` hoists per-column overlap (−0.20). PCSX2 +8.76 → +6.39 ms; **console: 1.96 ms** (proxy 3.95→2.39, net 2.20→1.97, pkt 0.73→0.56; total EE 7.92 → 5.95). **PCSX2 doesn't transfer per-function** (it over-weights libm; puts net above proxy, console the reverse) — attribute on hardware. Bit-identity checked: BLSSGRID/FEAT/OUT/FILL byte-identical over 44 s paired.
- **Activation table** `TYRA_BLSS_ACT_TABLE` (engine default now **512**; host `actTable` in `src/blss.cpp` — **one number in two files, same commit**): net 1.93 → **0.79 ms** on console (PCSX2 predicted 2.11). Until 2026-08-08 the engine's actTanh/actLogistic were never called.
- `tBlssAccum` (`proxy=total/accum` in FTSPLIT): 262 projections for 198 proxies touching **7.6 tiles each** → cost per PROXY. `addBag`'s four `floorf` were real out-of-line newlib calls, 68 instructions each (replaced by cast + compare).
- Measured negatives: interleaving the six tile accumulators is SLOWER (a grid row's 16 tiles already share one 64-byte line per array); moving composite EE work before `endScene`'s drain saves ≤ `tBlssEnd` = 0.05 ms PCSX2 / 0.11 hardware; `beginScene`'s `draw_wait_finish()` is NOT removable (PATH1 preempts in-flight PATH3; clear must finish before VU1 kicks).
- **Composite tail is a floor — stop looking for a libm win** (2026-08-09, hardware): `reproj` 0.275 + `feat` 0.190; `sqrtf` in `buildFeatures` is a bare `sqrt.s`; 346 instructions, zero `jal`, zero `div.s`. `/ kTile` folded to a multiply. Two bit-identical changes = +0.017 ms of 4.60: `finishTileStats` writes `feat[][1]/[3]/[4]/[5]` and `tGrad` directly (five per-tile arrays + one 224-tile pass deleted; work moved: feat 0.190 → 0.141, reproj 0.275 → 0.310), and `buildReproj` hoists the per-column/row screen ray and makes the neighbour-count average an exact binary scaling. **A divide prices at ~565 `div.s` = 0.007 ms (~2 100 EE cycles)** for the whole saving. Fixture trap: `proxy`/`accum` differ 0.051 ms between runs of the IDENTICAL ELF (scene settles at 201 vs 198 proxies) — check `BLSSGRID`'s proxy count first, discard mismatches. `reproj`/`feat` reproduce ±0.001.
- **Regime = heavy overdraw.** `upscaler-lab` at `0c3f05c3` (12 banks × 256 = 3 072 + fire/smoke/rain = 3 448 billboards, 17 emitters): **530 ms off vs 157 ms on (3.37x)** at 1.9 FPS. Retuned (6 × 32, **11 emitters / 568 billboards** — quote this): **52.95 off vs 32.42 on**, d = +20.53 ms, 95 % CI [+20.46, +20.61], n = 1024 paired frames, **1.63x**, for **4.60 ms EE** + 0.50 ms composite fill (jitter OFF, as shipped). Jitter-ON table: 52.86 / 32.98 / 1.60x; `BLSSFILL passes = 1.56` in both. Those ms predate the 2026-08-09 CC0 asset swap (fill unchanged, `--blss-coverage` 72.63 → 72.23; ~4 ms EE out of both arms) — absolute A/B owed a rerun.
- **Break-even 13.1 coverages at 512x448** (`0.7548 × 0.5174 × C > 4.60 + 0.50`), **11.5 at 512x512** (tool prints 11.4) — always quote with the raster. `breakEven()` and `--blss-coverage` print the right one: `kPassMs` became `kPassMsPerMpx` 2.2524 + `passMs(rasterPx)`; `speedFrom` takes the raster; `CoverageReport` echoes `outW`/`outH`. Retention fitted on hardware over five load points: 0.7548 saved, RMS 0.093, intercept 5.10 ms (= 4.60 + 0.50). `blssScale 0` = `Scale::X2Y2` = a quarter of the pixels, not half.
- **`drain ≈ 0` does NOT mean EE-bound**: GS backpressure stalls the EE inside submission (charged to `submit`); both arms of the 3.4x win read `drain = 0.02`. Change the GS load and see whether the frame shortens.
- Fixture traps: Live Debugger key is **`liveDebug`** (not `liveDebugger`), on = ~500 ms/frame of host network I/O; the rig's window mean summed ticks in a u32 (overflow above ~290 ms/frame; 500 ms printed as 37; now u64). `upscaler-lab` is a GS-bound stress case and a bad demo (tuned against PCSX2's 76x fill).

## Jitter = the "earthquake"
The ±¼-px per-frame jitter in `beginScene` IS the bob (three builds watched: off steady / jitter on "like an earthquake" / jitter off steady) → `blssJitter` defaults **false**; `examples/upscaler-lab` ships off since 2026-08-09 with a refitted net. Earlier "net-dependent" claims retracted (instrument on untextured `blssbug` and particle-moving `upscaler-lab`). Emitters frozen: 16.3 % of the picture below the HUD alternates between two byte-identical phases; cross-correlation lag (0,0) — a resample alternation on textured edges, not displacement.
- Stability gate (docs/profiling.md "The stability gate") confounds: HUD frame counter (turn `showFps`/`showMemory`/`showProfiler` off) and PAL interlaced field alternation (run at `displayMode` progressive). With both: 0.10-0.15/255 noise vs 0.77/255 artefact.
- Test for the PERIOD-2 SIGNATURE, never "did it change" — an even frame stride lands on one phase and reports stillness.

## Incompatibilities (build refuses them, per SCENE)
DoF, portals, split view (read/write display-res GS depth, now unallocated) and **frame extrapolation** (2026-08-11, docs/frame-extrapolation.md "Why not with the upscaler"): extrapolation halves world rate so the camera moves twice as far between RENDERED frames — exactly what the temporal pass reprojects across. Invisible parked, only in MOTION (every frozen-camera gate was built not to see it). Reporter's project, PCSX2 SW, `--pad`: each alone clean, pair tears into cells; per-corner reprojection offset peaks 158 px of 448 off vs 201 on. **Disproved, don't reopen**: not the two-buffer history degeneration (three-buffer rotation LOGGED: history always the previous rendered frame) and not raster state leaking across the warp. Dropping temporal reduced but didn't remove it → interlock, not degradation.
- Since `332f3193`: `blssClashes()` + `blssInterlock()` in `src/templates.cpp` emit `#error` into the generated `inc/scene_data.hpp` naming feature and scene; `generate()` prints the same. Conditions mirror the game: DoF per scene AND the `Set Depth Of Field` node, portals only when **linked**, split view only with a **second `Player`**, extrapolation when the preference is on and a scene resolves BLSS on. Preferences dialog and *Scene > Scene Preferences* ask live. Per scene: a portal refuses only its scene.
- Env maps, camera feeds, projected shadows nest now (not on the list). HUD/2D/post-fx draw at full res after the composite.

## Nets, corpora, evaluation
- Out-of-distribution numbers: `tyrax-editor --blss-eval --cv` (leave-one-shot-out), never a single split (the ±0.4 dB blamed on seed was which shot was held out; per-seed fold-mean sd 0.04 vs 0.35 fold to fold). Built-in corpus: **+0.42 dB over bilinear**, 39 fold-runs, 3 below bilinear, 1.80 mean passes, at jitter ON.
- Bestiary-only net is a lottery: −0.34 dB average, **−1.09 dB worst** over seven projects (`texDetail` zero on five). Bestiary + real projects (`--blss-train <a> <b> bestiary --all-shots`) scores +0.29 dB leave-one-**project**-out vs a project's own net +0.31 (fold sds 0.37/0.34), measured with `--blss-eval <a> <b> bestiary --cv --cv-groups`. `--blss-train <projectDir>` reaches +0.41 dB in distribution; the BLSS window defaults to that. docs/neural-upscaler.md "Can one net ship for every project?".
- `--threads N` (0 = all cores, clamp 32) moves only wall clock: same seed → byte-identical `blss.net` at any thread count and matches the pre-parallel binary. Check: `--threads 1` vs all cores, `md5sum`.
- The corpus RENDERER draws no emitters → PSNR for billboard-heavy scenes describes a frame the game never shows (docs/backlog.md).
