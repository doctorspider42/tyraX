# tyra-editor-dev — code generation and generated-file ownership

From upstream `codegen-and-generated-files.md`. The refresh-list *gate* and its
traps are in `tyra-editor-dev-chain.md`; this file is the catalogue.

## Where codegen lives
- `templates::generate(Project)` (`templates.cpp`, ~34.9k lines) returns
  `vector<File>` (relativePath + content): scene tables, game sources, flow-graph
  compilation, Makefile/compose, `.vscode/c_cpp_properties.json`,
  `.vscode/extensions.json` (recommends `tools/vscode-tyrax`),
  `THIRD-PARTY-NOTICES.txt`.
- `src/game_templates.inc` (~27.6k lines) is split into the shared runtime header
  `TPL_GAME_RUNTIME_HPP`, the two main heads `TPL_GAME_MAIN_ORBIT` /
  `TPL_GAME_MAIN_FPP`, and five shared subsystem bodies `TPL_GAME_SCENE` /
  `_LIGHTING` / `_COLLISION` / `_VEHICLES` / `_PHYSICS` (the split is for parallel
  compilation, not by topic). The game header is two copies in templates.cpp:
  `TPL_GAME_HPP_ORBIT` and `TPL_GAME_HPP_FPP` - a struct member goes in BOTH.
- Generated project layout: `src/terrain_game.cpp` (marker-owned main) +
  `src/gen/game_{scene,lighting,collision,vehicles,physics}.gen.cpp` +
  `inc/game_runtime.gen.hpp`. A loop-level fix usually has two homes (ORBIT/FPP).
- Shared helpers use named namespaces; mutable cache is C++17 `inline`; generated
  table arrays have shared identity (`inline constexpr` / `inline const`) and are
  runtime read-only (not `constexpr`), while `OCCLUSION_CULLING` stays
  `constexpr`. Use `SCENE_OBJECT_COUNTS[scene]`, never `sizeof`/`std::size` on an
  unsized array. Keep preprocessing guards on moved methods (incl. the road
  oracle). `presentExtrapolatedFrame` is a behavior switch that lands in ownable
  sources (two heads + two header declarations) so owned projects never get it.

## Scene object data TU
- Authored object values (incl. baked scroller clones and empty-scene placeholder
  rows), counts / identity hashes and conservative visibility proxies are defined
  once in `src/gen/scene_objects.gen.cpp`; `inc/scene_data.hpp` exports unsized
  `extern const` arrays + an extern count table. Moves/colours/add/remove change
  only the data TU. Preserve byte-identical writes and the row emitter; no
  dynamic initialization; do not change layout/index order.

## `project::refreshGenerated()` (`project.cpp`)
Runs at the start of every build (and `--refresh-gen`). Per file:
- **Always overwritten** (`// Generated by TyraX. Do not edit - regenerated on
  every build.`): an EXPLICIT path list - `Makefile`, `docker-compose.yml`,
  `src/main.cpp`, `inc/terrain_config.hpp`, `inc/scene_data.hpp`,
  `src/gen/scene_objects.gen.cpp`, `inc/game_runtime.gen.hpp`, the five game
  shards, `.vscode/c_cpp_properties.json`, every devkit runtime,
  `inc/blss_net.gen.hpp`, `src/gen/blss_interlock.gen.cpp`, `inc/daynight.gen.hpp`,
  `inc/vehicle_sound_loops.gen.txt`, plus `isVuGenerated()` VU outputs.
- **User-ownable**: `src/terrain_game.cpp`, `inc/terrain_game.hpp`,
  `inc/controls.hpp`, `inc/scripts/script.hpp`, `inc/scripts/flow_nodes.hpp`.
- **Written if missing**: `THIRD-PARTY-NOTICES.txt`, `run.ps1`, `run.sh`,
  `windows-pcsx2.ps1`, `.gitignore`, `bin/.gitignore`, `obj/.gitignore`,
  `.gitattributes`, `COLLABORATION.md`.
- **Merged**: `.vscode/extensions.json` via `templates::vscodeExtensionsMerged`.
- A conditionally emitted file is DELETED when it stops applying (e.g.
  `blss_interlock.gen.cpp`; menu state/list/description textures). `.gen.hpp` /
  `.gen.cpp` for new generated files. `writeFile` compares bytes first
  (`ofstream` raw writes once gave `res/save/list.icn` a fresh mtime every build).
  `TPL_GITIGNORE` spells `/.res-baked/*` + `!/.res-baked/gi/`;
  `TPL_RES_GITIGNORE` covers new projects and the append-if-missing block fixes
  existing ones (`/models/*.tmdl`, `/credits/pages/`, `/save/`).
- Output stays `git diff --check` clean. `examples/script-demo/` is a checked-in
  generated project. Byte-identical regeneration is the compatibility test (build
  the previous binary into the SAME directory; `c_cpp_properties.json` and
  `docker-compose.yml` embed the vendor path).

## Data-file twins (custom content loaded by `project::load`)
- `flownode.cpp`: `<project>/flow-nodes/*.flownode` -> `customFlowNodes()`
  (`flownode::loadForProject`, before graphs are parsed). Manifest: title/category/
  params, `in`/`out` pins, `exec_out`, `call`; behavior is an inline C++ snippet or
  `call = fn`. `writeExample` scaffolds the starter.
- `screenfx.cpp/.hpp`: `<project>/screen-effects/*.screenfx` ->
  `customScreenEffects()` (before placements). Manifest (title + up to four numeric
  params) + raw GS-blit C++ body; referenced via `ScreenFxPlacement` (key + stack
  `layer` + `enabled` + params), codegen'd to `src/gen/screen_fx.gen.cpp`
  (`screenFxSource`/`screenFxHeader`), run via `RendererCore::applyCustomPostFx`.
- Header keys / `{placeholder}` / `{pN}` of both formats are mirrored in the VS
  Code extension's `SPEC` (`tools/vscode-tyrax/extension.js`) and grammar; a
  `tools/vscode-tyrax` change is not done until the `.vsix` is repackaged.
- `ai-support/`: update in the SAME commit as a format/flow/menu/CLI change.

## Subsystem TPL identifiers (upstream)
- The five shared bodies are named `TPL_GAME_SCENE`, `TPL_GAME_LIGHTING`, `TPL_GAME_COLLISION`, `TPL_GAME_VEHICLES`, `TPL_GAME_PHYSICS` (e.g. `updatePlayerWalker` and `buildStaticBatchList` sit in `TPL_GAME_COLLISION`, `renderScene` in `TPL_GAME_PHYSICS`); the shared runtime header is `TPL_GAME_RUNTIME_HPP`.
