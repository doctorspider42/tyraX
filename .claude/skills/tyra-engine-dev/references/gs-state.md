# GS register state traps, and how to debug a GS pass you cannot see

Read when: you write any GS register (CLAMP, ALPHA, TEST, FBA, DIMX/DTHE, TEXA, COLCLAMP, ZBUF, FRAME, XYOFFSET, PMODE), build GIF tags/A+D packets, add a full-screen or render-to-texture pass, or chase a console-only picture fault. Golden rule: **PCSX2 hides most of this class** (no dithering of counts, no flicker-filter alpha, no EE cache, 76x under-reported fill); judge correctness on PCSX2's SOFTWARE renderer and confirm GS-state work on hardware with `--capture-frame` (tyra-testing).

## GIF packets
- **NLOOP must equal the register writes exactly.** Undercount: the stray qword parses as a giftag with garbage NLOOP → GIF stalls forever; game hangs on the loading screen in `draw_wait_finish()` / a FINISH that never arrives; no assert, clean log. Overcount is equally fatal (warp restore claimed 4, wrote 3). Count qwords after every `PACK_GIFTAG` edit.
- **REGLIST is not a generic replacement for PACKED A+D**: selectors are 4 bits; TEST, TEX1, ALPHA aren't selectable (TEX0 is). A 2026-09-21 `cull_tc` spike combined four A+D payloads behind one four-loop PACKED tag (header 9 → 6 QW, program 345 → 342 instructions): PCSX2 fine, **physical PS2 stalled on the first gameplay frame** → reverted. A retry starts with a minimal hardware-first FINISH harness. Resizing the static `packet2_t` for added uploads: two CNT/data pairs + END = 5 QW, not 3.
- **Reuse complete GS state; don't compact tag syntax.** Accepted path keeps all state GIFtags one-loop, emits TEST/TEX1/TEX0/ALPHA on package zero of a material bag, later cull/as_is TC/TD packages emit only PRIM. Bit 15 of their non-clip count word carries the choice (clip programs can't: bits 10..15 = plane mask). Reset at every bag/material boundary. Physical garage saved 1 864–1 984 GS QW/frame but only 0.04–0.20 ms — cleanup, not evidence GS state was the bottleneck.

## Texture wrap (CLAMP) — REPEAT is a per-frame contract
- `GS_REG_CLAMP` is global; nothing in the static/dynamic 3D pipelines emits it per mesh (no micro memory to carry it in-band like ALPHA). ps2sdk `draw_setup_environment()` ends with "Setup whole texture clamping" (CLAMP/CLAMP at init) → every 3D mesh used to sample clamped. Harmless for 0..1 STs; ruinous for terrain (STs = world pos × tile factor): ground drawn once at origin, edge texels stretched along world axes — streaks converging on the vanishing point, worst at grazing angles; reported as a mipmapping/upscaler bug.
- `Path3::clearScreen` writes REPEAT into the PATH3 packet that always precedes the frame's 3D pass (no extra transfer); `initDrawingEnvironment` writes it right after `draw_setup_environment`.
- **Diagnostic in one boot**: swap the ground texture for four saturated quadrant colours with a black border — REPEAT tiles them; clamp shows one tile at origin and border colour elsewhere. Don't reason from a photo of soft ground.
- **Per-bag clamp** (render targets: camera feeds, raytraced mirror — edge rows must not bilinear-wrap): since 1.126.3 written **in the bag's own chain** (`StaPipQBufferRenderer::setBagWrap`: `FLUSH` + `DIRECT` A+D `CLAMP_1` ahead of the bag's uniforms), never by draining. `RendererCoreGS::currentTextureWrap` follows when the packet is SUBMITTED (a culled bag's unsent packet is discarded with its write). PATH3 drawers relying on wrap must `align3D()` first (a queued write then lands before). History: drain-write-restore per bag → lazy drain in 1.123.1 (`Light_pools` 1.605 → 1.342 ms) → in-chain (old lazy drain cost 1.28 ms EE in garage night). Ordinary meshes pay one pointer compare.
- **Contract closers** (anything new that draws after the 3D pass joins this list): the next bag wanting another wrap; `Renderer2D`'s first sprite (inside the once-a-frame `drained3DFor2D` handling); `RendererCore::endFrame` right before `applyPostFx` (also before `RendererCoreAlphaMask`, which relies on it). The cache is legal only because other `GS_REG_CLAMP` writers (post-fx, warp, BLSS, alpha mask, frame profiler) run after the last 3D bag and `Path3::clearScreen` re-asserts REPEAT.
- STs that leave 0..1 for geometric reasons: clamp them where BUILT, on the EE (receiver patch STs -0.38..1.39 sampled the silhouette twice → dark streaks; `GS_SET_CLAMP` from the shadow pass "did nothing" because the pass never drained PATH1).

## Alpha, test, dither
- **`ATEST_KEEP_*` names what is PRESERVED** (`ps2sdk/ee/include/draw_tests.h`): `ATEST_KEEP_ZBUFFER` = 1 = FB_ONLY (colour written), `ATEST_KEEP_FRAMEBUFFER` = 2 = ZB_ONLY (z written), `ATEST_KEEP_ALL` = 0 = nothing. Upstream used `KEEP_FRAMEBUFFER` on the standard path → transparent cutout texels stamped z: foliage/grates/decals occluded later geometry, cut along the quad's straight edges. Cutout wants `ATEST_KEEP_ALL` (both pipelines); `PipelineZTest_TestOnly` deliberately keeps FB_ONLY.
- **ps2sdk `draw_setup_environment` programs `FBA = 1` for a 16-bit frame PSM** (`libdraw.a`: register `0x4A + context` gets `(psm & ~8) == 2`) → forces alpha MSB to 1, kills destination-alpha reads (torch `TEST.DATE` mask read SHADOW everywhere). `initDrawingEnvironment` writes `FBA = 0` after it; `RendererCoreAlphaMask::begin()`/`maskClear()` re-assert per frame.
- **DIMX entries are SIGNED 3-bit (-4..3)**; ps2sdk `GS_SET_DIMX` masks each with `0x03` (negative half collapses, one-sided dither) → `renderer_core_gs.cpp` packs the qword by hand. Keep entries non-negative anyway: a negative offset makes the 16-bit blender store `v - 1` when a pass adds zero (`(v << 3 + dimx) >> 3`) → every additive quad (corona, pool canvas, wall pass, particle) darkens its footprint by half a step on a console. Bayer >> 2 (0..3) since 1.70.4. Console rectangle the size of a sprite → suspect the sprite, not the pass sharing its frame.
- GS dithers only **16-bit destinations**; `DTHE` inert at 32bpp. **Never arm DTHE for PSMCT32/24** (unspecified; physical-hardware checker PCSX2 hides). Use `RendererSettings::isDitherActive()` at every DTHE restore site incl. alpha-mask brackets; `getDither()` is only the authored preference.
- **The GS dithers render-to-texture COUNTS** (`DTHE` global, on for the 16-bit picture): ±N per face got separate DIMX offsets, pairs stopped cancelling → green slivers + dark halo at 16-bit, one-pixel checkerboard at 32-bit; PCSX2 exact. Arithmetic targets bracket `DTHE = 0` (`countBegin` does; `emitRasterRestore` does NOT carry DTHE — restore yourself). Bisect with hidden `shadowVolumesDebug` 1/2/3 (docs/flashlight.md) + `--capture-frame`.
- **Interlaced flicker filter reads frame ALPHA**: ps2sdk `graph_set_framebuffer_filtered` leaves `PMODE.MMOD = 0` → the two read circuits blend by per-pixel alpha (a live channel here: shadow mask, HUD, shadow patches) → moiré/rectangles on TV only; RGB captures can't see it (`--capture-frame --alpha` can). `presentFrameBuffer` forces `MMOD = 1, ALP = 0x80` (1.70.3).
- **"Restoring" a register nothing else writes is a GUESS.** `TEXA` (and once `COLCLAMP`) are written only by the BLSS passes, which put TEXA back to the DRAWING-ENVIRONMENT value `(0x80, 0, 0x80)` (blss.md); the warp once "restored" them to a believed reset value and every later blend inherited it: `examples/showcase` (bloom + grain) hue-shifted (orange sky olive, grass orange, cyan crate magenta), geometry perfect; earlier fixtures had no post-fx. A pass that doesn't blend must not write them. Right on a bare fixture, wrong in a real scene → diff on POST FX first; check what global state a pass leaves.
- `ZBUF`: never write the mask from a full-screen pass; grep `GS_SET_ZBUF` first (blss.md).

## Raster rects and FRAME bases
- **A screen rect from projected vertices must be clamped on BOTH sides.** Count rect clamped only top-left; a vertex off the bottom → rect to row 3792, fifteen brackets a frame, FRAME.FBP slid below zero (1.70.5). Clamp to raster first, skip empty rects.
- **A slid FRAME.FBP is not something PCSX2 can vouch for.** Count band addressed its lower half with FRAME below its base (into z at 16-bit); arithmetic right, console drew marks along straight lines. Prefer full-height targets when VRAM allows; treat slides as suspect until measured on hardware.
- EE world→screen projection formula: static-pipeline.md (`px = W/2 + x/w·2048`).

## Debugging a GS pass you cannot see: one probe, one question
Found three faults in one evening (16-bit FBA regression, green count-band marks, a torch lighting no walls); every wrong turn came from a probe answering a different question. Multi-stage pipeline (build mask → resolve → gate a later pass) failing silently: make each stage VISIBLE, one build at a time:
1. **Is the CONSUMER gated?** Force the mask to its extreme (resolve paints "shadow" over its whole rect). Gated pass disappears → gate works, fault upstream. Don't force the ALPHA TEST instead (changes which fragments write, not what they write).
2. **What does the intermediate buffer hold?** Drop the write mask for one build (`FBMSK = 0`) so the resolve paints texels as COLOUR; count N = 32 shows as (32,32,32); screenshot + five-line histogram gives VALUE and SHAPE.
3. **Which inputs reached the stage?** One `TYRA_LOG` per frame-group in the generated game (take ownership of `src/terrain_game.cpp` by deleting its marker line): `recvN=2, recv[0] obj=1 sliceVerts=3999, recv[1] obj=4 sliceVerts=0` named a shared-budget bug after two hours of z-test theories.
4. **A/B the whole feature**: switch off, diff frames; "0 pixels changed" proves the pass contributes nothing.
Rules: a probe that skips a pass also skips what it restores (raster restore rides the same packet); forcing a test to pass ≠ forcing a value (with `TFX = DECAL` alpha comes from the texel via TEXA; zero texel writes zero); instrument OUTSIDE the perturbed loop, log every N frames (per-frame `TYRA_LOG` over `host:` changes timing); **revert engine probes first** — `vendor/tyra` is shared by every project on the machine and a forgotten `FBMSK = 0` looks like a new rendering bug to the next builder.
