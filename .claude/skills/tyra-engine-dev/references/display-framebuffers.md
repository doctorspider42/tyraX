# Display modes, framebuffers, colour depth, buffering, frame pacing

Read when: you touch `RendererCoreGS` (buffers, `programDisplay`, `flipBuffers`, `onVblank`, `allocateVramBuffers`), `RendererSettings` geometry/PSM, `DisplayMode`/`ColorDepth`, `setDisplayOutput`, 2D placement per mode, triple buffering, or FPS counters. VRAM allocator: textures-vram.md. Docs: docs/gs-vram.md, docs/frame-pacing.md, docs/ps2-viewport.md, docs/profiling.md.

## Modes
- **DTV (480p/1080i)**: ps2sdk `graph_set_screen` programs the full VCK width into DISPLAY.DW, and no 64-aligned width divides the 1440/1920-VCK rasters → GS scans garbage past the right edge. `RendererCoreGS::setDtvDisplay` programs DISPLAY1/2 directly. The gsKit/OPL 1080i recipe (interlaced FRAME + MagV--) **hard-crashes PCSX2 v2.3.205** (process dies after SetGsCrt); 1080i in FIELD mode with MAGV=2x is visually equivalent and works. SDTV interlaced FRAME is fine.
- **`DisplayMode::InterlacedField`**: 480i/576i with half-height 512x224 frame/z, SMODE2.FFMD=FRAME — fresh image per field, half fill/VRAM. DISPLAY window IDENTICAL to stock FIELD mode (full 448-line window; `graph_set_screen` mis-programs DY/DH here → `programDisplay` uses `setDtvDisplay`), no flicker filter. Game-facing space stays 512x448: projection built at `RendererSettings::getRenderHeightF()` (raster scale only; frustum planes from fov+aspect untouched), `RendererCore2D` halves sprite y, clears/post-fx/env-map restores use render height. **Physical framebuffer → `getRenderHeightF()`; game-facing layout → `getHeight()`** — mix them and one mode draws half off-screen. Per-field half-line alignment in `flipBuffers` (CSR.FIELD read after vsync, inverted — the frame being rendered displays one field later — then XYOFFSET +8 on odd fields appended to the flip packet).
- **`DisplayMode::Pal576i`**: 512x512 through the stock interlaced FIELD path (`programDisplay` default case, signal pinned to GRAPH_MODE_PAL, flicker filter kept; `graph_set_screen` handles it). Always 50 Hz (`getRefreshRate` special-cases it like DTV's 60). ~380 KB more VRAM (three 512-line buffers), ~1 MB left for textures.
- **Runtime switching** `RendererCore::setDisplayOutput(mode, ws)`: between frames only. Resets the VRAM allocator (`vram.reset()`), rebuilds frame/z + post-fx, `texture.evictAll()` (lazy re-upload). The ONLY caller allowed to `allocateBuffer()` after init. **Drain PATH1 and PATH3 before it resets the GS** (Hybrid double-buffer presentation may have an async copy in flight). Game scripts set `ScriptContext::requestDisplayMode` so changes apply at the boundary before `beginFrame`.
- Projection aspect: `RendererSettings::updateGeometry` (fixed 4:3-baseline look; widescreen anamorphic). **Host twin**: `App::ps2ViewportOutput` (app.cpp) resolves the same per-mode framebuffer size + aspect + flicker-filter choice for the editor's PS2 viewport (docs/ps2-viewport.md). Adding/resizing a `DisplayMode` = edit both.

## The 2D origin follows the framebuffer (`RendererCore2D::render`, `SPRITE_SPACE_HEIGHT`)
Sprite coords = framebuffer pixels, origin top-left (`drawHudText` at 16,16; menu compositor scales by `height/448`; `Renderer2D::note2dRect` hands rects to the warp as image coords). Upstream pinned vertical XYOFFSET to bare `SCREEN_CENTER` = top only for 448 rows. Measured PCSX2 `HiDef1080i` (448x540): HUD 46 rows too high (`(540 - 448) / 2`), FPS line off-screen; `Pal576i`: 32 rows. Fix centres the authored 448-row space in `getRenderHeightF()` (zero in 448-row modes). **Trap**: HALVE the space for `InterlacedField` (sprites already squeezed by `v0.y *= 0.5`; unhalved → every sprite 112 rows up). X keeps the raw constant on purpose (correct at 512 and 448 wide; symmetric "fix" pushes HUD off a 448 raster's left edge). Verify by BOOTING each mode. World-anchored sprites subtract `(getHeight() − 448) / 2` (0 stock, 32 Pal576i, 46 HiDef1080i).

## Framebuffer PSM and z (docs/gs-vram.md)
- `RendererSettings::getFrameBufferPsm()` = PSMCT32 or PSMCT16 per colour depth. **Everything writing a screen `FRAME` uses it**: `draw_setup_environment`, all of `RendererCorePostFx` (`fbPsm`/`psmFor`), env-map/shadow-map restores. Hardcoded `GS_PSM_32` decodes a 16-bit frame as garbage.
- **z FOLLOWS colour depth** (`RendererCoreDepth`): colour and z must share page geometry on hardware (64x32 pages at 32 bit, 64x64 at 16) → 16-bit colour runs `PSMZ16` with 16-bit Z scale (depth precision cost at distance; table in docs/gs-vram.md).
- 16-bit traps (`FBA = 1`, DIMX masking, DTHE inert at 32): gs-state.md.
- **Headroom uses whole page rows**: 64x32 at 32 bit, 64x64 at 16 bit, incl. Z format. A 512x224 CT16 target costs 256 KiB, not 224; rounding a pixel count to 2048 words isn't the allocator's layout.

## `ColorDepth::Hybrid`: draw 32, show 16 (1.126.0, docs/gs-vram.md "Hybrid")
`frameBuffers[0]` = only draw buffer (PSMCT32 over 32-bit z); `frameBuffers[1]` = PSMCT16 display; triple buffering adds `frameBuffers[2]` PSMCT16; only slots 1/2 rotate, slot 0 stays draw target incl. after layout rebuilds. `emitHybridPresent(target)` copies with DTHE armed only for the copy, restores via `emitRasterRestore`.
- **No unwaited FINISH**: double-buffer blit has no `draw_finish`; triple follows the blit with `emitDrawTargetSwitch(0)` and consumes its FINISH before publishing to the vblank handler. Never queue a copy in progress. Final DTHE-restore tag must have **EOP=1** (else PATH3 stays open and starves a between-frame PATH1 FINISH → video-mode changes freeze after a double-buffer hybrid fallback).
- **Anything reading VRAM between frames `sync.align2D()` first** (double-buffer flip doesn't wait for the copy; frame capture hung).
- **`hasRealFrame()` false** → motion blur and the warp have no 32-bit previous frame and stay off.
- `getFrameBufferPsm()` = DRAW format (32); `isDitherActive()` false; display-format code asks `isHybridOutput()`. Charge/allocate the third buffer with slot 1's PSMCT16, not the draw format. With limiter off, withdraw the pending copy under interrupt masking before reusing its target; no handler may latch the target during the copy. Two-buffer hybrid on physical PS2 was EE-neutral (`work` within 0.02 ms).

## Triple buffering (docs/frame-pacing.md)
- "Does it fit" is the WRONG question → boot crash. Third buffer = 229 376 words at 512x448x32, 262 144 in Pal576i; at 512x512 three buffers + z are EXACTLY 4 MB: allocation succeeds and the NEXT fails (`Out of VRAM for post fx buffers` assert before frame one).
- `allocateVramBuffers` REFUSES unless headroom ≥ `kThirdBufferReserveWords` (98 304 = 384 KB) + `kThirdBufferMinTextureWords` (65 536 = 256 KB): everything `RendererCore::init` allocates after `gs.init` (post-fx ~12 288 words, env map + z 32 768, camera feed + z 32 768, shadow slots ~20 480) plus a usable heap. In practice an `InterlacedField` feature (full-height 32bpp modes have no room). **Any new permanent allocation in renderer init joins that reserve.**
- The BLSS low-res target was exactly that miss - now reserved up front by `setLowResTargetScale(sx, sy, withDepth)`, including the Particles-only low-res z (`blss.allocate()` runs later: configure → rebuild → allocate, so it was in neither `getHeapWords()` nor the reserve) — guard handed out the third buffer against 114 688 words about to be claimed (128 KB heap instead of 576 KB at 512x448 1x2). Subtracted explicitly now from the live raster scale, host twin `project::tripleBufferingFit` too. **The reserve = everything allocated after that line, including in a REBUILD.**

## Present path
- **The vblank handler owns `DISPFB`; the queue is lock-free on purpose.** `RendererCoreGS::onVblank` runs in interrupt context; `presentFrameBuffer` = GS privileged-register stores only (no alloc/DMA/log). Three-slot queue needs no `DIntr()`: handler acts only when `pendingBuffer >= 0`, so `flipBuffers` writes `context` FIRST and `pendingBuffer` LAST. `draw_finish` handshake BEFORE queueing (GIF in-order; FINISH proves rasterised; else half-drawn frame on screen). Paths moving buffer addresses (`reinit`, `reallocateBuffers`) call `resetDisplayQueue()` first.
- **`context ^ 1` is a two-buffer expression — it presented BLACK frames** (fixed 1.20.1, docs/frame-pacing.md "The black-frame defect"). `allocateVramBuffers()` armed `displayedBuffer = context ^ 1`; it runs again in any game re-laying the permanent region (every BLSS game via `rebuildPermanentBuffers()`); after the ~2 s banner (~120 flips) `context` could be 2 → 3, one past `frameBuffers[]`; `flipBuffers`' `3 - shown - finished` wrapped in its `u8` cast → drew and PRESENTED through `framebuffer_t`s read past the array. One frame in three fully black, **no HUD** (rules out the composite). Needed triple buffering + BLSS. Rules: "the other buffer" (`^ 1`, `1 - x`, `!context`, `side ^ 1`) is two-buffer code; a rebuild can return FEWER buffers (context clamped now); `reallocateBuffers()` must re-present (skipping `programDisplay()` skips the only `DISPFB` write). **Instrument**: boot line `GS buffers: … x3, z …, drawing into N, showing M`, once per layout (the second print of a re-laying game is the one that matters).
- **`endFrame` only throttles when it renders**: `graph_wait_vsync()` (gated by `isFrameLimitOn`, default true) then flip. A loop drawing nothing isn't paced; PCSX2 races ahead. COP0 `Count` waits (294.912 MHz) measure wall time correctly only while frames are drawn. Boot splash (`info/banner.cpp`) holds ~2 s by re-rendering in a COP0-timed loop (also needed: `beginFrame` clears). Generated games run the first `loadScene` from the loop (not `init()`) so loading progress is vsync-paced.
- **`RendererCore::setFrameYield(true)`**: `beginFrame`/`endFrame` sleep 0.5 ms each (generated game sets it from `livedbg::attached()`). Off = −1.05 ms/frame; a sleepless loop with the Live Debugger attached hung the console (SIF stuck), cause unknown (docs/backlog.md). Anything else talking to `host:` every frame may need it — test attached, on hardware, for minutes.

## FPS counters
**`Info::getFps()` used to be wrong by the video mode.** It divided hardcoded `15625.0` by one frame's delta of **EE Timer 3**, which counts H-BLNK (SCANLINES): PAL 576i 15 626 Hz (exact), 480p 31 470 Hz → printed **29.76 for a true 59.94** (every progressive project read half). Now **COP0 `Count`** (294.912 MHz, mode-independent) over a 0.5 s window, returns float; twin `getPresentedFps()` counts flips via `Info::countPresentedFrame()` in `RendererCoreGS::flipBuffers` (extrapolation presents twice per loop). **T3-derived = inherits video mode; COP0-derived = doesn't.** docs/profiling.md "The three frame rate counters".
