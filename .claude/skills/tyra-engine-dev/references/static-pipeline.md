# Static pipeline (StaPip): culling, clipping, packages, bbox caches, lights, strips

Read when: you touch `StaPipCore::render`, `StaPipBagPackager`/`StaPipBagPackagesBBox`/`StapipBagBBoxesCacher`, `CoreBBox`, `PlanesClipAlgorithm`, `StaPipClipper`, `StaPipQBuffer` fill routines, `StaPipVU1Program::getMaxVertCount`, `StaPipBag` fields (`bboxVersion`, `contentVersion`, `packageSize`, `stripped`), spot/dynamic-light selection, or EE-side world→screen projection. Docs: docs/vu1-clipping.md, docs/render-submission-attribution.md, docs/model-pipeline.md "Triangle strips", docs/bag-content-version.md.

## Hard rules
- **Never submit bags with `frustumCulling = None`** (only billboards may). Off-screen geometry wraps the GS 4096-px raster window → "objects render twice / giant smeared polygons". PCSX2 HW renderer often masks it; SW renderer and hardware show it. This was the long-standing corruption bug — not the clipper patches (all bisected; pure upstream reproduced it).
- **Nothing backface-culls** (neither VU1 nor GS; "cull" programs = frustum). Two exactly coplanar faces dither-fight (dashed dark/light bands, worse with distance). Offset double-sided faces (`addPlane` in templates.cpp / `unitPlane` in primmesh.cpp: 0.01 local units).
- **Coplanar passes over ONE vertex array must share ONE package size.** `StaPipVU1Program::getMaxVertCount` derives size from the PROGRAM CLASS: **111** untextured + per-vertex colours, **75** textured, **90** textured + single colour, **150** untextured + single colour. An object with an untextured base pass and textured companion (reflective sphere without `map_Kd`, baked lightmap, untextured terrain under layer passes) split one array at different boundaries; with `fullClipChecks` a fully-inside package divides on VU1 while a straddling one is EE-clipped and drawn `as_is` → last-bit z differences → grey wedges under reflective objects, baked shadows z-fighting the ground. Fix: `StaPipBag::packageSize` (0 = derive), set by the generated game to the **MINIMUM** over an object's passes (`pinPackageSize` in templates.cpp). Minimum is mandatory (pinning above a class's own size overflows its VU1 buffer). Also: the frustum-bbox cache keys on `(maxVertCount, vertex pointer)`, so unpinned passes recomputed each other's boxes — pinning measured **+4–6 %** (126 → 133 FPS vsync-off PCSX2). `67e2893f`'s env pass `PipelineZTest_Standard` masked this defect; keep it (still correct).
- Judge rendering on PCSX2's **software** renderer (tyra-testing).
- Upstream `PlanesClipAlgorithm::clipMargin` pushes the near plane ~10 units out; generated games override it.

## Package size ceiling: 75 is essentially it
`setDoubleBuffer` splits 22..944 into two **460-quadword** halves; `getMaxVertCount` takes 9 for the GIF tag block and divides the remaining **451** by `elementsPerVertex + reglistCount` → textured classes 451/6 = **75** (was 72 on a multiple-of-9 step; relaxed to multiple of 3 in round four — that is all the slack at this layout).
- All of VU1 data memory caps a 6-qword-per-vertex package at **81** (clip scratch gone entirely: `DBUFFER_END` ≥ 1014 vs 80 qwords of scratch); **144 wants 1 770 of 1 024 quadwords** (the double buffer is the factor of two).
- Moving the clip plane table into per-mesh constants buys exactly zero. The per-class pin costs Motor District nothing (every class derives 75: `cull_tc`/`cull_tce` per-vertex colours, `cull_td` single colour; `cull_td` + per-vertex colours would derive 63 and is unreachable — `StaPipCore::render` asserts).
- The only lever left: six qwords/vertex; measure the PACKAGE COUNT, not payload (+16 bytes/vertex moved garage-day VIF1 wait 0.067 ms). docs/render-submission-attribution.md "Round three"/"Round four" (the way to 81, −8.0 % packages).
- **Raising `maxVertCount` moves the clip buffer too; nothing clamps fan-out at runtime.** `clipPackageSize()` derives from it; a clip package + full Sutherland–Hodgman fan-out must fit one 460-qword half; overrun = silent corruption PCSX2 can't show. Worst case **7 output triangles per input triangle** — exact (convex polygon gains ≤1 vertex per plane, six planes). The constructor's `elementsPerVertex`/`reglistCount` is the SIZING BUDGET, not the layout (`clip_d` budgeted `2 + 3` but uploads two streams and stores two qwords per emitted vertex) — read layout off the `.vclpp`. This took `clipDivisor` (`StaPipCore::clipDivisor()`) 5 → 6 at 75 (at 5 untextured single-colour landed on 459 of 460). The per-class check script lived in `examples/vehicle-playground/authoring/package-ceiling-75-2026-09-16` — **removed in 3e7b0f67a** (`git show 3e7b0f67a^:examples/vehicle-playground/authoring/package-ceiling-75-2026-09-16/…`).

## Classification
- History: 98k-vertex benchmark 12 → 50 FPS (EE-clipper outcode early-out, static pools, exact per-package classification). Packager's per-submit `new[]`/`delete[]` pooled (grow-only vectors in `StaPipBagPackager`; callers must not free) — worth ~2 % of the partial branch in PCSX2; real cost of partial geometry = per-package bbox classification + EE clipping, scaling with vertex count (a detail-16 box near the camera = 9.2k verts = ~36 ms EE; fix was authoring-side detail).
- Rebuild: planes transformed into bag object space once per bag (`CoreBBox::computeObjectSpacePlanes`); each package/subpackage tested p-vertex/n-vertex on min/max corners (`CoreBBox::frustumCheckAABB`); no per-package corner transforms, no merged 8-corner boxes, `clipFrustumCheck`'s duplicate zero-guard-band re-check gone; VU0 `vmini`/`vmax` scan in `CoreBBox(const Vec4*, count)`; `memcpy` fills in `StaPipQBuffer::fillByCopy*`. 47 → 73 FPS vsync-off 98k, pixel-identical; VU1 clipping 120 FPS there.
- **AABB invariant**: every CoreBBox the packager sees has `vertices[0]`/`vertices[7]` as min/max; only the matrix-transform constructor breaks that and must never feed the AABB test.
- **Per-package rejection pays for itself**: buys 2.60 ms, the whole `checkFrustum` bracket costs 1.79 ms (garage day, `work`; 1.09 of the 2.60 is VIF1 wait). Any redesign keeps an equivalent test; 1.79 ms caps what cheaper classification can save.
- **Coarser classification is a net LOSS, don't reopen**: one classification per eight-package coarse group measured **+4.59 ms** with fewer triangles than accept-all (coarser boxes cross more planes → whole groups take the expensive CLIP route; `packet` +1.08 ms, flushes +26).
- A "1/3-bbox part" is a third of a PACKAGE (`StaPipBagPackagesBBox` splits into `maxVertCount / 3`-vertex parts); per-part classification = three tests where there is one, nothing amortises. The amortising level exists: one box per 24 parts = 8 packages, short-circuiting wholly-in/out groups.
- Coarse AABBs: eight full packages (24 thirds), follow `bboxVersion` rebuilds, only inherit whole-IN/OUT; partial groups keep exact child/guard-band tests. Package-bbox cache: fixed 256-bucket hash over buffer id + VU package capacity; buckets/collision links store vector INDICES (relocation-safe, hits allocate nothing, index rebuilt only when expiry compacts); 1 024 bytes + 4 bytes/entry on the EE. Keep `bboxVersion`, vertex count, capacity and the 250-frame unused-lifetime checks.
- Wholly visible bags skip redundant classification and (1.86.3) point each qbuffer at the bag's contiguous source range (no pooled package descriptors); partial and EE-clip paths still use packages + writable copy pools. Aster: hardware-neutral (Total 34.349 → 34.342, Objects 25.051 → 24.951 ms) over >3360 frames — "removed work", not an FPS gain.
- A probe forcing `IN_FRUSTUM` without the test is CORRUPT (near-plane geometry to cull programs, which don't clip). Map only `OUTSIDE_FRUSTUM`; cover the coarse test too.

## Guard band: `PARTIALLY_IN_FRUSTUM` ≠ "needs clipping" (worth 2.2 ms)
Packages classify against the VIEW frustum (screen edge); VU1 cuts against near/far and an X/Y band at `VU1_CLIP_XY_BAND` (0.9) of w. Projection divides by `projectionScale` 4096 → screen edge at `width/4096` of w (**0.125** at 512 px); the band is ~7× that (a triangle may hang ~1590 px past an edge; the GS scissor crops during DDA, unseen pixels cost no fill). `StaPipBagPackage::guardBandOnly` (packager) / `StaPipCore::isGuardBandOnly` route such packages to **cull**, whole and by pointer (they used to be split into thirds, memcpy'd and run through S-H with an empty mask). `examples/large-terrain`, 2922 paired frames: clip-routed packages 11 164 → 2 127 per 50 frames, flushes 1 287 → 756, work 6.887 → 4.670 ms (**1.475x**, CI [-2.258, -2.175]); picture unchanged (A/B byte-identical over four poses; two boots of the SAME build were not — chunk streaming is the noise floor, always capture a same-build control). ~7 % more triangles in 54 % fewer packages (cost is per PACKAGE).
- **Eight planes**: cull programs' `fcand 0x3FFFF` covers all six clip flags of three vertices incl. z vs ±w, while the guard band's near constant is looser (`clipMargin`) → a thin shell where the clipper draws what cull would ADC away (hole at point-blank). `computeClipObjectSpacePlanes` builds the six VU planes PLUS exact near (`z <= w`) / far (`z >= -w`) at indices 6..7 — EE-only, never uploaded; `clipPlaneMask` masked to six bits before VU1. New plane → decide which side of that line first.
- **Active-plane mask**: don't derive it from `FrustumPlanes` (clipper uses actual MVP + `clipMargin`; env-map passes widen the frustum on purpose). `StaPipBagPackager` transforms the six VU clip half-spaces into object space once per mesh, tests partial package AABBs against them. Bits travel through qbuffer ORs in bits 10..15 of the clip-only 16-bit count header (bits 0..9 = vertex count). Zero mask must fail safe to all six (manually built clip qbuffers). VU program reverses bits so each `ibltz` consumes the next plane from the VI sign bit.
- **EE world→screen is `px = W/2 + x/w·2048`, `py = H/2 + y/w·2048`** — never `(x/w·0.5+0.5)·W`, never a second y flip (matrix carries GS downward y in `data[5] = -h`; `Renderer3DUtility::convertVertices`, shadow-map STs all ADD `2048·y/w`). Made twice: flashlight count-rect scissor (NDC form, sliced mesh shadows flat until 1.65.0) and god-rays/lens-flare sun (`updateSunFx`, NDC + extra flip until 1.65.1: disc drawn at (410,127) of 512×512 reported at (275,272)). 2D sprites are a different space (display-framebuffers.md).

## bbox cache and version stamps
- Keyed by the **vertex-buffer pointer**, not the bag (`StapipBagBBoxesCacher` `id = reinterpret_cast<u32>(bag->vertices)`): bags sharing an array share an entry; a bag swapped between arrays gets two.
- Geometry changing at runtime must bump `bboxVersion`, or culling uses stale boxes.
- **Do NOT bump when the buffer didn't change**: disables two caches (package boxes recomputed in `bounds`; retained command blocks rebuilt in `dispatch` — `bboxVersion` is in that key). docs/wheel-rebake-skip.md. Sticky stamp valid only while buffer ADDRESS and LENGTH are unchanged (cacher stores no count); retained key has no bag pointer (one bag across several buffers fine; one buffer across several contents not). Attribution example: 0.618 ms was 10.5 `recalculate()` calls/frame forced by a caller bumping every frame.
- **`contentVersion`** for arrays REWRITTEN IN PLACE (re-shaded colours): the baked VIF stream inlines payload, so a re-shade goes stale where a move doesn't. Generated games own it structurally via `BagArray<T>` (`data()` const; mutation API stamps it; `tools/bag-array-enforcement.sh`). docs/bag-content-version.md, submission-dma.md.
- **Count variants** (2026-09-28 night-entry): Ravager/Pica base and coat bags share pointer + package size with different counts → four fresh package-bbox replacements/frame, ~2.9 ms EE. Now a bounded two-count-variant cache: third count replaces the least-recently-touched variant; expiry 250 frames; keep version-in-place invalidation and the bound (dynamic particle counts must not grow entries for 250 frames). Physical PS2: 52 273 comparisons, zero mismatches; deep-counter-off same-ELF work 23.933–23.995 → 21.372 ms (still above PAL budget). Raster and dynamic-light suppression were diagnostic probes, not shipped cuts. (Report `examples/vehicle-playground/authoring/night-entry-hardware-2026-09-28/fix/README.md` removed in 3e7b0f67a; docs/ee-submission-rearchitecture.md, docs/backlog.md.)

## Lights
- One dynamic-light slot per bag (engine-additions.md for the pick and its three levers).
- **A selected light need not contribute** (1.150.2): `stapip_spot_bounds.hpp` checks the existing local AABB against exact `StaPipClipperSpot` constants after selection/transform; conservative interval expansion keeps boundary cases; unknown bounds, billboards and custom overrides stay lit. `setBagLight(light, bounds)` borrows bounds only for immediate uniform prep, never DMA. Don't use the picker's approximate world sphere to switch off a shader (object-space range matters, esp. nonuniform models). A full transformed-light cache was rejected: 65/65 warm hits still went 21.196 → 21.436 ms and held 24 KiB — a hit rate proves reuse, not an EE saving. (Report `…/night-entry-hardware-2026-09-28/lighting/README.md` removed in 3e7b0f67a; docs/flashlight.md.)
- `sendObjectData` (1.78, 2026-09-27 A/B): omits the three spot quads when the light is inactive and the shared clip block unless the bag can enter a VU1 clip program (program overrides keep both; direct calls default to the old clip upload). Mode 24 saved 0.04..0.13 ms `work`. Retaining copies of each bag's uniform groups added 0.30..0.80 ms — rejected (docs/ee-submission-rearchitecture.md "Round six").
- Spot cone sizing and the VU-side gate: vu1-microprograms.md.

## Transform reuse
`StaPipCore` frame-local last-transform cache for consecutive TyraMVP material bags: reuses MVP + object-space frustum planes only when model pointer, model-matrix contents and view-projection contents all match (content key required: physics mutates matrices in place; portal/split passes switch cameras). `onFrameEnd()` invalidates; TyraMP bypasses. Aster PCSX2 (portal/mirror-free): Total 21.322 → 19.172, Objects 14.102 → 12.425 ms over six alternating boots, but attributed Prepare only 1.375 → 1.341 — directional until measured on hardware (docs/performance-transform-reuse.md).

## Triangle strips (1.95.0)
`StaPipBag::stripped` = `vertices` is a TRIANGLE STRIP. **Zero VU1 instructions** (cull programs' per-vertex ADC over the last three `clipw` IS the triangle a strip vertex kicks).
- GS primitive is per BUFFER: `StaPipQBuffer::stripped` → `PRIM_TRIANGLE_STRIP` in `StaPipVU1Program::addStandardBufferDataToPacket` on a COPY of the shared `prim_t` (a stripped bag's clip packages travel as lists in the same flush).
- **Runs ARE packages**: bake chops strips into independent runs of exactly `packageSize` vertices (`meshstrip::kRun` = **75** — was 72 before the round-four rounding change; the smallest size any static class derives) and the submitter pins `packageSize`. No runtime two-vertex overlap; every run a multiple of 3, padded with a repeat of the last vertex. Consumers guard (`stripRun <= minPackageSize()` else fall back to a list), so old `.tmdl`s stay correct, slower.
- `renderStrippedPkgs` is a separate route; stripped bags never reach `renderSubpkgs` (1/3 subpackages aren't strips; `fillByCopyMax`/`fillByCopy1By2` would fuse two).
- A package genuinely crossing a clip plane is expanded to a LIST on the EE (`StaPipQBuffer::fillByStripExpand`, into the double-buffered pool); **odd primitives swap their first two vertices** (else inside-out odd triangles → giant textured wedges at the near plane). Then clipped as before (`clip_*` and EE clipper unchanged), chunked at a list subpackage's triangle budget. Garage day: fired 0 times; inside a building 29.5 packages/frame.
- Anything walking TRIANGLES reads the run length: generated game `GeoPart::stripRun` — the three flashlight receiver passes and the portal exit clipper step one vertex inside a run and skip triples spanning runs; the portal clipper's output is a list (clears `stripped` + pin on its cached bag). Vertex walkers (shading bake, env normals, `renderAtFloor` y-clamp, coarse AABB) need nothing.
- Telemetry: `packagesStrip`, `packagesStripExpanded`, `verticesSubmitted`. **Triangle counts aren't comparable across representations** (`triangles*` = GS primitives incl. degenerate joins/padding; one surface 25 650 as list vs 38 427 as strips, a real 1.498x with 11.3 % fewer vertices) — compare `verticesSubmitted`, or producers' `ROADSTRIP`/`TERRAINSTRIP` lines in `bin/log.txt` (degenerates dropped). Both strip-counting bugs are FIXED in `stapip_core.cpp`: `recordGuardBandPackage` now uses `recordPackage`'s rule (guard had averaged 21.5 tri/package vs cull's 37.9 from size/3 vs size−2), and `recordOutsideBag` charges `packages * (runLength - 2)` (was `count - 2`, over-counting by `2 * (packages - 1)`).

## Generated game grids (1.96.0)
Roads/terrain strip too (93 150 road vertices vs 13 176 in all district models). Not via `meshstrip` (a ribbon's/heightfield's rows ARE the strip; `buildRoads` tessellates on the EE at scene load, no budget for weld hash + six-orientation walk). Same run contract (run = `meshstrip::kRun`, static_assert in `roadgen.cpp`; multiples of 3, padded tails, two-vertex joins, `stripped` + `packageSize` pinned — roads in `procFinishChunks`, terrain via `pinPackageSize(pins, stripRun)`).
- Strip along the grid's LONG axis — for roads it changes: dense span = row of lateral cells (strip ACROSS); a span the planar reduction COLLAPSED = one full-width quad (strip ALONG). Laterally a collapsed span is 4 + 2-vertex join vs list's 6 — break-even with 3× GS primitives, two thirds degenerate (measured).
- Interleaving picks which DIAGONAL splits each quad; only one reproduces the list stitch's cut (invisible in counts, obvious on a crest).
- Terrain strips only with a terrain MATERIAL: untextured fallback = two-green checker belonging to the QUAD; a strip vertex belongs to two → flattens it. Height, shade, ST, splat weight, geomipmap edge snap are per grid coordinate and share; `emisCols` reads the same per-quad base, same gate.
