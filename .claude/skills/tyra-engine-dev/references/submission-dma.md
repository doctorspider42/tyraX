Docs: docs/ee-submission-rearchitecture.md, docs/retained-static-commands.md, docs/baked-vif-stream.md, docs/baked-stream-acceptance-gate.md, docs/static-submission-batching.md, docs/vu1-and-dma-cache-cost.md, docs/vu1-clipping.md "Real hardware: the slot-pool race".

## The REF rule (the root of most of this file)
- Vertex arrays go **by reference**: `ref`/`refs`/`refe` tags whose `qwc` counts quadwords at ANOTHER address; the tag is ONE quadword. Chain walkers advance 1 for those, `1 + qwc` only for inline `cnt`/`next`. Anything wanting the geometry dereferences on the EE while addresses are live.
- **`packet2_utils_vu_add_unpack_data` does NOT copy** — ps2sdk emits a REF to your pointer. Never pass a temporary/local array to async submission. SH (1.74.1) did this for mode-adjusted colours → lighting flashes despite passing VU arithmetic tests. Both lighting senders now use CNT/UNPACK with inline colour floats (+4 packet qwords, same VU layout). DynPip waits before resetting its reusable packet (uniform capacity 24 qwords); StaPip keeps inline values in its double-buffered combined packet and doesn't reuse a side until the intervening submission completed. StaPip packet: 185 qwords/side before 1.93 (57 uniforms/barrier + 128 for one 16-group half), **784 qwords/side** since 1.93.
- **The renderer's OWN copies are REF'd too — slot pool is double-buffered (1.81.1).** `fillByCopyMax`/`fillByCopy1By2` merge small in-frustum packages into a per-slot pool (both clipping modes); `fillByCopy1By3`/`writeChunk` copy for the EE clipper; REFs point at the pool; `flushBuffers()` reset slot indices on SEND → next bag overwrote slot 0 while DMA read it: a lamp corona as a sliver to the screen corner in 4/24 frames (Sony vcl) up to 19/30 (openvcl — schedule moves the window); EE clipper drew screen-sized slabs. PCSX2 completes DMA before the EE continues, shows nothing. Pool has sides flipped with `context` in `sendPacket()` (`StaPipQBuffer::flipPoolSide`); the wait before send makes the written side the finished one. **Per-bag EE `dma_channel_wait` "fix" measured −4 FPS.** Also added: `FLUSHE` at the head of StaPip and DynPip uniform chains (absolute-address unpacks of MVP/OPTIONS/clip planes while the previous batch may run), and a VIF1 wait before the projected-shadow pass rewrites shared `projClamp`.
- Lessons: a hardware-only defect wants a **failure rate on a parked pose**, never one frame; **bisect with barriers** (GS FINISH per bag, VIF FLUSH per bag, VIF-stream-only FLUSH, EE wait at one site) before reading microcode (two days went into the innocent clipper assembler).
- VU1 clipping references immutable source streams like culling; legacy EE clipping still copies into writable qbuffers.

## Packet shape
- `sendObjectData` prepares uniforms without waiting for the previous mesh, at the head of the current double-buffered geometry packet; first buffer flush appends, writes one END, submits once after the ordinary VIF1 wait. A wholly culled mesh may replace the unsent packet. Never let a draw escape `render()` with pending geometry referencing stack MVP/light data; capacity ≥ worst-case uniform chain + one 16-group half.
- **ONE native packet from the start** (1.86.4): leading FLUSHE, uniform unpacks, geometry, one END. **Never fuse finished chains**: removing one chain's END and byte-appending with `packet2_add` stalled at the first gameplay frame in PCSX2 (packet2 chain/TTE contract); rewriting the END as a zero-QWC DMA NEXT to the geometry chain ran faster in PCSX2 but **froze a physical PS2** on the first gameplay frame in three boots. Native combined path ran >2100 hardware frames with a correct GS capture. Effect: removes one VIF1 kick + one EE wait per visible bag; Aster (five settled physical captures) DMA submit 3.034 → 2.029, Dispatch 16.827 → 15.544, VU1 wait 5.847 → 5.130 ms; Total stayed fill-bound ~34.3. PCSX2 alone is not acceptance here.
- Every submitted combined or geometry-only packet uses the SDK's full D-cache writeback (REF streams may point outside packet storage). Walking every REF with `SyncDCache` regressed a hardware render-cost capture ~58 → 79 ms. Measure cache policies on the EE.
- **Object data fast path** (1.127.2, `emitUnpack` in stapip_qbuffer_renderer.cpp): packet2 open/close cost ~1.4 µs/bag. Headers made once by packet2 into a scratch packet and cached per (VU address, length) — bytes stay packet2's. New block address/length → new header automatically; changing packet2 conventions → prove identity with the VIF-hash gate (docs/baked-stream-acceptance-gate.md). Cache holds 32 headers, asserts when full.
- **Retained blocks must not carry anything POSITION-dependent** (1.127.1): the buffer header's `VU1_STAPIP_EMIT_STATE_FLAG` ("send GS state again", set only when the program changed) is, so the replay re-flags it (`StaPipVU1Program::emitsStateFlag`, `kPackedCountWord`). A strip block captured mid-run replayed after an expanded clip LIST drew as a triangle list: holes in roads, per camera, in PCSX2 too (docs/roads.md "Holes in the road"). New header words depending on the previous buffer need the same.
- Bag texture wrap rides in the bag's chain (`setBagWrap`): gs-state.md.

## Bounded cross-bag batching (1.93)
`StaPipCore::beginSubmissionBatch()`/`endSubmissionBatch()` = explicit ownership scope, only around direct static bags whose vertex/ST/colour/normal streams stay alive and unchanged through the next VIF1 sync. End submits async (not a fence). Close before view changes, GS operations, render-cost drains, pipeline switches.
- One native contiguous chain; each bag keeps `FLUSHE -> inline uniforms -> geometry`; never join packets with `NEXT`/`CALL`. MVP, light matrices/directions, single colours inline only for retained bags. Excluded: partial-frustum classification, VU1/EE clipping, qbuffer copies, billboards, program overrides (no bounded qbuffer writer ABI → the eight-qword command bound can't be assumed; any installed override is a GLOBAL exclusion). `setOverride(slot, program)` doesn't require the program's self-reported name to match the slot → use the repository's cached any-override state, not a name query.
- Resident textures batch only with both wrap axes REPEAT. Texture miss/upload/update/free/eviction invokes the active StaPip mutation barrier: submit pending geometry + `align3D()` before VRAM contents/addresses change. Track already-submitted textured batches (`objectDataPending == false` ≠ GS finished sampling). Register the hook in `allocateOnUse`, clear only for the owning pipeline in `deallocateOnUse`, drain readers before clearing.
- **Bound: four direct bags of ≤ 15 VU packages each.** Large-bag experiment regressed garage submission 37.286/43.546 → 38.264/44.580 ms (packet build +~0.2 ms, VIF1 wait +~0.6). Don't restore geometry-only continuations without a new hardware hypothesis. Shipped gate saved 0.95/1.14/0.37/0.34 ms submission over four poses — not a whole-game FPS jump. `packet2_create` asserts `qwords % 4 == 0` for uncached types: keep `kWorstBagPacketSize * kSubmissionBatchSize` a multiple of 4 (`packetSize` 784).

## `Vif1Queue` (1.125.3; `renderer/core/paths/path1/vif1_queue.{hpp,cpp}`, `TYRA_VIF1_QUEUE` 1)
Up to `TYRA_VIF1_QUEUE_DEPTH` (4) packets in flight; each a complete chain ending in END; next one starts at the next submit/wait. Physical: `work` −0.50..−0.72 ms over four Motor District poses.
- **Every VIF1 user calls `Vif1Queue::drain()`, not `dma_channel_wait(DMA_CHANNEL_VIF1, 0)`** (a plain wait can return between two queued chains and start a chain under the queue). Every engine site and the generated `projClamp` barrier converted; new senders too. In the 0 arm `drain()` IS the old wait.
- **No more "the other buffer"**: `side ^ 1`, "sides 0 and 1", `!context` are bugs. Use `kPacketCount` (= depth or 2) / `kPoolSides`. `deallocateDynamicData`'s "0 or 1" pooled test freed arrays the pool still owned; the retained cache reusing that heap fed VIF1 vertex floats as tags (`Unknown VifCmd 3f` in PCSX2). A chain validator in `sendPacket` (every CNT/REF payload vs the UNPACK/DIRECT size its VIFcodes consume) found it in one boot — **rebuild that validator before debugging a VIF1 error by reading code.**
- **REF targets must stay unchanged up to three packets later**: `sendObjectData` copies MVP, light matrix/directions, single colour inline in queue mode (`kInlineUniforms`, +0.23 ms `prepare` at night). Copy pools: per-context sides; baked arenas: two-frame graveyard. A new REF target needs the same answer.
- **Lazy write-back** (`TYRA_VIF1_QUEUE_LAZY_FLUSH` 1, −0.26..−0.51 ms): `Vif1Queue::start` calls `FlushCache(0)` only for a chain submitted after the last write-back. Nothing may write a SUBMITTED chain or what it references. `start` never in an interrupt (FlushCache is a syscall); static_assert ties the flags. **Depth 8 measured worse** (+0.19..+0.41 ms, all `prepare`).
- **2D rides VIF1** (`TYRA_2D_VIF1_DIRECT` 1, 1.126.1): once VU1 is up `RendererCore2D` appends each sprite's GIF packet as `NOP` + `DIRECT` to a VIF1 chain opened by `FLUSHA` (−0.37..−0.50 ms). **Every GIF-channel (PATH3) send calls `path3Fence()` first** (`paths/path3/path3_fence.hpp`, free when no 2D pending) — else an upload overwrites a texture queued sprites sample, or CLAMP/ALPHA changes their state. An OPEN 2D chain is submitted by the next `submit()`/`drain()` (`setOpenChainCloser`); `endFrame` fences before vsync wait (no interrupt starts a queued chain while the EE sleeps).
- **2D chain state cache** (`TYRA_2D_CHAIN_FAST` 1, `RendererCore2D::renderIntoChain`): sprite writes XYOFFSET/TEX1/ALPHA/TEX0 only when different from what the open chain set; `closeChain` restores 3D XYOFFSET. Anything writing those registers mid-frame closes the chain first (`path3Fence` does).
- **`endFrame` drains the 3D queue too** (1.166.1): `path3Fence()` only drains in frames that drew a sprite; a scene with NO 2D left up to `kPacketCount - 1` chains unstarted; next frame's first submit started them AFTER present/draw-target switch/clear → last bags drew into the NEXT back buffer under its sky/terrain. Self-sustaining backlog (a submit starts ≤1 and adds 1), triggered for good by one GS-heavy frame (terrain lightmap). Opaque z-tested bags survive; blended no-z-write vanish: **baked shadow decals and blob shadows invisible in `examples/baked-shadows`**, every byte and VU1 word identical to a good frame. Found by walking a PCSX2 GS dump per draw (`pcsx2-capture.py` `GsWalker`, tyra-testing skill): the decal's 858 kicks sat after the next frame's `FRAME_1` write. **"Every byte matches but nothing shows" → look at WHEN the GS gets it.** New frame-boundary PATH3 senders go after this drain.
- **`TYRA_VIF1_QUEUE_HOLD` is a probe, never a mode** (0): collects chains until the EE first waits; `endFrame` logs VU1+GS time alone (`GPUHOLD us`). Run with `TYRA_VIF1_QUEUE_DEPTH 80` (128 threw `std::bad_alloc` on a console). `work` meaningless. GPU ≈ 40 % of the EE's time (docs/ee-submission-rearchitecture.md "The GPU-only frame").
- **Never start chains from a DMAC interrupt** (`TYRA_VIF1_QUEUE_ISR` 0): PCSX2 clean; physical PS2 under ps2link took EE exceptions at the instruction after `EIntr()` — first `ExitHandler()` (`ei` in the handler) let a nested interrupt corrupt the thread's `s0`; without it an instruction fetch at 0 with `Status.EXL` set (inside kernel interrupt dispatch). **EXL set ⇒ "in an interrupt"; EPC not updated, names the interrupted main-thread instruction** — `symbolize EPC` points at innocent code.

## Retained static command data (1.96.0, `TYRA_STAPIP_RETAINED_COMMANDS` 1)
Stops rebuilding unchanged DMA/VIF commands per frame.
- **Captured, not re-derived**: `addBuffersDataToPacket` runs the ordinary builders on a miss and memcpys the bytes OUT of the packet → byte-identical for every class, strips/lists, and game programs. Don't "simplify" into a struct describing the format (a second description that drifts).
- Copying finished tags is legal because none names its own position (CNT counts following qwords, REF is absolute, TTE VIFcodes ride the tag's upper half). `NEXT`/`CALL` are the exception; the pipeline writes neither.
- Retained storage is EE-private, NEVER DMA-referenced (REFs still name the bag's arrays) → no new DMA-lifetime exposure. Only the CULL route is retained (clip count word carries a camera-dependent plane mask; copied/merged/strip-expanded buffers point into the pool).
- **Key = every input the block encodes**: stream pointers, count, package size, `bboxVersion`, resolved VU1 program pointer, prim state, Z scale (`RendererCoreDepth::scale`, moves on display-mode switch), single-colour/strip flags. Adding to package commands → add to the key in `beginRetainedBag` in the same edit. Unconditional clears: pipeline teardown (`deallocateOnUse`) and VU1 clipping-mode switch. A recycled address with the same layout produces the same block (addresses + counts, no vertex data).
- **Clipping chain** (`addClipChain`, 15 quadwords = 52 float stores per mesh) depends only on near/far + guard band → captured once; `init()`/`setVU1Clipping()` drop it. Since 1.127.5 also kept as a plain VIF stream (`clipBlockVif`: CNT tags' DMA halves zeroed into VIF NOPs) that every bag REFs; rewritten only after `Vif1Queue::drain()` (any shared REF'd block: same rule).
- Counters: `StaPipCore::takeRetainedCommandHits/Builds/getRetainedCommandBytes` (reset on read); debug engines log `STAPIPRET` every 300 frames. PCSX2 Motor District, three boots/arm: 18 `--capture-frame` images hash to one value; garage day 27.889 → 30.769 median FPS (35.86 → 32.50 ms, **−3.36 ms**) vs 0.222 FPS control spread, 0.001 FPS repeatability; 76 % of blocks replay (`retained=772 rebuilt=246, cache=106 KB`). 8 qwords/package + no eviction measured **1.35 FPS slower** than the shipped 7-qword + bounded LRU. PCSX2 has no EE data cache → its delta is an upper bound.

## Baked VIF stream (`TYRA_STAPIP_BAKED_STREAM`, default 1 since 1.117.1)
A wholly visible static bag's per-frame VIF1 stream emitted once and replayed by ONE DMA REF. docs/baked-vif-stream.md.
- **A REF payload may contain NO DMA tags** (DMAC feeds every word to VIF1 as VIFcode): block = `STCYCL` + `UNPACK` + inline data, repeated, then `FLUSH` + `MSCAL`/`MSCNT`. (TTE chains already give VIF1 a word stream with codes/data unaligned; `packet2_utils_vu_open_unpack` + `packet2_add_float` in `sendObjectData`'s `submissionBatchCandidate` branch is the existence proof.)
- **Transcoded, never re-derived**: `bakeBlock` walks the fragment the ordinary writers produced; each tag → one header qword with the tag's two VIFcodes verbatim, preceded by two VIF `NOP`s (in FRONT — UNPACK eats following words), followed by the transferred qwords (aligned → copy, not shift). Anything not CNT/REF refuses the bake.
- **Program kick is a bake-time fact**: `addBuffersDataToPacket` picks MSCAL/MSCNT off `lastProgramName`, but `StaPipCore::render` calls `clearLastProgramName()` once per BAG, so package 0 = `MSCAL <addr>`, later = `MSCNT`; kick lives in the block and the program's micro-memory address joins the key. Stop clearing per bag → silent breakage.
- **Baked blocks ARE live DMA memory**: written once, never patched; eviction frees through a two-frame graveyard; arena hand-aligned to 16 bytes (DMA address drops low 4 bits).
- Only the DIRECT wholly-visible cull route bakes; a REF run stops at the 16-group flush boundary (moving cadence would move `packetFlushes`, pinned by the counter gate — lifting it needs the hash gate in docs/baked-stream-acceptance-gate.md; that is where a bigger saving is). `StaPipQBuffer::bakeIndex` reset by `getBuffer()` like `retainIndex` (a half flush spans several bags).
- Worth **1.287 ms garage-day `work` on hardware** (floor 0.012) — a fifth of the 5.5–6.5 ms planned; measured with no instrument in either arm. `total_ms` unchanged in garage day (saving goes into `present`, vsync rung 10.42 ms away); garage night stops juddering (43.9 averaged → flat 39.959). Only half the bags take the direct route (`dsDirectBags` 53.5 vs `dsPartialBags` 59); `prepare` RISES 0.315 ms.
- **EE pays per package**: construction 1.898 ms / 803.5 packages = **2.362 µs/package**; replaying 360 predicts 0.850, measured 0.808. Badly packed geometry (projected shadows, wheels: 22–25 tri/package vs a strip's ~70) = 16 % of packages for 7.6 % of triangles.
- **Key must cover contents → `BagArray`/`contentVersion`**: `bboxVersion` speaks about POSITIONS; in-place colour re-shades (Motor District dynamic lights) replayed stale lighting: `TYRA_STAPIP_BAKED_VERIFY` mismatched 1438 times, all colour-only, first diff on the first COLOUR qword. Retained cache is immune (REFs follow the arrays). Frozen fixtures can't see it. Moving-route verifier: 169 843 blocks, zero failures.
- Adversarial modes (required before enabling changes): `TYRA_STAPIP_BAKED_VERIFY` (rebuild + compare, no control arm, run under `--keep-routes` with traffic MOVING); `TYRA_STAPIP_BAKED_POISON` (overwrite evicted arenas immediately) + `TYRA_STAPIP_BAKED_BUDGET_QW` (default 262 144) far below need → proves DMA lifetime; poison passes at 16 384 qwords vs 1 541 KB wanted, picture byte-identical.
- Cost: every static vertex stored twice (~49 bytes/vertex textured per-vertex-colour), originals can't be freed (bbox cacher, clip route, game read them). `STAPIPBAKE` (`TYRA_STAPIP_BAKED_REPORT` 0) prints arena size + per-frame chain qwords (compiled in both arms). Shipping flip (physical PAL, 2026-09-20, 83-road-chunk carless district, three captures/arm): total 18.776 → 17.012 ms median, procedural 8.856 → 7.769; EE memory 14.3 → 15.7 MB; 187 904 non-HUD pixels identical.
- **`STAPIPMISS` names WHY a bag rebuilt** (`bbox`, `prim`, `streams`, `program`, `size`, `new`, `incomplete` + largest moved bag by vertex/package count). Garage held pose: one `bboxVersion` bump + two prim-state collisions/frame = 64 rebuilt packages (bags of 31 and 51 packages); outer road: zero. Shapes: unconditional `bboxVersion` bump (docs/wheel-rebake-skip.md); a second pass over one array thrashing the single entry per (array, package size). Keep this counter when touching the key.

## Instancing: one baked body, many MVPs (`StaPipCore::renderInstances`, 2026-10-23)
Draws N copies of one bag under N model matrices. The first visible copy goes through `renderNow` (uniforms + whole-bag replay); `replayWholeBakedBag` records the arena it REF'd, and every further copy wholly inside the guard band + exact near/far is `StaPipQBufferRenderer::appendBakedInstance`: FLUSHE, MVP inline, one REF to the SAME arena - 7 qwords, no per-package work, ~110 copies per packet, `submissionBatchBags` counted so `flushPendingPacket` sends instead of resetting.
- **Only the MVP may differ** between appended copies: no lighting bag, billboard, program override, non-REPEAT wrap; `instancing` turns off stamps (a stamp hides the arena) and the fog-box shortcut (options would be judged from one copy's box). A copy that needs clipping goes the ordinary way and does NOT disarm the run (it uploads the same options + the clip block the cull body never reads).
- **The baked cache holds ONE entry per vertex array**: buckets that shared positions and differed only in colour evicted each other every frame - 88 ordinary submits for 28 groups, `crossing 0`. Give each colour variant its own position array (generated game `ProcInstGeo`); one `bboxVersion` per array, never bumped (docs/wheel-rebake-skip.md).
- Physical PS2, 2,800 spruces on 10 ha: SCENE 8.3 ms, 209 appended / 23 ordinary per frame (14.5 ms before the per-bucket arrays). Generated-game side: docs/procedural-generation.md "Instanced".

## FlushCache and cached/uncached packets (2026-09-15/16, physical PS2)
- `dma_channel_send_packet2(p, ch, true)` = `FlushCache(0)` (syscall 100, write-back-invalidate of the whole 8 KiB D-cache) + `dma_channel_send_chain`. 131.65 submissions/garage-day frame → bracket 2.358 ms, 17.9 µs/call. Redundant flushes cost 0.61 ms for the first, 0.437 ms each further on a clean cache.
- **Suppressing the flush hangs the console** (`flush_cache = false` wedged ps2link until physical Reset). What DMA must see coherently is the PACKET (written µs before send) and qbuffer copy pools; static REF'd arrays were written at load and long evicted. Removing it needs an owner for those buffers (`P2_TYPE_UNCACHED`/`_ACCL` or hit-based write-back by address).
- Probes (`TYRA_STAPIP_PROBE_*` in `stapip_probes.hpp`, all 0, gated like `TYRA_STAPIP_ATTRIB` — `#ifndef NDEBUG` is NOT the gate): `FlushCache` worth 0.84 ms of send / 1.09 ms of work (half the prediction); **dropping it CORRUPTS the picture even with packets `P2_TYPE_UNCACHED`** and pools still flushing (1 271 of 262 144 pixels, a 14-row band at the horizon); uncached + still flushing is BYTE-IDENTICAL → the flush itself matters (another written buffer, or an ordering barrier). **Unresolved — answer before removing the flush.**
- **Uncached packets are slow: +7.55 ms** (packet2 writes floats one at a time; uncached stores don't gather).
- **`P2_TYPE_UNCACHED_ACCL` is unsafe with stock ps2sdk**: `packet2_vif_close_unpack_auto` does `lbu` byte 3 / `sb` byte 2 of the open unpack VIFcode (disassembled `libpacket2.a`), chain helpers back-patch QWC the same way; under UCAB that goes through the 128-byte write-gather buffer → corrupt VIFcode → hung VIF1. `P2_TYPE_UNCACHED` is the safe arm.
- ps2sdk has no cheap range write-back: `_SyncDCache` loops all 128 indices × both ways with `sync` around every `cache` op, then compares tags (why per-REF syncing was slower). Forking ps2sdk is allowed (AFL-2.0; `tools/toolchain/bin2s` already vendors AFL code) but it's the wrong lever: cost ∝ NUMBER of submissions, which retained/baked commands remove.
- Parked fixtures can't see stale-line bugs from per-frame rebakes writing identical bytes → re-run flush experiments with `--keep-routes`.
- Reports: `examples/vehicle-playground/authoring/ee-probes-2026-09-16/README.md` (removed in 3e7b0f67a; `git show 3e7b0f67a^:<path>`), docs/ee-submission-rearchitecture.md.
