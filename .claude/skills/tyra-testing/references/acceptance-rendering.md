# Acceptance recipes — lighting/GI, skeletal animation, impostors, triangle strips

Read when: you change animated directional GI / RGB SH lighting, skeletal animation timing/LOD, foliage/model impostors (capture, views, GPU bake, picking), or mesh stripification.

## Animated directional GI / RGB SH

- Scratch copy of `examples/probe-lighting`: `--bake-gi DIR --gpu`, build, boot PCSX2 software; walk courtyard → doorway with Remote Pad. Compare frozen poses against the old dominant-lobe path with the SAME baked table. Two pose-sharing instances near opposite side lights must keep separate directions. Check yaw + uniform scale, GI disabled / dead probes, both viewport shading modes. Signed RGB SH must keep independent coloured directions and darken back-facing normals; L2 and surface-transfer PRT are not implemented.
- Verified (Windows): GPU bake, Docker/PCSX2 software boot, fixed-pose L1 A/B with byte-identical return-to-new control, both editor shading modes, separately built GI-disabled fallback (example README records sampled coefficients; not hardware performance).
- `--vu-check` covers signed chromatic coefficients + the numeric RGB oracle; still needs a PS2 build and a software-renderer walk through `examples/probe-lighting`.
- Animation timings: enable `TYRA_SKEL_PROFILE` in `skel_instance.hpp`, rebuild, read per-instance `SKELTIME` during ordinary playback (not the frozen lighting comparison). LOD stress: three humanoids at meshLod 1.5 in a scratch copy, walk through the doorway; force all three tiers in generated code if distances don't cross each threshold. Distinguish a reproduced hang from an old unreproduced observation.
- Restoring generated C++ with `Copy-Item`: touch LastWriteTime or clean scratch objects (old timestamp → make relinks the previous instrumented object).
- Lighting DMA lifetime: temporal check (fixed pose, frame sequence excluding FPS HUD, then animate/walk); `--vu-check` validates microcode, not EE source pointers.

## Impostors (`examples/impostor-grove`; README has reproducible generators)

- `--resave` keeps `impostor`, `impostorDistance`, `impostorBillboard`; `--refresh-gen` collects both model paths; build/run a short-path copy. With *Show frame profiler* the game logs `IMPOSTOR object=... far=...` transitions and `IMPOSTOR VIEW` sector changes; walk towards/away and orbit. Frozen-camera control with every distance 0. Verify binary alpha and deterministic atlas bytes after regenerating assets. Rendering changes need a screenshot, not just the model table.
- Eight-view: frozen single-tree near/far pair + orbit; 512x256 atlas, all eight ordered parts, yaw rotation, fallback for tilted transforms.
- Host fixture C++ helpers go under `authoring/`: a root-level `.cpp` expands the Makefile's unquoted find glob → empty SOURCES → `undefined reference to main`.
- Universal capture: non-tree multi-material OBJ (grove's Waystone), Properties tab > *Distance and LOD* > *Far away* > *Billboard* > *Bake*, save/reopen, inspect assignment + alpha/Kd. Material overrides, missing textures, reflection failures: no assignment may change on failure.
- **GPU impostors**: `--bake-impostor <proj> <model.obj> <outStem> 4|8|16 [--gpu]` prints backend + time without assigning. CPU vs GPU for all counts on a cutout tree and Waystone: same dims, binary alpha, close silhouette masks, matching Kd/interior colours (GL edge coverage not byte-identical). Invalid counts fail before output. *Views* (Distance and LOD > Distant version) changes saved `impostorViews` only after a successful bake; resave an old eight-view object; boot mixed 4/8/16 in PCSX2 while orbiting. After shared bake-context changes run `--gi-gpu-check` and inspect the viewport after GPU baking (context restore bugs).
  - Verified 1.75.0 (Windows): model UI baked/saved 16 GPU views, Tree Generator 4; choosing 16 without baking kept a legacy 8. Capture oracle passed all counts (Waystone IoU 1.0, oak > 0.999); forced CPU fallback byte-identical to CPU PNG; invalid counts wrote nothing; GI shared-context oracle 0.0022% relative mean error. Mixed 4/8/16 grove booted; Remote Pad motion updated sectors without allocation failures. Higher counts cost VRAM: ~35 KiB free after moving, evictions during motion — don't call larger view counts free.
- **Selection/picking** (no PS2 rebuild): list selection shows the full model box; a viewport click hits the same model; a frozen orbit camera aimed into an empty part of the AABB tests fallback; an alpha-cutout card in front of a smaller prop must not steal the hit (opaque version wins itself); distant billboard and rotated/scaled instances. Script: aim the scratch project camera at the point, `click 'Viewport canvas'`, `key ctrl+s`, read `editor.selectedObject` in the manifest (scene rows aren't checkable widgets). Verified 1.74.1 on Windows.
- Grove ground regression: freeze Player at (48, 0, 48), heading -135, pitch -12. Floor material `-s 16 16` loses detail, `-s 0.5 0.5` restores it (PCSX2 software). Terrain material scale = repeats per world unit, not per map. Compare a fixed ground crop; a flat colour alone doesn't prove a missing binding.

## Triangle strips: host property test, then one knob in PCSX2

- `src/meshstrip.cpp` harness (`g++ -std=gnu++20 -O1 -I src -o stripcheck harness.cpp src/meshstrip.cpp`). Property: the strip draws the SAME TRIANGLES — expand (triangle i of a run = `v[i], v[i+1], v[i+2]`, never across runs), canonicalise winding (nothing backface-culls), drop degenerates, compare multisets. Invariants: every run but the last exactly `kRun` (75) vertices, run lengths multiples of 3, result smaller than the list. Inputs: grids in BOTH orientations (a 200-cell row vs column found seed order and three-vs-six seed orientations), a cube, ten cubes, a pile of disjoint triangles (must be REFUSED).
- Multiset over the attributes the BAG receives: `meshstrip::Weld::kNoNormal` welds on position + UV, so normals may differ legally (docs/model-pipeline.md "The weld key is a property of the BAG") — an all-eight-float comparison fails a correct stripper. (Worked instance against real baked wheels, `wheel-strip-2026-09-17/stripcheck-wheels.cpp`, was removed in 3e7b0f67a; `git show 3e7b0f67a^:examples/vehicle-playground/authoring/wheel-strip-2026-09-17/stripcheck-wheels.cpp`.)
- A hand-written grid strip needs a PICTURE: the quad diagonal flips unless each column pair is emitted far-corner-first (54 px of a 512x512 self-capture vs arms byte-identical over three repeats). `meshstrip` output is immune; roads, terrain and the projected-shadow receiver patch are not.
- PCSX2 arm = one knob: two editor binaries from the SAME worktree differing only in whether the bake calls `meshstrip::build`, one project dir → identical engine/assets/game except the `.tmdl`. Freeze the camera from a global script, `displayMode: progressive`, capture with `--capture-frame` (Motor District: three byte-identical captures per arm). Wheel strips also have `TYRA_STRIP_WHEELS` (generated game, default 1).
- Aim a pose at the clip path: the guard band sends most straddling packages down the cull route, so an outdoor vantage exercises strip-to-list expansion zero times (`sexp=0` in `FTCLIP`); park inside a building → thousands. Read `verts` from `FTCLIP`, not triangle counts (degenerate joins count as triangles).
- Roads/terrain strips: acceptance-vehicles-roads.md.
