# Performance, profiling and fixture hygiene for measurements

Read when: you quote a frame time / FPS, measure a performance change in PCSX2 or on a console, use the frame profiler / FRAMETIME / render-cost / hardware timeline, or build an instrumented fixture.

## Instruments

- **PCSX2 FPS overlay**, software renderer, 3+ samples. Full PAL = 50 FPS (generated showcase scenes hold it).
- **Frame profiler**: debug profile + *Project Preferences > Build & debug > Show frame profiler* → per-phase EE ms on the HUD (whole frame / scene / usable-highlight / particles).
- **GS VRAM**: debug builds print `VRAMSTAT` to `bin/log.txt` (binds/hits/uploads/re-uploads/evictions, resident, free MB, largest block) — thrashing vs heavy (docs/gs-vram.md).
- **COP0/HUD deep dive** (own the generated `terrain_game.cpp`, bracket phases with `mfc0 $9`, deterministic camera orbit, in-run A/B, engine-side counters) and the **frame-timing rig** (docs/profiling.md): engine counters behind `TYRA_FRAME_PROFILE` (`vendor/tyra/engine/inc/debug/frame_profile.hpp`, default 0), once-a-second `FRAMETIME` mean/median/p95 + raw per-frame dump for PAIRED comparison. Frames are almost always EE-bound; `endFrame` is mostly vsync idle. Rules: drive the camera from a **frame index in an object script**, not `--pad`; turn Live Link / Live Debugger / Live Logic / Remote Pad / Time Machine **off**; run the page's **GS fill calibration** before any PCSX2 GS-cost number (PCSX2 under-reports fill **76x**).
- **`TYRA_FRAME_PROFILE 2` for ABSOLUTE frame time** (1.123.8): level 1 adds the packet walker + pipeline telemetry and is not transparent (HUD SCENE 13.21 ms uninstrumented, 17.70 at 1, 13.04 at 2). Prove transparency by matching SCENE with an uninstrumented boot. Read `pre`/`stall`/`period`/`miss` as well as `work` (`work` starts at `beginFrame()`, so a frame can miss its field with `over20=0`). Level 1 = what a frame is made of; quote only its deltas. Level 1 also prints `FTCLIP` every 50 frames (package/triangle counts per clipper route, `flush`, `verts`, `out`; ÷50 per frame; total VU1 packages = `cull + clip + guard + out`). Measurement flips are identical in every arm and reverted before committing.
- **Render cost**: `--profile-frame <dir> -o report.csv` (debug game, Live Debugger on, live host server). Verify matching sequence/footer, finite phase/object values, repeated captures, CSV. UI: *Render cost / Measure render cost / Keep as baseline / Copy render cost CSV*; column headers sort, third click restores grouping. Object rows are nested inside Objects. Measurements drain the pipeline → verify ordinary FPS separately and on physical PS2. Row `Roads` = road/junction cull + submission (built once at load); `Procedural` skips owner `-3` road chunks — pre-1.117.6 CSVs lumped both under `Procedural` (sum new rows to compare). `Wheels` is a diagnostic phase, not a hardware FPS result.
- **Hardware timeline** (docs/hardware-profiler.md): `tools/hardware-trace.py arm PROJECT` before boot, export complete `bin/hardware-trace.csv` to HTML/Perfetto; or (1.92) *Debugger > Hardware timeline* (`src/hardware_timeline.cpp`, same CSV; arms next boot, frame selection, zoom, tooltips, inclusive totals; no browser/Python). Bounded RAM events, written after sampling. Scope totals overlap; VIF1 DMA wait ≠ VU1 execution; VIF/GIF snapshots ≠ utilization. Compare unarmed/armed controls; reject dropped/stale events; rank performance from unarmed controls. Debug builds: check `Live_debug_poll`/`Live_debug_flush` before blaming update spikes (unattached debugger = one boot marker, no periodic flushes; a valid command attaches it). Vehicles: `Vehicles_update`, `Vehicle_smoke_update`, `Vehicle_skids_update`; nested `Vehicle_sleep` = parked instances skipping ground/collider/suspension.

## A debug build over ps2link is NOT the player's frame (2026-09-23)

| devkit cost | cadence over ps2link | effect |
|---|---|---|
| Remote Pad polls `host:livepad.bin` | every 4th frame (every frame in PCSX2) | network round trip in `loop()` before `beginFrame()` |
| Live Debugger polls `livedbg.cmd` / writes snapshot | every 25th (6th in PCSX2) | same, rarer |
| HUD `MEM` (`showMemory`) — fixed 1.123.10 | every 2 s | `getAvailableRAM()` malloc-probed: **+31 ms**, **+75 ms** fragmented; now `mallinfo()` + `EndOfHeap() - sbrk(0)` |
| `TYRA_FRAME_PROFILE 1` | every frame | SCENE 13.21 → 17.70 ms |

Pad + debugger: day frame **26.3 ms, 15/50 missed fields; compiled out 20.4 ms, 0–1/50** (14.5–16.5 round trips per 50 frames vs 14–16 misses). MEM = the 2-second hitch (one 94 ms frame per 50 at 25 FPS; 8 spikes vs 0 paired). Debug builds were also the ones whose software reset wedged the console.

**Clean console measurement:**
1. `.tyra`: `remotePad`, `liveDebug`, `liveLink`, `liveLogic`, `timeMachine`, `inputRecorder` false (+ `showMemory` before 1.123.10). No Remote Pad = no scripted day/night toggle; plan poses.
2. `TYRA_FRAME_PROFILE 2`.
3. `--refresh-gen`, then `tools/toolchain/native-build.ps1` (or `.sh`) directly.
4. Bare `execee` after a power cycle (devkit-and-ps2link.md); read `FRAMETIME` off ps2client stdout. `pre + work + stall` = `period`; high `miss` + low `over20` = cost OUTSIDE the render. `FTUPD` splits the update half of `pre` into ten sections; large `in` = devkit host polling.
5. Transparency: same pose uninstrumented, HUD SCENE must match (13.21 vs 13.04 passes).
6. `FTRAW` = every frame's `work`. Periodic spike = a timer: equal gaps = frame-counted; gaps alternating 50/51 or 99/101 = seconds via `g_frameDt` (`everyFrames(s)`) — found the MEM probe in one read.

- **Both arms must look at the same thing**: a pad resting off-centre moved the view on one boot (car glance camera until 1.124.2, faked +2.7 ms). Compare `Loop_past_draw_count`/`Loop_past_coarse_count` first; `--capture-frame` each arm.
- `quiet-debug` profile (benchmark tooling): debug with `liveLink`, `liveDebug`, `liveLogic`, `timeMachine`, `remotePad`, `inputRecorder` off. Live tools' pollers put +3.5 to +4.4 ms outliers inside `update` (`livepad::tick`, `livedbg::tickFromLoop` `fopen` over `host:` every frame) cost 4.79 ms of `update` / 6.44 ms of `work` (control read 36.51 vs published 30.42); off, tables agreed to 0.35 ms `work`, repeatability floor **0.016 ms**. **State the profile of every frame-time table.** Sporadic multi-ms `update` outliers = host-I/O contention. quiet-debug turns Live Debugger OFF → `--capture-frame` doesn't work; for pixels flip `"liveDebug": true` in BOTH arms.
- **Adaptive BLSS hardware gate**: PCSX2 verifies codegen, forced threshold transitions and the moving-picture gate, but its software rasterizer may never cross the fill-bound threshold. On PS2 capture the same parked pose native and adaptive; log must report `Adaptive resolution: REDUCED`; capture via `--capture-frame <dir>`; compare HUD frame/scene ms. Flat scene + shorter frame = GS-fill gain. Stop the host session before the next boot.
- PCSX2 emulates no EE data cache: its ms mislead for cache-sensitive changes (label any PCSX2 delta as an upper bound); its **counts and pixels are exact**.

## Fixture hygiene (every instrumented A/B)

- **Full-asset gate**: an isolated native build is not an asset bake. A copy excluding `bin` and `.res-baked` must first materialise complete baked resources (an editor build), then instrument and use native-build directly. Before timing, compare deployed PNG/TMDL/MTL with the intended baked reference, reject missing/different, verify fresh frame IDs, inspect GS captures after the window. A Sept-14 fixture with only sfx/vehicles dirs lacked 66 PNGs + 11 TMDLs and gave falsely reassuring matching triangle counts (docs/performance-hardware-recheck.md). Empty redirected host logs or a failed ping don't prove a failed boot — check fresh telemetry.
- **Generated sources are half the gate**: a copied example carries its **committed** (drifted) `inc/*.gen.hpp`, `src/gen/`, `src/terrain_game.cpp`. vehicle-playground 2026-09-15: stale fixture showed **12.17 re-uploads/frame** and **+3.6 ms** submission vs 0.000 / 0 evictions regenerated — a whole VRAM investigation chased it. `--build`/`--refresh-gen` once before instrumenting; check counters against the last known-good run.
- **The editor binary can be older than HEAD**: `--refresh-gen` with an old exe regenerates with the OLD baker (2026-09-16: exe 15:17, VU1 ceiling commit 17:07 → seven arms with `stripRun = 72u` vs `meshstrip::kRun` 75). Capture hash doesn't catch it (strip run changes cutting, not pixels). Check baker outputs: `grep -E "ROADSTRIP|TERRAINSTRIP" <results>/host.log` (packages 470 / 588 verts, 8 pkgs at 75) and `grep -n "stripRun = 7" <fixture>/src/terrain_game.cpp`; compare exe mtime with `git log -1 --format=%ad <path>`. Build the editor from the worktree you measure (`./build.ps1` ~6 min; a wrong fixture costs a day). Shared-wrong-fixture rounds keep their DELTAS, lose absolute comparability.
- **Control arm from a stale editor = a different game**: control carried `keyL=0`/`batchStatic=0` vs candidate `keyL=3` → **-2.949 ms** reported vs honest **-1.838**, +682/+875 phantom triangles. Rebuild the editor for the control arm from the intended commit and diff the two generated `terrain_game.cpp` (only your change; `keyL=`/`batchStatic=` are canaries).
- **Hash the two ELFs before believing a null.** Swapping only `src/terrain_game.cpp` between compiles: `Copy-Item`/`cp -p`/`git checkout` keep the old mtime → make does nothing → byte-identical ELFs, every counter delta 0.0 (sources differed by 332 lines). Stamp the file, delete matching `.o` in the project AND the `-Cache` tree, hash ELFs (must differ). (`tools/instrument-frame-cost.py` rewrites the file, which is why that flow doesn't hit it.)
- **Content change where the arm is the EDITOR** (1.105): build both editors from the worktree (`./build.ps1`, copy exe aside, `git checkout <base> -- src/<changed>`, build, copy, restore), record both hashes, hold the baked asset tree constant. Copies must live INSIDE the checkout (editor finds `tools/toolchain`, `vendor/tyra` relative to itself; else "Native toolchain files are missing"); same SIZE binaries → confirm they differ by a grep of the generated output.
- A map-wide count is not a frame: road reduction removed 9 798 triangles district-wide, **614** from garage-day. Measure the slow pose.
- Turn quality criteria into numbers: terrain-burial (worst coarse-ground rise above road lift at every dense road sample) and LOD-step (worst mesh disagreement in pixels at the switch distance) scripts ran in seconds with no console (were `road-lod-2026-09-16/terrain-lod-burial.py`/`terrain-lod-step.py`; removed in 3e7b0f67a, retrievable with `git show 3e7b0f67a^:examples/vehicle-playground/authoring/road-lod-2026-09-16/<file>`).
- Night poses on the Motor District flicker (lamps, star twinkle) and never settle (differ at 6 s and 30 s): base pixel A/Bs on DAY poses (byte-identical across three captures), quote night within-arm spread as noise. Check repeats PER POSE.
- Launch PCSX2 per arm yourself (`pcsx2-qt.exe -batch -nogui -logfile <yours> -elf <abs path>`); delete `bin/livedbg.cmd` and `bin/frame.tga` before boot and between captures; run `--build --run` once beforehand so `HostFs` and `Renderer = 13` are set. (`--build --run` now closes only the PCSX2 whose `-elf` is this project's ELF, since 1.22.0 — still avoid it while another agent measures, since builds share containers/volumes.)
- Scenario overrides run after the initial scene creates vehicle instances, at the simulation boundary (a first-loop override can see an empty array and be replaced by `bootFirstScene()`). Export traffic positions/speeds; reject a "parked" control if any car moves. Select continuous driving windows by actual position, not frame count. Quality-reduction probes change FPS and thus physics substeps — compare render/finish as well as total work.
