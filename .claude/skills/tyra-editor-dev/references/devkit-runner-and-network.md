# Devkit live channels, the Runner, PCSX2/ps2link, collaboration transport

Read when you touch the build/run pipeline (`runner.cpp`, `pcsx2_config.cpp`), any devkit channel (Live Link, Live Logic, Live Debugger, time machine, Remote Pad, input recorder, texture hot reload, render-cost/hardware capture), the release audit (`elfsym`), the session log, `devsession`, or the collaboration/WebSocket transport (`session.cpp`, `wire.cpp`).

## The devkit's zero-cost rule (docs/devkit.md)

A release build carries NOTHING: (1) the generated runtime becomes an empty TU, (2) the generated header keeps the API as `inline` no-ops with compile-time-`false` predicates so call sites fold away, (3) instrumentation in `flow_graph.gen.cpp` is not emitted, (4) no static arrays. Never a runtime `if (debugEnabled)`.
- **CHECKED**: `elfsym::auditRelease` scans the ELF for `TXDEVKIT-<layer>` markers (`__attribute__((used))`; the PS2 toolchain strips symbols) and channel file names (`kStringNeedles` in elfsym.cpp), reporting text/data/bss; `--audit-release` exits 0/1; the Runner runs it after every release build. A new layer **plants its own marker**, adds its file name to `kStringNeedles`, routes instrumentation through a generated no-op header, and puts its `.cpp`/`.hpp` in `refreshGenerated`'s overwrite list (the Remote Pad runtime reached a RELEASE ELF because it was generated once at creation). Run the audit BOTH ways: against the DEBUG ELF it must FAIL naming your layer; against release it must be clean.
- **A new channel file is deleted before launch in BOTH Runner clean-up blocks** (PCSX2 path and ps2link deploy): a leftover is applied on the first poll (Remote Pad: a game walking before anyone touched it). Also files the game WRITES: `bin/frame.tga` is deleted (last session's picture is a valid answer to the first capture). That is why the Debugger keeps captures as PNGs under the project's `screenshots/`; `platform::revealInFileManager` walks up to the nearest existing ancestor (Explorer opened Documents for a missing path).
- `elfsym.cpp/.hpp` (~320+120): ELF32 reader (sections, symbols, section bytes) + `auditRelease()`; future base for named-memory reads (needs an unstripped ELF/map first).
- Devkit cadence (1.90.0): `ProjectSettings` `liveLinkPollFrames`, `liveLogicPollFrames`, `liveDebugPollFrames`, `liveDebugSnapshotFrames`, `timeMachineFrames` - each 0 (platform default) or 1..120 game updates; format 54 additive; keep model, equality, serialization, Preferences and templates in sync. Link cadence also controls texture polling. Cadence never gates graph execution, watch sampling, Remote Pad or replay input. Halted debugger commands use two loop ticks; forced reports bypass cadence; devkit_ui.cpp scales heartbeat-silence tolerance with reports/FPS.
- All channels gate on the **debug** build profile + their `ProjectSettings` switch and are ticked each frame from `drawUI` (`liveLinkTick`, `liveLogicTick`, `livedbgTick`, `livetimeTick`, `remotePadTick`, `replayTick`, `pollGameError`); each stands down on `!hasProject_`.
- `devkit_ui.cpp` (~3.8k): the host side - ticks above, Debugger window, time-machine panel, game-error modal, Remote Pad window, `uiScriptTick`, Render cost tab, Hardware timeline, and readers for what the GAME writes: `dbgReadCrashReport`, `dbgReadVuCapture`, `dbgReadFrameShot`. **"The file changed" is its TIMESTAMP, never its size** (two captures of one scene are the same length); a poll landing mid-write is committed only after a few tries (a truncated file reports instead of retrying forever). The Screen tab keeps decoded RGBA beside its GL texture so **Copy image** publishes the bitmap via `platform::copyImageToClipboard` (don't re-read the transient TGA).
- **`std::filesystem` file times are NOT system-clock times**: `file_clock`'s epoch is implementation-defined and on this libstdc++ in the FUTURE, so real files have NEGATIVE `time_since_epoch()`. Using 0 for "absent" compares NEWER than anything (the chat's game-is-up wait timed out forever). Use `LLONG_MIN`/optional for absent; for a file's age use `fs::file_time_type::clock::now()`, never the system clock.

## Live Link (`App::liveLinkTick`, docs/live-link.md)

Debug profile + `ProjectSettings::liveLink` (default on; toolbar LIVE chip, Build > Live Link, Preferences > Build). The editor streams scene edits by rewriting `bin/livelink.bin` (atomic tmp->rename; `TXLL` header - `LL_VERSION` 4 in the generated poller - + one 80-byte record per object + seq-echo footer); generated `src/gen/live_link.gen.cpp` (`templates::liveLinkScript`; empty TU in release or with the preference off) polls over `host:` (the channel PCSX2 and ps2link already serve assets through). (The comment above `liveLinkScript` in templates.cpp still describes v2/64-byte records - stale.)
- Records address objects by `project::liveLinkIdHash` (baked as `SCENE_*_OBJECT_ID_HASHES`), so renames/reorders are safe; new objects are **live-spawned** from an equal-recipe template via the spawn pool; deleted ones hidden.
- Consistency: as-built `bin/livelink.sig` (`project::liveLinkSigFile`: per-object id + `liveLinkRecipeHash` + context hash, stamped by the Runner at build start, which also deletes stale `livelink.bin`). Recipe drift / unspawnable new objects (`liveLinkCanSpawnLive`: baked lights, projecting decals, mirrors, objects with graphs/scripts) flip the chip green LIVE -> amber LIVE (rebuild) and stop writes.
- **New object property**: build-time-baked or clone-relevant fields join `liveLinkRecipeHash` (new unspawnable categories join `liveLinkCanSpawnLive`), or Live Link silently drops that edit while claiming LIVE. Streamed fields (player speed tiers via `ScriptContext::playerSpeeds`) stay OUT. `commentText` is out (nothing downstream).
- Snapshot seq is seeded from the clock at attach (a restarted editor must not reuse a seq the running game applied).
- **Texture hot reload** (`App::liveTexNotify` in mateditor_ui.cpp; poller `liveTexScript` / `live_tex.gen.cpp`) rides the same gate. **The game knows a texture by the path it was SHIPPED under**: `bakeAnimAssets` renames every texture an animated model's override `.mtl` names into a copy next to the `.tskl` (`animBakedTextureRel`: `res/materials/x.png` ships as `models/hero__ovr<hash>_x.png`). `templates::animTextureAliases` is the single reverse lookup; a paint updates AND announces every alias as one GROUP (one record matching nothing is expected; a whole group matching nothing is a failure - the poller soft-errors naming each path). Changing where a texture bakes changes `animBakedTextureRel` and both callers.

## Live Logic (`App::liveLogicTick`, docs/live-logic.md)

Debug + `ProjectSettings::liveLogic`. The editor compiles graphs itself so editing one needs no rebuild.
- `livelogic.cpp/.hpp` (~850+225): `livelogic.hpp` is the single source of the IR (`BlockKind`/`OpCode`/`CondOp`/`PosKind`, `Block`/`Instr`/`Program`, caps); **templates.cpp GENERATES the interpreter's enums and dispatch switch from it** (a missing body is a `#error`). `compile()` mirrors `flowGraphScript`'s resolution (`resolveTarget` / `posExpr` / `boolInputsOr`) but writes INDICES, linearizes exec chains into blocks (a `Delay` owns the block it arms), allocates per-node state slots. `capability()` is the honest gate (explicit node set; rejects number links and branching nodes). `graphHash()` EXCLUDES node positions. `builtListText()`/`loadBuiltList()` = `src/gen/livelogic.built` (per graph: scene + object id + hash), the "what did the ELF compile" record; only differing graphs are patched.
- Seam: one line per script, `if (livelogic::patched(scene, ownerIdx)) return;` - a graph is EITHER interpreted or compiled.
- **A new interpreted node is a twin**: opcode in `livelogic.hpp`, runtime body in `liveLogicOpBodies()` (templates.cpp), mapping in `actionMap`/`triggerMap` (livelogic.cpp); the body must behave exactly like `actionCode`'s C++. Patched graphs share everything with compiled ones (`flowInt/flowBool/flowPos` statics via generated accessors, save values, RuntimeObject state, Live Debugger node keys in each instruction).

## Live Debugger (`App::livedbgTick`, docs/live-debugger.md)

- `livedbg.cpp/.hpp` (~450+280): formats + history, host-only. `Symbols` (`src/gen/livedbg.sym`: node key -> scene + object id + node id, watch list, table hash), `Snapshot` (`bin/livedbg.bin`: cumulative hits, ring of recent fires with AGE in frames, watch values, halted flag, break key), `Command` (`bin/livedbg.cmd`: full breakpoint list, halt/step/step-until-fire, force-fire keys), `Timeline` (per-frame fire history). **Every layout has a twin in the generated runtime; caps `kMaxNodes`/`kMaxBreakpoints`/`kMaxForced`/`kMaxEvents` are read by codegen from this header.** Torn writes rejected by exact size + footer echo; commands apply only when `seq` changes (a repeated Step bumps it).
- **v4 stats block = 64 bytes**; the two frame-rate fields (tenths of fps, rendered and presented, offsets 60 and 62) landed ADDITIVELY (old editors/games read/leave zeros), so the reader treats 0 as "not reported" and falls back to the whole-number field. The block is now full: the next field is a version bump. Know WHICH rate: the header times the game's frame counter against the editor's wall clock and the Stats tab relays the game's COP0 measurement (both RENDERED frames); `presented` counts flips (about 2x under extrapolation) (docs/profiling.md, "The three frame rate counters").
- Codegen (`debugSymbols` in templates.cpp) assigns ONE KEY per instrumented node (walk scenes -> objects -> nodes); that enumeration feeds `livedbg::hit(key)` calls in `flow_graph.gen.cpp`, tables in `src/gen/live_debug.gen.cpp`, `livedbg.sym`, and the ELF hash that turns the chip amber on mismatch. Never hand-roll a second enumeration. Instrumented = triggers + actions (`!t->pure`).
- `inc/scripts/live_debug.gen.hpp` is ALWAYS emitted (the on/off seam: off -> inline no-ops, `halted()` compile-time false; the loop's `|| livedbg::halted()` folds away). The halt reuses the menu pause (`menuActive`/`menuOwnsPad`/`g_gameplayPaused`); an owned `terrain_game.cpp` loses the freeze but keeps reporting (a fallback global Script pumps it; `tickFromLoop` sets a flag permanently disabling `tickFromScript`).
- Breakpoints: `Project::debugBreakpoints` as `"<objectId>:<nodeId>"` - editor state in the `.tyra`, not a collaboration section. Watches: ONE array - flow variables via `flowDbgReadVar` (emitted beside the `flowInt/flowBool/flowPos` statics) then save values off `ScriptContext`; the sym entry's `kind` distinguishes.
- **Gate = `liveDebugEnabled` (profile + preference), NOT `liveDebugOn`** (which also demands an instrumented node and removed the whole channel - stats, VRAM, free RAM, VU capture, crash report - from graph-less projects; symptom: `[ps2]` lines arrive, panel shows nothing, no `livedbg.bin`). `NODES` can be 0: `hits[]` is sized `NODES > 0 ? NODES : 1`.
- The runtime writes its boot/liveness snapshot unconditionally; periodic snapshots start only after a valid `livedbg.cmd` proves an editor is attached - keep command polling alive (it is the attach). On a physical PS2 the old unconsumed 25-frame flush cost 7.2 ms and periodically doubled a frame. Hardware traces expose `Live_debug`, `Live_debug_poll`, `Live_debug_flush`.
- **An empty panel says why** (`App::dbgSilenceReason`, one string for the state block and Stats tab; `dbgSilenceDetail` holds the paragraph in a hover). The tick stats the FILE's age independently of snapshot arrival; a frozen-but-valid file reads STALE SNAPSHOT, not WAITING FOR THE GAME.
- **One-shot asks ride spare bits of the command flags word** (old games ignore unknown bits; no version bump): bits 0-2 transport, 3 VU capture, 4 its index, 5 free-RAM measurement, 6 screenshot, 7 render-cost capture, 8-23 flush index, 24-31 fact-override count. Editor half = four edits: the field on `livedbg::Command`, `sameStateAs`, the bit in `encodeCommand`, and the one-shot RESET in `livedbgTick`'s write block beside `captureVu`/`measureRam` (else it re-fires on every resend).
- **Self-screenshot traps** (`writeFrameCapture` in templates.cpp): `framebuffer_t::address` is in GS WORDS, libdebug wants BLOCKS (`/64`, else SBP's 14 bits overflow and buffer 0 reads scrambled); use `getPreviousRealFrameBuffer()` (never current, nor `getPreviousFrameBuffer()` which may be synthesized); readback lands behind the EE data cache - flush a line after every transfer (hardware repeats rows; PCSX2 emulates no cache); `ps2_screenshot` REFUSES while VIF1 DMA is busy (return value only) - count refusals. **The file is written with our own `fopen`/`fwrite`; libdebug's `ps2_screenshot_file` must not return**: its `open(O_CREAT|O_WRONLY)` arrives at ps2link's `host:` as a MKDIR of the target (directory `frame.tga`, open -1, returns 0 anyway). Verdict = bytes actually written. stb_image here is `STBI_ONLY_PNG` + `STBI_ONLY_JPEG`, so `dbgReadFrameShot` decodes TGA by hand.
- **Render-cost capture** (1.78): command bit 7 requests one synchronized renderScene pass; the generated hook measures phases and object draws only while armed and writes `bin/rendercost.txt`; livedbg validates bounded rows/footer and exports CSV; devkit_ui owns the Render cost tab + baseline; `--profile-frame`. Keep generated on/off hook declarations paired. Captures serialize async rendering - the total is not normal frame time.

## Time machine (`App::livetimeTick`, docs/time-machine.md)

- `livetime.cpp/.hpp` (~160+115): `Snapshot` (`bin/livetime.bin` from the game / `bin/livetime.rst` from the editor) + `History` (capture ring). Same torn-write guard. **The editor does not understand the payload** (codegen detail); the header's `layout` hash stops a capture landing in a differently built world. `History` is bounded by a BYTE budget, keeps at least the newest capture, and CLEARS when a capture's frame goes backwards (a restart; a restore keeps the frame counter running forward - it is the ordering key). RAM only; disk = two fixed-size channel files.
- **The capture walk in `liveTimeSource` (templates.cpp) is the list of everything a rewind restores.** A new field the RUNNING game mutates (on `RuntimeObject`, flow-variable storage, save values) joins it, or rewind silently loses it. Capture and restore are twins in one function pair, one file, same order - never two lists. What the walk cannot reach via `ScriptContext` (walker fall speed, a graph class's own timers) is named in the panel and doc. Changing the walk's shape bumps the layout-hash mix in `liveTimeSource`.

## Remote Pad (`App::remotePadTick`, docs/remote-pad.md)

- `livepad.cpp/.hpp` (~350+105): the editor (or `--pad`) writes `bin/livepad.bin`; the game overlays it on the physical pad - nothing needs focus. Same harness shape and torn-write guard. The file is absolute STATE (a dropped poll cannot swallow a press): the game expires an overlay whose `seq` stopped moving for `kStaleFrames` (120), so every writer keeps refreshing at ~25 Hz. Button mask indexed by `kPadButtonNames`. `parseScript` resolves a pad script into (state, seconds) `Step`s (checkable with no FS/game); CLI (`padFromCli` in main.cpp) and panel (`drawRemotePadWindow`) share the encoder (`livepad::write`). Game twin: `templates::livePadSource`.
- Generated `livepad::tick` stays at the TOP of both loops but AFTER each `Pad::update()` (update rebuilds from hardware), and uses `injectVirtual` **slot 1** (the USB keyboard/mouse fold owns slot 0; sharing makes held buttons re-click every frame).
- The AI Assistant's `press_pad` uses `livepad::parseScript` + `padScriptTick`; `remotePadTick` drives whenever a SCRIPT runs, not only with the panel open (state cleared at the end - a held direction looks like a stuck pad).

## Input recorder (`App::replayTick`, docs/input-replay.md)

- `livereplay.cpp/.hpp` (~510+220): the game writes every frame's input to `bin/replay.out`; feeding one back via `bin/replay.in` reproduces the session. **Only INPUT travels** (ten minutes ~1 MB, committable beside the bug); non-determinism is recorded too: `dt` and procedural seeds (`inputreplay::seed`, the one place the game asks `clock()`). **CHUNKED with per-chunk CRC + a terminal chunk** (a killed emulator is the normal ending: the parser keeps every valid chunk, reports `Recording::truncated`, `finalize` canonicalizes; the terminal chunk distinguishes a finished short file). The game's read path STREAMS (~3.6 MB per half hour; EE RAM is spoken for). **`encode(parse(x)) == x`** is pinned (Save round-trips files). `project::inputLayoutHash` = coarse "same world" hash (scene shapes, input map, multiplayer/kbd settings; NOT transforms) - a mismatch WARNS; a frame-rate mismatch REFUSES at boot. Game twin: `templates::inputReplaySource`.
- `ProjectSettings::inputRecorder` is the one devkit switch defaulting FALSE (the file grows).
- **`inputreplay::tick` is the LAST stage of a frame's input** in BOTH loops (after `Pad::update()`, the keyboard fold and `livepad::tick`): replay uses `Pad::setState`/`KbdMouse::setState`, which OVERWRITE (that is why ~30 pad read sites and three kbdMouse workarounds needed no change). **`KbdMouse::forced` is required** (readers gate on `isEnabled()`). **The fingerprint script stamps the frame CURRENTLY executing, not `frameNo`** (it runs after tick() bumps the counter; stamping the bumped value disabled divergence checking: 1 of 705 frames carried one before, 669 after). **The Runner stages the channel** (`Runner::replay_`, consumed by `stageReplayChannel`, which clears every `replay.*` FIRST on every launch - a leftover `replay.in` replays the last session).

## Game error catcher (`App::pollGameError`)

Fatal game errors reach the editor through its log: a failed `TYRA_ASSERT` prints a dump bracketed by `======= TYRA =======` ... `================` to `bin/log.txt` (PCSX2 host:) or the `[ps2]` runner stream (ps2link) and halts quietly. `pollGameError` tails both (throttled), `extractLastTyraAssert` takes the last block, a new one raises the copyable `drawErrorModal` (+ `glfwRequestWindowAttention`/`glfwFocusWindow`). Same block format for `TYRA_SOFT_ERROR` (recovered; modal wording switches on the `Non-fatal` header). Dedupe by block text (`errorSeenSig_`), **forgotten when a log source shrinks** (`errorGameLogSize_`/`errorRunnerLogSize_`; the Runner deletes `bin/log.txt` before each launch, so an identical re-run error pops again). Both baselined in `attachProject`. Don't revert to text-only dedup re-baselined per run. `EditorConfig::errorPopup` (default on) gates the dialog. Note: **the game writes no `bin/log.txt` under ps2link** (`writeLogsToFile = !ps2link`).

## Hardware timeline

`tools/hardware-trace.py arm PROJECT` before a boot, then export the complete `bin/hardware-trace.csv` to HTML/Perfetto. The engine captures bounded RAM events without new drains and writes after sampling. Scope totals overlap; VIF1 DMA wait is not VU1 execution; VIF/GIF snapshots are not utilization. Compare unarmed/armed controls; reject dropped or stale events (docs/hardware-profiler.md). Native view (1.92): `src/hardware_timeline.cpp` reads the same CSV; Debugger > Hardware timeline arms the next boot, loads completed captures on demand (frame selection, zoom, raw marker tooltips, inclusive totals; host-only, never polls the PS2). Engine detail scopes separate package creation/classification, qbuffer copies, packet construction. Rank performance with unarmed controls.

## The Runner (`runner.cpp/.hpp` ~1.95k+170)

- Worker-thread pipeline (states Idle/Running/Success/Failed): `buildAndRun(p, run, rebuild)`, `runEmulatorOnly`, `buildAndRunPs2`, `exportIso`, `deployToPs2`, `launchPCSX2`. Default backend is native PS2DEV + vendored OpenVCL (`ProjectSettings::buildBackend = "native"`; `tools/toolchain/native-build.sh` + `.ps1` bridge); Docker (`docker compose`, image `${TYRAX_IMAGE:-h4570/tyra}`, set per project via `.env` or machine-wide via Edit > Preferences > Build toolchain - empty = say nothing) is the fallback. Read `docs/toolchain-image.md` before touching the image (which parts can move is measured there).
- **Pre-flight `project::checkScriptNamespaces`**: user-owned scripts in `src/scripts/` live in the namespace derived from the project NAME, and renames don't rewrite owned files - so "copy an example, rename it" leaves scripts registering into a dead namespace (the compiler says `no known conversion from 'Old::Thing*' to 'New::Script* const&'`). The ONE refresh-time failure treated as FATAL. `TYRA_SCRIPT`'s qualified argument is the check.
- **Incrementality is fragile: anything that WRITES a file the compiler reads must not write when nothing changed.** `cp` sets an mtime; PS2SDK headers are ordinary user headers in `.d` files; the audsrv overlay re-applied every build invalidated 16 of 18 TUs. The overlay and the engine's `Makefile.base` copy are stamped/compared; a new "idempotent copy" step needs the same. `rebuild` (Build > Rebuild, `--build --rebuild`) is the escape hatch (recreate container, drop `/src/obj`, `/src/bin`, compiled engine incl. VU microprograms).
- Native incremental builds (docs/native-toolchain.md, "Incremental builds"): shared by `native-build.sh` and its Windows bridge; preserve unchanged base Makefile timestamps (objects depend on compiler flags there); engine/game rules track real `bin/` outputs and the game depends on `libtyra.a`; native engine make runs even on retries; toolchain source identity uses relative names (identical worktrees don't rebuild OpenVCL). Windows mirrors inputs/toolchains under `~/.cache/tyrax/native` in WSL and copies `bin/` back on success; Linux builds directly. Keep debug prefix maps pointed at authored sources; preserve Windows runtime channels during sync. Sound effects: `wavconvert::bakeSounds` runs AFTER texbake and BEFORE either backend (audio.md).
- **Every "clear the field" step is per PROJECT, never by process name**: `claimPs2Channel` (ps2link file server) and `killEmulatorsFor` (PCSX2, keyed on `-elf <path>`), both on the target's own command line. `platform` has no by-name kill. The `-elf` argument is an **absolute, native-separator path** (PCSX2 rebases a relative one below the ELF dir and fails before `bin/log.txt`); `killEmulatorsFor` uses the same spelling. **PCSX2's `host:` loader silently refuses ELF paths over ~145 chars** (logs `ELF Loading: ...`, never `is executing`, black window); `launchPCSX2` warns. A Linux home + deep tree hits it sooner.
- **ps2link file server ownership** (`Runner::claimPs2Channel`, docs/ps2link-setup.md "One file server at a time"): `deployToPs2`/`stopPs2`/`clean` used `taskkill /F /IM ps2client.exe` machine-wide, killing every OTHER project's session (the console keeps running blocked on `host:`, devkit files frozen, while the UDP log stream continues - two transports, one dead; recognise that shape before blaming formats). Now: handle first (our spawned `Process`, killed as a tree), then a SEARCH over `platform::processesNamed("ps2client")` reading each command line (`-h <ip>` = console, `execee host:<name>.elf` = game): ours and stale same-project ones are reaped; one a running editor owns is REFUSED naming the project; unclaimed orphans are reaped. An unreadable command line is NEVER a target; "is that editor alive" = `devsession` heartbeat OR a live editor pid (the heartbeat stops while an editor sits in a native file dialog).
- `devsession.cpp/.hpp` (~180+75): every running editor publishes which project it is debugging (editor.ini's recent list says what was opened, not what is open). `--debug-state` reads it.
- `sessionlog.cpp/.hpp` (~120+60, docs/ps2link-setup.md "The session log"): the ps2client pump also writes every `[ps2]` line to `<project>/logs/ps2-<stamp>.log`, flushed per line; bounded to the last N lines (rewritten down to N at 2N, so a crash leaves the END) and last K files (name order IS age: millisecond stamps, `_2` collision suffix sorts after `.log`). N/K are `editor.ini` keys copied onto `Project` like the ps2link IP.
- `pcsx2_config.cpp/.hpp` (~195+30): finds `PCSX2.ini` (portable dir next to the exe first; then Documents on Windows - beware OneDrive redirection - or XDG config / flatpak sandbox on Linux); before launch forces `HostFs = true` and, with `ProjectSettings::keyboardMouse`, points USB ports at host devices (`ensureUsbKbdMouse`: `[USB1] Type=hidkbd` bound to `Keyboard`, `[USB2] Type=hidmouse` to `Pointer-0` + buttons; docs/keyboard-mouse.md).
- `iso9660.cpp/.hpp` + `isoexport.cpp/.hpp` (~390+50, ~320+60): in-tree ISO9660 writer + disc layout planning (Project > Export PS2 ISO, Disc Layout window).

- **Is the game up?** `Runner::watchGame(const Project*)` (each frame from drawUI) runs a helper thread that, ~1/s, finds an emulator whose command line names THIS project's absolute ELF (the `killEmulatorsFor` rule) or our live ps2client; `Runner::gameStatus()` = running / onPs2 / seconds (from our launch or deploy, or first sight). The top bar's Run reads "Running mm:ss" and turns into Stop on hover (`##MainMenuBar/Run` checked = running). The Live Debugger's "stopped reporting" needs that process alive; a snapshot already old when first seen is never attached to.
- `wire::probeTcp(host, port, timeout)` = the transport's own connect, closed without a byte (Preferences > ps2link *Test connection*, tcp/18193, 2 s, on `std::async`).

## Collaboration and network transport

- Presence carries an optional `"cam":[yaw,pitch,dist,tx,ty,tz]` (older peers ignore it - no `kProtoVersion` bump) and is re-sent unchanged every 3 s, so a late joiner gets the camera and selection. *Follow* eases the camera to a peer's (and their scene) until you move yours, they leave or the session ends. Host and Join keep separate ports and join codes (session state, not editor.ini).

- `session.cpp/.hpp` (~1.33k+215, docs/collaboration.md): `Session` (Host/Client), one worker thread (Runner idiom: atomic state, mutex-guarded event/command queues); the UI drains `drainEvents()` once per frame in `App::sessionTick()` (the ONLY place session data touches `project_`/ImGui). Host scans+hashes the project (model files from `project::manifestFiles()`, the rest from disk minus bin/obj/.git/.res-baked/*.history) and serves a content-hash `manifest`; the client diffs against `remote-cache/<projectId>`, fetches misses in 256 KiB chunks, opens the materialized project. Handshake: proto version (`kProtoVersion`) + 6-digit join code, `deny`/`bye`, ping/timeout keepalive, kick/close. `broadcastFrame`/`sendFrameToHost` + `AppEvent::Frame` carry live sync (LWW per `Section`, edits detected via `modelEditSerial_`). A client REFUSES to migrate a host's project.
- `wire.cpp/.hpp` (~830+140): **the only place sockets live** (no project.hpp). Frame codec `[u32 jsonLen][u32 binLen][json][bin]` LE with per-part caps + incremental `FrameDecoder`; `wire::Transport` (listen/connect/poll/send/kick, single-thread contract) with `makeTcpTransport()` (Winsock2 + WSAPoll, LAN collaboration) and `makeWebSocketTransport()` (RFC 6455 SERVER: SHA-1 + base64 upgrade, unmasking, ping/pong, fragmentation; phone camera link). WebSocket = a per-connection `WsCodec` in front of the same `FrameDecoder`; one binary message = one `encodeFrame` image. A WS peer is announced on UPGRADE, not accept (a browser GET served the HTML page never becomes a peer or an unmatched `Disconnected`); a dying codec sets `closeAfterFlush` (else the served page truncates). Binary payloads ride the raw trailer, never JSON (json.cpp collapses `\u`). Also `fnv1a64`/`hashFile` (exact bytes; transfer cache), `hashFileEolAgnostic` (every bake signature), `localIPv4()`. Socket shims (Winsock vs BSD) stay mapped in place here, outside platform.cpp.
