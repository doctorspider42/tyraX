# The editor viewport (`viewport.cpp/.hpp`, ~8.8k + ~1.6k)

Read when you touch the editor's 3D preview: camera/navigation, picking/selection, gizmos and overlays, preview windows (material/anim/tree/import), the PS2 output/shading simulations, GI/AO display, light beams, or any GL texture upload.

## GL rules

- **Never hand pixels straight to `glTexImage2D`.** Every RGBA upload goes through `glUploadTexRgba(w, h, pixels)` (`gl_loader.h`): allocate empty, fill with `glTexSubImage2D`. The one-call form takes an access violation inside the AMD driver (`atio6axx.dll`, `0xc0000005`, same offset) with valid arguments - a user hit it as an instant crash opening a tool (PROGRESS 101). FBO attachments allocate with `nullptr` (fine); non-RGBA formats (the R32F heightmap) do the same two steps inline. The impostor GPU capture follows the same allocate-then-fill rule.
- `gl_loader.h/.cpp` (~185+30): hand-rolled GL 3.3 loader, only what the viewport needs. The GPU bakers use private function tables (bakegl.hpp) and never overwrite its pointers.
- **Every preview window owns its OWN framebuffer** (`renderMaterialPreview`/`prevFbo_`, `renderAnimPreview`/`animFbo_`, `renderTreePreview`/`treeFbo_`, `renderImportPreview`, one per future preview): several tool windows are open at once with independent sizes; a shared target thrashes `glTexImage2D` sizes and makes each `ImGui::Image` show the other's draw. Only `ensurePreviewBackdrop` (gradient+checker) is shared.
- The viewport must never write ALPHA while drawing particles (`glColorMask` alpha off): ImGui composites the image with its alpha, so translucent smoke previewed nearly black.

## Camera

- Orbit camera tips both ways to `kOrbitPitchLimit` (1.5 rad = +-85.9 deg, not 90: `camView`'s up is world +Y and the basis degenerates when aligned). The camera passes THROUGH the terrain on purpose (`orbit()` has no floor - lifting the pivot read as lying on the terrain then jumping). To see the sky, raise the pivot: `pan`, or `dolly` (right+middle drag, down = forward), which moves the pivot along the FULL view direction and leaves `distance_` alone (a pan, not a zoom); speed `NavConfig::dollySensitivity` (0.1..8).
- **One camera, one place**: `camView()` resolves the projection (perspective / parallel / six locked axis views - `Viewport::Projection`, docs/orthographic-views.md) plus the Cutscene/look-through override into eye + orthonormal basis; `camRay()` turns image coords into a world ray; `projectToImage()` is its inverse (used by app-side overlays such as `App::drawMeasureOverlay` and screen icons). `render()`, `pick()`, `terrainRaycast()`, `placementRaycast()` ALL use them (each used to rebuild a hardcoded 50-degree perspective ray). `orbit`/`pan`/`fly` read the same basis; orbiting a locked axis view seeds yaw/pitch from that axis and falls back to `orbitBase_` (the projection before the axis view, recorded by `setProjection`). The ortho depth range straddles the eye (a Top view still draws what is above the camera).
- Corner **axis gizmo** is app-side (`App::drawAxisGizmo`, ImDrawList, axes from the view matrix columns): it does its own hit test and returns "cursor is over me"; every click-consuming branch (pick, rubber-band start, paste commit) must honor that veto.

## Picking and selection

- **A click tests what the object DRAWS; `pickBounds()` is the one answer**: model mesh AABB, a marker mesh's own extents (measured from its vertex array), a primitive's unit box, a fixed-size gizmo (emitter cone, scroller origin) at its hardcoded size WITHOUT the object's scale; roads test their tessellated asphalt triangles. Everything used to test the scaled unit cube (= a 1.8-unit Player's shins). A new marker/gizmo mesh needs its case.
- `selectionBounds` (1.74.1) grows a world AABB from `pickBounds` plus the actual far representation (`pickVisual`); it serves static-model picking and all local/peer outlines. Surface hits use cached CPU OBJ triangles and alpha masks before the AABB/margin fallback; placement keeps the authored bounds. Clear pick caches with asset invalidation, alpha masks on texture painting. Selection outlines disable depth only for their pass. Keep capture yaw/eligibility in sync with the model draw.
- `pickAll()` returns candidates front to back, with two tiers behind exact hits: a few pixels of grab margin (a padded-only hit never steals from a real hit) and the WIRE BOXES (Area, Scatter, Box with `collisionMode == 3`), which otherwise swallow clicks inside what they enclose (showcase's `boundary-south`). `App::viewportPick` cycles that list on repeated clicks at one spot; the right-click `##pickmenu` lists it by name; `pickStackStatus` is the status line. Screen-space icons (comments, emitters) are hit-tested FIRST, at the head of `viewportPick`.
- **A no-drag click on the transform gizmo is a click**: `gizmoEdited_` compares the anchor's TRS before/after `Manipulate` (ImGuizmo reports manipulation on a motionless press), the release commit runs only when it changed, and `gizmoClick` lets the release reach the picker (a merged district mesh's gizmo sits exactly where you click).
- `placementRaycast` shares `pickBounds` but no margin, and skips wire boxes (not a surface).
- Static-model draws call `modelInView` on imported local bounds and the actual MVP before the per-material loop; keep bounds conservative. Animated poses bypass it, reflected views keep their own path (docs/editor-performance.md has measurement caveats).
- Selection outline + per-peer session outlines (`setPeerSelections`, drawn under the local amber).
- Road-handle overlays must clip pixels AND ImGui item bounds to the canvas (1.151.1): an off-canvas `InvisibleButton` calls ItemSize and grows the scroll extent; restoring the cursor does not undo it. The scene Viewport uses NoScrollbar/NoScrollWithMouse + zero offsets; the welcome list keeps scrolling. Test wheel zoom with road controls outside the frame.

## Previews and caches

- Scatter asset previews no longer use the global 4,000-point proxy cutoff.
  `updateProcPreview` appends per-asset LOD/draw-distance settings alongside each
  volume's asset slots. The renderer uses camera-to-instance distance, loads
  the selected mesh, then calls `modelInView` on its transformed bounds. Keep
  the settings aligned when combining volumes; unassigned points alone draw
  crosses. Prefab expansion and frozen saved-chunk previews remain separate.

- Preview shading is BAKED into vertex colours (`shadeOf`, the `g*` light globals). The tool windows' *Light* combo (`PreviewLight`) re-bakes the preview's own meshes under a scoped global swap (`ScopedShade`, private unit-shape copies, light folded into the `matPrevModel_` key) - never `setLighting` (scene-wide; rebuilds every mesh incl. the terrain AO grid).
- Material Editor preview: a primitive, a project `.obj`, or an animated `.glb/.fbx` in bind pose (`buildMatPrevAnimated`, the assigned `.mtl` name-matched like the console, staged values of the selected entry); `materialPreviewPick` (paint raycast); `updateTexturePixels` (live painted texture, shared `texCache_` id so the scene updates too).
- `modelBounds()` is the GL-FREE model AABB (objparser + own cache) used by the AO occluder pass instead of `modelDraw()` (reading bounds must never upload mid-frame).
- `grabPreviewRgb()` reads the LAST image back as RGB for the phone link: blits into its own small FBO first (a straight `glReadPixels` of 1600x900 stalls); source `lastImageFbo_` with `lastImageW_/H_` (not `fbWidth_/fbHeight_`), so a graded frame streams graded.
- Material refresh (1.152.0): `App::listMaterialAssets` returns a cached const ref (asset mutations invalidate; external changes picked up within 1.5 s); `drawMaterialCombo` owns the Edit button before Texture feed; material saves call `Viewport::invalidateMaterial` (keeps unrelated geometry/textures). Static models record parsed mtllib dependencies; animated overrides go stale without joining background jobs; road/crossing draws record their source material. Never replace with global `invalidateAssets` on a slider commit.
- Animated-model bake is ASYNC (`AnimBakeJob` workers + `animBakeCollect` at the top of `render()`): `invalidateAnimatedModels` marks entries stale and the old bake draws until the new one lands. Workers get copies and no `SkelCache` (not thread-safe); `shutdown()`/`clearModelCache()` join them first; `animBakesPending()` drives the Animation Editor spinner.
- Vehicle Editor live preview is a separate lazily created `Viewport` owned by App (vehicles-and-roads.md).

## PS2 output mode and simulations (docs/ps2-viewport.md)

- **PS2 output** (`Ps2Output`/`setPs2Output`) decouples RENDER size from panel size: `render()` reassigns its `width`/`height` to the GS framebuffer (512x448...), and a final pass (`PS2_FS`, sharing `GRADE_VS`/`gradeVao_`) point-scales `fbo_`/`gradeFbo_` into the panel-sized `outFbo_` with the letterbox. Consequences: `fbWidth_/fbHeight_` = GS size in that mode (panel = `outW_/outH_`); the letterbox lives in `CamView::boxSx/boxSy`, so **`camRay`/`projectToImage` take/return PANEL coords**; `projMatrix()` is the box-scaled twin (ImGuizmo) while `render()`'s matrix is not; `Viewport::ps2LetterBox` must agree with `App::drawSafeAreaOverlay`.
- Geometry is resolved by `App::ps2ViewportOutput` from `project::displayModes()` (the ONE geometry table, also read by the Menu Editor's per-resolution preview) - host twin of the engine's `RendererSettings::updateGeometry` + `RendererCoreGS::presentFrameBuffer`. **A new engine display mode is one entry in each of those three places and nothing in the viewport.**
- **PS2 shading** (`setPs2Shading`): scene shader becomes VS+GS+FS; the geometry stage runs the ONE shared lighting chunk (`SHADE_COMMON`: litShade/envSt/envColor, also the per-pixel FS's source) per corner with the winding normal; `uPs2Flat` mirrors TyraShadingFlat; `u*_` uniform locations are RE-QUERIED for the active program (`useSceneProgram`; previews force per-pixel); GL_LINES detour through the pix program. **A new lighting term goes into SHADE_COMMON or the two looks drift.** The `PS2_VERTEX` define inside it is the ONE sanctioned divergence: dynamic lights switch to the console's VU1 slot (radial `1-d^2/r^2`, cone for spots, no N.L, added on top of GI - `buildSpotForBag`/`CalculateTyraSpotLight` in vendor/tyra), plus terrain AO applied per PIXEL in `FS_VTX_MAIN` (`uAoPerPixel`, terrain draw only) because the console's is a map pass.
- **GS colour** (`setGsColorSim`): 5-bit quantize + the engine's DIMX matrix inside the grade pass (which then runs even with neutral grading); "match project" resolved from `ProjectSettings::colorDepth`/`dither` each frame.
- Static object/batch vertex colours are Gouraud in the generated game (terrain stays flat); keep the PS2 preview in sync (1.77.1).

## Baked lighting display

- GI lightmaps are drawn per PIXEL (`setGiTerrain`/`setGiAtlas` -> `uploadGiMaps`, `uLmMode` + `lmApply`): terrain map by world position; the atlas through `lmMeshFor` (per-object copy of the primmesh tessellation whose UV slot is the atlas ST; region read off the LOCAL normal in builder order, (u,v) = primmesh's face UV - what aobake's `regionPoint` inverts). A lit receiver is untextured, freeing the slot. **Both shading programs must set the `uLmTex` sampler to unit 4** (the PS2 program sets samplers at link, not in init()) - miss one and lightmapped surfaces draw BLACK in that mode.
- Probe receivers: `SHADE_COMMON::giProbe` uses `uGiReceiver` for the centre lookup and signed RGB sum (lighting-and-bakes.md, "Probe lighting").
- AO occluder uniforms come from `aobake::collectOccluders`; with no terrain the AO ground-contact uniform is forced off (the shader's fallback is the y=0 plane). `Viewport::terrain_.enabled`: `buildTerrainMesh` builds nothing (world axes still draw), `terrainRaycast` misses.
- Terrain splat layers: `buildTerrainChunkMesh` (9-float layer meshes drawn with the particle shader) twins templates.cpp's `buildTerrainChunk`; `tintNoise2` macro variation is a twin too.

## Light beams (`drawLightBeams`, docs/flashlight.md)

Not a simulation mode: the corona billboard and, for `Beam: corona + shaft`, the eight-segment cone are geometry the GAME submits, so they draw in every shading mode and mirror `updateAndRenderLightBeams` number for number - including the camera PULL (a quarter of the light radius, capped at 3/4 of the camera distance, size-compensated; without it the editor shows the z-fight seam the console removed). Runtime LEVEL (flicker, Set Light, streamed-out lights) is deliberately left out. `coronaTex()` is the ONE upload of the kind-2 flare bake, shared with the ground pools, read at `menubake::kCoronaSpriteSize` (pools once read `kFlareSpriteSize` after the bake moved to 128 - a quarter of the image).
