# Neural upscaler (BLSS)

Read when you touch `blss*.cpp`, `blss_ui.*`, `blss_window.cpp`, `resources/blss-default.net`, BLSS settings/codegen/interlock, or quote any BLSS number. Docs: docs/neural-upscaler.md, docs/blss-reconstruction.md (the twin contract), docs/profiling.md ("Calibrating the speed model against hardware").

## Files

- `blss.{hpp,cpp}` (~1.3k+4.1k): feature vector, 6-12-3 MLP (forward + Adam), the ORACLE, trainer, emitter. `blsscorpus.{hpp,cpp}` (~340+3k): deterministic software rasteriser manufacturing training frames. `blssscene.{hpp,cpp}` (~260+1.07k): walks a real PROJECT into world triangles (primitives via primmesh, static .obj via objparser, terrain as 16-cell chunks - gibake's three sources - PLUS animated .glb posed per console frame; `updateAndRenderAnimObjects` submits them through `stapip.core.render()` like any bag). Host-only, driven by `--blss-train` / `--blss-eval` / `--blss-emit` / `--blss-coverage`.
- `blss_ui.{hpp,cpp}` (~750+1.56k): pure parsers/arithmetic for the window (no ImGui, no App): `parseEval`/`parseCv`/`parseFeatures`, `summarise()`, `corpusHealth()`, `parseCorpusScenes`, `parseProbe`/`probeVerdict`, `recommend`, `speedFrom`/`breakEven`, the `fill::` speed model. Harness: link `blss_ui.cpp.o` + `platform.cpp.o`, stub `kFeatureNames`.
- `blss_window.cpp` (~4.5k): Tools > Neural Upscaler (BLSS) window (key `"blss"` - in `showFlagForKey` AND `kLayoutWindowKeys`), plus the settings block drawn by BOTH this window and Project Preferences.

## The window runs the editor's own binary

Every driver in blss.cpp (`buildCorpus`, `labelCorpus`, `gatherSamples`, `evalRecurrent`, `crossValidateOnce`, `featureReport`, `netField`) is in an ANONYMOUS namespace; a window re-implementing them would be a second answer to "what does --blss-eval measure". So `blssui::Job` spawns `tyrax-editor --blss-<verb>` on a worker and parses stdout. `App::blssPoll` runs every frame from `drawUI` (a run ending while the tab is shut still lands).
- Parser traps: `%-11s` OVERRUNS on the two long method names - find columns by "first wholly numeric token", never position; `--features`' per-shot header is FIXED WIDTH (a truncated shot name contains a space: `poles pa`). Raw output stays on screen under the tables (a parse must be falsifiable).
- Corpus = ONE switch in the header (`blssCorpusProject_` + `blssCommonArgs()`, project dir as an ABSOLUTE positional - the job's cwd is the project and the `blss.net.args` sidecar records it), defaulting to the project with `--all-shots` (per-tab copies evaluated a project net against the bestiary unnoticed).
- Evaluate tab states a VERDICT (three branches: no headroom / net worse than not using it / margin and fraction of ceiling) via `blssui::summarise()`. Cross-validate tab warns on a project corpus (six moves of one scene are not thirteen kinds of content). Provenance of an editor-trained net = `blss.net.args` sidecar; a net newer than its sidecar reports "unknown".
- Bands are bounded (output pane 35% of the body, header capped and scrolling): the tab child measured 111 px at 1080p and Evaluate's controls were submitted below its edge (see clipped-widget trap).
- **Log source**: the game writes no `bin/log.txt` under ps2link, so the panel falls back to the runner's `[ps2]` stream and names the source.

## Settings (8 on `ProjectSettings`)

`blssEnabled`, `blssScale` (0 = 2x2, 1 = 1x2), `blssNetwork` (the MODE: true = network, false = Plain), `blssAdaptive`, `blssSharpen`, `blssTemporal`, `blssJitter`, `blssDebugView`.
- **Two layers from one definition** (`drawBlssSettings(s, BlssDetail)`): `Essentials` (Preferences): *Use the upscaler*, *Mode*, *Render scale*, VRAM line, ONE verdict line from `blss::measureCoverage`, per-scene/mixing notes, clash block, `Advanced...`; `Everything` adds the four network knobs (sharpen, temporal, jitter, debug view; grey in plain mode) and the long half of each tooltip (one string whose long half is APPENDED, never a second string). Nothing was deleted from the window (every published number came from that instrumentation).
- **A simpler UI must not become a more confident one**: Preferences' verdict = `blssui::recommend(EvalSummary{}, false, speed, true, mode)`, the same function as the window ("TOO CLOSE TO CALL" quotes no multiplier; picture quality named UNMEASURED; no quality claim).
- **Price re-derived EVERY FRAME** (`blssSpeedFor(s)` from `blssPoll`, and from Preferences against the STAGED settings): the two modes' break-evens are 13.1 and 2.6.
- **Plain mode** (`blssNetwork = false`, "Plain mode"): keeps reduced raster, VRAM saving and the interlock, deletes the network (no bag proxies, reprojection, feature grid, MLP; 4 grid vertices instead of 476): EE bill 4.60 ms -> 0.52, break-even 13.1 -> 2.6 coverages at 512x448. Its own bool (a third question; additive bool defaulting true regenerates byte for byte, a tri-state would need migration). Engine forces jitter off there (one place, `configure()`); codegen emits no net `#include` and no `setNet()`.
- **Adaptive Plain** (`blssAdaptive`, opt-in, serialized only when true): codegen reserves both raster layouts at boot and calls `updateAdaptiveResolution()` before the BLSS render bracket in both game templates; keep the automatic overdraw budget keyed to the actual reduced state. The whole-frame timer uses the previous loop - never scene CPU time (cannot see GS fill stalls). Hardware is the decision gate (PCSX2 software fill timing doesn't reproduce the console threshold).
- **Per scene**: `SceneOverrides::upscaler` carries `blssEnabled` + `blssNetwork` (format v13, additive/inheriting). **`p.settings.blssEnabled` is the project DEFAULT and almost never the question**: use `project::resolvedSettings(p, sc)` per scene and `project::blssUse(p)` for the project (any/anyNative/anyNetwork/mixed); `blssUse(p, defaults)` answers for a not-yet-committed default (the dialog states mixing costs: 0.375 / 0.875 / 0.125 MB free heap at 512x512). `mixed` is decided on RESOLVED values (byte-identical regeneration is a property of the outcome). Per-scene machinery (`BLSS_ENABLEDS[]`/`BLSS_NETWORKS[]`/`BLSS_NATIVE_SCENES`, eighth `configure()` argument, `setScene()`) appears only when scenes disagree. Scale, jitter, sharpen, temporal, debug view stay PROJECT-wide (one net + `.meta` per project). Scene > Scene Preferences draws the same two controls with the same wording.
- Colour-target reserve: `RendererCoreGS::setLowResTargetScale`, separate from pinned Z and active scene raster; `configure()` sets it before `needsBufferRealloc()` (a mixed project rechecks triple-buffer headroom even when Z never shrinks); preserve it across native-scene video-mode switches; `setScene()` must not change it.

## Codegen and the interlock

- Four placeholders - `{{BLSS_INCLUDE}}`, `{{BLSS_INIT}}`, `{{BLSS_SCENE_SETUP}}`, `{{BLSS_SCENE_RENDER}}` - filled by `blssInclude`/`blssInit`/`blssSceneSetup`/`blssSceneRender`/`blssNetHeader`, each emitted into BOTH orbit and FPP (SCENE_SETUP in the shared `loadScene`). Everything emitted only when ON (even `BLSS_ENABLED = 0` would change every project's `scene_data.hpp`). `inc/blss_net.gen.hpp` is in the overwrite list.
- `blssBake()` bakes the project's net, else `resources/blss-default.net` (+ `.meta`, embedded by `cmake/embed_binary.cmake`), else (only when the embedded asset cannot be read, i.e. `kNetVersion` moved without a refit) random init; the generated header AND boot log name the source. `--blss-eval`/`--blss-emit` fall back the same and print `[blss] net source=...`.
- Codegen sets **`PipelineInfoBag::blssProxy = false`** for the sky dome, star field and sun/moon discs (a shell's AABB pinned `depth`/`depthGrad`/`coverage` at 1.0 across a frame).
- **`blssClashes()` (templates.cpp) is the conflict interlock and source of truth**: BLSS cannot combine with depth of field, portals or split view (all need real GS depth at display resolution). `blssInterlock()` writes `#error` lines into a TU OF ITS OWN (`src/gen/blss_interlock.gen.cpp`), emitted only while clashing and DELETED by `refreshGenerated` when it stops. It used to live in `inc/scene_data.hpp` (~14 TUs; one clash printed a 340-char paragraph 42 times) and the word "upscaler's" put a *missing terminating ' character* warning everywhere (an unpaired apostrophe after `#error`). So: ONE SHORT LINE per clash naming the pair, the scene and one fix; `errorSafe()` on the WHOLE line. Asked PER SCENE (of every scene resolving the upscaler on): DoF quantised to 1/128 with non-zero focus, **the `Set Depth Of Field` flow node** (mode 0), portals only when the target resolves to another `Portal` in the same scene, split view only with a **second `Player`**.
- The editor mirrors those four conditions from ONE place (`blssClashesFor`/`drawBlssClashWarning`, blss_window.cpp) - edit together with `blssClashes()`. `blssClashesFor(..., assumeProjectDefaultOn)`: walks scenes INHERITING the default as though on (explicit off still skipped), set exactly when the caller labels the block informational (else the informational branch was unreachable for a project with the feature off); false = the build's question verbatim.
- **BLSS x frame extrapolation is PREVENTED**, not warned (setting vs setting, both in `drawBlssSettings`): whichever is on greys the other with the reason IN LINE. Only the TICK is blocked, never the untick (a project can arrive with both on - hand-edited `.tyra`, older editor, Set Frame Extrapolation node - so the build interlock stays); the upscaler side gates on `s.blssEnabled`, not "does any scene resolve it on" (else an all-override-off project locks a ticked box). Scene Preferences carries the same rule. The other four clashes are setting vs scene CONTENT (cannot grey a placed portal).

## Shot plan (`Project::blssShots`, `BlssShotPlan`, `Section::BlssShots`)

The author's choice of which of the six automatic camera moves the corpus shoots, frame counts, whether Cutscene takes join, plus own vantages (typed, grabbed from the viewport, or bound to a Camera). **A default plan writes NOTHING** (corpus byte-identical; published fold tables reproducible; checked by md5). Resolution = `project::blssResolveShot` (project.cpp), called by the window preview and blssscene's walk. The panel checks the trainer obeyed (`parseCorpusScenes` compares `[blss] scene ...N shot(s)` lines with the plan). `--ignore-shot-plan` reproduces the old behaviour. A take DISPLACES an automatic move (`examples/upscaler-lab` has never had a `strafe` shot). The corpus is **13 shots**; shots 0..6 render bit-identically to the original seven.

## The twin and the objective

- **`composite()` is a TWIN of the engine's `RendererCoreBlss`**: the GS's five blend passes in 8-bit with `(A-B)*C>>7` truncation, 12.4 UV quantisation, 4-bit bilinear weights, 0..255 clamps (the oracle optimises that formula). Mirrored functions: `accumulate`/`buildReproj`/`buildFeatures`/`Net::forward`, `bagOf()` <-> `RendererCoreBlss::addBagBox()`, proxy split (`kProxyVerts` = 24, cap 32, consecutive merge) <-> StaPipCore's one box per VU1 package. Weight-field interpolation is piecewise linear over two triangles (`triLerp`, pins the engine's TRIANGLE_STRIP order; math doc section 5).
- **The corpus may only DESCRIBE a frame through `BagProxy`** (screen bbox, w range, one material scalar - what the EE knows while submitting), even though it renders real images for ground truth; **all normalisation, differencing, clamping lives in `buildFeatures()`**, which is PURE (no per-tile state survives a frame).
- **Six channels** (`kFeatures` = 6, `kHidden` = 12; was eight): `histAge` deleted (let the net memorise "still a while"), `luma` deleted (the EE can only fill it from `color->single` - constant 0.5 on per-vertex-lit meshes vs 0..0.48 in the corpus). Settled by `--cv --cv-seeds 3 --drop-feature <name>` against `edgeDens` as a CONTROL (tables in `src/blss.hpp`). **Bump `kNetVersion` (now 3) with any change to `kFeatures`/`kHidden` and refit `resources/blss-default.net` in the SAME commit** (the file carries no topology).
- **Objective = THREE terms**: accuracy + `--flicker-weight` (vs reprojected history) + `--fill-weight` (per full-screen pass, a STEP on the quantised alpha byte the engine's skip test reads). Shipped 0 and **16**, swept and chosen (`kFlickerWeight` = 0 after measuring: costs 0.02 dB, moves flicker not at all under CV; fill is a plateau 12..24). Set fill weight and weight decay TOGETHER (1e-5 vs 1e-4 decay give different answers; 1e-4 ships). Anything absent from the objective does not exist for the network (made four times in the first four commits). Objective changes live only in `oracle()` (no engine counterpart).
- `--blss-eval` prints PSNR, flicker AND **occupancy** (fraction of cells each pass draws; mean passes per frame: 1.00 = plain bilinear, 5.00 = everything); a parity break shows as the trained row falling well below the oracle row.

## Measurement rules (quote these, not older numbers)

- **NEVER quote a plain `--blss-eval` held-out column; use `--blss-eval --cv`** (one split is a sample of one; the "+-0.4 dB seed" variance was split selection: fold-to-fold sd 0.35 dB vs per-seed fold-mean sd 0.04). Bestiary: **+0.41 dB over plain bilinear** (13 shots x 3 seeds = 39 fold-runs, sd 0.34, 3 below bilinear, 1.79 mean passes, `--act-table 512`), +0.27 dB over the six shots not used to choose defaults; `corridor` loses (-0.12) because `depth` (clamped 1/w) is pinned at 1.0 there (58.6% of all tiles read exactly 1.0; depthGrad 61.5%, coverage 71.9%). **A saturated feature is one the network does not have**: `--blss-eval --features` prints per-channel/per-shot stats; `--probe "<BLSSFEAT line>"` places a console vector in that distribution.
- **Do not ship the bestiary net alone**: over seven projects -0.34 dB average, -1.09 worst (out-of-range inputs; `texDetail` is identically zero on five). **The shipped universal net** (`resources/blss-default.net`, md5 `6a93196c96aa15993150ec724716a27d`) was fitted with `--blss-train <the seven screened projects> bestiary --all-shots --frames 660 --no-jitter` (12 frames/shot over 55 shots - the leave-one-project-out setup; `--no-jitter` because every example ships `blssJitter` false). `--blss-eval <a> <b> bestiary --cv --cv-groups` = leave-one-PROJECT-out: **+0.29 dB on an unseen project vs that project's own net's +0.31** (fold sds 0.37/0.34). Real projects WITHOUT the bestiary degenerate (deadzone 0: 2.15 passes, -0.10 dB, 22/42 folds below bilinear). Fitting the project with `--all-shots` reaches +0.41 in distribution (what the console runs); don't quote a project corpus' held-out dB (-0.17, 9 of 18 below bilinear).
- The old "-0.40/+0.06/+0.77" row mixed samplers (ceiling jitter ON +0.773, margins jitter OFF, ceiling +0.345); `generate()` now announces the sampler. On `examples/showcase` the ORACLE scores +0.00 dB - but the corpus renderer draws NO emitters (showcase has 8), so re-measure when it grows billboards. The corpus builder prints a four-line WARNING naming the emitter count (on `examples/upscaler-lab`, 11 emitters and 1.63x measured on a PS2, it used to print "THIS SCENE WILL NOT BENEFIT").
- **Provenance is a `<net>.meta` SIDECAR, never a longer header** (net bytes are published anchors: `e069f286...` shot plan, `6b2fba90...` `--threads`, `879146bd...` default). `--blss-train` writes it (no timestamp: re-running its `command` reproduces it byte for byte); `blss::checkProvenance` REFUSES on version/topology/tile and WARNS on activation table/scale/jitter. The activation-table check compares against `blss::kEngineActTable` (512, twin of `TYRA_BLSS_ACT_TABLE`), NEVER `detail::gActN` (the live `--act-table`, 0 in a process that ran no BLSS verb - `--refresh-gen` warned about every net).
- **`--blss-emit` round-trips through `selfTestEmitter()`** (`%.9g` renders 0.0f as `"0"` and `0F` is not a float literal - for three commits every BLSS project without a net failed to compile). `Net` stays a flat float block (`static_assert`; Adam walks it as `float*`).
- **`--threads N`** (0 = all cores, clamped 32) bounds `parallelFrames` (blsscorpus.cpp) and `parallelFor` (blss.cpp) - WALL-CLOCK only: item i goes to a fixed worker touching only item i, so a seed writes a byte-identical `blss.net` at any thread count and matches the pre-parallel binary (`6b2fba90d0f059f055134a55df478c8e` on examples/procedural, 156 frames, 400 epochs, --all-shots). Check with `--threads 1` vs all cores + `md5sum`. `prevLow` is re-rendered from its own camera/jitter phase (frame i depends on i alone; 1.5% more work). `--blss-train` prints `timing - corpus X, oracle Y, fit Z`: at 6 cores oracle 10.4 s (56%), corpus 1.9 s (10%), FIT 6.2 s (34%, sequential Adam, untouched by threads). Per-shot corpus lines report cpu ms, not wall ms.
- Held-out SHOTS (not random frames) are the eval split (neighbouring frames leak).

## Speed model (`fill::` in blss_ui.hpp) - hardware-fitted

`saved(ms) = 0.7548 x fill - 5.10` over five load points (RMS 0.093): `kSavedFraction` 0.7548, `kEeCostMs` 4.60, `kCompositeGsMs` 0.50; `kEeCostPlainMs` 0.52 is arithmetic over hardware terms (begin 0.41 + end 0.10 survive; deleted terms read 0.000 in PCSX2). `breakEven(rasterPx, network)` is DERIVED, never written down. The assumed 0.741 was right (2% conservative); the fit's intercept reproduces 4.60 + 0.50. **`kPassMs` is per PIXEL** (`fill::kPassMsPerMpx` 2.2524 + `fill::passMs(rasterPx)`; 0.5896 ms at 512x512, 0.5174 at 512x448 on one console, perMpx agreeing to 0.3%) because `FrameProfile::gsFillProbe` sizes its sprite from the framebuffer and the fixture ran PAL 576i. **Quote a break-even WITH its raster**: 13.1 coverages at 512x448, 11.4 at 512x512 (the bare 11.5 once quoted was a 576i figure). `CoverageReport` echoes `outW`/`outH` so window and CLI cannot price one scene two ways. The per-pixel fix corrects none of the coverage over-read below (both instruments ran on one fixture at one resolution, so it cancels).
- `--blss-coverage <projectDir>` (`blssCoverageFromCli` in main.cpp) = headless twin of "Will the frame get faster?" (same `blss::measureCoverage` + `blssui::speedFrom`; per-shot and overall mean/p95, geometry/emitter split, `[blss] coverage ...` lines). On `examples/upscaler-lab` it reads **72.23** (0.96 geometry + 71.27 emitters) vs **58.7** blended-pass equivalents from the hardware fit (`kAnchorCoverages` 58.7). Falsified explanations: the unit theory (geometry 0.98 vs ceiling <= 1.14; re-weighting moves 0.49 of a 13.93 gap) and the camera theory (authored still vantage at the parked FPP standpoint reads 78.99, the Cutscene tour 85.64 - higher). It is a constant SCALE error: haze stepped 6/4/2/0 banks gives 78.99/46.82/19.55/1.55 vs hardware 58.70/37.17/15.40/1.14 (ratios 1.35/1.26/1.27/1.36 over a fifty-fold range) - placement and puff size fine, PRICE wrong. The counter is deliberately left alone; the window calls the figure an overdraw INDEX, names the cameras and spread, and points at Training shots > Your own vantages.
