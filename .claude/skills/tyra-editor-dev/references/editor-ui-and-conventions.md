# Editor UI: shell, windows, preferences, ImGui traps

Read when you add or change a panel/window, a preference (project or machine-global), a window layout, the theme, the Tools menu, the log panels, `--ui-script` support, or the project open/close path.

## The shell and its translation units

- `app.cpp` (~17.2k) is the ImGui shell: `run`/`drawUI`, menu bar + toolbar, the Viewport window (gizmo, sculpt, rubber-band, overlays), window layouts, undo/redo + clipboard + placement, Project/Scene/Layers/Assets/Music/Sounds/Save-data/Scripts panels, asset import, sessions, Terrain/Menus/Grading/Ambience/Disc-Layout windows, every Preferences dialog, viewport <-> project <-> runner wiring.
- **`app.hpp` (~3.9k) declares the WHOLE `App` class**; the `*_ui.cpp` TUs (props, flowgraph, hud, procui, cutscene, credits, menustyle, mateditor, devkit, chat, facts, prefab, particle, batch, atlas, junction, vehicle, vu, modelimport, update, blss_window, droneui, assetbrowser) only hold definitions. A new member is declared in app.hpp regardless of which file defines it.
- `app_internal.hpp` (~300): file-scope helpers shared by MORE THAN ONE of those TUs (`PickKind` pickers, `sanitizeAssetName`, `fileSizeOr0`, `readTextFileTail`, `prefHelp`, `walkSpeedDrag`, ...). A helper used by one TU stays in it. Included by ~20 TUs: keep it small, includes cheap.
- **Keep TUs splittable**: `-O3` is ~2/3 of compile time and superlinear in TU size; app.cpp at 26k lines took ~48 s alone, after the split the same edit costs ~9 s. When a window/subsystem grows past ~2000 lines give it its own `*_ui.cpp` (assetbrowser.cpp/save_assets.cpp precedent) instead of appending to app.cpp. `templates.cpp` is the tail of a clean build.
- `props_ui.cpp` (~3.7k): `drawPropertiesWindow`, `drawMultiProperties`, `drawLodOverrides`, `drawDistantVersion`, area/script pickers. A SOLID object's fields are grouped by the local `section(label, open)` lambda (Model, Transform, Material, Gameplay, Distance and LOD, Performance, Lighting and shadows, Scripts); other types get flat panels (the lambda returns true, draws nothing). A new solid-object field joins the section whose question it answers.

## Editing model details (beyond SKILL.md rule 1)

- `commitChange()` is the one verb, project-wide data included: the undo snapshot carries only `project_.scenes`, so for project-wide collections (menus, credits, loading screens, splashes, Input Map, fonts, button icons, HUD, save values, per-asset overrides) `history_.push()` returns false - no undo step, but it still dirties and bumps `modelEditSerial_`. Committing per widget is therefore free and cannot spam undo during a drag.
- **`saveAll()` only for an explicit save command or a file-system side effect the model must match.** It writes project + history and clears dirty (save icon never lights, exit prompt never appears, every slider release rewrites the project, serial bump skipped, other pending edits persisted). Current call sites: the save commands (Ctrl+S, File > Save, toolbar, discard modal, "Layout saved"), the AI Assistant's `save_project` tool, the three asset imports (music, sfx, HUD image), the Drone Generator's render. Adding another is almost certainly wrong. (`credits_ui.cpp` once documented the opposite rule in its header - that is how two conventions coexisted.)
- **A hand-set `bool changed` is not enough** (the Menu Editor left the save icon dark for titles/colours/sizes/images). A window owning a `project::Section` also compares `project::sectionJson()` across the whole body:
  ```cpp
  const std::string before = project::sectionJson(project_, project::Section::Credits);
  ... window body ...
  if (changed || project::sectionJson(project_, project::Section::Credits) != before)
      commitChange();
  ```
  Early returns -> a local `commitIfEdited` lambda called at each exit (`drawLoadingScreenWindow`, `drawCreditsWindow`, `drawGradingWindow`, `drawCutsceneWindow`); two sections -> concatenate both blobs. Take `before` AFTER any on-entry repair (`if (fonts.empty()) push_back`) or opening the panel reads as an edit. Every project-wide panel has the guard (Save Editor, Menus, Credits, Loading Screens + Splash, UI Editor, icons, Font Manager, Input Map, Animation Editor, Color Grading, Ambience, Cutscene Director, Prefabs, World Facts) - copy the nearest.
- **View state is not an edit**: render mode, projection, active scene are read off the viewport by `saveProject()` (`setViewProjection` is the reference). Stored editor state with no undo meaning (window layouts, debugger breakpoints) uses `setDirty(true)`.
- Collaboration detects edits only via `modelEditSerial_` (bumped in `commitChange()`, `applySnapshot()`, `setDirty(true)`); a mutation path avoiding all three never reaches session peers.
- **`commitChange()` does not touch the viewport.** A setting that changes the PICTURE calls `applyProjectToViewport()` itself (the GI switch didn't, so unticking left baked light on screen). Settings that only affect a future bake must NOT call it (per-frame terrain rebuild while dragging).
- A window that commits a big derived rewrite (particle effects copy into scenes) commits only when `!IsAnyItemActive()` or a drag becomes sixty undo steps.

## Project Preferences window (`drawPreferencesWindow`, key `projectprefs`)

A new setting lands inside this shape:
- **A WINDOW that applies LIVE.** It was a modal staging into `prefSettings_` with OK/Cancel; non-modal means the project can change underneath (undo, peers, the AI Assistant, windows its buttons open), so a late OK would overwrite with stale values, and `prefTerrain_` stages the ACTIVE scene's terrain (a scene switch would write A's size onto B). `prefSettings_` is now a ONE-FRAME copy - re-seeded from `project_.settings` at the top, compared (`operator==`) and written back at the bottom - so any widget in any tab is covered. Nothing reaches disk until Save; project-wide settings were never in undo.
- **Destructive controls keep a scratch**: terrain width/depth/detail cap change heightmap dimensions and `project::ensureHeightmap` NEAREST-NEIGHBOUR resamples (typing 128 over 64 passes through 1 and 12; dragging detail to its left stop destroys the map; `Viewport::setTerrain` re-centres the camera on any size change). `prefTerrain_`/`prefGridDetail_` write back only on `IsItemDeactivatedAfterEdit` and re-seed from the model whenever the widget is neither active nor just committed. Any future destructive setting wants this shape, not a modal.
- **A CHECKBOX NEVER REPORTS `IsItemDeactivatedAfterEdit()`** (activates on mouse-down, edits+deactivates on mouse-up). Use the return value: `if (ImGui::Checkbox(...)) commitChange();`. `Fog enabled`, `Gradient sky dome` and a VU stage's `Enabled` were asking; two survived only via the Ambience section-JSON backstop. Rule: `IsItemDeactivatedAfterEdit` for DRAGGED widgets (sliders, drags, colour edits, text); click-commit widgets report via return value.
- **Viewport refresh is deferred**: the body sets `prefsViewportDirty_`; `applyProjectToViewport()` runs on the first frame with `!ImGui::IsAnyItemActive()`, BEFORE the commit (it also resamples the heightmap after a grid change).
- **Footer pinned outside the scroll region**: each tab body is a `BeginChild` reserving `-footerH` (Scene Preferences was the precedent). Put the same reserve in any long modal.
- **Five pages by GOAL, essentials first**: *Game*, *Picture*, *World*, *Graphics*, *Build & debug* (old names still accepted by `prefsFocusTab_` - `prefCatAlias`). Each page is one essentials card, then an **Advanced** fold (`advanced(summary)`, closed by default, `prefsAdvOpen_`) holding everything a person tuning performance or chasing a hardware detail needs - the upscaler + frame extrapolation live together in *Graphics > Advanced* because they refuse each other. A new page should be rare; a new expert setting goes under Advanced.
- **Every row ends with `prefRow("<label>")`**, and the label MUST be a `kPrefIndex` entry (asserted). The entry carries the page, the group, the `sectionJson` settings KEYS it writes, whether it is Advanced, and search-only words (old names). From the keys come the changed-from-default dot in the card's gutter (an InvisibleButton `Reset <label>`), the page's change count, *Show what I changed*, and Reset - all against `project::newProjectSettings` (what `create()` gives a new project), not the struct defaults. A row's lines since the previous `prefRow` belong to it (hints, warnings, readouts). Rows with no settings key (terrain size, buttons) have `""`.
- **A row that needs a trailing button** (an explicit speed tier's *Auto*): `ui::SetNextRowFieldTrim(px)` before the `ui::` widget shortens its field, then `SameLine()` + the button. Readouts (m/s next to units/s) go in the field's own format string, not as trailing text - and drop from the end when the field is narrow (`walkSpeedDrag`/`speedTierDrag` in app_internal.hpp).
- **No meaning line under every caption** (`ui::RowMeanings` is gone from here): the explanation is the caption's hover (`prefHelp`), and an ESSENTIAL row that needs a word of orientation gets `prefHint("short plain sentence")`. Long warnings are one amber line with the detail on hover (triple buffering). Captions are plain words (*TV region*, *Picture mode*, *Colours*, *Texture colours*, *Torch shadows*) - the jargon is in the hover and in the index's search words.
- **Buttons that open other windows just open them** (as a modal, *Advanced...*/*Open Ambience Editor* raised untouchable windows and *Open Loading Screens editor* discarded staged edits). Hazard now: a window opening on top makes a `--ui-script` click on covered Preferences items land on it - assert those with `expect-checked` (does not click).
- **`prefHelp` belongs to the widget it FOLLOWS** (`SameLine` + dimmed `(?)`); placed later it chains onto the wrong widget (Live Link/Live Logic once had three markers in a row on the crash handler). ImGui does no accelerator parsing: `&&` in a label draws two ampersands.
- New Project modal: per-field prose goes into `prefHelp` tooltips, not `TextDisabled` paragraphs pushing buttons off-screen.

## Machine-global editor settings (editor.ini)

- Per-installation, NOT in the `.tyra` (UI scale, navigation, emulator path, dev-PS2 IP, theme, native title bar, chat options, GPU GI bake, session log limits...): a field on `EditorConfig` (struct in app.cpp) + lines in `loadEditorConfig`/`saveEditorConfig` (key=value in `editor.ini` under `platform::configDir()`) + an App member seeded at startup + the Edit Preferences dialog (`drawEditorPreferencesModal`). Every save funnels through `App::saveGlobalConfig()` so no field is dropped. If the Runner needs it, copy it onto `project_` in `attachProject` (`emulatorPath`/`ps2LinkIp` live on `Project` only as runtime transport). It may be edited elsewhere (`errorPopup` from the Debug window, `giGpuBake` beside the Bake buttons) as long as it goes through `saveGlobalConfig()`. `editorcfg.hpp` exposes `configPath()`/`recentProjects()`/`defaultProjectsDir()` to non-GUI code (`--debug-state`).
- **A new `NavConfig` field is four places**: the struct in app.hpp, the `match("nav...")` line in `loadEditorConfig`, the `<<` line in `saveEditorConfig`, the widget in `drawNavigationModal`. `orbitAroundSelection` has a second door in the View menu; both must reset `navFocusedIndex_`.

## Window layouts

- `Project::windowLayouts` (`WindowLayout{name, ini, recipe, openWindows}`) + `activeLayout`. Empty `ini` + a `LayoutRecipe` id is built by `App::buildLayoutRecipe` (DockBuilder) the first time shown. Built-ins: Default / Director / Material / Debugger / Procedural / Menu Designer (Menu Editor + standalone `Menu Preview`).
- **A new built-in layout is FOUR places**: `LayoutRecipe` enum (project.hpp), a `case` in `buildLayoutRecipe` (app.cpp), a row in `seedBuiltinLayouts`, and the `hasRecipe` top-up in `project::load` (else existing projects never see it).
- A recipe cannot choose the ACTIVE tab of a shared dock node: a fresh node activates whichever window is submitted first and `drawUI`'s order is fixed, so Menu Designer gives the preview its own node. `pendingFocusWindow_` settles only one window.
- Switching/capture: `switchLayout`/`applyActiveLayout`/`captureActiveLayout`, applied at a frame boundary. `openWindows` holds string keys (order cosmetic). **A new optional window must be registered in BOTH `App::showFlagForKey` AND `kLayoutWindowKeys` (app.cpp)** - the array is what capture/apply iterate; a missing flag leaks across every switch (the Input Map bug, PROGRESS 221). Layouts are editor state (setDirty), not undo.

## Project lifetime

- **`attachProject()` / `closeProject()` are a pair.** Every open path (`openProjectAt`, `openRemoteProject`, New Project) ends in `attachProject()`; `closeProject()` returns to boot state (`hasProject_ = false`, empty `Project`, `drawWelcomeScreen()`). Per-frame channels and tool windows open with `if (!hasProject_)` - **that guard is what a new window or channel owes the close path**. `closeProject` explicitly handles only state that would outlive the project: worker threads (phone camera link, GI baker, running build, Drone render) and disk-derived caches keyed by project-relative paths (`viewport_.invalidateAssets()`, layer-RAM / WAV / model-info / GLB-info caches). A new subsystem with a worker or such a cache joins `closeProject`. The unsaved-edit guard is `requestCloseProject()` (like `requestOpenProject`/New/Exit, via `PendingAction` + the discard modal).
- **Local opening is staged on the main thread**: `openProjectAt` records the folder; `projectLoadTick` first gives `drawProjectLoadingScreen` a frame to reach the GPU, then runs stage 0 (`project::load(out, dir, &cancel)`) on a WORKER - cancellable between object files and before the heightmaps (Cancel / Esc on the loading screen) - and stage 1 (migration, viewport, `attachProject()`) on the main thread, not cancellable. `project::load` replaces the process-wide custom flow-node, screen-effect and menu-style registries, so `projectLoadJoin` restores them after an abandoned read (also at shutdown and the next open). The bar is indeterminate on purpose (no truthful work total).
- Traps the guard does not cover: (1) a tick called BEFORE its window's `!hasProject_` return still runs after close - `droneTickRender()` appends to `project_.music` and calls `saveAll()`; cancel+join such workers in `closeProject` in `App::run`'s shutdown order (audio device first - its callback holds the `LiveSynth` - then the render thread). (2) Audio does not stop by itself: `closeProject` calls `droneStop()`. Caches always invalidated together are cleared together (`modelInfoCache_` + `glbInfoCache_`).

## Log panels (`logview.cpp/.hpp` ~200+85, docs/log-panels.md)

- Output and Debug share ONE body: `logSetText`/`logRefresh`/`drawLogPanel` over a `LogView`; a new log surface calls those three. `LogView::visible` holds INDICES into `LogView::text`, so replacing the text mid-frame (Clear log, the source combo) must be followed by `logRefresh` before drawing (`drawLogPanel` calls it itself). The Debug window READS its file before submitting widgets (buttons report on classified lines) - hence `debugReloadNow_` arming the next frame's read.
- `logview` is a pure function of text (harness-testable). (1) A diagnostic is a RUN of lines: continuation lines inherit the entry's level (`Line::cont`), chips count ENTRIES. (2) The earliest marker in a line wins (`[editor] Warning: texture bake failed` = warning, `[editor] ISO export failed` = error); engine prefixes `LOG:`/`==WARN:`/`====ERR:` are exact (vendor/tyra debug.hpp - change there = change here). A `> <command>` echo skips the scan (keeps `-Werror` out of errors). (3) Parse is incremental (`parse(log, from, state, out)` + `appendPartial`); a harness must assert line-at-a-time == one-shot.

## Theme (`theme.cpp/.hpp` ~345+85, docs/editor-theme.md)

- Four interface themes; a theme is eleven colours (`Palette`) from which all ~60 `ImGuiCol_` entries AND the `ground`/`field` tones are DERIVED; metrics (rounding, hairline borders, trackless scrollbars, accent tab overlines, tree lines) are shared by all themes including stock-ImGui.
- **A widget asks for a MEANING, never a colour**: hand-drawn chrome reads `theme::semantics()` (accent/accentMuted/ok/warn/danger/special/text/textDim/surface/border/ground/field/axisX-Z). New theme = one `Palette` literal + one `info()` row + one `paletteOf()` case; new semantic colour = a `Semantics` field filled by `apply()` for EVERY theme. `applyImNodes()` tints both node canvases (per-node/pin colours are data, left alone). `hoverAnim()` = 0..1 hover ramp stored in the window's `ImGuiStorage` by `GetItemID()`.
- Docked panels as cards: the dockspace HOST and its splitters draw with the host's `WindowBg`, so `theme::push/popDockspaceColors()` around `DockSpaceOverViewport` ONLY gives the ground-coloured gaps (`DockingSeparatorSize` 6); never push it around panel windows.
- Window frame = `shell_ui.cpp`. The main menu bar is TALLER than a row: ImGui sizes it from `FramePadding` at `BeginMainMenuBar`, so `drawMenuBar` pushes a big `FramePadding.y` for that call ONLY and pops before anything inside - popups and toolbar keep normal metrics. The bar holds no menus: `drawLogoMenu` (shell_ui.cpp) draws the mark + "TyraX" + caret as ONE `InvisibleButton("TyraX menu")` whose popup (`##tyrax_menu`, opened by click / F10 unless the Live Debugger owns it / a lone Alt tap / `logoMenuOpenRequest_`) calls `App::drawMainMenus()` (app.cpp) - the ten `BeginMenu` blocks, unchanged, as submenus. A new menu or entry goes in `drawMainMenus`; the popup reports its items as window `##MainMenuBar` (`uiscript::aliasCurrentWindow`) so scripts keep naming them. The palette's search button and the "N unsaved" marker (`unsavedEditCount()` = `History::stepsFromSaved()` + project-wide commits counted once per ImGui active id, reset by `markEditsSaved()` in `saveAll`/open/close) are in `drawToolbar`; `drawToolbar` centres controls at `y0 = (barH - frameH)/2` and right-aligns in SCREEN space (`SameLine(x)` in a menu bar is offset by `MenuBarOffset`). The status bar is `BeginViewportSideBar("##StatusBar", Down)` - always `End()` even when it returns false. Toolbar/status hit boxes keep their ids (`##tb_save` = the "N unsaved" marker, `Search##tb_palette` = the wide search field (magnifier only when short of room; workspace labels get room first), `Run###tb_run` (script `##MainMenuBar/Run`, checked = game running), `Run options###tb_run_more`, `Stop###tb_stop` (the `##`-only forms could not be scripted), `##tb_build`, `##tb_profile` now a pill+popup, `PCSX2##tb_target`/`PS2##tb_target`, `Scene picker`, `Build status`, `##tb_live*`, `##tb_session`) and the chip LABELS (LIVE/DBG/LOGIC/SESSION/BUILDING) are documented vocabulary across ~20 docs - keep them.
- Viewport overlays (app.cpp, after the gizmo/gear and BEFORE the keyboard shortcuts): glass cards (`ui::OverlayGlassPanel` over `Viewport::blurBackdrop`'s quarter-size blurred copy, set per frame with `ui::SetOverlayBackdrop`; falls back to `OverlayPanel`), then `OverlayIconButton`/`OverlayTextButton`/`OverlayMenuButton(label, text, ...)` placed by `SetCursorScreenPos`. Layout: tool palette top-left, view pill top-centre (`Proj: <name>`, `View: <name>`, `Render mode`, `Surface snap`, `World`/`Camera`; wraps or hides between palette and gizmo), gear + selection readout bottom-left (Frame = ID `Center selection`, key F), `Editor`/`As PS2` bottom-right. IDs are the old labels even where the visible text differs; toggles call `uiscript::markLastItemChecked`. The viewport texture is `AddImageRounded` over a `Dummy` (bottom corners follow `DockNodeRounding`).
- Properties (props_ui.cpp) runs inside a `ui::InspectorRows` scope: the `ui::` wrappers (InputText, BeginCombo, Combo, DragFloat/2, DragInt, SliderFloat/Int, AxisDrag3, ColorHex) draw the caption in a left column and give the widget its exact label with its own caption clipped - outside a scope / in popups / after SameLine / for `##` labels they are the stock widget. `prefHelp` -> `ui::RowHelp` (help on the caption). Solid objects: tabs `Object##ptab`/`Material##ptab`/`Physics##ptab` (selector only, content drawn after the bar; `propsTab_`). It uses `ui::Switch` instead of `Checkbox` (same signature/return/MixedValue; it calls `IMGUI_TEST_ENGINE_ITEM_INFO` with `Checkable|Checked` itself - any new switch-like widget must too, or `expect-checked` breaks) and `ui::Section` instead of `CollapsingHeader` (same ID, no band). The header's "Name" InputText is clipped to its own rect so its label is never drawn; keep the label (scripts type into `Properties/Name`). Switch knobs ease over ~0.1 s of `DeltaTime`; `--ui-script` frames are much shorter than 1/60 s, so `wait 0.5` before a `shot` of a just-toggled switch.
- **Merged title bar** (macOS/Windows default, editor.ini `nativeTitleBar` / *Edit > Preferences > Appearance > Use the native title bar*, applied at startup only: `titleBarMerged_` is what this session did, `nativeTitleBar_` the preference): the top bar IS the window's top edge. `drawMenuBar` starts with a Dummy of `titleBarInsetLeft()` (macOS traffic lights) and ends with `drawTitleBarControls()` (shell_ui.cpp: Windows caption buttons `Minimize##caption`/`Maximize##caption`/`Close##caption`, then `platform::updateTitleBar` with the bar height and "pointer over a bare part"); `drawToolbar` right-aligns against `barRight = window right - titleBarInsetRight()`. Anything new drawn on the bar that should NOT drag the window must be an item (InvisibleButton/Dummy with hover); a plain draw-list decoration is draggable, like the logo. Mechanism and pitfalls: build-platform-release.md.
- **Multi-viewports** (`multiviewport.hpp/.cpp`, namespace `mvp`; editor.ini `multiViewports`, *Edit > Preferences > Appearance > Windows can leave the main window*, applied LIVE between frames in `run()`; default `platform::multiViewportsByDefault()` = off only under Wayland, and `mvp::supported()` = the backend's `PlatformHasViewports`, false on Wayland, greys the switch). **With it on, every ImGui position is DESKTOP space** - the main window's top-left is `GetMainViewport()->Pos`, not 0,0. Code that mixes ImGui coords with GLFW window coords must add the window position (the file-drop callback does, and is installed on every panel's OS window too). Anything sized/centred on "the screen" uses `GetMainViewport()` (Pos/WorkPos), never 0,0 / `io.DisplaySize`. Frame order in `run()`: toggle -> `fitLayoutIni` on a pending layout load -> backend NewFrame -> `uiScriptTick` -> `mvp::routeInjectedMouse` (scripted cursor -> `AddMouseViewportEvent`, even when the position did not change - ImGui drops repeated positions) -> `NewFrame` -> `mvp::newFrame` (script undocks, bring-back after a live switch-off) -> ... -> main `RenderDrawData` -> shots -> `mvp::renderPlatformWindows` (UpdatePlatformWindows + RenderPlatformWindowsDefault + main context current again) -> swap. `mvp::install` wraps the backend's `Platform_CreateWindow` (owner = `ParentViewport`'s window via `platform::ownToolWindow`, drop callback, user pointer) and `Renderer_RenderWindow` (script shots), and sets `ImGuiBackendFlags_HasParentViewport` + `io.ConfigViewportsNoDefaultParent = false` so ImGui knows panels sit above the main window - the TYRAX popup patch (vendor/imgui-tyrax/TYRAX-PATCHES.md) uses that to give a popup that a panel window would cover its own OS window. `ConfigViewportsNoTaskBarIcon` on, `NoAutoMerge` off (a window dropped over the editor rejoins it). After the main window exists `GLFW_MAXIMIZED` is reset - hints stick, and every panel window would open maximized. All GL work (viewport renders, `renderGameView` slots, `assetOrbitView`, `prefabThumb`, anim previews, `blurBackdrop` - which reads the viewport's own texture, so a viewport in its own window keeps its frosted cards) runs on the MAIN context during drawUI; other windows only sample shared textures - never create a VAO/FBO inside a draw callback. Layouts: ImGui stores a floating window's `ViewportPos` (desktop) and a floating dock node's `Pos` in the current mode's space; `mvp::fitLayoutIni` rewrites the text before `LoadIniSettingsFromMemory` so nothing opens off every monitor (on) or outside the main window (off). *Layout > Bring all windows back* = `mvp::bringWindowsBack` (floating windows via `SetWindowPos`, floating nodes via `DockBuilderSetNodePos/Size`; ImGui then merges them into the main viewport). `dockToolWindows` finishes the target's ROOT node (it may be a floating node in another OS window). The palette pins itself to the main viewport (`SetNextWindowViewport`); modals dim every viewport (ImGui). Unverified on Windows/Linux X11.
- Panel chrome: `ui::PanelChromeNewFrame` (drawUI, before the dockspace) sets `NoTabBar` through the WINDOW CLASS (`DockNodeFlagsOverrideSet`, never saved) for Project/Properties/Viewport/Output/Debug/Flow Graph while alone in a node; they draw `ui::PanelHeader`/`PanelInlineTitle`, whose empty part ("Move panel") undocks via `StartMouseMovingWindowOrNode`. The dockspace has `NoWindowMenuButton`; multi-window nodes show pill tabs (`ImGuiStyle::TabPillInset`, ImGui patch). Console drawer: Output/Debug/Debugger share the Default recipe's bottom node; `drawLogHeader` (actions + Select text + right-aligned chips, wraps), `drawLogTabBadge` (count pill over the tab's `UnsavedDocument` slot), `LogView::times` + `logview::Line::stamp` (time column). Outliner: chips (`sceneFilterCat_`, `outlinerCategory()`), folders with `###` ids, row eye = `SceneObject::editorHidden` (saved, undoable, editor-only - codegen ignores it; format 95); a lone Viewport draws its header in the `##viewport_header` child, layer chip strip.
- Project panel = ONE page (`leftPage_`, picked by `drawRail` in shell_ui.cpp: Outliner / Layers / Assets / Audio / Scripts); `drawSceneSection`/`drawLayersSection`/`drawAssetsSection`/`drawScriptsSection` have no header any more, Music/Sounds use `ui::Section`. Rail buttons are named by page ("Outliner", "Assets"...) - a script must `click Assets` before targeting `Project/Browse assets...`. Outliner rows: `Selectable` with transparent text keeps the `name  (type)` label (ID, `expect-checked` via `markLastItemChecked`), icon/name/type drawn on top.
- Workspaces in the top bar (`drawToolbar`) are NOT a new concept: each finds the first `windowLayouts` entry with recipe Default/Debugger/Director/MenuDesigner and `switchLayout`s to it (no format change). The command palette (`palette_ui.cpp`) rebuilds its entry list every open frame from a HARVEST pass over the menus (`menu_actions.hpp`: `menuact::BeginMenu/EndMenu/MenuItem` are the plain ImGui calls when drawing and record items when harvesting; invoking an ordinal runs that item's own code). **A new main-menu item must use `menuact::MenuItem`**, or it works in the menu and is missing from the palette. Only things no menu has are hand-written (Run/Stop, profile, New scene, Center on selection); `windowTitle` only brings a Tools window forward. Its dim + card are drawn on the palette's OWN draw list with the clip opened to the viewport (the foreground list would dim the palette too); `ImGuiWindowFlags_NoBackground` for that reason. Ctrl+Enter (Cmd+Return; ImGui swaps Ctrl/Cmd on macOS, so `io.KeyCtrl`) or the footer's "Ask the AI assistant" appends the query to `chatInputBuf_`, opens the AI Assistant and sets `chatFocusInput_` (caret into the draft; never sent by itself). Shortcut text shown to users goes through `ui::ShortcutChord` (Ctrl vs the Command sign, with a "Cmd" fallback when the face lacks U+2318) and keycaps through `ui::Keycap`.
- Panels as rounded cards = `ImGuiStyle::DockNodeRounding` (an in-tree ImGui patch, `vendor/imgui-tyrax/TYRAX-PATCHES.md`) set by `theme::applyMetrics`: tab bar rounded on top, docked window bg at the bottom. Full-bleed content in a docked panel (the viewport image) must round its own bottom corners with `DockNodeRounding` - the Viewport draws its texture with `AddImageRounded` over a `Dummy` for that reason.
- Design-check round (1.173): **sliders are the in-tree ImGui patch `ImGuiStyle::SliderThinTrack`** (thin track, accent fill, round knob, mono value at the row's end; click the value / double-click / Ctrl+click types) - never hand-draw a slider track; `ui::SetNextSliderGradient` gives a colour-cue track (Grading Temperature); DragFloat stays for free numbers, Slider for ranges; the Simple views keep `ui::TrackSlider` (word values). `ui::GoButton` = the green "go" action (Run, Drive it); `ui::KeyButton` = a button with its shortcut tile. **Splitter widths: clamp per frame, store only on a drag** - a docked window's first frames are a few px wide and a stored clamp pins the columns for the session. `importModelAsset()/importModelFile()` only OPEN a dialog that finishes later: code needing the imported file uses a `ModelImportFor` purpose handled in `modelImportPlace()` (e.g. `Borrow`), never a before/after file-list diff. Focusing a window that does not exist yet: `SetNextWindowFocus()` on its next Begin (SetWindowFocus by name is a no-op). ## Conventions and ImGui traps

- **Panel text is terse.** A panel states facts: numbers, names, one-line verdicts. A multi-line `TextDisabled` paragraph is a defect (the animation-import section's got "wielka litania"). Explanations go in a 1-3 line tooltip on the thing; the long story in `docs/`. Prefer no `(?)` marker at all. An empty panel must still SAY WHY in one line (remedy visible, reasoning in the `prefHelp` hover) - the `dbgSilenceReason`/`dbgSilenceDetail` split.
- **Tools menu = ONE flat list under `SeparatorText` headers, alphabetical within each**: *Assets*, *Scene*, *Lighting & rendering*, *Screens & menus*, *Gameplay*, *Running game*, *AI* (last). No submenus (every doc/tooltip/AI prompt/`--ui-script` names a tool as `Tools > X`). Vehicle Editor is in Assets after Tree Generator; Global Illumination follows Color Grading.
- **DPI/zoom: wrap literal pixel sizes in `App::scaled(px)`** (`px * uiScaleApplied_`). `applyUiScale()` scales fonts and style spacing but NOT literals passed to ImGui (`SetNextItemWidth(180)`, `BeginChild(ImVec2(170,0))`, `SameLine(190)`, `Indent(46)`, fixed buttons, hand-drawn previews). Negative/`-FLT_MIN`/fill widths and `CalcTextSize`-derived sizes already scale. Free functions drawing fixed-size widgets take a `scale` param (`gradingWheel`). `ScaleAllSizes` does not reach third-party style structs (`ImNodesStyle`): the Flow Graph scales it itself; any new vendored widget lib owes the same.
- **A zoomable canvas scales its font with `PushFont(nullptr, sizePx)`, never `SetWindowFontScale`** (since ImGui 1.92 the per-window scale does not reach `BeginChild` content - silent no-op). Derive every length from the ROUNDED font pixel size (snap zoom to whole font pixels so the view stays self-similar), and stored node positions carry the same factor incl. UI scale (PROGRESS 233).
- **A widget drawn over a `Selectable` is dead unless the Selectable used `SetNextItemAllowOverlap()`** - the chat-history `x` passed its click to the row and OPENED the chat being deleted. Lay row-with-actions lists out in COLUMNS (measure the widest label with `CalcTextSize`, fixed `SameLine(x)` offsets from the row's `GetCursorPosX()`), not by flowing `SameLine()` after text.
- **An ImGui label IS its ID**: two knobs captioned "Mix" collide (`Mix##delay` / `Mix##reverb`); a combo listing two lists with overlapping names (procedural Pick Prefab: prefabs then scene objects - capture guarantees overlap) needs `##<prefix><index>` on every entry. `--ui-script` cannot open a `##`-labelled combo (no name to target); ImGui's conflict detector cannot be driven with a synthetic cursor (PROGRESS 210).
- **Popup IDs: `OpenPopup`/`IsPopupOpen`/`BeginPopupModal` must use the SAME string; `ImHashStr` resets only on `###`.** A `"Title##id"` modal with `OpenPopup("id")` is opened but never drawn, and an open-undrawn modal swallows every click in the window (PROGRESS 215).
- **A tooltip helper must run AFTER every `IsItem*` query on its widget** (ImGui's "last item" is context-global; a tooltip before `IsItemDeactivatedAfterEdit()` silently stops the edit committing).
- **Widgets pushed below a window's bottom edge still submit and report a rect, but no LABEL** (ItemInfo is skipped for clipped items, ItemAdd is not), and a `--ui-script` click there hits whatever is behind. Symptom: `dump` shows the widget as `-` with the right size/place. Verify widgets added to dense panels with `--ui-script ... dump` and check the label came back. (The GI GPU switch is pinned at the bottom of the GI tab's Bake column for this reason; the BLSS window bounds its output pane at 35% and caps the header for the same reason.)
- `--ui-script`'s `hover` does not hold a synthetic cursor across steps (the GLFW backend rewrites `io.MousePos`), so a DELAYED hover tooltip cannot be screenshotted; one shown during a `click` step can. An `InvisibleButton` hit box should carry a real label (`"Copy message"`, not `"##copy"`) so scripts can target it.
- Files: `snake_case.cpp/.hpp`, paired header/impl, flat `src/`. Comments explain constraints, not narration; match existing density.

## UI scripting (`uiscript.cpp/.hpp` ~590+150, docs/ui-scripting.md)

- (1) Item registry: ImGui declares four `extern` hooks under `IMGUI_ENABLE_TEST_ENGINE` (`ImGuiTestEngineHook_ItemAdd`/`ItemInfo`/`Log`, `ImGuiTestEngine_FindItemDebugLabel`) - we implement them (label + rect + checked/open/inputable for every widget) with no imgui_test_engine dependency (licence). The define is `PUBLIC` on the imgui target (changes `ImGuiContext` layout); collection is gated on ImGui's `TestEngineHookItems` (one untaken branch per widget normally).
- (2) Script: `parseScript` -> `Step`s executed by `App::uiScriptTick` (devkit_ui.cpp) by injecting `io.AddMousePosEvent`/`AddMouseButtonEvent`/`AddKeyEvent` - no OS input, no focus needed. The tick must stay BETWEEN the GLFW backend's NewFrame and `ImGui::NewFrame`. `find(target, clickable)` must keep excluding whole-window items for clicks (a bare window name otherwise clicks the window's middle - it pressed R3 once). `rightclick` = `click` on mouse 1 (makes context menus assertable). The tokenizer strips DOUBLE quotes only (`'two words'` = two tokens). The four pointing steps take an optional `<dx>,<dy>` offset from the target centre - the only way to reach things the editor DRAWS (viewport content): anchor on a nearby real item, offset into it. Assertions take no offset.
