# Game screens: menus, stylesheets, fonts, text icons, HUD, credits, save system

Read when you touch `GameMenu`/`MenuEntry`, `menubake`/`menulayout`/`menustyle`, the Menu Editor, fonts or text rendering, inline icons, the HUD/UI Editor, loading screens, credits rolls, the memory-card save system, or add a texture the game loads.

## VRAM rule for any texture the game loads

The engine uploads to GS VRAM on a texture's FIRST RENDER (`RendererCoreTexture::useTexture`) and pins it forever - no LRU, only an all-or-nothing flush when the next texture doesn't fit, ~1.33 MB budget (+8 KB per allocation). Add lazily; never call `useTexture()` eagerly unless you WANT it resident (streamed model textures do); prefer 4-bit for anything tinted at runtime. Do NOT "fix" residency by freeing on hide: `RendererCoreGSVRam::free` is a bump-pointer pop (`pointer = address`), freeing anything but the newest allocation rewinds past live textures. Any texture-size change can shift every later address and GS cache behaviour (vehicles-and-roads.md, palettizing trade) - price it.

## Menus and option blocks (`GameMenu`/`MenuEntry`, project-wide)

- Baked to a panel sprite at build (menubake.cpp; the PS2 has no font), edited in the Menu Editor (`drawMenusWindow`, app.cpp), driven at runtime by `updateGameMenu`/`renderGameMenu` with data in `menu_data.gen.hpp` (`MenuEntryData`/`MenuData`).
- Stateful **Toggle/Choice** rows store an option index in a named save value (label from a baked value strip).
- **Option blocks**: `MenuEntry::settingBind` (`Setting` enum, 0 = none) -> codegen `bind` column -> `TerrainGame::applyMenuBindings()` (each frame in both loops, before `applyVideoRequests`) maps the option index onto the setting: music/sfx volume, deadzone (`g_deadzoneL/R`), stick curve (`g_stickCurve`), display mode/widescreen (via `scriptCtx` video requests).
- **Display-mode row (bind 5)**: each option carries an explicit engine mode (`MenuEntry::optionModes` -> `MenuEntryData::optModes`; codegen fills a short/absent table positionally); the editor offers the five `Tyra::DisplayMode`s + "Default (project)" (-1, resolved at runtime to `g_defaultDispMode`, the boot mode latched at init - main.cpp may promote Interlaced to Pal576i on a PAL region via `ProjectSettings::palFullHeight`). **A new engine mode bumps the -1..4 clamps in project.cpp load, the templates.cpp emitter and the app.cpp lists/seeds.** With an **Apply video mode** row anywhere (`MenuEntry::ApplyVideo`, action 9; `MENU_HAS_APPLY_VIDEO`) bind 5 defers: cycling stages the save value, APPLY commits (`updateGameMenu` case 9), outside a menu the row snaps back to the live mode each frame (also covers a reverted keep-or-revert). Without it bind 5 switches on change.
- **`MenuEntry::RebindKey`** (action 10): `bindAction` names the Input Map action, `param` the save value holding an `inputCodes()` index (0 = preset). Pad-only (see flow-graph-input-player.md). Its value is drawn as RUNTIME text from the menu font's glyph atlas (so `Project::atlasFontIndices()` bakes an atlas for any menu with such a row; `MenuData::font` is that FONTS slot) and `updateGameMenu` has a capture mode (`menuRebindRow`, cleared on every menu transition). Bind 8 = `BindInputPreset` cycles Input Map presets.
- Menu Editor scaffolders (`addOptionBlock`/`addOptionsMenuPages`/`addRebindRows`, app.cpp) create rows + backing save values (DISPLAY page includes APPLY, CONTROLS the rebind rows).
- A menu change can touch: `MenuEntry` (+ `==`) -> menu JSON in project.cpp -> `MenuEntryData` codegen + `applyMenuBindings` -> the runtime setting site (audio call, `axis`, `applyVideoRequests`) -> Menu Editor UI.
- Menu roles on `GameMenu`: `titleScreen`, `pauseMenu`, `saveMenu`, `skipMenu` (one per project each; the role buys the Menu Editor, serialization and panel bake for free).

## A menu's LOOK is a stylesheet (docs/menu-styles.md)

- `menustyle.{hpp,cpp}` (~400+1.7k): model, CSS-shaped parser, cascade, registry (`loadForProject`, called by `project::load` BEFORE menus are read). No GL/ImGui/layout/raster - harness-testable. **`propSpecs()` is the ONE property table** (parser, writer, Style-tab widgets, tooltips). The built-in `defaults()` ARE the Classic look (so "no sheet" == "classic sheet", one code path); the **`classic` built-in sheet is deliberately EMPTY of rules** (restating a default freezes a value the MENU should supply - it re-froze every project's `accent`, caught by the pixel diff). `write(parse(t))` must be STABLE (the Style tab saves through it). `stage()`/`unstage()` are the preview's door into the registry (one lookup path; the editor cannot show a different sheet than the build bakes).
- `menulayout.{hpp,cpp}` (~150+540): the single place a menu's geometry is decided; read by menubake (rasterizes), the Menu Editor (preview + cost) and templates.cpp (`menu_data.gen.hpp`) - none may re-derive it. `compute(menu, project)` resolves the sheet over `baseFor()` (**the menu's own accent/sizes/font/panel width are the BASE of the cascade** - the compatibility story), lays out the vertical flow, uniform-pitch rows (runtime cursor = `row0Y + i * rowH`), state/description/list atlases and the VRAM estimate. Host-only, no fonts. `kMaxRows` = 32 (was 8; a scrolling list moved rows into their own windowed texture).
- `menustyle_ui.cpp` (~1.5k): Style tab, raw Stylesheet tab, shared preview. Style edits have their OWN undo stack (a stylesheet is not project data; `commitChange()` must not see it). The widget comes from the property's `Kind`; WHERE it shows is `propsFor()`. The override CHECKBOX seeds its declaration from the currently resolved value (turning an override on moves nothing); the preview stages the unsaved sheet via `menustyle::stage`.
- New **style property** = a `propSpecs()` row + a `case` in `applyDecl` + a `propsFor()` entry + wherever menulayout/menubake reads it.
- A pixels-only property never reaches codegen; one that moves a sprite is what `menu_data.gen.hpp` carries, and `renderGameMenu` is a **compositor over that table that decides nothing about the look** - adding look logic to the runtime is the mistake this design prevents.
- **Stale-file delete**: `refreshGenerated` writes state/list/description textures only when the sheet needs them and REMOVES them when it stops (else a non-scrolling menu ships a strip into VRAM).
- Logical 512x448 space; runtime scales by `(width/512, height/448)` per display mode (`Tyra::Sprite` per-axis `drawSize`, tyra-engine-dev). `project::displayModes()` is the ONE geometry table.
- **Widescreen is anamorphic (a 2D problem)**: `renderGameMenu`'s horizontal factor divides `RendererSettings::getWindowAspect()` back out over 4:3. Cannot bake twice - Set Widescreen and the DISPLAY row flip aspect at runtime, so derived values resolve per frame (cutscene bars ship a STYLE + runtime `barsFractions` twin; `seqBarsFractions` takes the aspect). Runtime text inside a compensated panel carries the same squeeze (`drawFontText`'s `sx`). The Menu Editor preview applies the factor plus an **Aspect** override.
- **Motion is sprite properties only** (`@transition` reacts, `@animate` loops): an animated background is a LAYER whose sampling window moves; a scroll bakes two tile copies per scrolled axis (no wrap mode). Anything over the panel is cropped by hand (2D sprites are unclipped - the sheen first appeared beside the menu).
- **An empty `GameMenu::style` bakes byte-identically to the pre-stylesheet editor**: check with `--refresh-gen` on an example with both binaries, diff `res/menus/*.png`.
- `.menustyle` editor support lives in `tools/vscode-tyrax`: repackage the `.vsix` (codegen-and-generated-files.md).
- `menubake.cpp/.hpp` (~2.7k+500): panel bake (title, labels, hints, border, images; vertical flow AboveTitle/AboveEntries/BelowEntries + Background/Overlay layers), all text bakes (`bakeTextRGBA`/`bakeTextPNG`), credits strip, icon atlas, glyph atlases.

## Text: fonts and icons

- **`Project::fonts` (`GameFont`) is the single font registry** (Tools > Font Manager, `drawFontManagerWindow`, hud_ui.cpp). Text carries a font NAME (`HudText::font`, `GameMenu::font`); only `GameFont::fontPath` names a file, resolved in `menubake::resolveFontPath` (Consolas Bold fallback chain; system lookup via `platform::systemFontPath`). `fonts[0]` is the fallback for empty/stale names (`Project::findFont`); the last entry cannot be deleted. Pick with `App::fontCombo`; `fontSourceCombo` (TTF picker) belongs to the Font Manager. Renames via `App::renameFont` (texts, menus, `FontName` node params).
- **Static text** (HUD texts, menus, loading screens) is rasterized at build (`menubake::bakeText*`); the font never reaches the PS2.
- **Runtime text** (Display Text node, rebind rows, vehicle HUD/controls card) uses a **glyph atlas** (`atlasLayout`/`bakeAtlasPNG` -> `res/fonts/atlas-<name>.png`, metrics into `inc/font_data.gen.hpp` via `fontDataHeader`, both from ONE `atlasLayout()` call). Only fonts in `Project::atlasFontIndices()` get one (must list the save menu's font, menus with rebind rows...). Atlases bake WHITE and are tinted at runtime. One runtime slot per node: `dynTextSlots()` is walked identically by `fontDataHeader` and `flowGraphScript`. `drawFontText` CENTRES on x (left-align = add half of `fontTextWidth`) and has a trailing `alpha` (128 = old output).
- `fontGlyphSprite` (shared generated helpers) owns one persistent sprite + atlas link per font (1.150.1); `setupVehicles` (inside `loadScene`) prepares valid HUD fonts for driveable instances and does their first evictable `useTexture` (AI-only/HUD-disabled instances don't); scene revisits reuse the texture. Runtime inline icons stay lazy until a resolved, nonempty icon draws in the foreground pass; numeric vehicle strings and unknown tokens must not load the sheet. Preserve glyph metrics, centering, shadow, widescreen squeeze.
- **Inline text icons** (`{{cross}}` / `{{action:jump}}`, docs/text-icons.md): `Project::textIcons` (`TextIcon`: name + PNG + scale, seeded per pad button by `project::ensureTextIcons`, edited in UI Editor > Button icons). Parser shared header-only (`parseTextIcons` in project.hpp -> `TextRun`s); two TWIN renderers: `textWidth`/`drawText` in menubake.cpp (baked sprites: menus, HUD texts, loading screens, value strips) and the game's `resolveIconToken`/`drawFontText` blitting `res/hud/icons.png` with rects from `inc/icon_data.gen.hpp`. Both take geometry from `menubake::iconAtlasLayout`; `iconAdvance`/`iconAdvanceFor` change together. Icons are not tinted (DualShock palette), skipped in shadow passes; an unknown `{{token}}` stays literal. `menubake::optionalBuiltinIconNames()` = drawable built-ins NOT seeded by `ensureTextIcons` (stick glyphs; `project::ensureStickIcons` adds them when the controls card is ticked).

## Credits rolls (`CreditsRoll`/`CreditsBlock`, docs/credits.md) - "a whole screen the game hands over to"

- **The roll owns the frame**: the loop hook (BOTH game-cpp heads, right after the boot-splash block) ticks `credits::tick` and `return`s while `credits::playing()` (inline over one extern int - asked every frame). Anything owning the screen must ALSO own the pad, or the ending press reaches gameplay.
- **A finish action, not a caller contract**: `CreditsRoll::Finish` (resolved to indices in `credits_data.gen.hpp`); the player reports `credits::Result`; the loop turns it into existing requests (`scriptCtx.requestScene` / `openMenu` / `pendingEvent`). `pendingEvent` exists because `updateGameMenu` is the single place that clears `menuEvent` - an earlier-queued event is promoted there or wiped. A SKIP runs the same finish action.
- **`On Credits Finished` cannot be a falling edge** (a roll freezes every graph): the runtime counts finished rolls (`credits::endCount()`), the node fires when its copy falls behind; a scene reload re-syncs to the LIVE count. Any "the world was frozen while it happened" trigger needs this shape.
- `credits_ui.cpp` (~980): rolls are project-wide (outside undo) but still committed with `commitChange()` (it once called `saveAll()` per widget). **The roll's BAKE is the single source of its look**: `menubake::bakeCreditsStripRGBA` lays blocks out and rasterizes a strip of pow2 PAGE textures; the preview uploads THOSE pixels and positions them with the generated player's arithmetic. `creditsPreviewRefresh()` re-bakes on change (`CreditsRoll::operator==` + the fonts' TTF paths - not a hand-built signature). Pages are a VRAM decision (`menubake::kCreditsMaxPages` = 16; the GS pins every drawn texture): the window reports pages/duration/VRAM and says *content clipped*. Height splitter `creditsSplit_` (the `matEdSplit_` idiom: InvisibleButton + `MouseDelta` + `saveGlobalConfig()` on release, editor.ini). **Jump to** list inverts the roll timing ("when is this block centred").

## Save system (`savebake.cpp/.hpp` ~930+130, Tools > Save Editor, docs/save-editor.md)

- `icon.sys` (964 B; browser title with `|` line break; the PS2 browser renders ONLY full-width Shift-JIS, so ASCII maps to 0x81/0x82-row full-width forms) and `list.icn` (PS2 3D icon). Geometry sources (`iconInfo`/`iconIcn`): flat image quad, a `res/models` `.obj` (+ map_Kd), or an animated `.glb` whose clip is sampled into <= 8 morph shapes via `glbparser::bake`.
- **Animation encoding**: each frame's keys are that shape's WEIGHT envelope (tent peaking at its own tick, shape 0 closes the loop); the browser lerps keys and blends by weight. One key per frame reads as weight ~0 and the icon renders INVISIBLE (semantics per mymcplus/ps2icon.py; key 0 sits where old docs saw "two unknown" u32s).
- **Idle motion** (`iconMotions()`/`applyMotion()`): sources without animation get one of six presets baked as displaced copies of shape 0. `iconMotions()` order IS the enum (append only); `.tyra` stores the string key; `iconMotionIndex("")` = sway (pre-setting behavior). Amplitudes derive from model height and stay small (the browser LERPS shapes; big rotations cut through the model).
- `iconPreviewFrames()`: small software rasterizer (z-buffer, barycentric, two-sided abs(N.L)) over the SAME `buildGeo` result, one image per shape - a model without `map_Kd` carries colours in VERTICES against a near-white `modelFallbackTexture`, which the old texture-only preview showed as a blank square. Preview and stats come from one bake.
- Written to `res/save/` every `refreshGenerated` (through `writeFile`); copied to the card by the generated save system (`saveEnsureIcons`, buffer sized from `iconInfo().bytes`).
- **The save menu is a `GameMenu` with `saveMenu = true`** (seeded by `project::ensureSaveMenu`, found with `saveMenuIndex`). Its `entries` are NOT authored: `menubake::asBaked()` swaps in `Project::saveSlotsPerPage` blank rows (panel, preview and row metrics count alike). Labels draw at RUNTIME with `drawFontText` (`MenuData::row0Y/rowH/font`) because baked labels cannot page.
- **Async writes** (`SAVE_ASYNC`): `saveWriteBegin`/`saveWritePoll` drive open/write/close one step per frame with `mcSync(MC_NOWAIT)`: **0 = still executing, 1 = finished, -1 = nothing registered** (treat -1 as failure or the poll spins forever). The payload is COPIED to a static first. Loads stay blocking.
- **Busy spinner**: a sprite SHEET walked with `Sprite::offset` (`MODE_REPEAT`; `MODE_STRETCH` ignores `size`). **Both sheet dimensions must be powers of two** (192x24 asserts and the game never leaves the TyraX splash - reads as a hang). `savebake::spinnerInfo()` is the single arbiter: validates a user PNG (POT sides, width divisible by cell count) and FALLS BACK to the built-in, so codegen, preview and warning agree. Any "pick your own PS2 texture" setting: validate host-side, fall back, say why in the panel. `busyText()` = single source of the "checking memory card" sprite + its size constants.
- `save_assets.cpp` (~540): built-in save-menu HUD sprites as embedded PNGs written to `res/hud/` when missing (slot-row geometry `y = 40 + slot * 24` is mirrored by the generated `renderSaveMenu()`).
