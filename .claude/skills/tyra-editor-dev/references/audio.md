# Audio: the Drone Generator, editor audio output, WAV conversion

Read when you touch `dronegen`, `droneui.cpp`, `audiopreview`, `wavconvert`, sound import/bake, or any game-side sound playing (for SPU2 voices and reverb buses see scene-objects-and-gameplay.md, "Areas").

## Drone / ambient music generator (`dronegen.cpp/.hpp` ~2.6k+470, Tools > Drone Generator, docs/drone-generator.md)

- Host-only, no GL, no `Project` (harness: link dronegen.cpp alone, render presets, measure). Output is an ORDINARY asset: a 16-bit PCM WAV in `res/audio/` + a `.drone` patch sidecar; nothing downstream knows the generator exists - never add a project field for a patch.
- (1) **The audition IS the renderer**: `Synth::render` is the only DSP; `LiveSynth` wraps it for the audio thread; offline `render()` runs the same loop then masters. A knob sounding different in file vs preview means duplicated DSP.
- (2) **`Params` determinism**: every random stream derives from `seed` through `mix32`; re-renders are bit-identical; new random sources derive the same way.
- (3) **`visitParams` is the ONE field list** the `.drone` writer and reader walk; a `Params` field missing there is silently never saved.
- Seamless looping ADDS the rendered tail over the head (what a looping player hears) instead of crossfading, but the fold MUST be windowed to zero at its end (unity then raised cosine): an un-windowed add left a step one loopTail into the file - an audible tick, 0.37 vs a 0.11 p99 neighbour jump (PROGRESS 212). Reverb = 8-line FDN (comb banks ring metallic at 30-second tails).
- **Timeline**: `paramTable()` is built by walking `visitParams` (every saveable scalar automatable by byte offset); `Params` carries fixed-capacity `AutoLane`s (no heap - copied into the audio thread). `applyAutomation` runs once per control block INSIDE the synth's own copy (modulation still layers on top). Tempo/format/mastering fields are excluded (`autoExcluded`): `barSeconds` is read once per `render()`, so a tempo lane would do nothing.

## The window (`droneui.cpp` ~1.9k)

- Owns widgets the rest of the editor lacks: rotary `knob()` (vertical drag, Shift fine, double-click resets, `curve` for frequency/time, symmetric ranges drawn bipolar), `knobInt`, arc-envelope editor, scope/analyzer/meters strip. **A knob's label IS its ImGui ID** (two "Mix" knobs collide: `Mix##delay`/`Mix##reverb`).
- **`AutoWriteHook`**: arming Write automates all ~137 parameters without any knob call site knowing (a knob binds straight to a `Params` field, so its pointer IS the parameter address; the hook turns that into a lane).
- Transport: Generate (free-running past the end) and Record (stops at the end; `Rec` arms keyframe writing); BOTH play from the playhead; the end-of-piece stop is POLLED on the UI thread, never fired from the audio callback.
- **A seek must SETTLE** (`Synth::setTime`, PROGRESS 216): state at time T is the product of 0..T, so a bare jump lands in the opening fade-in. It snaps notes to the chord and an attack-since-chord-start level, jumps periodic LFOs analytically, and pre-rolls 1-3 s of discarded audio for delay/reverb lines. Dragging passes `settle=false`; the release settles once.
- Rules: every parameter edit ends in `dronePushParams()` (live playback); the render runs on `droneRenderThread_` and is read only after `droneRenderDone_` (Runner idiom); `droneTickRender()` writes the WAV + `.drone` and calls `saveAll` (one of the sanctioned call sites); `droneHeadSec_` is the ONE playhead; all pixel literals go through `scaled()`. On project close: `droneStop()` and cancel+join the render (audio device first, then the render thread - editor-ui-and-conventions.md, "Project lifetime").

- **Simple view** (`drone_simple_ui.cpp`, the default; `droneDetailed_` / editor.ini `droneDetailed` flips to Detailed = `drawDroneDetailed`): NO saved field - every control reads back from `Params` and writes via `dronegen::simple` (moods, `read/write` of six sliders, feelings, shapes, length, loudness; host-only, harness-checked `read(write(P0,r0,r)) == r` and `write(P0,r0,r0) == P0` bit for bit). A drag writes from a snapshot taken on `IsItemActivated` (`droneDragP0_`), never accumulates; a laned field is transformed keyframes and all and reads as the lane mean. Mood recipes start from `moodBase()` (NOT `Params()`, whose default mod rows would leak). *+ Play in another scene* adds OnStart -> PlayMusic with one `commitChange`. IDs: `##drn_mood_N`, `##drn_bright`...`##drn_chimes`, `##drn_shape`, `##drn_feeling`, `##drn_loud`, chips `30 s`/`1 min`/..., `Another take`, `Undo`, `Save to project`, `Open in Flow`, `+ Play in another scene...`, view switch `Simple`/`Detailed` (qualify with `Drone Generator/` - the Ambience Editor has the same pair).

## Editor audio output (`audiopreview.cpp/.hpp` ~160+70)

The editor's only audio path: a miniaudio (`vendor/miniaudio`, in deps.sh + deps.ps1) playback device pulling interleaved stereo floats from a callback. The ONLY TU including miniaudio, trimmed to the raw device API. Backends are dlopen'd (WASAPI / ALSA / Pulse / JACK): no system package, no link-time dependency; no sound card is expected - `start()` returns false and the caller stays an offline renderer. `stop()` joins the audio thread (`ma_device_uninit`), making it safe to destroy what the callback captured (App::run does this before teardown). `audiopreview::EngineLoop` is the vehicle engine audition (vehicles-and-roads.md).

## WAV conversion and the sfx bake (`wavconvert.cpp/.hpp` ~280+40)

- Reads the fmt chunk (1 = integer PCM - the only thing the PS2 side streams, 3 = float; `WAVE_FORMAT_EXTENSIBLE` resolved); converts IN PLACE to 16-bit PCM (imported and hand-dropped assets fixed where they are; no second copy).
- Sound effects (1.157.0): `wavconvert::soundIssue` requires canonical mono PCM16/22050; import and Project > Sounds > Convert downmix too. The Runner calls `wavconvert::bakeSounds` AFTER texbake and BEFORE either build backend, preparing `.res-baked/sfx` without modifying `res/sfx`. Both encoders read this mirror, check cached APCM byte 5 for mono and byte 6 for loop intent, and keep the source path for role matching. A conversion error must FAIL the build. Music stays stereo unless its own mono option is chosen.
- Verify: stereo PCM16, PCM24, float, extended headers, an odd metadata chunk; duration, source hashes, incremental mtime stability, ADPCM mono/loop headers in BOTH backends. Decode the actual ADPCM and compare waveforms - header checks alone missed adpenc's corrupt stereo reader (`fread(wave+i, 2, ...)` advances by one byte).
- Vehicle loop intent: `inc/vehicle_sound_loops.gen.txt` (vehicles-and-roads.md); legacy `-loop.wav` still works.
