# Raw evidence: inside `bounds` and inside the package box (2026-09-16)

The 960 per-frame rows behind the second half of
[docs/render-submission-attribution.md](../../../../docs/render-submission-attribution.md)
— the split of the static pipeline's `bounds` bracket and of the "package
creation and classification" residual inside `dispatch`. **PCSX2 only**; no
console was touched. PCSX2 models no EE data cache, so the SHARES here travel
to hardware and the milliseconds do not.

## Why this round exists

`bounds` had already been attacked twice, plausibly and carefully, for a
combined **2%** of the bucket: a branchless `frustumCheckAABB` (4.132 → 4.073
ms on the console) and a compacted `partBounds` stride (4.073 → 4.051). The
remaining suspect on the page was the bbox cacher. This round measured it
instead of guessing a third time, and **the cacher is not it either** — see
below.

## The arms

One fixture, regenerated by the editor under test, then copied. The engine half
(`TYRA_STAPIP_ATTRIB`) and the one-line `setMaxVertCount` early-out are the only
knobs; the assets, the generated game and the `.tyra` are common mode.

| arm | counters | the fix | what it is for |
| --- | --- | --- | --- |
| `attrib-before` | **1** | no | the attribution table |
| `attrib-after`, `attrib-after-boot2` | **1** | yes | the same table after, and its repeatability |
| `control-before-boot1/2` | 0 | no | the shipped configuration, twice |
| `control-after-boot1/2` | 0 | yes | the shipped configuration after, twice |

The control pairs are the same ELF booted twice: on `bounds` they differ by
**0.000–0.004 ms**, which is the floor every delta is read against.

## How they were made

```powershell
python examples\vehicle-playground\authoring\benchmark-district.py `
    $env:TEMP\tyra-editor-test\dbnd --profile release
build\tyrax-editor.exe --build $env:TEMP\tyra-editor-test\dbnd   # REGENERATE
#   then copy per arm, and from here on native-build ONLY - an editor --build
#   would regenerate the instrumentation away
python examples\vehicle-playground\authoring\instrument-frame-cost.py <copy> --attribute
#   set TYRA_STAPIP_ATTRIB in stapip_attrib.hpp per arm
tools\toolchain\native-build.ps1 -Project <copy> -Engine <worktree>\vendor\tyra `
    -Cache <the editor's own cache for this worktree> `
    -Toolchain $env:LOCALAPPDATA\tyra-editor\toolchain\ps2dev
#   boot each ELF in PCSX2, wait for bin/frame-attrib.csv (960 rows, ~55 s)
```

## Reading them

```bash
python summarize_bounds.py before=<dir> after=<dir>
```

It prints the per-pose means plus the derived subtractions. The two that matter
are `bounds residual` and `dispatch residual`: the children must sum to their
parent, and they do — **0.050 of 2.055** and **0.023 of 5.835** on garage day,
in all four poses of every arm.

## What the hooks cost

Stated because a table that does not state it is not finished. `attrib-before`
against `control-before`, garage day, same fixture:

| bracket | counters out | counters in | hook cost |
| --- | ---: | ---: | ---: |
| `bounds` | 1.933 | 2.055 | **+0.122** |
| `prepare` | 1.089 | 1.113 | +0.025 |
| `dispatch` | 5.773 | 5.835 | **+0.062** |
| `submit` | 14.457 | 14.609 | +0.152 |

So the `bounds` children over-report by **6.3%** and the `dispatch` children by
**1.1%**; subtract that before quoting a child as a share of the shipped
bracket. `bounds` carries seven bracket pairs per bag — fourteen `mfc0` reads —
which prices one COP0 read at about **11 cycles (0.038 µs)**. That is a real,
measurable cost, unlike the previous round's engine half, which had a tenth as
many brackets and did not reach the noise floor.

## The picture

Twelve `-PrintWindow` captures — both DAY poses, both arms, three repeats each
— are **byte-identical, 0 pixels changed**, once the emulator's own chrome is
cropped (`--crop-top 35 --crop-bottom 30`: PCSX2's title bar and its live FPS
readout are the only things that move in a parked frame). `compare_captures.py`
checks the within-arm repeats FIRST and refuses to report a between-arm number
until they are clean.

The NIGHT poses are deliberately not compared: the district's lamps flicker and
its stars twinkle, so three captures of one arm differ from each other there and
no between-arm difference is readable. That is a property of the fixture, not of
anything measured here.

## Limits

Four parked poses of one scene in one emulator. Every included bucket contains
its children, so nothing may be summed across levels or inverted into a frame
rate. `vif_wait_included_ms` brackets `dma_channel_wait(VIF1)` and is not a
measurement of VU1 execution. `dsDirect`, `dsRender` and `dsFlush` are
INCLUSIVE of the packet construction and the send reached from inside them;
`dsClassify` is the one exclusive bracket. The `triangles` column counts GS
primitives, so its value for a stripped scene includes degenerate joins.
