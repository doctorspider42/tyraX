# Raw evidence: attributing render submission (2026-09-16)

The 960 per-frame rows behind
[docs/render-submission-attribution.md](../../../../docs/render-submission-attribution.md).
Four arms of one Motor District fixture, **PCSX2 only** — no console was
touched, and PCSX2 models no EE data cache, so the SHARES here travel to
hardware and the milliseconds do not.

## The arms

One fixture, built once by the editor under test, then copied four ways. Only
the two instrumentation knobs differ; the assets, the generated game and the
`.tyra` are common mode.

| arm | game half | engine half | what it is for |
| --- | --- | --- | --- |
| `armC-boot1`, `armC-boot2` | plain `instrument-frame-cost.py` | `TYRA_STAPIP_ATTRIB` 0 | the control, twice, for the noise floor |
| `armB` | `--attribute` | 0 | prices the game-side phase brackets |
| `armA` | `--attribute` | **1** | the engine's per-bag split |
| `armA2` | `--attribute`, plus the four subset brackets | **1** | the same, with the wheel/terrain/probe/object splits |

`armA` and `armA2` are different ELFs of the same measurement and agree to
**0.003 ms of `submit_ms`**; the two `armC` boots are the same ELF twice and
differ by **0.056 ms**, which is the floor every delta on the doc page is read
against.

## How they were made

```powershell
python examples\vehicle-playground\authoring\benchmark-district.py `
    $env:TEMP\tyra-editor-test\dattr --profile release
build\tyrax-editor.exe --build $env:TEMP\tyra-editor-test\dattr   # REGENERATE, then
#   copy to dattrA / dattrA2 / dattrB / dattrC
python examples\vehicle-playground\authoring\instrument-frame-cost.py <copy> [--attribute]
#   set TYRA_STAPIP_ATTRIB in stapip_attrib.hpp for the A arms
tools\toolchain\native-build.ps1 -Project <copy> -Engine <worktree>\vendor\tyra `
    -Cache <a cache of your own> -Toolchain %LOCALAPPDATA%\tyra-editor\toolchain\ps2dev
#   then boot each ELF in PCSX2 and wait for bin/frame-attrib.csv
```

`--build` once, `native-build` after that: an editor build would regenerate the
instrumentation away. The full-asset gate
(`../vu-cost-dma-cache-2026-09-15/check_assets.py`) reports **105 reference
files, 105 deployed, none missing** against the September-15 manifest; 28 of
them differ and 4 model-AO hashes moved, which is the fixture having been
regenerated by the editor under test rather than built from the example's
committed generated sources. That is required, not a defect — see
docs/vu1-and-dma-cache-cost.md, "the fixture was stale".

## Reading them

```bash
python summarize_attrib.py A2=<dir containing both CSVs>
```

It prints the per-pose means of every column plus the derived subtractions
(`game_ee_in_rs`, `wheel_rebake`, `objLoop_tests`, `sp_uncovered`,
`dispatch_resid`, `rs_residual`). `rs_residual` is the check that matters: the
thirteen renderScene phases must sum to renderScene, and in all four poses of
all three attributed arms they do, to **0.000 ms**.

## Limits

Four parked poses of one scene in one emulator. Every included bucket contains
its children, so nothing may be summed across levels or inverted into a frame
rate. `vif_wait_included_ms` brackets `dma_channel_wait(VIF1)` and is not a
measurement of VU1 execution. The `triangles` column counts GS primitives, so
its 40 502 for a 25 650-surface scene is the strip representation's degenerate
joins, not a miscount (see `StaPipTelemetry`'s header).
