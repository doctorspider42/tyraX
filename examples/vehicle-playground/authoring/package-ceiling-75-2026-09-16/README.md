# Raw evidence: raising the VU1 package ceiling to 75 (2026-09-16)

The derivation behind
[docs/render-submission-attribution.md](../../../../docs/render-submission-attribution.md),
"Round four", and behind the clip-buffer budget section of
[docs/vu1-clipping.md](../../../../docs/vu1-clipping.md).

Round three ([package-ceiling-2026-09-16](../package-ceiling-2026-09-16/README.md))
established the bound and took no change. This round takes the cheap half of
it — the rounding step in `StaPipVU1Program::getMaxVertCount`, which moves the
package ceiling from **72 to 75** and the baked strip run with it — and it
turned out not to be free in the way round three assumed.

## `clip-buffer-margin.cpp`

**The one that matters.** Round three checked that a clip package still fits
its VU1 double-buffer half using the constructor's `elementsPerVertex` /
`reglistCount` pair. That pair is `getMaxVertCount`'s *sizing budget*, not the
buffer *layout*: the `d` and `td` classes spend part of it on an uploaded
normal stream rather than on output registers, so using it here reports
overruns on classes that ship today and work.

This harness transcribes the real layout off the five `stapip_clip_*_vu1.vclpp`
sources — uploaded streams, quadwords stored per emitted vertex, and the size
of the GIF tag block each one writes — and prices the worst-case
Sutherland–Hodgman fan-out against the 460-quadword half, for every combination
`StaPipCore::render` can actually reach.

```bash
g++ -O2 -std=c++17 -o clip-buffer-margin clip-buffer-margin.cpp
./clip-buffer-margin
```

What it reports, as the tightest margin over every reachable class:

| arm | tightest clip-buffer margin |
| --- | ---: |
| before this round: rounding `/9`, `clipDivisor` 5 | 35 quadwords |
| the naive relaxation: rounding `/3`, `clipDivisor` 5 | **1 quadword** |
| shipped: rounding `/3`, `clipDivisor` 6 | **91 quadwords** |

The one-quadword row is `clip_c` with a single colour. Relaxing the rounding
takes that class from 144 to 150 vertices, so `clipPackageSize()` takes it from
27 to 30, so it occupies 459 of 460 quadwords. It **fits** — the bound of 7
output triangles per input triangle is exact, because Sutherland–Hodgman on a
convex polygon gains at most one vertex per plane and the plane loop runs
exactly six times — but one quadword of headroom on the one path PCSX2 cannot
verify is not a margin to ship. Hence `clipDivisor` 5 → 6 in the same commit.

It is close to free where this scene lives: `cull_tc`, `cull_tce` (per-vertex
colours) and `cull_td` (one colour) all derive a clip package of **12 under
both** the old and the new configuration, so their clip route is unchanged and
only the cull route's packages get 4% fewer.

**Re-run this after any edit to `getMaxVertCount`, `clipPackageSize`,
`clipDivisor`, or a clip image's buffer layout.** It needs nothing from the
tree — every constant is copied in and named next to the file it came from.

## What the round-three harness still says

[`../package-ceiling-2026-09-16/derive-package-size.cpp`](../package-ceiling-2026-09-16/derive-package-size.cpp)
already carried a `/3` column, and it is unchanged and still correct:
`minPackageSize()` over the six reachable combinations is **72** with the old
rounding and **75** with the new one, which is what `meshstrip::kRun` must
equal. Its `DBUFFER_END` sweep is also unchanged, and it is still what says the
remaining lever (81, by reclaiming the clipping scratch) needs `DBUFFER_END` at
1014 or above.

Both arms were regenerated by the editor that built them and their ELFs hash
differently, which is the check that stops two "arms" from being one
(`benchmark-district.py`'s own docstring, and docs/vu1-and-dma-cache-cost.md's
retraction, are about exactly that failure).

## Limits

This is arithmetic, not a measurement: it bounds the worst case, and the worst
case is what a corruption bug needs. It says nothing about milliseconds. The
frame-level counters for this change are in the round-four section of the
attribution doc, and like everything else in this directory below the recipe
they were taken in PCSX2 — **no console was touched.**
