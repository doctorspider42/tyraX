# Physics and frame-escape rig

The rig behind the 2026-11 physics and frame-spike work (PR #311: body
batches, terrain settle, incremental broad phase, off-screen sleep, vehicle
prebake steps). Where the parent rig ([../README.md](../README.md)) compares
arms by window medians, this one records **every frame** of a scripted drive
into a crate field and a parked car, so a single 25 ms frame can be taken
apart.

A run is one arm, one ELF, on the physical PS2. PCSX2 proves correctness only.

## How a run works

`game/kf.py` adds a scripted drive (frames 250..750: full throttle + nitrous,
straight ahead) and a ring of 1000 frame records (frames 200..1199). Nothing is
printed while the ring fills; at frame 1300 the game dumps it as `KF` lines
(per-frame period, pre, work, stall and the loop's own scopes, 0.01 ms units)
and `KFL` lines (36..43 = the slots the optional probes fill). A frame whose
period is over 17.5 ms is a **miss**.

## Files

| Path | What it is |
| --- | --- |
| `make_stress.py SRC DST [PARTS]` | A stress copy of a vehicle-playground project: `cratefield`, `crates`, `props`, `buildings`, `pavements`, `cars`, `instanced`, `release`. Deterministic. |
| `engine/setup.py DST` | The rig engine: a copy of `vendor/tyra` at `DST` with every engine probe applied in order, then `rig-base.patch`. `vendor/tyra` is never touched. |
| `engine/*.py`, `engine/rig-base.patch` | Engine probes (late-event ring, `TYRA_LOG` mute, GPU-wait totals, StaPip route costs and PMU, stamp census) and the counters the game probes read. |
| `arm.sh NAME SRC [probes...]` | Copy `SRC` to `$RIG_ROOT/NAME`, regenerate it with the current editor, instrument it, build it against the rig engine. |
| `game/apply.py PROJECT [probes...]` | The instrumentation: always `kf kf2n kf3 physlaps phys2`, then the named optional probes in a fixed order, prerequisites added. |
| `game/*.py` | One probe each; the docstring says what it records and which KFL slots it takes. |
| `analysis/*.py` | Log readers: `kfmiss.py` (misses + work median/p95), `lab_miss.py` (labels on missed vs clean frames), `settle_sum.py`, `gw_sum.py`, `late_sum.py`, `kf_sum.py`/`kf2_sum.py`/`kf3_sum.py` (timeline around the hit), `warm_sum.py`/`pmu_sum.py`/`ab_sum.py` (StaPip routes). |

Optional probes, by question:

| Question | Probes |
| --- | --- |
| Is the run's own logging costing frames? | `mute` (always use it for timing) |
| Which loop phase ran late? | `late` |
| Static batches and settles | `batchlap`, `settlelap`, `reblap` (after `settlelap`) |
| Bake events in a window | `bakeev2` (env `BEV_F0`, `BEV_F1`) |
| GPU waits vs EE work | `gpuwait` (not with `settlelap`) |
| Terrain chunks | `terrlap`, `chunklap`, `chunkid`, `emitlap` |
| Object loop, broad phase, awake bodies | `objlap`, `bplap`, `awakevis` |
| Memory held per system at frame 150 | `memmap` |
| StaPip routes per frame, same-ELF arms | `route`, `arm`, `warm`, `stampcen`, `site`, `stamplap`, `cell` |

Probes that fill KFL 36..43 overwrite each other: one family per arm.

## Running

All commands from Git Bash on Windows; `RIG_ROOT` defaults to `/c/tx` and
must stay short (ps2link's `loadelf` crashes on long `host:` paths).

```bash
python tools/ps2rig/physics/engine/setup.py C:/tx/tyra-phys
```

```bash
python tools/ps2rig/physics/make_stress.py examples/vehicle-playground C:/tx/STC cratefield,crates,pavements,release
```

```bash
bash tools/ps2rig/physics/arm.sh P1 /c/tx/STC mute settlelap
```

```bash
bash tools/ps2rig/deploy.sh /c/tx/P1 /c/tx/run-P1.log noreset
```

Run the deploy as a background task and stop it after ~40 s (the dump comes
at frame 1300), then:

```bash
python tools/ps2rig/physics/analysis/kfmiss.py /c/tx/run-P1.log
```

Rebuild the editor (`build.ps1`) before `arm.sh` when the change is in
codegen: the arm is regenerated by `$EDITOR` (default `build/tyrax-editor.exe`).
Re-run `engine/setup.py` after `vendor/tyra` changed; mirror an engine fix
there before measuring it.

## Traps

- **Judge 60 FPS in release.** A debug build costs ~1.1-1.4 ms a frame more
  (docs/profiling.md). Use the `release` part for headline numbers.
- **Console wedges.** A ps2link reset after a near-full (~29.5 MB) stress
  build can end in `DMA Busy`: power-cycle and deploy `noreset`. Run the heavy
  arms last; the crates-only scene resets fine.
- **Fixture.** The 2026-11 numbers were taken on a copy of a user project with
  a hand-built ~120-crate run (`crates,pavements` on it = 366 crates);
  `cratefield,crates,pavements` on the example rebuilds the same shape, not
  the same frames. Compare arms built from one fixture only.
- **Anchors.** Every probe edits by exact anchors and stops with the anchor it
  missed. Update the anchor; never loosen it.
- **Never reuse an arm name**, never kill `ps2client` by name.
